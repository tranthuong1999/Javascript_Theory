2. Mục tiêu cần nắm và áp dụng
Sau bài này, bạn cần:
- Truy cập được HTML , head , body từ document
- Phân biệt children với childNodes.
- Sử dụng firstChild, lastChild, nextSibling, previousSibling.
- Phân biệt parentNode với parentElement
- Hiểu Dom collection là gì đặc điểm live/read-only và cách chuyển thành Array.
- Duyệt DOM chỉ với element node khi không cần text/commment node
- Truy cập các hàng và ô trong bảng HTML bằng những thuộc tính riêng biệt 
- Biết khi nào nên sử dụng DOM navigation trong React và vì sao Backend Nodejs không có DOM mặc định 

3. Nội dung bài học
3.1. On top: documentElement and body
Giới thiệu 3 thuộc tính của document để truy cập các node ở cấp cao nhất
| HTML element | JavaScript                 |
| ------------ | -------------------------- |
| `<html>`     | `document.documentElement` |
| `<head>`     | `document.head`            |
| `<body>`     | `document.body`            |

<!-- 
console.log(document.documentElement);
console.log(document.head);
console.log(document.body);
 -->
Trong đó:
-  document.documentElement là node đại diện cho thẻ <html>
-  document.head là node đại diện cho <head>.
-  document.body là node đại diện cho <body>.
Trường hợp dễ nhầm: document.body có thể là null.
<!-- 
<html>
<head>
  <script>
    console.log(document.body); // null
  </script>
</head>

<body>
  <script>
    console.log(document.body); // HTMLBodyElement
  </script>
</body>
</html>
 -->
Trình duyệt đoc HTMl từ trên xuống . Khi script trong head chạy, trình duyệt chưa đọc đến thẻ body , nên document.body chưa tồn tại
Khi script trong body chạy , trình duyệt đã tạo node đó nên có thể truy cập 
Ý nghĩa của null trong DOM: node chưa tồn tại hoặc không có node tương ứng

3.2. Children: childNodes, firstChild, lastChild
Trước tiên cần phân biệt hai khái niệm:
- Child nodes: các node con trực tiếp của một node
- Descendants : toàn bộ node nằm bên trong node đó , bao gồm con ,  cháu và các cấp sâu hơn
Ví dụ:
<!-- 
<body>
  <div>Begin</div>

  <ul>
    <li>
      <b>Information</b>
    </li>
  </ul>
</body>
 -->
- Children trực tiếp: div, ul và các text node chứa khoảng trắng/xuống dòng.
- Descendants: ngoài các node trên còn có li, b và các node bên trong chúng.
childNodes:
Trả về collection chứa tất cả các node con trực tiếp , bao gồm :
- Element node
- Text node 
- Comment node
<!-- 
const body = document.body;

console.log(body.childNodes);
 -->
Với HTML có xuống dòng và khoảng trắng, kết quả có thể chứa cả những text node chỉ chứa whitespace
firstChild và lastChild
- firstChild : node con đầu tiên 
- lastChild : node con cuối cùng
Tài liệu chỉ ra hai quan hệ tương đương:
<!-- 
elem.childNodes[0] === elem.firstChild;

elem.childNodes[elem.childNodes.length - 1] === elem.lastChild;
 -->
Ngoài ra:
<!-- elem.hasChildNodes(); -->
Kiểm tra node có node con hay không
Case dễ nhầm:
<!-- 
<div>
  <p>Hello</p>
</div>
 -->
<!-- 
const div = document.querySelector('div');

console.log(div.firstChild);
 -->
Kết quả có thể là 1 text node chứa kí tự xuống dòng và khoảng trăắng , không phải p
Vì vậy, đừng mặc định firstChild luôn trả về thẻ HTML đầu tiên.

* DOM collections
childNodes trông giống array nhưng thực tế là một collection đặc biệt , có tính chất array like và iterable.
Đặc điểm 1: Có thể dùng for...of
<!-- 
for (const node of document.body.childNodes) {
  console.log(node);
}
 -->
Vì collection hỗ trợ Symbol.iterator.
Đặc điểm 2: Không có đầy đủ Array methods
<!-- 
const nodes = document.body.childNodes;

console.log(nodes.filter); // undefined
 -->
Muốn sử dụng filter, map, reduce... cần chuyển thành Array:
<!-- 
const nodes = Array.from(document.body.childNodes);

const elements = nodes.filter(
  node => node.nodeType === 1
);
 -->
Đặc điểm 3:DOM collections là read-only
Không thể thay thế phần tử trong collection bằng cách gán trực tiếp :
<!-- elem.childNodes[0] = anotherNode; // Không thay thế node trong DOM -->
Muốn thay đổi DOM phải sử dụng các phương thức thao tac DOM 

Đặc điểm 4: DOM collections thường là live
<!-- 
const children = document.body.childNodes;

console.log(children.length);

document.body.append(document.createElement('div'));

console.log(children.length);
 -->
Nếu children là live collection , số lượng node sẽ tự cập nhật khi DOM thay đổi
Tài liệu lưu ý: hầu hết DOM collections là live, chỉ có một số ngoại lệ.
Đặc điểm 5: Không dùng for...in để duyệt collection
<!-- 
for (const prop in document.body.childNodes) {
  console.log(prop);
}
 -->
for...in duyệt các enumerable properties, có thể bao gồm length, item, values và những thuộc tính khác mà bạn không muốn duyệt 
Hãy dùng for...of để duyệt các node.

3.3. Siblings and the parent
Siblings là những node có cùng một node cha.
<!-- 
<html>
  <head></head>
  <body></body>
</html>
 -->
head và body là siblings vì chúng có cùng cha là html.
Tài liệu giới thiệu ba thuộc tính:
| Thuộc tính        | Ý nghĩa                |
| ----------------- | ---------------------- |
| `nextSibling`     | Node anh em tiếp theo  |
| `previousSibling` | Node anh em phía trước |
| `parentNode`      | Node cha               |
<!-- 
// Parent của body là html
console.log(
  document.body.parentNode === document.documentElement
); // true

// Node sau head là body
console.log(document.head.nextSibling);

// Node trước body là head
console.log(document.body.previousSibling);
 -->
Case dễ nhầm: nextSibling và previousSibling tính cả text node và comment node.
Ví dụ:
<!-- 
<div>
  <p>First</p>
  <p>Second</p>
</div>
 -->
<!-- 
const first = document.querySelector('p');

console.log(first.nextSibling);
 -->
Kết quả có thể là text node chứa khoảng trắng/xuống dòng giữa hai thẻ p,chứ chưa chắc là thẻ p thứ 2
Nếu muốn đi đến element kế tiếp, cần dùng nextElementSibling ở phần tiếp theo.

3.4. Element-only navigation
Các thuộc tính trước đó tính tất cả node.Nhưng nhiều lúc chúng ta chỉ muốn duyệt những element HTML, không quan tâm text node hoặc comment node.
| Thuộc tính               | Ý nghĩa                   |
| ------------------------ | ------------------------- |
| `children`               | Các element con trực tiếp |
| `firstElementChild`      | Element con đầu tiên      |
| `lastElementChild`       | Element con cuối cùng     |
| `previousElementSibling` | Element anh em phía trước |
| `nextElementSibling`     | Element anh em tiếp theo  |
| `parentElement`          | Element cha               |
Ví dụ:
<!-- 
<div>
  <p>First</p>

  <p>Second</p>
</div>
 -->
<!-- 
const div = document.querySelector('div');

console.log(div.children);
console.log(div.firstElementChild);
console.log(div.lastElementChild);
 -->
Kết quả chỉ tập trung vào các element,bo qua text node do khoảng trắng và xuống dòng
Phân biệt parentNode và parentElement
Thông thường hai thuộc tính này trả về cùng một kết quả, nhưng có một ngoại lệ quan trọng trong bài:
<!-- 
console.log(
  document.documentElement.parentNode
); // document

console.log(
  document.documentElement.parentElement
); // null
 -->
Giải thích:
- document.documentElement chính là <html>.
- Node cha của <html> là document.
- parentNode trả về bất kỳ loại node cha nào.
- - parentElement chỉ trả về node cha nếu nó là element.
Vì document không phải element node nên parentElement trả về null.
Ứng dụng trong bài: muốn đi ngược từ một element lên các element cha cho đến <html>, tài liệu đưa ra cách:
<!-- 
while (elem = elem.parentElement) {
  console.log(elem);
}
 -->
Vòng lặp dừng khi không còn element cha.
Phân biệt phải nhớ
<!-- 
elem.parentNode       // Cha thuộc bất kỳ loại node nào
elem.parentElement    // Chỉ lấy cha nếu cha là element

elem.childNodes       // Tất cả node con
elem.children         // Chỉ element con

elem.nextSibling      // Node tiếp theo
elem.nextElementSibling // Element tiếp theo
 -->
3.5. More links: tables
Giới thiệu các thuộc tính chuyên biệt để điều hướng trong HTML table
Đây là trường hợp quan trọng vì table có cấu trúc riêng và trình duyệt có thể tự thêm tbody vào DOM.
Đối với table:
| Thuộc tính      | Ý nghĩa                             |
| --------------- | ----------------------------------- |
| `table.rows`    | Collection các hàng `tr` trong bảng |
| `table.caption` | Tham chiếu đến `caption`            |
| `table.tHead`   | Tham chiếu đến `thead`              |
| `table.tFoot`   | Tham chiếu đến `tfoot`              |
| `table.tBodies` | Collection các `tbody`              |
Tài liệu lưu ý tBodies có thể chứa nhiều tbody, nhưng sẽ luôn có ít nhất một trong DOM, kể cả khi HTML nguồn không viết tbody.
Đối với thead, tfoot, tbody:
<!-- tbody.rows; -->
Trả về các hàng tr nằm trong phần đó
Đối với tr:
| Thuộc tính           | Ý nghĩa                                                     |
| -------------------- | ----------------------------------------------------------- |
| `tr.cells`           | Collection các ô `td` và `th`                               |
| `tr.sectionRowIndex` | Vị trí của hàng trong `thead`, `tbody` hoặc `tfoot` chứa nó |
| `tr.rowIndex`        | Vị trí của hàng trong toàn bộ bảng                          |
Đối với td và th:
<!-- td.cellIndex; -->
Trả về vị trí của ô trong hàng tr chứa nó.
Ví dụ trong bài gốc
<!-- 
<table id="table">
  <tr>
    <td>one</td>
    <td>two</td>
  </tr>
  <tr>
    <td>three</td>
    <td>four</td>
  </tr>
</table>
 -->
3.6. Summary
Bài gốc tổng kết hai nhóm điều hướng chính:

Nhóm áp dụng cho tất cả node:
<!--

firstChild
lastChild
previousSibling
nextSibling
 -->
Nhóm chỉ áp dụng cho element node :
<!--

 -->
Ngoài ra 1 số element có các thuộc tính riêng để truy cập nội dung , ví dụ HTML table
4. Bổ sung ngoài tài liệu gốc: Những case dễ nhầm khi áp dụng
4.1. children không phải lúc nào cũng là Array
<!-- 
const children = document.body.children;

console.log(Array.isArray(children)); // false
 -->
Nếu cần dùng Array methods:
<!-- 
const childArray = [...document.body.children];

childArray.map(child => {
  console.log(child.tagName);
});
 -->
4.2. Live collection có thể khiến vòng lặp bị thay đổi ngoài dự kiến
<!-- 
const items = document.getElementsByTagName('li');

for (let i = 0; i < items.length; i++) {
  items[i].remove();
}
 -->
getElementsByTagName() trả về live collection . Khi xoá 1 phần từ , collection thay đổi ngay, khiến phần tử kế tiếp có thể bị bỏ qua
Nếu muốn thao tác trên danh sách cố định:
<!-- 
const items = [
  ...document.getElementsByTagName('li')
];

for (const item of items) {
  item.remove();
}
 -->
Đây là ví dụ bổ sung để hiểu rõ đặc tính live collection, không phải ví dụ nguyên văn của bài.
4.3. Khi nào dùng navigation, khi nào dùng querySelector?
Ví dụ muốn lấy element kế tiếp:
<!-- 
const current = document.querySelector('.item');

const next = current.nextElementSibling;
 -->
Nếu muốn tìm 1 element theo class hoặc selector phức tạp :
<!-- const target = document.querySelector('.list .item.active'); -->
Không cần cố dùng children, parentElement để thay thế mọi trường hợp tìm kiếm.
- Biết chính xác quan hệ cha/con/anh em: dùng DOM navigation.
- Muốn tìm theo selector: dùng querySelector hoặc querySelectorAll.

5. Bài này áp dụng trong React và Backend như thế nào?
5.1. React / Next.js
React vẫn sủ dung DOM thật trong trình duyệt . Kiến thức DOM navigation giúp bạn hiểu và kiểm tra cấu trúc element mà React render ra
Ví dụ:
<!-- 
function TodoList() {
  return (
    <ul className="todo-list">
      <li>Learn JavaScript</li>
      <li>Learn React</li>
    </ul>
  );
}
 -->
Trong react , nếu cần truy cập element thật , bạn có thể sử dụng useRef
<!-- 
import { useEffect, useRef } from 'react';

function TodoList() {
  const listRef = useRef(null);

  useEffect(() => {
    const list = listRef.current;

    console.log(list.children);
    console.log(list.firstElementChild);
  }, []);

  return (
    <ul ref={listRef}>
      <li>Learn JavaScript</li>
      <li>Learn React</li>
    </ul>
  );
}
 -->
Bạn có thể áp dụng kiến thức:
- children : lấy các element con của danh sách
- firstElementChild : lấy item đầu tiên
- nextElementSibling: lấy item tiếp theo.
-  parentElement: đi lên element cha.
Nhưng cần nhớ: trong React, không nên lạm dụng việc tự duyệt và sửa DOM để cập nhật giao diện. Hãy ưu tiên state, props và React rendering.
