3. Nội dung bài học
3.1. Giới thiệu: DOM Tree
Theo bài gốc , HTML document được xây dựng từ các thẻ (tags)
DOM (Document Object Model) biểu diễn mỗi thẻ HTML thành 1 object . Các thẻ lồng nhau trở thành qua hệ cha con .
Nội dung văn bản bên trong thẻ cũng được biểu diễn thành object.
Ví dụ:
<!-- 
<body>
  <h1>Hello</h1>
  <p>JavaScript</p>
</body>
 -->
Trình duyệt biểu diễn HTML trên thành 1 cây DOM . JS có thể truy cập các object này đẻ đọc hoặc thay đổi nội dung trang 
Ví dụ trong tài liệu:
<!-- 
document.body.style.background = 'red';

setTimeout(() => {
  document.body.style.background = '';
}, 3000);
 -->
document.body: object đại diện cho thẻ body
style.background: thay đổi màu nền.
setTimeout : đưa việc khôi phục màu nền vào sau 3s
Ngoài style.background, tài liệu còn nhắc đến 1 số thuộc tính như :
- innerHTML : nội dung HTML bên trong node.
- offsetWidth: chiều rộng của node tính bằng pixel.
Điểm cần hiểu: DOM không phải chuỗi HTML ban đầu. Nó là cấu trúc object mà trình duyệt tạo ra từ tài liệu HTML
3.2. An example of the DOM
<!-- 
<!DOCTYPE HTML>
<html>
<head>
  <title>About elk</title>
</head>
<body>
  The truth about elk.
</body>
</html>
 -->
DOM biểu diễn tài liệu thành một cây:
Element nodes
Là các thẻ HTML, ví dụ:
<!-- 
<html>
<head>
<body>
<p>
 -->
Chúng tạo nên cấu trúc cây DOM
Text nodes
Là nội dung văn bản nằm bên trong các element.
Ví dụ :
<!-- <p>Hello JavaScript</p> -->
DOM có:
- Element node: p
- Text node: Hello JavaScript
Điểm rất dễ nhầm : khoảng trắng và xuống dòng cũng tạo thành text node
Ví dụ:
<!-- 
<body>
  <p>Hello</p>
</body>
 -->
Khoảng trắng và ký tự xuống dòng nằm giữa body và p cũng có thể tạo thành text node.
Tài liệu lưu ý hai ngoại lệ ở cấp cao nhất:
1. Khoảng trắng và xuống dòng trước thẻ <head> bị bỏ qua vì lý do lịch sử.
2. Nội dung đặt sau </body> sẽ được trình duyệt tự chuyển vào bên trong body.
Nếu loại bỏ khoảng trắng và xuống dòng giữa các thẻ  , các text node chỉ chứa khoảng trăngs tương ứng cũng sẽ không còn
Một lưu ý khác: DevTools thường ẩn các text node chỉ chứa khoảng trắng để giao diện dễ nhìn hơn . Vì thế , DOM hiển thị trong element 
khônng phải lúc nào cũng thể hiện đầy đủ các text node

3.3. Autocorrection
Trình duyệt có khả năng tự sửa HTML không hợp lệ khi tạo DOM
Ví dụ, HTML:
<!-- Hello -->
Dù không viết HTML , head , body trình duyệt vẫn tự tạo cấu trúc cần thiết trong DOM
Một ví dụ khác:
<!-- 
<p>Hello
<li>Mom
<li>and
<li>Dad
 -->
Các thẻ chưa được đóng đầy đủ sẽ được trình duyệt xử lý để tạo DOM hợp lệ theo quy tắc HTML
Trường hợp đặc biệt trong bài: Table luôn có tbody.
<!-- 
<table id="table">
  <tr>
    <td>1</td>
  </tr>
</table>
 -->
Khi tạo DOM, trình duyệt tự thêm tbody:
<!-- 
<table id="table">
  <tbody>
    <tr>
      <td>1</td>
    </tr>
  </tbody>
</table>
 -->

3.4. Other node types
Ngoài element node và text node, DOM còn có những loại node khác.
Comment node
Ví dụ :
<!-- 
<body>
  The truth about elk.

  <ol>
    <li>An elk is a smart</li>
    <!-- comment -->
    <li>...and cunning animal!</li>
  </ol>
</body>
 -->
Comment:
<!-- comment -->
cũng trở thành 1 node trong DOM , dù không hiển thị trên giao diện 
Lý do: những gì có trong HTML thì cũng có vị trí tương đương trog DOM tree
DOCTYPE cũng là một DOM node.
Ví dụ:
<!-- <!DOCTYPE HTML> -->
Nó nằm trong DOM tree ngay trước thẻ html
DOM có tổng cộng 12 loại node. Tuy nhiên , trong thực tế chúng ta thường làm việc với 4 loại 
| Loại node    | Ý nghĩa               |
| ------------ | --------------------- |
| `document`   | Điểm truy cập vào DOM |
| Element node | Các thẻ HTML          |
| Text node    | Chứa văn bản          |
| Comment node | Chứa comment HTML     |
Chú ý: document cũng chính thức là một DOM node, không chỉ là 1 object truy cập DOM

3.6. Interaction with console
Tương tác giữa tab Elements và Console.
Lấy element từ Elements sang Console
1. Chọn một thẻ <li> trong tab Elements.
2. Nhấn Esc để mở Console.
3. Truy cập element đang được chọn bằng $0
Ví dụ:
<!-- $0.style.background = 'red'; -->
Trong đó:
- $0: element đang được chọn gần nhất.
- $1: element được chọn trước đó.
- $2: element trước $1, cứ tiếp tục như vậy.
Đi từ Console sang Elements
Nếu bạn có biến đang tham chiếu tới một DOM node :
<!-- const node = document.body; -->
Bạn có thể chạy:
<!-- inspect(node); -->
DevTools sẽ chuyển sang tab Elements và hiển thị node tương ứng
Hoặc đơn giản:
<!-- 
console.log(document.body);
 -->
Bạn có thể mở rộng và kiểm tra object DOM trực tiếp trong Console.

3.7. Summary
Theo phần tổng kết của bài gốc:
- HTML/XML document được trình duyệt biểu diễn thành DOM tree.
- Tags trở thành element nodes.
- Text trở thành text nodes.
- Mọi nội dung trong HTML, kể cả comment, đều có vị trí trong DOM.
- DevTools giúp kiểm tra và chỉnh sửa DOM trực tiếp.
- DOM nodes có các thuộc tính và phương thức để duyệt cây , chỉnh sửa node và di chuyển các phần tử

4. Bổ sung ngoài tài liệu gốc: Các trường hợp dễ nhầm
1. children và childNodes không giống nhau
<!-- 
<div>
  <p>Hello</p>
</div>

const div = document.querySelector('div');

console.log(div.children);
console.log(div.childNodes);
 -->
children : chỉ lấy elment node 
childNodes : lấy tất cả các child node , bao gồm cà text node và comment node 
2. innerHTML và textContent khác nhau
<!-- 
const div = document.querySelector('div');

div.innerHTML = '<strong>Hello</strong>';
 -->
Sẽ tạo element Strong bên trong div
Trong khi:
<!-- 
div.textContent = '<strong>Hello</strong>';
 -->
Chỉ đặt nội dung văn bản , không tạo thẻ strong
3. Không nên giả định DOM luôn giống hệt HTML bạn viết
Đặc biệt với table, tbody, các thẻ chưa đóng và khoảng trắng. Khhi kết quả khác mong đợi , hãy kiểm tra Elements thay vì chỉ nhìn source HTML.
