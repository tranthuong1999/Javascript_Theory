và Static Collection

3. Nội dung bài học
3.1. document.getElementById or just id
Nếu 1 element có thuộc tính id , ta có thể tìm nó bằng:
<!-- const elem = document.getElementById('elem'); -->
Ví dụ:
<!-- 
<div id="elem">
  <div id="elem-content">Element</div>
</div>
const elem = document.getElementById('elem');

elem.style.background = 'red';
 -->
Cách truy cập trực tiếp bằng tên biến toàn cục
Tài liệug giới thiệu 1 đặc điểm của trình duyệt :
<!-- elem.style.background = 'red'; -->
Khi HTML có id="elem", trình duyệt có thể tạo biến global tên elem tham chiếu đến element đó
Nếu ID chứa dấu gạch ngang:
<!-- <div id="elem-content">Element</div> -->
Có thể truy cập thông qua:
<!-- window['elem-content']; -->
Tuy nhiên , nếu khai báo biến JS cùng tên :
<!-- 
let elem = 5;
console.log(elem); // 5
 -->
Biến JS cùng tên sẽ được ưu tiên , và không còn tham chiếu đến DOM element
Tài liệu khuyến cáo không nên dựa vào biến global được tạo từ ID vì :
- Có thể xung đột tên với biến JS
- Người đọc code không biết đến từ đâu
- Phụ thuộc vào HTML bên ngoài đoạn JS
Trong thực tế, hãy dùng:
<!-- document.getElementById('elem'); -->
ID phải duy nhất
Trông mỗi document , ID phải là duy nhất
Nếu có nhiều element trùng ID, kết quả của các phương thưucs tìm theo ID có thể không xác định theo cách bạn mong muốn .
Ví dụ , getElementById có thể trả về 1 trong những element trùng ID
Một lưu ý quan trọng: getElementById chỉ được trên document , không goi tên 1 element khác
<!-- 
document.getElementById('elem'); // Đúng

const container = document.querySelector('.container');

container.getElementById('elem'); // Không có method này
 -->
3.2. querySelectorAll
để tìm tất cả element khớp với CSS selector bên trong một phạm vi.
Cú pháp :
<!-- elem.querySelectorAll(css); -->
Ví dụ từ bài gốc :
<!--  
<ul>
  <li>The</li>
  <li>test</li>
</ul>

<ul>
  <li>has</li>
  <li>passed</li>
</ul>

const elements = document.querySelectorAll(
  'ul > li:last-child'
);

for (const elem of elements) {
  console.log(elem.innerHTML);
}
-->
Kết quả : test => passed
Giải thích selector:
- ul: chọn element ul.
- >: chỉ chọn element con trực tiếp
- li:last-child: chọn li là con cuối cùng
Điểm mạnh của querySelectorAll là bạn có thể sử dụng các CSS selector, kể cả pseudo-class.
Ví dụ:
<!-- const hoveredElements = document.querySelectorAll(':hover'); -->
Trả về các element mà con trỏ chuột đang nằm trên đó .Kết quả được sắp xếp theo thứ tự lồng nhau, từ html bên ngoài đến element sâu nhất.
Lưu ý: querySelectorAll trả về Static NodeList , không tự cập nhật khi DOM thay đổi .Phần live colllection sẽ giải thích kỹ hơn

3.3. querySelector
Khác với querySelectorAll, phương thức này chỉ trả về element đầu tiên khớp CSS selector.
<!-- const elem = document.querySelector('.item'); -->
Tương đương về kết quả với:
<!-- const elem = document.querySelectorAll('.item')[0]; -->
Nhưng querySelector chỉ cần tìm một element , thay vì tìm tất cả rồi chọn phần tử đầu tiên
Nếu không tìm thấy element ,kết quả trả về null
Ví dụ:
<!-- 
const elem = document.querySelector('.not-exist');

console.log(elem); // null
 -->
Vì vậy, khi thao tác với kết quả, hãy chú ý kiểm tra null:
<!-- 
if (elem) {
  elem.style.background = 'red';
}
-->
**Phân biệt cần nhớ:**

| Tiêu chí       | `querySelector`  | `querySelectorAll`     |
| -------------- | ---------------- | ---------------------- |
| Kết quả        | Một element      | NodeList               |
| Số lượng       | Phần tử đầu tiên | Tất cả phần tử phù hợp |
| Không tìm thấy | `null`           | NodeList rỗng          |
| Live?          | Không áp dụng    | Static                 |

3.4. matches
Hai phương thức trước dùng để tìm element trong DOM.
<!-- elem.matches(css); -->
Không tìm kiếm element. Nó chỉ kiểm tra xem chính element đang có khớp với CSS selector hay không.
Kết quả là true hoặc false.
Ví dụ trong bài gốc:
<!-- 
<a href="http://example.com/file.zip">File</a>
<a href="http://ya.ru">Website</a>
 -->
<!-- 
for (const elem of document.body.children) {
  if (elem.matches('a[href$="zip"]')) {
    console.log('Archive:', elem.href);
  }
}
-->
Giải thích selector:
- a: element phải là thẻ liên kết.
- [href$="zip"]: gía trị href kết thúc bằng zip
- - $=: toán tử CSS selector có nghĩa là kết thúc bằng chuỗi chỉ định.
Khi duyệt từng element, matches() giúp lọc element nào đáp ứng điều kiện.

3.5. closest
closest(css) tìm ancestor gần nhất khớp với CSS selector.
Điểm đặc biệt : element gọi phương thức cũng được kiểm tra , không chỉ các element cha
Ví dụ trong bài gốc:
<!-- 
<h1>Contents</h1>

<div class="contents">
  <ul class="book">
    <li class="chapter">Chapter 1</li>
    <li class="chapter">Chapter 2</li>
  </ul>
</div>
 -->
<!-- 
<h1>Contents</h1>

<div class="contents">
  <ul class="book">
    <li class="chapter">Chapter 1</li>
    <li class="chapter">Chapter 2</li>
  </ul>
</div>
 -->
Giải thích:
- closest('.book'): đi lên và tìm ul.book.
- closest('.contents'): tiếp tục tìm nên và gặp div.contents
- closest('h1'): không có h1 trong chuỗi ancestor nên trả về null

Điểm cần nhớ:

closest() đi từ element hiện tại lên phía cha, không đi xuống tìm con.
Trường hợp thứ hai trả về chính element vìclosest() kiểm tra cả element ban đầu.

3.6. getElementsBy*
Tài liệu giới thiệu tìm các phưnong thức tìm element theo tag , class và name
getElementsByTagName(tag)
Tìm tất cả element theo tên thẻ.
<!-- const divs = document.getElementsByTagName('div'); -->
Tham số "*" có nghĩa là tất cả tag:
<!-- const allElements = document.getElementsByTagName('*'); -->
getElementsByClassName(className)
Tìm các element có class được chỉ định :
<!-- const articles = document.getElementsByClassName('article'); -->
document.getElementsByName(name)
Tìm các element có thuộc tính name trong toàn bộ document:
Phương thức này ít được sử dụng.

3.7. Live collections
Tài liệu phân biệt:
- Các phương thức getElementsBy* trả về Live Collection
- querySelectorAll trả về Static Collection

Live Collection
Luôn phản ánh trạng thái hiện tại của DOM . Khi DOM thay đổi , colllection tự cập nhật 
Ví dụ trong bài gốc:
<!-- 
<div>First div</div>

<script>
  const divs = document.getElementsByTagName('div');

  console.log(divs.length); // 1
</script>

<div>Second div</div>

<script>
  console.log(divs.length); // 2
</script>
 -->
divs vẫn là cùng một collection, nhưng số lượng phần tử thay đổi khi trình duyệt đọc thêm div
Static Collection
querySelectorAll trả về danh sách cố định tại thời điểm phương thức
<!-- 
<div>First div</div>

<script>
  const divs = document.querySelectorAll('div');

  console.log(divs.length); // 1
</script>

<div>Second div</div>

<script>
  console.log(divs.length); // 1
</script>
 -->
Dù DOM có thêm div, collection đã lấy trước đó vẫn giữ kết quả cũ.
So sánh:
| Phương thức              | Loại collection | Tự cập nhật khi DOM đổi? |
| ------------------------ | --------------- | ------------------------ |
| `getElementsByTagName`   | Live            | Có                       |
| `getElementsByClassName` | Live            | Có                       |
| `getElementsByName`      | Live            | Có                       |
| `querySelectorAll`       | Static          | Không                    |

3.8. Summary
| Method                   | Tìm theo     | Gọi trên element? | Live?         |
| ------------------------ | ------------ | ----------------- | ------------- |
| `querySelector`          | CSS selector | Có                | Không áp dụng |
| `querySelectorAll`       | CSS selector | Có                | Không         |
| `getElementById`         | ID           | Không             | Không áp dụng |
| `getElementsByName`      | Name         | Không             | Có            |
| `getElementsByTagName`   | Tag          | Có                | Có            |
| `getElementsByClassName` | Class        | Có                | Có            |
Hai phương thức bổ sung:
- elem.matches(css): kiểm tra element có khớp selector hay không
- elem.closest(css): tìm ancestor gần nhất khớp selector ,có kiểm tra cả element hiện tại.
Bài gốc còn nhắc đến:
<!-- elemA.contains(elemB); -->
Trả về true nếu elemB nằm bên trong elemA (là descendant), hoặc nếu elemA chính là elemB.
Ví dụ:
<!-- 
const parent = document.querySelector('.parent');
const child = document.querySelector('.child');

console.log(parent.contains(child));
 -->
Nếu .child nằm trong .parent, kết quả là true.

4. Bổ sung ngoài tài liệu gốc: Những case dễ nhầm
4.1. querySelectorAll không trả về Array
<!-- 
const items = document.querySelectorAll('.item');

console.log(Array.isArray(items)); // false
 -->
NodeList có thể duyệt bằng for...of , nhưng không có đầy đủ array method
Nếu muốn dùng map, filter:
<!-- 
const itemArray = Array.from(items);

const activeItems = itemArray.filter(item =>
  item.classList.contains('active')
);
 -->
4.2. Selector sai cú pháp có thể gây lỗi
<!-- document.querySelector('div['); -->
Selector không hợp lệ sẽ gây SyntaxError , khác với trường hợp selector hợp lệ nhưng không tìm thấy element (trả về null)
4.3. closest() có thể trả về chính element hiện tại
<!-- 
const button = document.querySelector('button');

console.log(button.closest('button') === button); // true
 -->
Không nên hiểu closest() chỉ tìm element cha.
4.4. Live Collection và Static Collection trong vòng lặp
Ví dụ:
<!-- 
const items = document.getElementsByClassName('item');

for (let i = 0; i < items.length; i++) {
  items[i].classList.remove('item');
}
 -->
Không xoá class item , collection live giảm số lượng ngay. Vì vậy , giảm một số element có thể bỏ qua 
Nếu cần danh sách cố định để xử lý:
<!-- 
const items = [
  ...document.getElementsByClassName('item')
];

for (const item of items) {
  item.classList.remove('item');
}
-->
5. Bài này áp dụng trong React và Backend như thế nào?
5.1. React / Next.js
React thường không yêu cầu bạn tự tìm DOM element để render giao diện .React quản lý giao diện thông qua state, props và component.
Nhưng khi cần truy cập vào DOM thật , các phương thức trong bài vẫn rất hữu ích :
Ví dụ với useRef:
<!-- 
import { useEffect, useRef } from 'react';

function SearchForm() {
  const formRef = useRef(null);

  useEffect(() => {
    const form = formRef.current;

    const input = form.querySelector('input');
    const button = form.querySelector('button');

    console.log(input, button);
  }, []);

  return (
    <form ref={formRef}>
      <input type="text" />
      <button type="submit">Search</button>
    </form>
  );
}
 -->
Ở đây:
- useRef: giữ tham chiếu đến DOM element
- querySelector : tìm element bên trong form
- Không cần tìm kiếm trên toàn bộ document.

Một ứng dụng thực tế khác: Event delegation
Khi có nhiều button bên trong một container , có thể sử dụng closet() để xác định button được click
<!-- 
function handleClick(event) {
  const button = event.target.closest('button[data-action]');

  if (!button) return;

  console.log(button.dataset.action);
}
 -->
Đây là kỹ thuật DOM hữu ích trong JavaScript thuần . Trong React , thông thường bạn nên dùng onClick trực tiếp 
hoặc cơ chế event của React thay vì tự gắn listerner toàn document
Với Next.js:
- Client Component có thể truy cập DOM sau khi component được render trên browser.
- Không gọi document.querySelector() trong quá trình Server Rendering.
- Nếu cần thao tác DOM, thường đặt trong useEffect hoặc callback phù hợp.
5.2. Backend Node.js
Node.js không có các API:
<!-- 
document.querySelector();
document.getElementById();
document.body;
 -->
Muốn đdùng các API này ở Backend , bạn cần thư viện cung cấp môi trường DOM như jsdom:
Ví dụ:
<!-- 
import { JSDOM } from 'jsdom';

const dom = new JSDOM(`
  <div class="container">
    <p class="message">Hello Backend</p>
  </div>
`);

const document = dom.window.document;

const message = document.querySelector('.message');

console.log(message.textContent);
 -->
Một số ứng dụng:
- Phân tích HTML
- Lấy dữ liệu từ HTML
- Kiểm thử code có phụ thuộc vào DOM
-  Xử lý nội dung HTML phía server
