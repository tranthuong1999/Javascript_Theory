2.1. Prototype là gì?
Trong lâppj trình , đôi khi chúng ta có 1 object và muốn tạo 1 object khác dựa trên nó , có thể tái sử dụng properties và method
mà không cần sao chép lại
Ví dụ : chúng ta có object user chứa thông tin và các phương thức chung . Sau đó muốn tạo admin và guest với 1 số đặc điểm riêng
JS cung cấp cơ chế Prototypal inheritance để qiair quyết vấn đề này
2.2. Thuộc tính [[Prototype]]
Trong JS , mỗi object có thuộc tính nội bộ đặc biệt tên là :
<!-- [[Prototype]] -->
Thuộc tính này có thể tham chiếu đến obj khác hoặc có gía trị null
Object được tham chiếu đến gọi là prototype
Ví dụ :
<!-- 
let animal = {
    eats: true
};

let rabbit = {
    jumps: true
};

rabbit.__proto__ = animal;
 -->
Ở đây:
- animal là prototype của rabbit
- rabbit kế thừa từ animal
- rabbit vẫn giữ propety riêng tên jump
2.3. Đọc property từ prototype
<!-- 
let animal = {
    eats: true
};

let rabbit = {
    jumps: true
};

rabbit.__proto__ = animal;

console.log(rabbit.eats);  // true
console.log(rabbit.jumps); // true
 -->
Tại sao rabbit.eats trả về true mặc dù rabbit không có property eats
JS thực hiện quá trình tìm kiếm :

1. Tìm eats trong rabbit
2. K tìm thấy
3. Tiếp tục tìm trong prototype là animal
4. Tim thấy  animal.eats
5. Trả về true

Quy tắc: Khi đọc 1 propety không tồn tại trong object , JS sẽ tìm tiếp trong prototype

2.4. Kế thừa methods
Không chỉ properties , object còn kế thừa method từ prototype
Ví dụ trong tài liệu:
<!-- 
let animal = {
    eats: true,

    walk() {
        console.log("Animal walk");
    }
};

let rabbit = {
    jumps: true,
    __proto__: animal
};

rabbit.walk(); // Animal walk
 -->
Giải thích:
- rabbit không có method walk().
- JavaScript tìm thấy walk() trong animal.
- Method được gọi thành công thông qua rabbit.
Đây chính là cách tái sử dụng mà không cần sao chép chúng

2.5. Prototype chain
Prototype không chỉ giới hạn ở 1 cấp . Chúng ta có thể tạo ra 1 chuỗi kê thừa
Ví dụ trong tài liệu:
<!-- 
let animal = {
    eats: true,

    walk() {
        console.log("Animal walk");
    }
};

let rabbit = {
    jumps: true,
    __proto__: animal
};

let longEar = {
    earLength: 10,
    __proto__: rabbit
};

longEar.walk();  // Animal walk
console.log(longEar.jumps); // true
 -->
Khi đọc longEar.walk():
 longEar
   │
   │ Không có walk
   ▼
 rabbit
   │
   │ Không có walk
   ▼
 animal
   │
   │ Tìm thấy walk
   ▼
Thực thi method
Tương tự, khi đọc longEar.jumps:
1. Không tìm thấy trong longEar.
2. Tìm trong rabbit.
3. Tìm thấy jumps: true.
Đây gọi là prototype chain (chuỗi prototype).

2.6. Hai giới hạn của prototype
Giới hạn 1: Không được tạo vòng lặp
<!-- 
let animal = {};
let rabbit = {};

animal.__proto__ = rabbit;
rabbit.__proto__ = animal; // TypeError
 -->
JS khoông cho phép prototype tham chiếu vòng tròn
Giới hạn 2: Prototype chỉ nhận object hoặc null
<!-- 
let animal = {};

let rabbit = {
    __proto__: animal
};
 -->
Giá trị __proto__ có thể là:
Một object hoặc null
Các kiểu dữ liệu khác như string , number , boolean sẽ bị bỏ qua khi gán qua setter__proto__.
Ngoài ra , một object chỉ có 1 prototype trực tiếp , không thể kế thừa trực tiếp từ hai object khác nhau
2.7. Phân biệt [[Prototype]] và proto

| Tiêu chí  | `[[Prototype]]`                  | `__proto__`                               |
| --------- | -------------------------------- | ----------------------------------------- |
| Bản chất  | Thuộc tính nội bộ                | Getter/setter đặc biệt                    |
| Chức năng | Chứa tham chiếu prototype        | Dùng để truy cập hoặc thiết lập prototype |
| Đặc điểm  | Không phải property thông thường | Là cách truy cập mang tính lịch sử        |
Ví dụ:
<!-- 
let animal = {
    eats: true
};

let rabbit = {};

rabbit.__proto__ = animal;
 -->
Dòng trên thiết lập :
<!-- rabbit.[[Prototype]] = animal; -->
Lưu ý: __proto__ đã cũ và không được khuyến khích sử dụng trong code hiện đại. JavaScript cung cấp:
Tuy nhiên, bài này sử dụng __proto__ để minh họa cơ chế prototype rõ ràng hơn. Chúng ta sẽ học các phương thức hiện đại ở bài sau.

Phần 2. Writing doesn't use prototype
2.1. Nguyên tắc: Prototype chỉ được sử dụng khi đọc property
Đây là điểm rất quan trọng:
- Read: JS tìm kiếm propety trong object và prototype chain
- write : JS ghi trực tiếp vào obj hiện tại 
- delete : JS xoá propety khỏi object hiện tại
<!-- 
let animal = {
    eats: true,

    walk() {
        console.log("Animal walk");
    }
};

let rabbit = {
    __proto__: animal
};

rabbit.walk(); // Animal walk
 -->
rabit không có walk () , nên JS tìm thấy method trong animal
Bây giờ thử ghi đè method:
<!-- 
rabbit.walk = function() {
    console.log("Rabbit! Bounce-bounce!");
};

rabbit.walk(); // Rabbit! Bounce-bounce!
 -->
Điều gì xảy ra?
1. JS không thay đổi animal.walk
2. JS tạo propety mới trực tiếp trên rabbit
3. Khi gọi rabbit.walk() JS tìm thấy method ngay trong rabbit
4. Method của animal không được gọi thông qua rabbit

2.2. Phân biệt đọc và ghi
| Thao tác             | JavaScript xử lý                   |
| -------------------- | ---------------------------------- |
| `rabbit.eats`        | Tìm trong rabbit rồi prototype     |
| `rabbit.walk()`      | Tìm method trong prototype nếu cần |
| `rabbit.walk = fn`   | Ghi property vào rabbit            |
| `delete rabbit.walk` | Xóa property của rabbit            |

Lưu ý: Gán một property mới không làm thay đổi property cùng tên trên prototype.

2.3. Ngoại lệ: Accessor properties
Theo tài liệu gốc, accessor properties là một ngoại lệ cần chú ý.
Khi gán gía trị cho accessor property được kế thừa , setter của prototype sẽ được gọi 
<!-- 
let user = {
    name: "John",
    surname: "Smith",

    set fullName(value) {
        [this.name, this.surname] = value.split(" ");
    },

    get fullName() {
        return `${this.name} ${this.surname}`;
    }
};

let admin = {
    __proto__: user,
    isAdmin: true
};

console.log(admin.fullName); // John Smith

admin.fullName = "Alice Cooper";

console.log(admin.fullName); // Alice Cooper
console.log(user.fullName);  // John Smith
 -->
 Khi đọc:
 1. admin không có getter fullName
 2. JS tìm getter trong user
 3. Getter được gọi 
   
Khi ghi:
admin.fullName = "Alice Cooper";
1. admin không có setter của fullName
2. JS tìm setter trong user
3. Setter được gọi với this là admin
4. admin.name và admin.surname được cập nhật 

2.4. Ghi nhớ phần 2
Writing doesn't use prototype
│
├── Read
│   └── Tìm kiếm trong prototype chain
│
├── Write
│   └── Ghi trực tiếp vào object hiện tại
│
├── Delete
│   └── Xóa property trên object hiện tại
│
└── Ngoại lệ: Accessor properties
    └── Gọi setter được tìm thấy trong prototype

3. The value of “this”
3.1. this có bị ảnh hưởng bởi prototype không?
Quay lại ví dụ user và admin ở phần trước:
<!-- 
let user = {
    name: "John",
    surname: "Smith",

    set fullName(value) {
        [this.name, this.surname] = value.split(" ");
    },

    get fullName() {
        return `${this.name} ${this.surname}`;
    }
};

let admin = {
    __proto__: user,
    isAdmin: true
};

admin.fullName = "Alice Cooper";

console.log(admin.fullName); // Alice Cooper
console.log(user.fullName);  // John Smith
 -->
Quy tắc quan trọng:
this hoàn toàn không bị ảnh hưởng bởi prototype .Trong một method call , this luôn là object đứng trước dấu chấm
Dù method được tìm thấy ở object hiện tại hay prototyoe , this vẫn phụ thuộc vào cách gọi method
3.2. Ví dụ animal và rabbit
<!-- 
let animal = {
    walk() {
        if (!this.isSleeping) {
            console.log("I walk");
        }
    },

    sleep() {
        this.isSleeping = true;
    }
};

let rabbit = {
    name: "White Rabbit",
    __proto__: animal
};

// modifies rabbit.isSleeping
rabbit.sleep();

console.log(rabbit.isSleeping); // true
console.log(animal.isSleeping); // undefined
 -->
3.3. Nhiều object có thể dùng chung method
Giả sử có thêm bird , snake cùng kế thừa từ animal
<!-- 
let bird = {
    __proto__: animal
};

let snake = {
    __proto__: animal
};
 -->
Cả ba object đều có thể sử dụng:
rabbit.sleep();
bird.sleep();
snake.sleep();
Nhưng this bên trong mỗi lần gọi sẽ là object khác nhau

Kết luận của bài gốc:
- Methods are shared: Các method có thể được chia sẻ thông qua prototype.
- Object state is not: Trạng thái riêng của từng object không bị chia sẻ chỉ vì chúng cùng kế thừa một prototype.

Bài tập :
<!-- 
let parent = {
    count: 0,

    increase() {
        this.count++;
    }
};

let child = {
    __proto__: parent,
    count: 10
};

child.increase();

console.log(child.count);
console.log(parent.count);
 -->
 Giải thích từng bước:
1. child.increase() tìm method increase trong prototype parent.
2. Vì gọi bằng child.increase() nên this === child.
3. Thực hiện this.count++, tương đương child.count++.
4. child.count từ 10 tăng thành 11.
5. parent.count không thay đổi, vẫn là 0.

Method được kế thừa nhưng this vẫn là object method

4. for…in loop
4.1. for...in duyệt cả property kế thừa
<!-- 
let animal = {
    eats: true
};

let rabbit = {
    jumps: true,
    __proto__: animal
};

console.log(Object.keys(rabbit));
// ["jumps"]

for (let prop in rabbit) {
    console.log(prop);
}
// jumps
// eats
 -->
 Giải thích :
 rabbit có 2 propety có thể đươc truy cập :
 jumps : propety riêng của rabbit
 eats : propety kế thừa từ animal
 Object.keys(rabbit)
- Chỉ trả về property riêng của rabbit.
- Không lấy property kế thừa.
for...in
- Duyệt property riêng.
- Đồng thời duyệt cả property kế thừa từ prototype.

4.2. Phân biệt property riêng và property kế thừa
hasOwnProperty() để kiểm tra 1 propety có thuộc tính trực tiếp từ object hay không
<!-- 
let animal = {
    eats: true
};

let rabbit = {
    jumps: true,
    __proto__: animal
};

for (let prop in rabbit) {
    let isOwn = rabbit.hasOwnProperty(prop);

    if (isOwn) {
        console.log(`Our: ${prop}`);
    } else {
        console.log(`Inherited: ${prop}`);
    }
}
 -->
| Phương thức        | Ý nghĩa                         |
| ------------------ | ------------------------------- |
| `hasOwnProperty()` | Kiểm tra property riêng         |
| `for...in`         | Duyệt property riêng và kế thừa |
| `Object.keys()`    | Lấy danh sách key riêng         |

4.3. Vì sao hasOwnProperty không xuất hiện trong for...in?

Bởi vì:
- hasOwnProperty được kế thừa từ Object.prototype.
- Property này có thuộc tính enumerable: false.
- for...in chỉ duyệt những property có enumerable: true.

4.4. Các phương thức lấy key/value khác
<!-- 
Object.keys(obj);
Object.values(obj);
Object.entries(obj);
 -->
Chúng không lấy property kế thừa từ prototype.

5. Summary – Tổng kết Prototypal inheritance

Theo phần tổng kết của javascript.info, có 7 ý chính:
1. Mọi object đều có internal property [[Prototype]], tham chiếu đến một object khác hoặc null.
2. Có thể truy cập prototype thông qua obj.__proto__ (cách cũ).
3. Object được tham chiếu bởi [[Prototype]] gọi là prototype.
4. Khi đọc property hoặc gọi method không tồn tại trên object, JavaScript tìm tiếp trong prototype chain.
5. Khi ghi hoặc xóa property, JavaScript thao tác trực tiếp trên object (ngoại trừ trường hợp accessor setter).
6. Khi gọi obj.method(), dù method được tìm thấy trong prototype, this vẫn là obj.
7. for...in duyệt cả property riêng và property kế thừa. Các phương thức như Object.keys(), Object.values(), Object.entries() chỉ lấy property riêng.
