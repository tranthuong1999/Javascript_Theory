3. Error handling with promises
3.1. Promise chain xử lý lỗi như thế nào?
Khi một Promise bị reject, quyên điều khiển sẽ chuyển đến rejection handler gần nhất ( trình xử lý lỗi gần nhất)
Ví dụ trong tài liệu:
<!-- 
fetch('https://no-such-server.blabla')
    .then(response => response.json())
    .catch(err => alert(err));
 -->
Phân tích:
1. fetch() gửi request đến một địa chỉ không tồn tại.
2. Request thất bại, Promise bị reject.
3. .then() không chạy vì Promise không fulfilled.
4. .catch() nhận lỗi và xử lý bằng alert(err).
Điểm quan trọng là catch không nhất thiết phải đặt ngay sau Promise bị reject .Nó có thể nằm sau 1 hoặc nhiều .then()
3.2. Ví dụ lỗi trong chuỗi nhiều Promise
<!-- 
fetch('/article/promise-chaining/user.json')
    .then(response => response.json())
    .then(user => fetch(`https://api.github.com/users/${user.name}`))
    .then(response => response.json())
    .then(githubUser => new Promise((resolve, reject) => {
        let img = document.createElement('img');
        img.src = githubUser.avatar_url;
        img.className = "promise-avatar-example";
        document.body.append(img);

        setTimeout(() => {
            img.remove();
            resolve(githubUser);
        }, 3000);
    }))
    .catch(error => alert(error.message));
 -->
Nó có thể xử lý lỗi nếu bất kỳ Promise nào phía trước bị reject , chẳng hạn :
- Lỗi mạng khi gọi API.
- JSON không hợp lệ khiến response.json() thất bại.
- Một Promise trong chuỗi bị reject
Tài liệu nhấn mạnh rằng thông thường .catch() này không chạy nếu mọi thao tác thành công.
3.3. Kết luận phần này
Bạn cần nhớ 3 ý:
1. Promise bị reject sẽ chuyển quyền điều khiển đến catch gần nhất
2. .catch() không cần nằm ngay sau Promise gây lỗi
3. Có thể đặt một .catch() cuỗi chuỗi để xử lý lỗi từ nhiều Promise và .then() phía trước

Kiểm tra hiểu bài:
<!-- 
Promise.resolve(10)
    .then(value => {
        console.log("A:", value);
        return fetch('/api/user');
    })
    .then(response => response.json())
    .then(user => {
        console.log("B:", user);
    })
    .catch(error => {
        console.log("C:", error.message);
    });
 -->
Giả sử request fetch('/api/user') thất bại.
1. Promise.resolve(10) fulfilled với giá trị 10.
2. .then() đầu tiên chạy và in A: 10.
3. fetch('/api/user') thất bại → Promise bị reject.
4. Các .then() xử lý thành công phía sau bị bỏ qua.
5. .catch() chạy và in lỗi tại C.

2. Implicit try…catch
Trong Promise , JS có cơ chế xử lý lỗi tương tự try...catch một cách tự động 
Xét ví dụ:
<!-- 
new Promise((resolve, reject) => {
    throw new Error("Whoops!");
}).catch(err => {
    console.log(err.message);
});
 -->
Khi throw xảy ra bên trong hàm executor của new Promise, Promise tự độngcnhuyeenr sang trạng thái reject 
với lỗi đó . Vì vậy .catch() nhận được lỗi mà không cần reject thủ công 
Tài liệu gốc gọi cơ chế này là “invisible try...catch” – một try...catch ngầm mà JavaScript tự thực hiện.
1. throw trong Promise executor
<!-- 
// Cách 1: throw
new Promise((resolve, reject) => {
    throw new Error("Whoops!");
}).catch(alert);
 -->
cách 2:
<!-- 
// Cách 2: reject
new Promise((resolve, reject) => {
    reject(new Error("Whoops!"));
}).catch(alert);
 -->
2. throw trong Promise handler (.then())
<!-- 
new Promise((resolve, reject) => {
    resolve("ok");
})
.then(result => {
    throw new Error("Whoops!");
})
.catch(alert);
 -->
Diễn biến:
1. resolve("ok") khiến Promise fulfilled.
2. .then() được thực thi.
3. throw new Error() xảy ra trong .then().
4. Promise được trả về từ .then() chuyển thành rejected.
5.  .catch() gần nhất bắt được lỗi.

3. Không chỉ lỗi do throw
Lỗi lập trình thông thường cũng được tự động bắt:
<!-- 
new Promise((resolve, reject) => {
    resolve("ok");
})
.then(result => {
    blabla(); // Hàm không tồn tại
})
.catch(error => {
    console.log(error.name);
    console.log(error.message);
});
 -->
Kết quả:
ReferenceError
blabla is not defined
Dù chúng ta k chủ động viết throw , JS vẫn tự phát sinh lỗi ReferenceError .Lỗi này được chuyển thành Promise rejection
và .catch() xử lý
Tóm tắt phần này
- throw trong Promise executor → Promise chuyển thành rejected.
- throw trong .then() → Promise trả về từ .then() chuyển thành rejected.
- Lỗi JavaScript như ReferenceError, TypeError trong executor hoặc handler cũng được bắt tự động.
- .catch() có thể xử lý những lỗi đó.
Kiểm tra nhanh
<!-- 
Promise.resolve(5)
    .then(value => {
        console.log("A:", value);
        return value * 2;
    })
    .then(value => {
        console.log("B:", value);
        unknownFunction();
    })
    .then(value => {
        console.log("C:", value);
    })
    .catch(error => {
        console.log("D:", error.name);
    });
 -->
 Bài tập :
 <!-- 
 new Promise((resolve, reject) => {
    resolve(10);
})
.then(value => {
    console.log("A:", value);
    return value + 5;
})
.then(value => {
    console.log("B:", value);
    throw new TypeError("Invalid data");
})
.catch(error => {
    console.log("C:", error.name);
    return 100;
})
.then(value => {
    console.log("D:", value);
});
-->
Luồng thực thi:
1. resolve(10) → Promise fulfilled.
2. .then() đầu tiên in A: 10, trả về 15.
3. .then() thứ hai in B: 15, sau đó throw new TypeError(...).
4. Promise chuyển sang rejected → bỏ qua các .then() thành công tiếp theo.
5. .catch() bắt lỗi, in C: TypeError, sau đó trả về 100.
6. .then() cuối nhận 100 và in D: 100.

Điểm cần nhớ: khi catch() xử lý lỗi và return một giá trị bình thường , Promise chain tiếp tục trở lại trạng thái fulfilled.

3. Rethrowing
.catch() ở cuối Promise tương tự như try..catch trong JS thông thường
Trong try...catch, chúng ta có thể:
- Phân tích lỗi 
- Xử lý lỗi nếu biết cách xử lý.
- Ném lỗi lại (throw) nếu k thể xử lý

1. Xử lý lỗi thành công
<!-- 
// the execution: catch -> then
new Promise((resolve, reject) => {
    throw new Error("Whoops!");
})
.catch(function(error) {
    alert("The error is handled, continue normally");
})
.then(() => alert("Next successful handler runs"));
 -->
Luồng thực thi:
1. Promise executor phát sinh lỗi.
2. Promise chuyển sang reject
3. .catch() nhận và xử lý lỗi
4. Callback .catch() kết thúc bình thường.
5. .then() tiếp theo được thực thi.

Điểm quan trọng : Khi .catch() xử lý lỗi thành công và không ném lỗi mới , Prommíe chain tiếp tục như 1 Promise fullfield
2. Rethrowing – Ném lỗi lại
Không phải lỗi nào chúng ta cũng có thể xử lý
Ví dụ: Một ứng dụng chỉ biết xử lý URIError, nhưng lại nhận được Error thông thường.
<!-- 
// the execution: catch -> catch
new Promise((resolve, reject) => {
    throw new Error("Whoops!");
})
.catch(function(error) { // (*)

    if (error instanceof URIError) {
        // handle it
    } else {
        alert("Can't handle such error");
        throw error;
    }

})
.then(function() {
    // doesn't run here
})
.catch(error => { // (**)

    alert(`The unknown error has occurred: ${error}`);

});
 -->
Phân tích:
1. Promise phát sinh Error("Whoops!").
2. .catch(*) nhận lỗi.
3. Kiểm tra error instanceof URIError trả về false.
4. Chương trình không biết xử lý lỗi này nên thực hiện throw error.
5. .then() tiếp theo bị bỏ qua vì Promise vẫn rejected.
6. .catch(**) tiếp theo nhận lỗi được ném lại.
Điều cần nhớ
- Nếu catch() xử lý lỗi và kết thúc bình thường => chain tiếp tục với .then().
- Nếu .catch() ném lỗi lại => chain chuyển đến .catch() gần nhất tiếp theo
- Có thể ném lại chính lỗi cũ hoặc ném lại 1 lỗi khác
  
3. Bổ sung ngoài tài liệu gốc – Ví dụ thực tế
Trong frontend, giả sử API trả về lỗi xác thực và lỗi hệ thống:
<!-- 
fetch("/api/user")
    .then(response => response.json())
    .catch(error => {
        if (error instanceof AuthError) {
            // Xử lý lỗi xác thực
            redirectToLogin();
            return;
        }

        // Không biết xử lý lỗi này
        throw error;
    })
    .catch(error => {
        console.error("Unexpected error:", error);
    });
 -->
Ý tưởng: xử lý những lỗi đã biết , chuyển tiếp những lỗi chưa biết đến nơi có khả năng xử lý phù hợp
Kiểm tra hiểu bài
<!-- 
Promise.reject(new Error("A"))
    .catch(error => {
        console.log("B:", error.message);
        throw new Error("C");
    })
    .then(() => {
        console.log("D");
    })
    .catch(error => {
        console.log("E:", error.message);
    });
 -->
Giải thích:
1. Promise.reject(new Error("A")) → Promise rejected với lỗi "A".
2. .catch() đầu tiên bắt lỗi và in B: A.
3. throw new Error("C") → ném lỗi mới, Promise tiếp tục rejected.
4. .then() tiếp theo không chạy nên không có D.
5. .catch() cuối bắt lỗi mới và in E: C.

Ghi nhớ: throw Error() hoặc throw new Error() bên trong catch() sẽ chuyển đến rejection handler tiếp theo.

4. Unhandled rejections
1. Điều gì sẽ xảy ra khi Promise bị reject nhưng không có .catch() 
Ví dụ trong tài liệu:
<!-- 
new Promise(function() {
    noSuchFunction(); // Error: no such function
})
.then(() => {
    // successful promise handlers
}); // Không có .catch()
 -->
1. noSuchFunction() không tồn tại → phát sinh ReferenceError.
2. Cơ chế implicit try…catch chuyển lỗi thành Promise rejected.
3. JavaScript tìm rejection handler gần nhất.
4. Không tìm thấy .catch() nào.
5. Promise rejection không được xử lý.
JavaScript engine sẽ theo dõi những Promise rejection không được xử lý và tạo ra một global error. Bạn có thể nhìn thấy lỗi trong Console của trình duyệt.

2. Sự kiện unhandledrejection
Trong trình duyệt , chúng ta có thể theo dõi lỗi Promise chưa được xử lý bằng sự kiện unhandledrejection
Ví dụ chính thức:
<!-- 
window.addEventListener('unhandledrejection', function(event) {
    // Hai thuộc tính đặc biệt
    alert(event.promise);
    alert(event.reason);
});

new Promise(function() {
    throw new Error("Whoops!");
}); // Không có catch
 -->
Hai thuộc tính cần nhớ :
| Thuộc tính      | Ý nghĩa                                          |
| --------------- | ------------------------------------------------ |
| `event.promise` | Promise gây ra lỗi chưa được xử lý               |
| `event.reason`  | Lý do Promise bị reject (thường là Error object) |

Ví dụ lấy thông tin lỗi:
<!-- 
window.addEventListener('unhandledrejection', function(event) {
    console.log("Promise:", event.promise);
    console.log("Reason:", event.reason);
    console.log("Message:", event.reason.message);
});
 -->
Khi Promise bị reject mà không có .catch() , sự kiện unhandledrejection được kích hoạt để ứng dụng có thể ghi nhận 
và xử lý tình huônngs này

3. Áp dụng trong Frontend
Ví dụ: Theo dõi lỗi Promise chưa được xử lý trong ứng dụng React.
<!-- 
window.addEventListener("unhandledrejection", event => {
    console.error("Unhandled Promise rejection:", event.reason);

    // Có thể gửi thông tin lỗi đến hệ thống monitoring
});
 -->
Lưu ý: đây là cơ chế giám sát lỗi toàn cục , không hay thế việc xử lý lỗi tại từng API hoặc Promise chain.
Tổng kết phần Unhandled rejections
- Promise rejected nhưng không có rejection handler => unhandled rejection.
- Trình duyệt có unhandledrejection
- event.promise: Promise gây lỗi
- event.reason: nguyên nhân lỗi.
- Có thể dùng để logging,monitoring và thông báo sự cố

Xét đoạn code:
<!-- 
window.addEventListener("unhandledrejection", event => {
    console.log("GLOBAL:", event.reason.message);
});

Promise.reject(new Error("API failed"))
    .then(value => {
        console.log("SUCCESS:", value);
    });
 -->
1. Promise.reject(new Error("API failed")) tạo Promise rejected
2. .then() không có rejectio handler nên callback success không chạy
3. Promise trả về từ .then() vẫn rejected.
4. Không có .catch() xử lý lỗi 
5. Trình duyệt phát sự kiện unhandledrejection
6. event.reason.message in ra "API failed".

Lưu ý : unhandledrejection là cơ chế giám sát toàn cục ,không nên dùng thay cho .catch() ở từng Promise chain.

Bài tập 

1. Promise executor chạy.
2. setTimeout() đăng ký callback chạy sau 1 giây.
3. Executor kết thúc mà không gọi resolve() hoặc reject() → Promise vẫn pending.
4. Sau 1s , callback của setTimeout chạy 
5. throw new Error()"Whoops!" tạo lỗi bên ngoài việc thực thi của Promise executor.
6. Lỗi k được chuyển thành rejection của Promise ban đầu

Vì vậy .catch(alert) không chạy.
Lưu ý: Không phải cứ throw ở bất kỳ đâu trong Promise là Promise tự động rejected. Cơ chế implicit try…catch chỉ bao quanh executor và Promise handlers, không bao quanh callback bất đồng bộ của setTimeout
3. Cách viết đúng nếu muốn .catch() bắt lỗi
<!-- 
new Promise((resolve, reject) => {
    setTimeout(() => {
        reject(new Error("Whoops!"));
    }, 1000);
}).catch(error => {
    console.log(error.message);
});
 -->
Bài học quan trọng: Khi làm việc với callback bất đồng bộ, phải chủ động chuyển lỗi thành reject() nếu muốn Promise chain xử lý lỗi đó.
