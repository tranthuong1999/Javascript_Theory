3. Học lý thuyết
3.1. Promises chaining
Giả sử chúng ta có nhiều task vụ bất đồng bộ cần thực hiện lần lượt 
1. Tải script thứ nhất.
2. Tải script thứ hai.
3. Tải script thứ ba.
Làm thế nào để tổ chức các task vụ này mà không tạo ra nhiều callback lồng nhau
Promise cung cấp một cách giải quyết: Promise chaining.
Ví dụ gốc:
<!-- 
new Promise(function(resolve, reject) {

    setTimeout(() => resolve(1), 1000);

}).then(function(result) {

    alert(result); // 1
    return result * 2;

}).then(function(result) {

    alert(result); // 2
    return result * 2;

}).then(function(result) {

    alert(result); // 4
    return result * 2;

});
 -->
Giải thích cách hoạt động
Bước 1: Promise ban đầu được fullfiled sau 1s với giá trị 1
Bước 2 : .then() đầu tiên nhận result = 1.
<!-- 
.then(function(result) {
    alert(result); // 1
    return result * 2; // 2
})
 -->
 Callback trả về 2
Bước 3: .then() tiếp theo nhận giá trị 2.
<!-- 
.then(function(result) {
    alert(result); // 2
    return result * 2; // 4
})
 -->
Callback trả về 4.
Bước 4: .then() cuối nhận 4 và hiển thị kết quả.
Hai nguyên tắc quan trọng
Nguyên tắc 1: Mỗi lần gọi .then() đều trả về 1 Promise mới
Đó chính là lý do chúng ta có thể gọi .then() tiếp theo.
Nguyên tắc 2: Khi 1 handler trả về giá trị , giá trị đó trở thành kết quả của Promise mới
Trường hợp A – Promise chaining
<!-- 
let promise = new Promise(resolve => {
    setTimeout(() => resolve(1), 1000);
});

promise
    .then(result => {
        console.log(result);
        return result * 2;
    })
    .then(result => {
        console.log(result);
        return result * 2;
    })
    .then(result => {
        console.log(result);
    });
 -->
Kết quả : 1 => 2 => 4
Trường hợp B – Nhiều handler trên cùng Promise
<!-- 
let promise = new Promise(resolve => {
    setTimeout(() => resolve(1), 1000);
});

promise.then(result => {
    console.log(result);
    return result * 2;
});

promise.then(result => {
    console.log(result);
    return result * 2;
});

promise.then(result => {
    console.log(result);
    return result * 2;
});
 -->
Kết quả : 1 => 1 => 1
Vì cả ba handler đều nhận kết quả của cùng Promise ban đầu.
Giá trị return của handler thứ nhất không chuyền sang handler thứ 2
Tổng kết phần 3.1
Bạn cần nhớ:
- .then() trả về một Promise mới.
- return truyền kết quả cho .then() tiếp theo.
- Nhiều .then() cùng gắn vào một Promise sẽ xử lý độc lập.
- Promise chaining thường được sử dụng để tổ chức các tác vụ bất đồng bộ tuần tự.

Bổ sung ngoài tài liệu gốc – Một lỗi dễ gặp
Quên return:
 <!--
 Promise.resolve(5)
    .then(result => {
        result * 2;
    })
    .then(result => {
        console.log(result);
    });
-->
Kết quả là undefined, vì callback đầu tiên không trả về giá trị 
Bài tập thực hành:
<!-- 
Promise.resolve(2)
    .then(value => {
        console.log(value);
        return value * 3;
    })
    .then(value => {
        console.log(value);
    });

Promise.resolve(2).then(value => {
    console.log(value * 5);
});
 -->
Ở đây có 2 Promise độc lập:
- Promise thứ nhất có một chuỗi gồm 2 .then().
- Promise thứ hai có một .then() riêng

2. Thứ tự thực thi
Bước 1: JavaScript chạy code đồng bộ
JS đăng ký các callback .then() vào 
Callback .then() thứ hai trong chuỗi chưa được đưa vào hàng đợi , vì nó phải đợi callback đầu tiên hoàn thành
Bước 2: Microtask thứ nhất chạy
<!-- 
.then(value => {
    console.log(value); // 2
    return value * 3;   // 6
})
 -->
Gía trị 6 được chuyển cho Promise tiếp theo trong chuỗi.
Lúc này callback .then() thứ 2 của Promise thứ nhất được đưa vào hàng đợi microtask
Bước 3: Microtask thứ hai chạy
<!-- 
Promise.resolve(2).then(value => {
    console.log(value * 5); // 10
});
 -->
In ra : 10
Bước 4: Microtask thứ ba chạy
3. Sơ đồ thứ tự thực thi
Đăng ký callback
- Promise 1: callback A
- Promise 2: callback B
Microtask 1:
Promise 1 → in 2 → tạo kết quả 6
Microtask 2
Promise 2 → in 10
Microtask 3
Promise 1 → in 6
4. Kiến thức quan trọng cần nhớ
Có hai điều bạn cần phân biệt:
- Promise chaining : .then() tiếp theo phải đợi .then() trước hoàn thành
- Promise độc lập: callback của nó có thể chạy xen giữa các bước trong chuỗi khác , tuỳ thứ tự được đưa
vào microtask queue.
Lưu ý: Đây là phần giải thích bổ sung về Microtask Queue để hiểu thứ tự output, không phải một mục mới trong tài liệu gốc.

2. Returning promises
Phần này giải thích điều gì xảy ra khi trả về một Promise bên trong .then() : .then() tiếp theo sẽ chờ Promise đó hoàn thành
thay vì chạy ngay chính Promise được trả về 
2.1. Lý thuyết
.then() có thể tạo và trả về một Promise()
Khi đó:
1. Promise mới được trả về
2. .then() tiếp theo phải chờ Promise mới hoàn thành.
3. Khi Promise hoàn thành , kết qủa của nó truyền cho then tiếp theo

2.2. Ví dụ trong tài liệu gốc
<!-- 
new Promise(function(resolve, reject) {
    setTimeout(() => resolve(1), 1000);

}).then(function(result) {

    console.log(result); // 1

    return new Promise((resolve, reject) => {
        setTimeout(() => resolve(result * 2), 1000);
    });

}).then(function(result) {

    console.log(result); // 2

    return new Promise((resolve, reject) => {
        setTimeout(() => resolve(result * 2), 1000);
    });

}).then(function(result) {

    console.log(result); // 4

});
 -->
Phân tích từng bước:
1. Promise ban đầu
Sau 1 giây, resolve(1) → .then() đầu tiên nhận 1.
2. .then() thứ nhất
In 1, sau đó trả về một Promise mới. Promise này đợi 1 giây rồi resolve(2).
3. .then() thứ hai
Chỉ chạy sau khi Promise vừa trả về hoàn thành. Nhận 2, in 2, rồi trả về Promise mới chứa kết quả 4.
4. .then() thứ ba
Đợi Promise trước hoàn thành, nhận 4 và in 4.
2.3. So sánh hai cách viết
Cách 1: Trả về Promise
<!-- 
Promise.resolve(1)
    .then(result => {
        return new Promise(resolve => {
            setTimeout(() => resolve(result * 2), 1000);
        });
    })
    .then(result => {
        console.log(result); // 2
    });
 -->
.then() tiếp theo chờ Promise bên trong hoàn thành.
Cách 2: Không trả về Promise
<!-- 
Promise.resolve(1)
    .then(result => {
        new Promise(resolve => {
            setTimeout(() => resolve(result * 2), 1000);
        });
    })
    .then(result => {
        console.log(result); // undefined
    });
 -->
Ở cách 2, callback không return Promise. Vì vậy Promise do .then() tạo ra hoàn thành với undefined, không chờ Promise bên trong.
2.4. Ứng dụng thực tế
Khi làm Frontend , ta thường cần thực hiện các tác vụ bất đồng bộ nối tiêp nhau :
<!-- 
fetch("/api/user")
    .then(response => response.json())
    .then(user => {
        return fetch(`/api/posts/${user.id}`);
    })
    .then(response => response.json())
    .then(posts => {
        console.log(posts);
    });
 -->
Gọi API user
    ↓
Đọc dữ liệu user
    ↓
Gọi API posts theo user.id
    ↓
Đọc dữ liệu posts
    ↓
Hiển thị posts
Điểm quan trọng: return fetch(...) giúp Promise chain chờ request tiếp theo hoàn thành.
Tổng kết phần 2
- then() có thể trả về 1 Promise
- .then() tiếp theo chờ Promise đó settle.
- Kết quả resolve được chuyển tiếp xuống chain
- Nhớ return Promise khi muốn nối các tác vụ bất đồng bộ.

Kiểm tra nhanh :
<!-- 
Promise.resolve(5)
    .then(value => {
        return new Promise(resolve => {
            setTimeout(() => resolve(value + 3), 1000);
        });
    })
    .then(value => {
        console.log(value);
    });
 -->
Diễn biến thực thi:
1. Promise.resolve(5) tạo Promise fulfilled với giá trị 5.
2. .then() đầu tiên nhận value = 5.
3. Callback trả về một Promise mới. Promise này đợi setTimeout 1 giây rồi resolve với 5 + 3 = 8.
4. .then() tiếp theo chờ Promise mới hoàn thành, sau đó nhận value = 8.
5. console.log(value) in ra 8

3. Example: loadScript
Promise chaining vào một tình huống thực tế: tải nhiều file JavaScript theo thứ tự, đảm bảo file sau chỉ được tải khi file trước đã tải xong.
Giả sử chúng ta đã có hàm loadScript() trả về Promise (đã học ở bài Promise basics).
<!-- 
loadScript("/article/promise-chaining/one.js")
    .then(function(script) {
        return loadScript("/article/promise-chaining/two.js");
    })
    .then(function(script) {
        return loadScript("/article/promise-chaining/three.js");
    })
    .then(function(script) {
        // Các script đã được tải xong
        one();
        two();
        three();
    });
 -->
1. Gọi loadScript() để tải one.js.
2. Khi one.js tải xong, .then() đầu tiên chạy và trả về Promise tải two.js.
3. JavaScript chờ Promise tải two.js hoàn thành.
4. Tiếp tục tải three.js.
5. Khi cả ba file đã tải xong, .then() cuối cùng chạy và gọi các hàm one(), two(), three().

Điểm quan trọng: Mỗi loadScript() tả về 1 promise .Vì vậy, khi trả Promise đó từ .then(), bước tiếp theo sẽ đợi 
nó hoàn thành
Viết ngắn hơn bằng Arrow Function
<!-- 
loadScript("/article/promise-chaining/one.js")
    .then(script => loadScript("/article/promise-chaining/two.js"))
    .then(script => loadScript("/article/promise-chaining/three.js"))
    .then(script => {
        one();
        two();
        three();
    });
 -->
Vì vậy, Promise chaining giúp code đi theo chiều dọc, dễ đọc và mở rộng hơn
Tổng kết phần 3
- Dùng return loadScript(...) để nối các thao tác tải script.
- Promise tiếp theo chỉ chạy khi Promise trước hoàn thành.
- Ưu tiên chaining thay vì lồng nhiều .then().
<!-- 
loadScript("one.js")
    .then(script => {
        return loadScript("two.js");
    })
    .then(script => {
        console.log("All scripts loaded");
    });
 -->
B. Để Promise của two.js được nối vào chuỗi, giúp bước tiếp theo chờ tải xong.

4. Thenables
.then() không bắt buộc trả về 1 promise thực sự . Nó có thể trả về object có phương thức then() (gọi là thenable).
4.1. Thenables là gì?
Thenable là một object bất kỳ có phương thức then().
Khi 1 promise handler trả về object này , JS sẽ xử lý tương tự Promise
4.2. Ví dụ trong tài liệu gốc
<!-- 
class Thenable {
    constructor(num) {
        this.num = num;
    }

    then(resolve, reject) {
        setTimeout(() => resolve(this.num * 2), 1000);
    }
}

new Promise(resolve => resolve(1))
    .then(result => {
        return new Thenable(result);
    })
    .then(alert); // 2 sau 1 giây -
 -->
1. new Promise(resolve => resolve(1)): Promise hoàn thành với kết quả 1.
2. .then() đầu tiên nhận result = 1.
3. return new Thenable(result) trả về một object có phương thức then().
4. JavaScript phát hiện object có phương thức then() và gọi nó, truyền vào hai hàm resolve, reject.
5. Sau 1 giây, resolve(this.num * 2) được gọi, tức resolve(2).
6. .then(alert) tiếp theo nhận kết quả 2.
Bài tập :
<!-- 
Promise.resolve(5)
    .then(value => {
        return {
            then(resolve) {
                resolve(value + 2);
            }
        };
    })
    .then(result => {
        console.log(result);
    });
 -->
Giải thích ngắn:
1. Promise.resolve(5) tạo Promise fulfilled với giá trị 5.
2. .then() đầu tiên trả về một thenable.
3. Promise gọi then(resolve) của object đó.
4. resolve(value + 2) tương đương resolve(7).
5. .then() tiếp theo nhận 7 và in ra màn hình.

5. Bigger example: fetch
Đây là phần quan trọng nhất về ứng dụng thực tế trong bài. Tài liệu sử dụng fetch() để gọi API và xử lý dữ liệu bằng Promise chaining.
5.1. fetch() hoạt động như thế nào?
<!-- let promise = fetch(url); -->
fetch thực hiện HTTP request và trả về 1 promise
Khi server phản hồi với headers, Promise được resolve và trả về một đối tượng Response.
Lưu ý: lúc này dữ liệu response có thể chưa được tải hoàn toàn
5.2. Đọc dữ liệu bằng response.text()
<!-- 
fetch('/article/promise-chaining/user.json')
    .then(function(response) {
        return response.text();
    })
    .then(function(text) {
        alert(text);
    });
 -->
Diễn biến:
1. fetch() gửi request đến server.
2. .then() đầu tiên nhận response.
3. response.text() đọc nội dung response và trả về Promise.
4. return giúp Promise tiếp theo chờ dữ liệu tải xong.
5. .then() thứ hai nhận nội dung dạng text.

5.3. Đọc dữ liệu bằng response.json()
Thông thường khi làm frontend, chúng ta muốn xử lý dữ liệu JSON thay vì chuỗi text.
<!-- 
fetch('/article/promise-chaining/user.json')
    .then(response => response.json())
    .then(user => alert(user.name));
 -->
| Phương thức       | Kết quả                                               |
| ----------------- | ----------------------------------------------------- |
| `response.text()` | Promise chứa dữ liệu dạng string                      |
| `response.json()` | Promise chứa dữ liệu đã parse thành JavaScript object |

5.4. Kết hợp nhiều API request
<!-- 
fetch('/article/promise-chaining/user.json')
    .then(response => response.json())
    .then(user => fetch(`https://api.github.com/users/${user.name}`))
    .then(response => response.json())
    .then(githubUser => {
        let img = document.createElement('img');
        img.src = githubUser.avatar_url;
        img.className = "promise-avatar-example";
        document.body.append(img);

        setTimeout(() => img.remove(), 3000);
    });
 -->
5.5. Vấn đề khi không return Promise
Sau khi avatar hiển thị và được xóa, nếu muốn thực hiện thêm hành động thì làm thế nào?
5.6. Tách thành các hàm có thể tái sử dụng
5.7. Bổ sung ngoài tài liệu gốc: một lưu ý quan trọng khi dùng fetch
fetch() không tự reject Promise chỉ vì server trả HTTP status như 404 hoặc 500.
Thông thường cần kiểm tra:
<!-- 
fetch('/api/users')
    .then(response => {
        if (!response.ok) {
            throw new Error('HTTP error: ' + response.status);
        }

        return response.json();
    })
    .then(users => {
        console.log(users);
    })
    .catch(error => {
        console.error(error);
    });
 -->
Tổng kết phần 5
Bạn cần nắm 5 ý:
1. fetch() trả về Promise.
2. response.text() đọc dữ liệu dạng text.
3. response.json() parse dữ liệu thành JavaScript object.
4. Có thể nối nhiều API request bằng Promise chaining.
5. Một thao tác bất đồng bộ muốn được chờ thì cần trả về Promise.

*******************************************************************************************************************
6. Summary
Tổng kết bài Promises chaining theo tài liệu gốc:
1. .then() trả về một Promise mới.
2. Giá trị được return trong .then() sẽ chuyển sang .then() tiếp theo.
3. Nếu trả về Promise, bước tiếp theo chờ Promise đó hoàn thành.
4. Nếu trả về thenable, Promise chain cũng tiếp nhận được.
5. Có thể nối nhiều thao tác bất đồng bộ như tải script, gọi API và xử lý dữ liệu.
6. Dùng chaining thay vì lồng nhiều .then() để code dễ đọc.

.then() truyền kết quả hoặc lỗi xuống bước tiếp theo trong Promise chain. Vì vậy, .catch() đặt phía sau có thể bắt cả lỗi phát sinh trong các handler trước đó.
