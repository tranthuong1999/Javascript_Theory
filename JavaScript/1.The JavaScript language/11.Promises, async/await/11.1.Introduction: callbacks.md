1.1. Hành động đồng bộ và bất đồng bộ
cần hiểu hai khái niệm quan trọng: Synchronous và Asynchronous.
1. Synchronous (Đồng bộ)
Các câu lệnh được thực hiện tuần tự . Cậu lệnh sau phải chờ câu lệnh trước hoàn thành
Ví dụ :
<!-- 
console.log("Task 1");
console.log("Task 2");
console.log("Task 3");
 -->
Kết quả:
Task 1 => Task 2 => Task 3
2. Asynchronous (Bất đồng bộ)
Một câu lệnh được khởi chạy trước nhưng hoàn thành sau . JS có thể tiếp tục thực hiện những câu lệnh khác mà k phải chờ
câu lệnh đó hoàn thành
<!-- 
console.log("Task 1");

setTimeout(() => {
  console.log("Task 2");
}, 1000);

console.log("Task 3");
 -->
 Task 1 => Task 3 => Task 2
 Giải thích:
1. In Task 1.
2. Đăng ký callback với setTimeout() để thực thi sau 1000ms
3. Tiếp tục in Task3
4. Sau khoảng 1000ms, callback được thực thi và in task 2

So sánh:
| Synchronous                           | Asynchronous                    |
| ------------------------------------- | ------------------------------- |
| Thực hiện tuần tự                     | Có thể hoàn thành sau           |
| Câu lệnh tiếp theo chờ câu lệnh trước | Không nhất thiết phải chờ       |
| Ví dụ: phép tính thông thường         | Ví dụ: `setTimeout`, tải script |

1.1.1. Kiểm tra kiến thức
<!-- 
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
 -->
Giải thích:
1. console.log("A") chạy ngay.
2. setTimeout(..., 0) đăng ký callback , không thực thi callback ngay lập tức
3. console.log("C") chạy tiếp.
4. Sau khi callback trống , callback được đưa vào thực thi và in B

Điểm cần nhớ: setTimeout(callback, 0) không có nghĩa là callback được chạy ngay . Nó chỉ có ý nghĩa là đủ diều kiện chạy sau
khoảng thời gian tối thiểu 0 ms;
1.2. Ví dụ với setTimeout()
setTimeout() cho phép thực hiện 1 hàm sau một khoảng thời gian nhất đinh
<!-- setTimeout(callback, delay); -->
callback : hàm sẽ được thực thi sau 1 khaongr thời gian chờ
delay : thời gian tính bằng ms
1000 = 1 giây.
2000 = 2 giây.
0 = Không yêu cầu chờ, nhưng callback vẫn được thực thi sau khi code đồng bộ hiện tại hoàn thành.
<!-- 
console.log("Start");

setTimeout(() => {
  console.log("Hello!");
}, 2000);

console.log("End");
 -->
Start => End => Hello
Giải thích thứ tự:
1. In start
2. Gọi setTimeout(), đăng ký callback để thực thi sau khoảng 2s
3. JS tiếp tục chạy end , không phải chờ 2s
4. Sau khi hết thời gian chờ và có thể thực thi callback , in Hello
Lưu ý: setTimeout() k đảm bảo callback chạy chính xác ngay tại thời điểm hết thời gian chờ . Nếu JS còn bận xử lý
code đồng bộ , callback phải đợi
Kiểm tra kiến thức
<!-- 
console.log("A");

setTimeout(() => {
  console.log("B");
}, 1000);

setTimeout(() => {
  console.log("C");
}, 0);

console.log("D");
 -->
Giải thích:
1. console.log("A") chạy ngay.
2. Callback thứ nhất được lên lịch sau 1000ms.
3. Callback thứ hai được lên lịch với delay 0ms.
4. console.log("D") chạy ngay vì code đồng bộ được ưu tiên.
5. Sau khi code đồng bộ hoàn tất , callback C chạy trước B vì thời gian chờ ngắn hơn

Ghi nhớ:setTimeout(callback, 0) k chạy ngay lập tức mà chờ code đồng bộ hoàn thành
1.3. Hàm loadScript()
Trong JS đôi khi chúng ta cần tải 1 file JS bên ngoài vào trang web để sử dụng các hàm hoặc các tính năng được đinh 
nghĩa trong file đó
Ví dụ, muốn tải file https://cdnjs.cloudflare.com/ajax/libs/lodash.js/4.17.21/lodash.min.js.
Ta có thể tạo hàm loadScript() để thực hiện việc này
Cách tải script bằng JavaScript
<!-- 
function loadScript(src) {
  let script = document.createElement("script");
  script.src = src;
  document.head.append(script);
}

loadScript("/my/script.js");
 -->
Giải thích:
- document.createElement("script"): Tạo một thẻ <script>.
- script.src = src: Thiết lập đường dẫn file JavaScript cần tải.
- document.head.append(script): Thêm thẻ script vào head của trang HTML.
- Trình duyệt sẽ tải và thực thi file JavaScript đó.

Vấn đề của cách viết trên
Giả sử file script.js chứa:
<!-- 
function sayHi() {
  console.log("Hello!");
}
-->
Ta viết:
<!-- 
loadScript("/script.js");

sayHi(); // Có thể xảy ra lỗi
 -->
Tại sao?
Bởi vì loadScript() chỉ bắt đầu quá trình tải file . Nó k đợi file tải xong mới chạy câu lệnh tiếp theo
Do đó, khi sayHi() được gọi, file script.js có thể vẫn chưa tải hàm xong và hàm sayHI() chưa tồn tại 
Đây chính là vấn đề khi làm việc với các hanhf động bất đồng bộ : làm thế nào để biết khi nào hành động đã hoàn thành ?

Điểm cần nhớ:
- loadScript() bắt đầu tải file.
- sayHi() có thể chạy trước khi file tải xong.
- Chúng ta cần một cơ chế để thông báo khi file đã tải hoàn tất. Đó chính là lý do cần callback.
1.4. Vấn đề khi không có callback
<!-- 
loadScript("/script.js");
sayHi();
 -->
 loadScript() bắt đầu tải file nhưng không thông báo cho chúng ta biết khi nào hoàn tất
 Vì vậy , sayHi() có thể gọi quá sớm
Giải pháp cần có
Chúng ta cần 1 cơ chế để 
1. Bắt đầu tải file JS
2. Chờ đền khi file tải xong
3. Sau đó mới thực hiện hàm sayHi().

Ví dụ, về mặt ý tưởng:
<!-- 
loadScript("/script.js");

// Chỉ gọi sayHi() sau khi script tải xong
 -->
Vấn đề là loadScript() hiện tại không có cách nào thông báo thời điểm hoàn thành cho đoạn code bên ngoài

Đây là hạn chế của cách viết hàm bất đồng bộ mà không có callback

Kiểm tra kiến thức
Điều gì còn thiếu trong phiên bản loadScript(src) hiện tại?

A. Cơ chế thông báo cho đoạn code bên ngoài khi script tải hoàn tất.

B. Cơ chế chuyển file JavaScript thành JSON.

Chúng ta cần callback để giải quyết vấn đề này:
<!-- 
function loadScript(src, callback) {
  // Tải script...

  // Khi tải xong, gọi callback()
}
 -->
Ví dụ sử dụng:
<!-- 
loadScript("/script.js", function () {

 -->
Khi script tải hoàn tất , callback() mới được gọi và sayHi() mới thực thi

2. Callback
2.1. Callback là gì?
1. Khái niệm
Callback là 1 hàm được truyền vào hàm khác dưới dạng tham số và được gọi lại bên trong hàm nhận nó
Nói đơn giản:
- Hàm A nhận hàm B làm tham số
- Khi cần thiết , hàm A gọi hàm B
- Hàm B chính là callback
2. Ví dụ cơ bản
<!-- 
function sayHello() {
  console.log("Hello!");
}

function processUser(callback) {
  console.log("Processing user...");

  callback();
}

processUser(sayHello);
 -->
Giải thích:
1. sayHello là 1 hàm 
2. processUser(sayHello) truyền hàm sayHello vào processUser
3. Tham số callback nhận tham chiếu đến hàm sayHello
4. callback() thực thi hàm sayHello
Lưu ý quan trọng:
<!-- 
processUser(sayHello);   // Truyền hàm
processUser(sayHello()); // Gọi hàm ngay rồi truyền kết quả trả về
 -->
Hai cách này khác nhau:
- sayHello : truyền hàm chính
- sayHello() : thực thi hàm ngay lập tức

3. Callback không nhất thiết phải là bất đồng bộ
Ví dụ trên là callback đồng bộ vì callback()  được gọi ngay trong quá trình thực thi processUser().
Callback có thể được sử dụng trong cả :
- Đồng bộ: array.map(), array.filter().
- Bất đồng bộ: setTimeout(), sự kiện click, tải script.
Kiểm tra kiến thức
<!-- 
function first() {
  console.log("First");
}

function second(callback) {
  console.log("Second");
  callback();
}

second(first);
 -->
Kết quả : Second => First
Khi gọi second(first):
1. Hàm second() bắt đầu chạy.
2. console.log("Second") được thực thi trước.
3. callback() gọi hàm first().
4. console.log("First") được thực thi.
Điểm quan trọng:
<!-- second(first); -->
first là hàm callback được truyền vào
callback() là lời gọi thực thi hàm

2.2. Truyền callback vào hàm
Ở phần trước, chúng ta đã biết callback là một hàm được truyền vào hàm khác dưới dạng đối số.
Bây giờ hãy tìm hiểu cách truyền callback để giúp một hàm linh hoạt hơn.

1. Ví dụ: Hàm xử lý người dùng
Giả sử chúng ta có 1 hàm ask() dùng để hỏi tên người dùng 
<!-- 
function ask(question, yes, no) {
  if (confirm(question)) {
    yes();
  } else {
    no();
  }
}

function showOk() {
  alert("You agreed.");
}

function showCancel() {
  alert("You canceled the execution.");
}

ask("Do you agree?", showOk, showCancel);
 -->
Giải thích:
- question: Nội dung câu hỏi.
- yes: Callback được gọi nếu người dụng chọn OK
- no : Callback được gọi nếu người dụng chọn Cancel
- confirm(): hiển thị hộp thoại xác nhận và trả về true hoặc false

2. Vì sao sử dụng callback?
Nếu không sử dụng callback chúng ta có thể viết riêng một hàm cho từng trường hợp 
Nhưng với callback , hàm ask() không cần biết phải thực hiện hành động nào sau khi người dùng lựa chọn 
Nó chỉ cần biết:
- Nếu đồng ý thì gọi yes().
- Nếu từ chối thì gọi no().
Nhờ vậy , chúng ta có thể tái sử dụng ask() với nhiều hành động khác nhau

3. Callback giúp tăng tính linh hoạt
Ví dụ , thay vì chỉ thông báo  chúng ta có thể truyền hành động khác
<!-- 
ask(
  "Do you agree?",
  () => console.log("Continue registration"),
  () => console.log("Cancel registration")
);
 -->
Cùng một hàm ask(), nhưng hành động thực hiện phụ thuộc vào callback được truyền vào.
Kiểm tra kiến thức
<!-- 
function processData(data, callback) {
  console.log(data);
  callback();
}

function finish() {
  console.log("Finished");
}

processData("Hello", finish);
 -->
Vai trò của finish là gì?
C. Callback được truyền vào processData() và được gọi bên trong hàm.
Giải thích:
<!-- processData("Hello", finish); -->
finish được truyền vào tham số callback.
callback() bên trong processData() thực thi hàm finish().
finish không được gọi ngay tại thời điểm truyền vào.
Kết quả:
<!-- 
Hello
Finished
 -->
Ghi nhớ:
- finish: truyền hàm
- finish() : thực thi hàm
- callback : tham số nhận hàm được tryền vào

2.3. Thực thi callback khi hoàn thành
Ở phần trước, chúng ta đã biết cách truyền callback vào một hàm.

Bây giờ áp dụng callback để giải quyết vấn đề đã gặp với loadScript().
1. Cải tiến hàm loadScript()
Ở phiên bản cũ:
<!-- 
function loadScript(src) {
  let script = document.createElement("script");
  script.src = src;
  document.head.append(script);
}
-->
Vấn đề : Hàm không thông báo khi script tải xong
Chúng ta bổ sung tham số callback
<!-- 
function loadScript(src, callback) {
  let script = document.createElement("script");
  script.src = src;

  script.onload = () => callback();

  document.head.append(script);
}
-->
Trong đó:
- src: đường dẫn file JS
- callback : hàm sẽ được gọi khi script tải thành công
- script.onload: sự kiện được kích hoạt khi script tải và thực thi thành công
2. Sử dụng callback
Giả sử file script.js chứa:
<!-- 
function sayHi() {
  console.log("Hello!");
}
-->
Ta sử dụng :
<!-- 
loadScript("/script.js", function () {
  sayHi();
});
 -->
Như vậy chúng ta đảm bảo được rằng sayHi() chỉ được gọi sau khi file script tải thành công
3. Callback có thể nhận tham số
Callback không nhất thiết phải là hàm không có tham số
<!-- 
function loadScript(src, callback) {
  let script = document.createElement("script");
  script.src = src;

  script.onload = () => callback(script);

  document.head.append(script);
}

loadScript("/script.js", function (script) {
  console.log(`Loaded: ${script.src}`);
});
 -->
Ở đây:
- callback(script) truyền phần từ script vào callback
- Hàm callback nhận nó thông qua tham số script
- Nhờ vậy , callback có thể sử dụng thông tin của phần tử vừa tải

Lưu ý: Ví dụ trên chỉ xử lý trươngf hợp tải thành công . Việc xử lý lỗi tải script sẽ đề cập ở phần sau
Kiểm tra kiến thưc :
<!-- 
function loadScript(src, callback) {
  let script = document.createElement("script");
  script.src = src;

  script.onload = () => callback();

  document.head.append(script);
}

loadScript("/script.js", () => {
  console.log("Script loaded");
});

console.log("Continue");
 -->
B. "Continue" được in trước, sau đó "Script loaded" khi script tải thành công.
Giải thích:
1. loadScript() bắt đầu tải file /script.js.
2. JavaScript tiếp tục chạy console.log("Continue").
3. Khi script tải và thực thi thành công, sự kiện onload được kích hoạt.
4. Callback được gọi và in "Script loaded".
Ghi nhớ:
- script.onload: Chạy khi script tải thành công
- callback(): Thực thi hàm được truyền vào.
- Callback giúp thực hiện công việc tiếp theo sau khi 1 hành động bất đồng bộ hoàn thành

2.4. Sử dụng callback để tải script
Chúng ta đã biết cách sử dụng callback sau khi script tải thành công
Bây giờ hãy xem cách sử dụng hàm loadScript() nhiều lần.
1. Tải một script
<!-- 
function loadScript(src, callback) {
  let script = document.createElement("script");
  script.src = src;

  script.onload = () => callback(script);

  document.head.append(script);
}

loadScript("/script.js", function (script) {
  console.log(`Loaded: ${script.src}`);
});
 -->
Khi script.js tải thành công, callback được gọi.
2. Tải script và sử dụng hàm bên trong
Giả sử script.js định nghĩa:
<!-- 
function sayHi() {
  console.log("Hello!");
}
-->
Ta viết:
<!-- 
loadScript("/script.js", function () {
  sayHi();
});
 -->
Điều này đảm bảo sayHi() chỉ được gọi sau khi script đã tải và thực thi thành công

3. Tải nhiều script theo thứ tự
Giả sử:
- script1.js định nghĩa hàm step1().
- script2.js định nghĩa hàm step2().
Nếu script2.js cần sử dụng step1() chúng ta cần đảm bảo script1.js tải xong trước
Có thể viết:
<!-- 
loadScript("/script1.js", function () {
  step1();

  loadScript("/script2.js", function () {
    step2();
  });
});
 -->
 Như vậy ,callback giúp chúng ta kiểm soát thứ tự thực hiện các hành động bất đồng bộ
 4. Điều cần chú ý
Khi tải nhiểu script phụ thuộc nhau , chúng ta phải đặt lời gợi loadScrpit() tiếp bên trong callback của lần tải trước
Đây là cách giải quyết vấn đề thứ tự thực thi , nhưng khi số lượng script tăng nên , callback có thể bị lồng nhiều tầng
Đó chính là vấn đề chúng ta sẽ tìm hiểu ở phần Callback in callback.

Kiểm tra kiến thức
Giả sử script2.js cần sử dụng hàm được định nghĩa trong script1.js. Cách nào đảm bảo thứ tự tải đúng?
<!--

4.1. Xử lý lỗi khi tải script

4.2. Error-first callback
Chúng ta đã biết cách sử dung onload và onerror để xử lý 2 trường hợp tải script thành công hay thất bại 
Tuy nhiên, hàm gọi loadScript() vẫn chưa nhận được thông tin về lỗi.
Giải pháp là sử dụng Error-first callback.
1. Error-first callback là gì?
Error-first callback là 1 quy ước truyền tham số cho callback:
Tham số đầu tiên là dành cho lỗi eror
Các tham số tiếp theo là dành cho kết quả (result)
Thông thường:
- Nếu có lỗi truyền vào tham số đầu tiên
- Nếu thành công : truyền null vào tham số và kết quả vào tham số tiếp theo

2. Áp dụng vào loadScript()
<!-- 
function loadScript(src, callback) {
  let script = document.createElement("script");
  script.src = src;

  script.onload = () => callback(null, script);

  script.onerror = () => callback(new Error(`Error loading script: ${src}`));

  document.head.append(script);
}
-->
Giải thích:
Trường hợp thành công:
<!-- script.onload = () => callback(null, script); -->
null : không có lỗi 
script : kết quả trả về , chính là phần tử script
Trường hợp thất bại:
<!-- script.onerror = () => callback(new Error(`Error loading script: ${src}`)); -->
Truyền đối tượng Error vào tham số ban đầu 
Không có kết quả nên k cần truyền tham số thứ 2
3. Sử dụng Error-first callback
<!-- 
loadScript("/script.js", function (error, script) {
  if (error) {

    return;
  }

  console.log(`Loaded: ${script.src}`);
});
 -->
Luồng xử lý:
Gọi loadScript()

function processPosts(posts) {
  getComments(posts[0].id, showComments);
}

function processUser(user) {
  getPosts(user.id, processPosts);
}

getUser(userId, processUser);
 -->

*******************************************************************************************************************
6.1. Tổng kết Introduction: callbacks
1. Synchronous và Asynchronous
| Kiến thức      | Nội dung                                              |
| -------------- | ----------------------------------------------------- |
| Synchronous    | Thực thi tuần tự, câu lệnh sau chờ câu lệnh trước     |
| Asynchronous   | Tác vụ hoàn thành sau, không chặn luồng code hiện tại |
| `setTimeout()` | Lên lịch thực thi callback sau một khoảng thời gian   |
2. Callback
Callback là hàm được truyền vào một hàm khác dưới dạng đối số và được gọi bên trong hàm đó.
<!-- 
function processUser(callback) {
  callback();
}

function sayHello() {
  console.log("Hello");
}

processUser(sayHello);
 -->
Phân biệt:
- sayHello: truyền tham chiếu hàm.
- sayHello(): gọi hàm ngay lập tức.

3. Callback trong xử lý bất đồng bộ
Callback giúp thực hiện bước tiếp theo khi một tác vụ bất đồng bộ hoàn thành.
<!-- 
function loadScript(src, callback) {
  const script = document.createElement("script");
  script.src = src;

  script.onload = () => callback(null, script);
  script.onerror = () => callback(new Error("Loading failed"));

  document.head.append(script);
}
 -->
 4. Error-first callback
Quy ước thường dùng trong Node.js và nhiều API callback:
<!-- callback(error, result); -->
| Trường hợp | Cách gọi                 |
| ---------- | ------------------------ |
| Thành công | `callback(null, result)` |
| Thất bại   | `callback(error)`        |
5. Callback Hell – Pyramid of Doom
Là tình trạng có quá nhiều callback lồng nhau, khiến code khó đọc, khó bảo trì và khó xử lý lỗi.

Hai hướng cải thiện đã học:
- Tách callback thành các hàm riêng.
- Giảm việc lồng callback bằng cách tổ chức lại luồng xử lý.
6. Những điểm cần nhớ
Kiến thức cốt lõi

- Callback là một hàm được truyền vào hàm khác.
- Callback có thể được thực thi đồng bộ hoặc bất đồng bộ.
- Callback thường dùng để xử lý kết quả sau khi tác vụ bất đồng bộ hoàn thành.
- Error-first callback đặt tham số lỗi ở vị trí đầu tiên.
- Callback Hell là vấn đề về cấu trúc và khả năng quản lý code.

Thay vì truyền chuỗi "User not found", nên truyền một đối tượng Error:
<!-- callback(new Error("User not found")); -->
Vì Error cung cấp thêm thông tin như name, message, stack.
