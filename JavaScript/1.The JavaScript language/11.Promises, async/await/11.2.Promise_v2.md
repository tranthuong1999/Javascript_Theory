1. Promise
1.1. Producing code và Consuming code
Trong JavaScript, khi xử lý một công việc mất thời gian, ví dụ gọi API, chúng ta thường có hai loại code:
Producing code – Code tạo ra kết quả
Là đoạn code thực hiện công việc và tạo ra kết quả sau 1 thời gian
<!-- 
function getUser() {
    return fetch("https://api.example.com/users/1");
}
 -->
Ở đây, getUser() thực hiện việc gọi API để lấy dữ liệu người dùng.
Consuming code – Code sử dụng kết quả
<!-- 
getUser().then((response) => {
    console.log(response);
});
 -->
.then() nhận kết quả sau khi promise thành công
Case dễ nhầm
- Producing code không nhất thiết phải là API. Nó có thể là đọc file, truy vấn database hoặc thực hiện một tác vụ bất đồng bộ khác.
- Consuming code không nhất thiết chỉ có một nơi sử dụng kết quả. Nhiều hàm có thể cùng đăng ký nhận kết quả từ một Promise.
( Bổ sung giải thích:
Promise không tụ thực hiện công việc bất đồng bộ . Công việc được thực hiện bởi Producing code; Promise là đối tượng đại diện cho
trạng thái và kết quả của công việc đó

1.2. Promise là gì?
Promise là một đối tượng JavaScript đại diện cho kết quả của một công việc chưa hoàn thành tại thời điểm hiện tại, nhưng có thể hoàn thành trong tương lai.
<!-- 
const promise = fetch("https://api.example.com/users");
console.log(promise);
 -->
 fetch() trả về 1 promise , chứ k trả ngay về dữ liệu API
 Khi API hoàn thành , Promise sẽ có kết quả thành công hoặc thất bại 
 Điểm cần nhớ: Promise giúp chúng ta đăng ký trước cách xử lý kết quả, thay vì phải chờ công việc hoàn thành rồi mới viết code xử lý.
1.3. Cú pháp new Promise()
<!-- 
let promise = new Promise(function(resolve, reject) {
    // executor
});
 -->
Giải thích:

| Thành phần      | Ý nghĩa                  |
| --------------- | ------------------------ |
| `new Promise()` | Tạo một Promise mới      |
| `function()`    | Executor                 |
| `resolve`       | Báo công việc thành công |
| `reject`        | Báo công việc thất bại   |
<!-- 
const promise = new Promise((resolve, reject) => {
    setTimeout(() => {
        resolve("Success");
    }, 1000);
});
 -->
Khi tạo Promise:
1. Executor được chạy ngay lập tức
2. setTimeout() lên lịch sau 1s
3. Sau 1 giây, resolve("Success") được gọi.
4. Promise chuyển sang trạng thái thành công

Case dễ sai
<!-- 
const promise = new Promise((resolve, reject) => {
    console.log("A");
});

console.log("B");
 -->
 Kết quả :
 A => B
 Lý do: Executor chạy ngay khi tạo Promise, không phải đợi promise hoàn thành 

1.4. Executor, resolve và reject
Executor là hàm được truyền vào new Promise() . Nó chứa phần code và thực hiện công việc 
JS cung cấp sẵn 2 callback:
resolve(value): Báo công việc hoàn thành thành công.
reject(error): Báo công việc thất bại.
Ví dụ thành công :
<!-- 
const promise = new Promise((resolve, reject) => {
    resolve("User found");
});
 -->
Ví dụ thất bại:
<!-- 
const promise = new Promise((resolve, reject) => {
    reject(new Error("User not found"));
});
 -->
Case rất dễ sai: Gọi resolve không dừng Executor
<!-- 
const promise = new Promise((resolve, reject) => {
    console.log("Start");

    resolve("Success");

    console.log("End");
});
 -->
Start
End
Tại sao?
resolve() chỉ thay đổi trạng thái Promise , không kết thúc hàm Executor
Muốn dưng thực thi ,cần dùng return :
<!-- 
const promise = new Promise((resolve, reject) => {
    console.log("Start");

    resolve("Success");

    return;

    console.log("End");
});
 -->
1.5. State và result
Case dễ nhầm
fulfilled không đồng nghĩa với pending, và rejected cũng không phải trạng thái chờ lỗi.

Một Promise chỉ bắt đầu ở pending, sau đó chuyển sang một trong hai trạng thái cuối cùng.
1.6. Settled – Promise chỉ có một kết quả
Một promise đã chuyển sang trạng thái fulfilled hoặc rejected được gọi là settled.
Điểm quan trọng: Promise chỉ được settle 1 lần
<!-- 
const promise = new Promise((resolve, reject) => {
    resolve("Success");

    reject(new Error("Failed"));
});
-->
Kết quả cuối cùng vẫn là:
fulfilled => Success
Lý do: resolve() được gọi trước, nên reject() sau đó bị bỏ qua.
Các case dễ sai
- Gọi resolve() nhiều lần: chỉ lần đầu có tác dụng.
- Gọi reject() sau resolve(): bị bỏ qua.
- Gọi resolve() sau reject(): bị bỏ qua.
- resolve() và reject() chỉ nhận một đối số có ý nghĩa; các đối số bổ sung bị bỏ qua.

1.7. Reject với Error objects
Khi có lỗi, tài liệu khuyến nghị sử dụng đối tượng Error hoặc đối tượng kế thừa từ Error.
<!-- 
const promise = new Promise((resolve, reject) => {
    reject(new Error("User not found"));
});
 -->
Có thể viết:
<!-- 
reject("User not found");
 -->
Nhưng cách này không được khuyến nghị.
Vì Error cung cấp thông tin như :
name: Tên loại lỗi.
message: Nội dung lỗi.
stack: Dấu vết lời gọi gây ra lỗi.
Nên dùng:
 <!--
 reject(new Error("Something went wrong"));
-->
1.8. Gọi resolve/reject ngay lập tức
Không bắt buộc Promise phải xử lý công việc bất đồng bộ mới gọi resolve() hoặc reject().
Ví dụ :
<!-- 
const promise = new Promise((resolve, reject) => {
    resolve(123);
});
-->
Promise được fullfield ngay trong Executor
Trường hợp thực tế: dữ liệu đã có sẵn trong cache k cần gọi lại 
<!-- 
const promise = new Promise((resolve) => {
    resolve("Done");
});

console.log("After");

promise.then(console.log);
 -->
Mặc dù Promise đã fulfilled ngay lập tức, callback trong then vẫn được thực thi bất đồng bộ sau đoạn code đồng bộ hiện tại 

1.9. State và result là thuộc tính nội bộ
Theo tài liệu, không thể truy cập trực tiếp:
<!-- 
promise.state
promise.result
 -->
Đây không phải các thuộc tính công khai để đọc trạng thái Promise
Chúng ta sử dụng:
- .then() để xử lý thành công.
- .catch() để xử lý lỗi.
- - .finally() để thực hiện công việc dọn dẹp.

2. Consumers: then, catch
Promise là cầu nối giữa Executor (Producing code) và các hàm nhận kết quả (Consuming code).
Chúng ta đăng ký các hàm nhận kết quả bằng 2 phương thức:
.then(): Xử lý kết quả thành công và có thể xử lý cả lỗi.
.catch(): Xử lý lỗi.
2.1. then()
<!-- 
promise.then(
    function(result) {
        // Xử lý khi thành công
    },
    function(error) {
        // Xử lý khi thất bại
    }
);
-->
.then() nhận tối đa hai hàm callback:
Trường hợp 1: Promise thành công
<!-- 
const promise = new Promise((resolve, reject) => {
    setTimeout(() => {
        resolve("done!");
    }, 1000);
});

promise.then(
    result => console.log(result),
    error => console.log(error)
);
 -->
Kết quả sau 1 giây: done!
Giải thích:
1. Promise được tạo.
2. Sau 1 giây, resolve("done!") được gọi.
3. Promise chuyển sang fulfilled.
4. Callback thứ nhất trong .then() được thực thi.
5. Callback thứ hai không chạy.
Trường hợp 2: Promise thất bại
<!-- 
const promise = new Promise((resolve, reject) => {
    setTimeout(() => {
        reject(new Error("Whoops!"));
    }, 1000);
});

promise.then(
    result => console.log(result),
    error => console.log(error)
);
 -->
Kết quả sau 1 giây: Error: Whoops!
Giải thích:
1. Promise được tạo.
2. Sau 1 giây, reject() được gọi.
3. Promise chuyển sang rejected.
4. Callback thứ nhất không chạy.
5. Callback thứ hai nhận lỗi và được thực thi.

Chỉ quan tâm đến kết quả thành công:
Nếu chỉ muốn xử lý khi Promise thành công, chúng ta có thể truyền một callback:
<!-- 
const promise = new Promise(resolve => {
    setTimeout(() => {
        resolve("done!");
    }, 1000);
});

promise.then(result => {
    console.log(result);
});
 -->
* Các case dễ sai
Case 1 – Nhầm hàm callback với kết quả trả về
<!-- 
promise.then(
    console.log("Success")
);
 -->
Đây là cách viết sai mục đích là đăng ký callback
Vì console.log("Success") được gọi ngay lập tức , và giá trị trả về của nó là (undefined) được truyền vào .then()
Cách đúng:
<!-- 
promise.then(() => {
    console.log("Success");
});
 -->
Case 2 – Nhầm thứ tự hai callback
<!-- 
promise.then(
    result => console.log("Success", result),
    error => console.log("Error", error)
);
 -->
Callback thứ nhất xử lý thành công 
Callback thứ hai xử lý thất bại 
Không được đảo ngược hai vị trí này.
Case 3 – Promise rejected nhưng không có callback xử lý lỗi
<!-- 
promise.then(result => {
    console.log(result);
});
 -->
Đoạn code này chỉ xử lý thành công . Nếu promise reject thì callback này không chạy và tiếp tục được truyền đi trong chuỗi Promise

2.2. catch()
Nếu chúng ta chỉ quan tâm đến việc xử lý lỗi, tài liệu gốc giới thiệu hai cách:
Cách 1: Dùng .then(null, errorHandlingFunction)
<!-- 
promise.then(
    null,
    error => {
        console.log(error);
    }
);
 -->
Ở đây:
- null : không đăng ký callback xử lý thành công
- Callback thứ hai: Xử lý lỗi.
Cách 2: Dùng .catch()
<!-- 
promise.catch(error => {
    console.log(error);
});
 -->
2 cách trên là hoàn toàn tương đương
<!-- promise.catch(errorHandlingFunction); -->
Tương đương với:
<!-- promise.then(null, errorHandlingFunction); -->
Vì vậy, chỉ cần khi xử lý lỗi , chúng ta thương xử dụng catch ngắn gon và dễ đọc hơn
Ví dụ thực tế
<!-- 
const promise = new Promise((resolve, reject) => {
    setTimeout(() => {
        reject(new Error("User not found"));
    }, 1000);
});

promise.catch(error => {
    console.log(error.message);
});
 -->
Kết quả: User not found
Nếu Executor ném lỗi bằng throw, Promise sẽ chuyển sang rejected:
<!-- 
const promise = new Promise((resolve, reject) => {
    throw new Error("Something went wrong");
});

promise.catch(error => {
    console.log(error.message);
});
 -->
Kết quả: Something went wrong
Đây là tình huống bạn thương xử lý khi gặp code bất đồng bộ 
Tổng kết phần 2
| Phương thức                      | Mục đích                              |
| -------------------------------- | ------------------------------------- |
| `.then(onFulfilled, onRejected)` | Xử lý thành công và/hoặc thất bại     |
| `.then(onFulfilled)`             | Chỉ xử lý thành công                  |
| `.then(null, onRejected)`        | Chỉ xử lý thất bại                    |
| `.catch(onRejected)`             | Xử lý thất bại, tương đương cách trên |

Điều cần nhớ nhất:
<!-- 
promise
    .then(result => {
        console.log("Success:", result);
    })
    .catch(error => {
        console.log("Error:", error);
    });
 -->
 Bài tập áp dụng :
 <!-- 
 
const promise = new Promise((resolve, reject) => {
    resolve("Success");
});

promise.then(
    result => console.log("A:", result),
    error => console.log("B:", error)
);

promise.catch(error => {
    console.log("C:", error);
});
-->
1. resolve("Success") khiến Promise chuyển sang fulfilled.
2. Callback thứ nhất của .then() được thực thi.
3. Callback thứ hai chỉ chạy khi Promise rejected.
4. catch() chỉ xử lý lỗi nên không được thực thi.

3. Cleanup: finally
3.1. finally()
.finally() là phương thức sử dụng để thực hiện 1 đoạn code sau khi Promise hoàn thành , bất kể Promise thành công hay thất bại
Ví dụ thực tế: Khi gọi API, chúng ta hiển thị loading. Khi API hoàn thành, dù thành công hay thất bại, đều phải tắt loading.
<!-- 
fetch("/api/users")
    .then(response => {
        console.log("Success");
    })
    .catch(error => {
        console.log("Error:", error);
    })
    .finally(() => {
        console.log("Hide loading");
    });
 -->
Nếu API thành công:
Success => Hide loading
Nếu API thất bại:
Error: ... => Hide loading

Đặc điểm của finally() : .finally() có các đặc điểm sau:
1. Không nhận kết quả hoặc lỗi làm tham số
<!-- 
promise.finally(() => {
    console.log("Finished");
});
 -->
Callback của finally() không nhận đối số result hoặc error.
2. Chạy bất kể Promise thành công hay thất bại
<!-- 
Promise.resolve("Success")
    .finally(() => {
        console.log("Finally");
    });
 -->
Kết quả: Finally
Với Promise thất bại:
<!-- 
Promise.reject(new Error("Failed"))
    .finally(() => {
        console.log("Finally");
    });
 -->
Kết quả: Finally
3. finally() chuyển tiếp kết quả hoặc lỗi ban đầu
Đây là đặc điểm rất quan trọng.
<!-- 
Promise.resolve("Success")
    .finally(() => {
        console.log("Cleanup");
    })
    .then(result => {
        console.log(result);
    });
 -->
Kết quả : Cleanup => Success
Mặc dù có finally(), giá trị "Success" vẫn được giữ nguyên và chuyển đến .then().
Tương tự với lỗi:
<!-- 
Promise.reject(new Error("Failed"))
    .finally(() => {
        console.log("Cleanup");
    })
    .catch(error => {
        console.log(error.message);
    });
 -->
Cleanup
Failed
4. Giá trị trả về từ finally() bị bỏ qua
Ví dụ:
<!-- 
Promise.resolve("Success")
    .finally(() => {
        return "Another value";
    })
    .then(result => {
        console.log(result);
    });
 -->
Kết quả: Success
Giá trị " Another value" không thay thế kết quả ban đầu
3.2. Các case dễ sai
Case 1 – Nghĩ finally chỉ chạy khi thành công
Sai. finally() chạy khi Promise fulfilled hoặc rejected.
Case 2 – Nghĩ finally nhận được kết quả
<!-- 
Promise.resolve("Hello")
    .finally(result => {
        console.log(result);
    });
 -->
result ở đây là undefined, không phải "Hello".
Nếu muốn nhận kết quả, hãy sử dụng .then().
Case 3 – finally làm mất kết quả ban đầu
<!-- 
Promise.resolve(100)
    .finally(() => 200)
    .then(console.log);
 -->
Nếu callback trong finally() phát sinh lỗi, Promise tiếp theo sẽ bị rejected bằng lỗi mới.
<!-- 
Promise.resolve("Success")
    .finally(() => {
        throw new Error("Cleanup failed");
    })
    .then(result => {
        console.log(result);
    })
    .catch(error => {
        console.log(error.message);
    });
 -->
Kết quả: Cleanup failed
Lỗi mới trong finally() làm thay đổi kết quả của chuỗi Promise
3.3. Tổng kết
| Phương thức | Mục đích                                   |
| ----------- | ------------------------------------------ |
| `then()`    | Xử lý thành công                           |
| `catch()`   | Xử lý thất bại                             |
| `finally()` | Thực hiện dọn dẹp sau khi Promise kết thúc |
Hãy nhớ: finally() thường dùng cho những công việc cần thực hiện dù thành công hay thất bại, chẳng hạn tắt loading, đóng kết nối hoặc giải phóng tài nguyên.

Ghi nhớ
- finally() không nhận result hoặc error.
- Giá trị trả về thông thường của finally() bị bỏ qua.
- Nếu finally() ném lỗi hoặc trả về Promise rejected, chuỗi Promise sẽ chuyển sang rejected.

4. We can attach handlers to settled promises
4.1. Đăng ký handler sau khi Promise đã settled
Trong các phần trước, chúng ta đã biết Promise có thể chuyển sang hai trạng thái cuối cùng:
- fulfilled: Hoàn thành thành công.
- rejected: Hoàn thành thất bại.

Một điểm quan trọng : chúng ta vẫn có thể đăng ký .then() , .catch() hoặc .finally() sau khi Promise đã settled
Các handler vẫn thực thi với kết quả tương ứng :
Ví dụ 1: Promise đã fulfilled
<!-- 
const promise = new Promise(resolve => {
    resolve("Done!");
});

setTimeout(() => {
    promise.then(result => {
        console.log(result);
    });
}, 1000);
 -->
Kết quả : Done!
Giải thích:
1. Promise được tạo.
2. resolve("Done!") được gọi ngay lập tức.
3. Promise chuyển sang fulfilled.
4. Sau 1 giây, chúng ta mới đăng ký .then().
5. Callback vẫn được thực thi và nhận "Done!".

Ví dụ 2: Promise đã rejected
<!-- 
const promise = new Promise((resolve, reject) => {
    reject(new Error("Failed"));
});

setTimeout(() => {
    promise.catch(error => {
        console.log(error.message);
    });
}, 1000);
 -->
Kết quả: Failed
Dù project đã reject trước đó . catch() vẫn nhận được nó
4.2. Tại sao điều này quan trọng?
Bạn không cần phải đăng ký handler ngay tại thời điểm tạo Promise
Ví dụ:
<!-- 
const promise = fetch("/api/users");

// Một đoạn code khác thực hiện công việc...

promise.then(response => {
    console.log(response);
});
 -->
Kể cả khi API đã hoàn thành trước lúc .then() được đăng ký, handler vẫn được thực thi 
Điều này giúp Promise linh hoạt hơn trong việc chia sẻ giữa nhiều phần code
4.3. Các case dễ sai
Case 1 – Nghĩ Promise settled rồi thì không thể đăng ký handler
Sai. Bạn có thể đăng ký handler bất cứ lúc nào, kể cả sau khi Promise đã settled.
Case 2 – Nghĩ callback chạy đồng bộ nếu Promise đã fulfilled
<!-- 
const promise = Promise.resolve("Done");

promise.then(result => {
    console.log(result);
});

console.log("After");
 -->
Mặc dù Promise đã fulfilled, callback . then() vẫn đưa vào hàng đợi microtask , k chạy ngay lập tức 
Case 3 – Đăng ký nhiều handler nhưng nghĩ chỉ một handler được chạy
<!-- 
const promise = Promise.resolve("Success");

promise.then(result => {
    console.log("Handler 1:", result);
});

promise.then(result => {
    console.log("Handler 2:", result);
});
 -->
Kết quả :
Handler 1: Success
Handler 2: Success
Cả hai hanlder đều được thực thi và nhận cùng 1 kết quả
Các callback .then(), .catch() và .finally() được thực thi thông qua cơ chế microtask của JavaScript
Dây là lý do chúng không chạy code đồng bộ ngay trong luồng code hiện tại , ngay cả khi Promise đã settled
4.4. Tổng kết
Bạn cần nhớ ba điều:
1. Có thể đăng ký handler sau khi Promise đã settled.
2. Handler vẫn nhận được kết quả hoặc lỗi đã được lưu trong Promise.
3. Hanler luôn chạy bất đồng bộ sau code đồng bộ hiện tại 
Bài tập thực hành 
<!-- 
const promise = Promise.resolve("A");

promise.then(result => {
    console.log(result);
});

console.log("B");

promise.then(result => {
    console.log(result + "C");
});
 -->
Giải thích theo thứ tự thực thi:
1. Promise.resolve("A"): Promise fulfilled ngay lập tức.
2. .then() thứ nhất: Đưa callback vào hàng đợi microtask.
3. console.log("B"): Chạy ngay vì đây là code đồng bộ.
4. .then() thứ hai: Đưa callback tiếp theo vào hàng đợi microtask.
5. Code đồng bộ kết thúc, JavaScript thực thi các microtask theo thứ tự đăng ký: in A, rồi AC.
Kiến thức cần nhớ
- Promise settled không có nghĩa callback chạy đồng bộ.
- Các handler được đăng ký nhiều lần có thể chạy
- Microtask được thực thi sau khi code đồng bộ hiện tại hoàn tất

5. Example: loadScript
Đây là phần quan trọng vì giúp bạn hiểu Promise giải quyết vấn đề gì trong thực tế.
5.1. Cách sử dụng Callback để tải Script
Giả sử chúng ta muốn tải 1 file JS từ bên ngoài vào :
<!-- 
function loadScript(src, callback) {
    const script = document.createElement("script");
    script.src = src;

    script.onload = () => callback(null, script);
    script.onerror = () => callback(new Error(`Script load error for ${src}`));

    document.head.append(script);
}
-->
Sử dụng:
<!-- 
loadScript("/my/script.js", (error, script) => {
    if (error) {
        console.log(error);
    } else {
        console.log("Script loaded:", script);
    }
});
 -->
Giải thích:
- src: Đường dẫn file JavaScript cần tải.
- callback: Hàm được gọi khi quá trình tải hoàn thành.
- script.onload: Chạy khi tải Script thành công.
- script.onerror: Chạy khi tải Script thất bại.

Callback nhận hai tham số:
| Tham số  | Ý nghĩa                           |
| -------- | --------------------------------- |
| `error`  | Lỗi nếu tải thất bại              |
| `script` | Phần tử Script nếu tải thành công |

Đây là cách viết theo mô hình Error-first callback.
5.2. Chuyển Callback sang Promise
Tài liệu gốc chuyển hàm loadScript() sang sử dụng Promise như sau:
<!-- 
function loadScript(src) {
    return new Promise(function(resolve, reject) {
        const script = document.createElement("script");
        script.src = src;

        script.onload = () => resolve(script);
        script.onerror = () => reject(new Error(`Script load error for ${src}`));

        document.head.append(script);
    });
}
-->
Sử dụng:
<!-- 
loadScript("/my/script.js")
    .then(script => {
        console.log("Script loaded:", script);
    })
    .catch(error => {
        console.log(error);
    });
 -->
Bước 1: Tạo Promise
Hàm loadScript() trả về một Promise để bên ngoài có thể đăng ký xử lý kết quả.
Bước 2: Tạo phần tử Script
<!-- 
const script = document.createElement("script");
script.src = src;
 -->
Tạo thẻ Script và thiết lập đường dẫn cần tải.
Bước 3: Xử lý khi thành công
<!-- script.onload = () => resolve(script); -->
Khi Script tải thành công, gọi resolve(script) để trả phần tử Script cho Promise.
Bước 4: Xử lý khi thất bại
<!-- script.onerror = () => reject(new Error(`Script load error for ${src}`)); -->
Khi tải thất bại, gọi reject() để Promise chuyển sang trạng thái rejected.
Bước 5: Đưa Script vào trang
<!-- document.head.append(script); -->
Trình duyệt bắt đầu tải file Script
5.3. Ưu điểm của Promise so với Callback
1. Code có thứ tự tự nhiên hơn
2. Có thể đăng ký nhiều handler cho cùng một Promise
<!-- 
const promise = loadScript("script.js");

promise.then(script => {
    console.log("Handler 1:", script);
});

promise.then(script => {
    console.log("Handler 2:", script);
});
 -->
Cả hai handler đều có thể nhận kết quả từ cùng một Promise.
Với Callback thông thường , bạn chỉ truyền 1 callback vào hàm loadScript().
5.4. Các case dễ sai
Case 1 – Quên return Promise
<!-- 
function loadScript(src) {
    new Promise((resolve, reject) => {
        // ...
    });
}
 -->
Hàm trên không trả Promise ra bên ngoài vì thiếu return.
Cách đúng:
<!-- 
function loadScript(src) {
    return new Promise((resolve, reject) => {
        // ...
    });
}
 -->
Case 2 – Quên gọi resolve hoặc reject
<!-- 
return new Promise((resolve, reject) => {
    const script = document.createElement("script");
    script.src = src;

    document.head.append(script);
});
 -->
Nếu không gọi resolve() hoặc reject() , Promise có thể ử trạng thái pending mãi mãi.
Case 3 – Nhầm resolve và reject
<!-- 
script.onload = () => reject(new Error("Failed"));
script.onerror = () => resolve(script);
 -->
Điểm quan trọng nhất : Promise không loại bỏ callback khỏi JS . Bản thân Promise vẫn đang sử dung callback trong then(),
catch() và finally(). Nó cung cấp cách tổ chức và quản lý kết quả bất đồng bộ thuận tiện hơn

<!-- 
function loadData() {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve("Data loaded");
        }, 1000);
    });
}

loadData().then(result => {
    console.log(result);
});
 -->
Câu hỏi: Vai trò của return new Promise(...) trong hàm loadData() là gì?

A. Để hàm loadData() trả Promise cho bên ngoài sử dụng .then().
B. Để bắt buộc setTimeout() chạy đồng bộ.
C. Để tự động xử lý lỗi mà không cần catch().
D. Để callback trong then() chạy ngay lập tức.

6. Tasks
Bài tập 1:
<!-- 
let promise = new Promise(function(resolve, reject) {
    resolve(1);

    setTimeout(() => resolve(2), 1000);
});

promise.then(alert);
 -->
1. Promise được tạo, trạng thái ban đầu là pending.
2. resolve(1) được gọi → Promise chuyển sang fulfilled, kết quả là 1.
3. setTimeout() đăng ký callback chạy sau 1 giây.
4. .then(alert) nhận kết quả 1 và hiển thị 1.
5. Sau 1 giây, resolve(2) được gọi nhưng không có tác dụng vì Promise đã fulfilled.
Kiến thức cần nhớ:
Promise chỉ settle một lần. Khi đã fulfilled hoặc rejected, mọi lần gọi resolve() hoặc reject() tiếp theo đều bị bỏ qua.
