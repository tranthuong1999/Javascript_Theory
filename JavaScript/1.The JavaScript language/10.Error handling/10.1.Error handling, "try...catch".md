1. The “try…catch” syntax
1.1. Cú pháp try...catch
try...catch dùng để bắt và xử lý trong quá trình thực thi
Thông thường khi 1 lỗi k xử lý chương trình sẽ dừng luông thực thi hiện tại
try...catch giúp chúng ta kiểm soát chương trình đó thay vì dừng đột ngột 
Cú pháp
<!-- 
try {
  // Code có thể xảy ra lỗi
} catch (err) {
  // Xử lý lỗi
}
 -->
Trong đó:
- try chứa đoạn code cần thực thi 
- catch : chỉ chạy khi có lỗi xảy ra trong try
- err : chứa thông tin lỗi
Ví dụ 1: Có lỗi xảy ra
<!-- 
try {
  console.log("Start");

  let result = unknownVariable;

  console.log("End");
} catch (err) {
  console.log("Có lỗi xảy ra!");
}
 -->
Kết quả:
Start
Có lỗi xảy ra!
Giải thích:
1. "Start" được in ra.
2. JavaScript truy cập unknownVariable , nhưng biến này k được khai báo
3. Phát sinh ReferenceError.
4. Các câu lệnh còn lại trong try bị bỏ qua
5. Luồng thực thi chuyển sang catch

Ví dụ 2: Không có lỗi
<!-- 
try {
  console.log("Start");

  let result = 10 + 20;

  console.log("End");
} catch (err) {
  console.log("Có lỗi xảy ra!");
}
 -->
Kết quả:
Start
End
Vì không có lỗi catch bị bỏ qua
### Ghi nhớ

| Tình huống        | Luồng thực thi                              |
| ----------------- | ------------------------------------------- |
| Không có lỗi      | `try` → bỏ qua `catch`                      |
| Có lỗi            | `try` → `catch`                             |
| Có lỗi giữa chừng | Các câu lệnh còn lại trong `try` không chạy |

Câu hỏi kiểm tra 1.1
<!-- 
try {
  console.log("A");

  let x = undefinedVariable;

  console.log("B");
} catch (err) {
  console.log("C");
}

console.log("D");
 -->
 Giải thích luồng thực thi:
1. console.log("A") → in A.
2. undefinedVariable chưa được khai báo → phát sinh ReferenceError.
3. Lệnh console.log("B") bị bỏ qua.
4. Chuyển sang catch → in C.
5. Thoát khỏi try...catch, chương trình tiếp tục → in D.

1.2. Luồng thực thi khi không có lỗi
Khi không có lỗi xảy ra bên trong try , JS sẽ :
1. Thực thi toàn bộ câu lệnh try
2. Bỏ qua catch.
3. Tiếp tục thực thi câu lệnh phía sau try...catch.

Ví dụ :
<!-- 
try {
  console.log("Start");

  let result = 10 + 20;

  console.log(result);
  console.log("End");
} catch (err) {
  console.log("Có lỗi xảy ra!");
}

console.log("Continue");
 -->
Start
30
End
Continue
Giải thích:
- Start được in ra.
- 10 + 20 không có lỗi, nên result = 30.
- Tiếp tục thực thi các câu lệnh còn lại trong try.
- Vì không có lỗi nên catch bị bỏ qua.
- Chương trình tiếp tục chạy câu lệnh console.log("Continue").
  
Ghi nhớ:
| Tình huống   | Luồng thực thi                                 |
| ------------ | ---------------------------------------------- |
| Không có lỗi | `try` → bỏ qua `catch` → tiếp tục chương trình |
| Có lỗi       | `try` → `catch` → tiếp tục chương trình        |
Câu hỏi kiểm tra 1.2
<!-- 
try {
  console.log("A");
  console.log("B");
} catch (err) {
  console.log("C");
}

console.log("D");
 -->
Giải thích:
- A, B: được thực thi bình thường trong try.
- Không có lỗi nên bỏ qua catch ( C không được thực thi)
- Tiếp tục thực thi console.log("D").
  
Ghi nhớ: catch chỉ chạy khi có lỗi xảy ra trong try.

1.3. Luồng thực thi khi có lỗi
Khi một câu lệnh bên trong try phát sinh lỗi , JS sẽ dừng thực thi phần còn lại của khối try và chuyển quyền kiểm soát sang catch
Ví dụ:
<!-- 
try {
  console.log("A");

  let result = 10 / 0;
  console.log("B");

  let user = undefined;
  console.log(user.name);

  console.log("C");
} catch (err) {
  console.log("D");
}

console.log("E");
 -->
A
B
D
E
Giải thích:
1. A được in ra.
2. 10 / 0 trong JavaScript trả về Infinity, không phát sinh lỗi.
3. B được in ra.
4. user.name gây TypeError vì user là undefined.
5. console.log("C") bị bỏ qua.
6. Chuyển sang catch, in D.
7. Tiếp tục chương trình, in E.
Điểm cần phân biệt:
- Không phải mọi phép tính bất thường đều tạo ra lỗi . Ví dụ 10 / 0 trả về Infinity.
- Khi lỗi xảy ra , các câu lệnh còn lại trong try k được thực thi 
- Sau khi catch xử lý xong, chương trình có thể tiếp tục chạy 
Câu hỏi kiểm tra 1.3
<!-- 
try {
  console.log("A");

  let user = null;
  console.log(user.name);

  console.log("B");
} catch (err) {
  console.log("C");
}

console.log("D");
 -->
Ghi nhớ: Khi lỗi xảy ra giữa try, JavaScript không quay lại thực thi các câu lệnh đã bị bỏ qua.

1.4. try...catch chỉ xử lý runtime errors
Trong JS , try...catch chỉ xử lý được runtime error ,( lỗi xảy ra trong quá trình chương trình đang thực thi) ,
không xử lý được syntax errors ( lỗi cú pháp khiến JS k thể phân tích mã)
1.4.1. Syntax errors – Lỗi cú pháp
Là lỗi khiến JavaScript không thể phân tích cú pháp của chương trình
<!-- 
try {
  let user = ;
} catch (err) {
  console.log("Caught:", err);
}
 -->
Code trên k thể chạy vì let user = ; sai cú pháp.
JS phát hiện lỗi ngay trong giai đoạn phân tích cú pháp , trước khi thực hiện try...catch
Vì vậy , catch k thể bắt được lỗi này
1.4.2. Runtime errors – Lỗi khi thực thi
Là lỗi xảy ra khi JS phân tích cú pháp thành công và bắt đầu chạy chương trình
<!-- 
try {
  let user = null;

  console.log(user.name);
} catch (err) {
  console.log("Caught:", err.name);
}
-->
Caught: TypeError
Đoạn code hợp lệ về cú pháp , nhưng khi đến user.name , JS phát sinh TypeError 
Lúc này catch có thể bắt và xử lý lỗi
1.4.3. So sánh
| Tiêu chí                  | Syntax error                     | Runtime error                     |
| ------------------------- | -------------------------------- | --------------------------------- |
| Thời điểm                 | Khi phân tích cú pháp            | Khi thực thi                      |
| Code có chạy được không?  | Không thể thực thi đoạn code lỗi | Có thể chạy đến vị trí xảy ra lỗi |
| `try...catch` xử lý được? | Không                            | Có                                |
Ghi nhớ:
- Syntax error: JS không thể phân tích code
- Runtime error: JavaScript chạy đến một câu lệnh và phát sinh lỗi
- try...catch xử lý runtime errors
  
1.5. try...catch hoạt động đồng bộ
try...catch chỉ bắt được lỗi xảy ra trong quá trình thực thi đồng bộ bên trong khối try.
Nó k tự động bắt được lỗi xảy ra trong 1 callback được thực thi sau đó , chẳng hạn như setTimeout
1.5.1.Lỗi trong setTimeout không được bắt bởi try...catch bên ngoài
<!-- 
try {
  setTimeout(() => {
    throw new Error("Something went wrong");
  }, 1000);
} catch (err) {
  console.log("Caught:", err.message);
}
 -->
Điều gì xảy ra?
1. JavaScript chạy try.
2. setTimeout đăng ký callback thực thi sau 1s
3. Khối try kết thúc ,không có lỗi xảy ra tại thời điểm này.
4. catch bị bỏ qua
5. Sau 1s , callback được thực thi 
6. throw phát sinh lỗi nhưng try...catch bên ngoiaf đã kết thưc nên bên ngoiaf k bắt được 
   
1.5.2. Đặt try...catch bên trong callback
Muốn bắt lỗi này, cần đặt try...catch ngay bên trong callback:
<!-- 
setTimeout(() => {
  try {
    throw new Error("Something went wrong");
  } catch (err) {
    console.log("Caught:", err.message);
  }
}, 1000);
 -->
1.5.3. Ứng dụng thực tế
<!-- 
setTimeout(() => {
  try {
    const message = JSON.parse(incomingData);
    console.log(message);
  } catch (err) {
    console.log("Invalid message:", err.message);
  }
}, 1000);
 -->
Khi callback nhận dữ liệu và parse JSON , nếu dữ liệu không hợp lệ thì catch bên trong callback sẽ xử lý
| Trường hợp                                          | Bắt được lỗi? |
| --------------------------------------------------- | ------------- |
| Lỗi đồng bộ bên trong `try`                         | Có            |
| Lỗi trong callback `setTimeout` với `try` bên ngoài | Không         |
| Lỗi trong callback có `try...catch` bên trong       | Có            |

Ghi nhớ: try...catch không bắt lỗi xuyên qua ranh giới của một callback bất đồng bộ. Muốn bắt lỗi, hãy đặt try...catch bên trong callback đó.

2. Error object
2.1. Error object là gì?
Khi JS phát sinh lỗi trong quá trình thực thi , nó thường tạo ra một Error object chứa thông tin mô tả lỗi đố
Khi sử dụng try...catch, đối tượng lỗi được truyền vào biến err của catch.
<!-- 
try {
  let user = null;

  console.log(user.name);
} catch (err) {
  console.log(err);
}
 -->
Trong đó:
- TypeError: loại lỗi.
- Cannot read properties of null (reading 'name'): thông báo mô tả lỗi.
- err: đối tượng chứa thông tin lỗi.
Error object dùng để làm gì?
Trong thực tế , Error object giúp chúng ta:
1. Biết lỗi thuộc loại nào
2. Biết nguyên nhân hoặc mô tả lỗi 
3. Theo dõi vị trí lỗi thông qua stack trace.
4. Ghi log để debug và xử lý lỗi phù hợp 
Ví dụ trong ứng dụng chat, khi parse dữ liệu WebSocket thất bại ,chúng ta có thể lấy thông tin lỗi để ghi log à tìm nguyên nhân
Ghi nhớ: error không phải chuỗi thông báo lỗi đơn thuần , mà là 1 object chưa nhiều thông tin lỗi 
Câu hỏi kiểm tra 2.1
Trong đoạn code sau, err là gì?
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch (err) {
  console.log(typeof err);
}
 -->
Ghi nhớ:
- err: Error object.
- err.name: Tên loại lỗi.
- err.message: Nội dung mô tả lỗi.
- err.stack: Stack trace của lỗi.

2.2. Thuộc tính name
Error object có thuộc tính name dùng để xác định loại lỗi ( error type)
Ví dụ:
<!-- 
try {
  let user = null;
  console.log(user.name);
} catch (err) {
  console.log(err.name);
}
 -->
Vì chúng ta đang cố truy cập thuộc tính name của null, JavaScript phát sinh TypeError.
| Error name       | Ý nghĩa                                |
| ---------------- | -------------------------------------- |
| `Error`          | Lỗi chung                              |
| `SyntaxError`    | Lỗi cú pháp                            |
| `ReferenceError` | Truy cập biến chưa được khai báo       |
| `TypeError`      | Thao tác không hợp lệ với kiểu dữ liệu |
Ứng dụng thực tế:
Có thể sử dụng err.name để phân loại lỗi và xử lý phù hợp:
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch (err) {
  if (err.name === "SyntaxError") {
    console.log("Dữ liệu JSON không hợp lệ");
  }
} -->
Ghi nhớ:
- err.name trả về tên loại lỗi
- Có thể dùng nó để phân biệt các loiaj lỗi trong catch
<!-- 
try {
  let age = "25";
  age.toFixed(2);
} catch (err) {
  console.log(err.name);
}
-->
age là kiểu string.
toFixed() là phương thức dành cho kiểu Number.
Gọi phương thức này trên chuỗi sẽ phát sinh TypeError.

2.3. Thuộc tính message
Error object có thuộc tính message dùng để lấy nội dung mô tả (error message).
<!-- 
try {
  let user = null;
  console.log(user.name);
} catch (err) {
  console.log(err.message);
}
 -->
Phân biệt name và message
| Thuộc tính    | Ý nghĩa   | Ví dụ                               |
| ------------- | --------- | ----------------------------------- |
| `err.name`    | Loại lỗi  | `TypeError`                         |
| `err.message` | Mô tả lỗi | `Cannot read properties of null...` |
Có thể kết hợp cả hai:
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch (err) {
  console.log("Error type:", err.name);
  console.log("Error message:", err.message);
}
 -->
Ứng dụng thực tế:
Trong ứng dụng chat, khi dữ liệu nhận từ WebSocket k đúng định dạng json , có thể ghi log
<!-- 
try {
  const message = JSON.parse(incomingData);
} catch (err) {
  console.error(`${err.name}: ${err.message}`);
}
-->
Ghi nhớ:
- name cho biết thuộc loại lỗi nào
- message giải thích lỗi xaỷ ra như thế nào
- Hai thuộc tính này giúp debug và phân loại lỗi
2.4. Thuộc tính stack
Error object có thuộc tính stack chứa stack trace - thông tin về chuỗi lời gọi hàm dẫn đến lỗi , thường bao gồm vị trí xay ra lỗi
Nó rất hữu ích khi debug, đặc biệt khi lỗi xuất hiện sâu bên trong nhiều function.
<!-- 
function getUser() {
  let user = null;
  return user.name;
}

function loadData() {
  getUser();
}

try {
  loadData();
} catch (err) {
  console.log(err.stack);
}
 -->
err.stack có thể hiển thị dạng:
<!-- 
TypeError: Cannot read properties of null (reading 'name')
    at getUser (...)
    at loadData (...)
    at ...
 -->
Hiểu stack trace
Trong ví dụ trên:
1. Chương trình gọi loadData().
2. loadData() gọi getUser().
3. getUser() truy cập user.name khi user là null.
4. Lỗi xảy ra và stack trace ghi lại chuỗi lời gọi dẫn đến lỗi.
Phân biệt ba thuộc tính
### Phân biệt ba thuộc tính

| Thuộc tính    | Mục đích                                     |
| ------------- | -------------------------------------------- |
| `err.name`    | Xác định loại lỗi                            |
| `err.message` | Mô tả lỗi                                    |
| `err.stack`   | Theo dõi vị trí và chuỗi lời gọi dẫn đến lỗi |
Ứng dụng thực tế:
Trong ứng dụng React/Next.js , khi API hoặc xử lý dữ liệu gặp lỗi , stack giúp develop tìm lỗi trong quá trinhf phát triển
<!-- 
try {
  await fetchUser();
} catch (err) {
  console.error(err.stack);
}
 -->
 Lưu ý: k nên tuỳ tiện trả toàn bộ stack cho người dùng cuối trong production vì có thể tiết lộ thông tin nội bộ
 Ghi nhớ:
- name: Lỗi gì?
- message: Lỗi nói gì?
- stack: Lỗi xảy ra qua những lời gọi nào?
  TypeError: Cannot read properties of null
    at getUser()
    at loadData()
Ta biết:
- Lỗi xảy ra trong getUser().
- getUser() được gọi từ loadData().
| Thuộc tính    | Ý nghĩa                   |
| ------------- | ------------------------- |
| `err.name`    | Loại lỗi                  |
| `err.message` | Nội dung lỗi              |
| `err.stack`   | Chuỗi lời gọi dẫn đến lỗi |

3. Optional “catch” binding
3.1. catch không cần tham số err
Khi sử dụng catch , chúng ta truyền 1 biến để nhận Error Object
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch (err) {
  console.log(err.message);
}
-->
Tuy nhiên , nếu k cần sử dụng thông tin lỗi , JS cho phép bỏ qua tham số err
Ví dụ:
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch {
  console.log("JSON không hợp lệ!");
}
 -->
### So sánh hai cách viết

| Có tham số                   | Không có tham số                                |
| ---------------------------- | ----------------------------------------------- |
| `catch (err) {}`             | `catch {}`                                      |
| Có thể truy cập Error object | Không truy cập được Error object qua biến `err` |
| Dùng khi cần kiểm tra lỗi    | Dùng khi chỉ cần xử lý lỗi chung                |
Ứng dụng thực tế
Ví dụ khi đọc dữ liệu từ localStorage:
<!-- 
let user;

try {
  user = JSON.parse(localStorage.getItem("user"));
} catch {
  user = null;
}
 -->
 Nếu dữ liệu JSON k hợp lệ ,chúng ta chỉ cần đưa user về null , k cần lấy thông tin lỗi

6. Rethrowing
6.1. Vấn đề bắt nhầm lỗi
Khi sử dụng try...catch , chúng ta cần lưu ý 1 vấn đề : catch sẽ nhận tất các lỗi phát sinh trong khối try , không phân biệt lỗi
đó có phải loại lỗi mà chúng ta muốn xử lý hay không
<!-- 
try {
  const user = JSON.parse('{"age": 25}');

  if (!user.name) {
    throw new Error("Name is missing");
  }

  console.log(user.name);
} catch (err) {
  console.log("User data is invalid");
}
 -->
Kết quả :User data is invalid
Trong ví dụ này, catch xử lý lỗi thiếu name.
Nhưng giả sử trong qúa trình xử lý còn xuất hiện một lỗi k liên quan đến dữ liệu người dùng , chẳng hạn ReferenceError do viết sai tên biến:
<!-- 
try {
  const user = JSON.parse('{"name": "Martin"}');

  console.log(user.name);

  unknownFunction();
} catch (err) {
  console.log("User data is invalid");
} -->
Kết quả:
<!-- 
Martin
User data is invalid
 -->
Vấn đề:
- unknownFunction() gây ReferenceError.
- Nhưng catch vẫn bắt lỗi đó.
- Chương trình lại hiển thị thông báo "User data is invalid".
- Thông báo này không đúng với nguyên nhân thực tế.
Tại sao đây là vấn đề?
Trong ứng dụng thực tế, mỗi loại lỗi có thể cần một cách xử lý khác nhau:
- SyntaxError: Dữ liệu JSON không hợp lệ.
- TypeError: Thao tác không hợp lệ với kiểu dữ liệu.
- ReferenceError: Lỗi trong code.
- Các lỗi khác: Có thể cần chuyển đến tầng xử lý cao hơn.
  Nếu xử lý tất cả bằng cùng 1 thông báo , chúng ta dễ che giấu lỗi lập trình và gây khó khăn khi debug
Ghi nhớ:
catch bắt mọi lỗi phát sinh trong try, nhưng không có nghĩa là chúng ta phải xử lý tất cả những lỗi đó tại đây.
Đây chính là kĩ thuật rethrowing - ném lại lỗi mà chúng ta k biét xử lý

6.2. Nguyên tắc rethrowing
Rethrowing là kỹ thuật bắt lỗi, kiểm tra loại lỗi và ném lại lỗi đó không phải lỗi mà chúng ta có thể xử lý
Nguyên tắc:
1. Dùng try...catch để bắt lỗi.
2. Kiểm tra loại lỗi trong catch.
3. Nếu là lỗi đã biết và có thể xử lý → xử lý.
4. Nếu là lỗi không biết hoặc không thể xử lý → dùng throw để ném lại lỗi.

<!-- 
try {
  const user = JSON.parse('{"name": "Martin"}');

  unknownFunction();
} catch (err) {
  if (err instanceof SyntaxError) {
    console.log("Invalid JSON");
  } else {
    throw err;
  }
}
 -->
Luồng thực thi:
- JSON.parse() thành công.
- unknownFunction() phát sinh ReferenceError.
- catch nhận lỗi.
- Kiểm tra err instanceof SyntaxError → false.
- Chạy throw err để ném lại lỗi.
- - ReferenceError tiếp tục lan truyền lên nơi gọi hàm hoặc môi trường thực thi.
Tại sao phải rethrow?
Nếu k rethrow , lỗi k mong muốn có thể bị che dấu
<!-- 
catch (err) {
  console.log("Invalid JSON");
}
 -->
Cách viết này khiến mọi lỗi đều bị xem là lỗi JSON
Trong khi đó:
<!-- 
catch (err) {
  if (err instanceof SyntaxError) {
    console.log("Invalid JSON");
  } else {
    throw err;
  }
}
 -->
Chỉ xử lý lỗi JSON, còn lỗi khác được chuyển tiếp để nơi phù hợp xử lý.
Ghi nhớ: Chỉ xử lý những lỗi mà tầng hiện tại hiểu và có trách nhiệm xử lý. Không nên nuốt những lỗi không thuộc phạm vi của mình.
6.3. Kiểm tra loại lỗi bằng instanceof
instanceof giúp kiểm tra 1 object có thuộc một constructor hoặc class cụ thể hay không
Trong xử lý lỗi , ta dùng nó để xác định loại lỗi được ném ra
6.3.1. Cú pháp
<!-- error instanceof ErrorConstructor -->
<!-- 
try {
  JSON.parse("{ invalid json }");
} catch (err) {
  console.log(err instanceof SyntaxError); // true
  console.log(err instanceof Error);       // true
  console.log(err instanceof TypeError);   // false
}
 -->
 Giải thích:
- SyntaxError: true vì JSON k hợp lệ 
- Error: true vì SyntaxError kế thừa Error
- TypeError : false vì đây k phải là lỗi dữ liệu

6.3.2. Kiểm tra nhiều loại lỗi
<!-- 
try {
  // Xử lý dữ liệu
} catch (err) {
  if (err instanceof SyntaxError) {
    console.log("Dữ liệu JSON không hợp lệ");
  } else if (err instanceof TypeError) {
    console.log("Lỗi kiểu dữ liệu");
  } else {
    throw err;
  }
}
 -->
Điểm cần nhớ:
- instanceof kiểm tra loại object dựa trên chuỗi prototype.
- Lỗi con cũng là instance của lớp cha.
- - Có thể kết hợp instanceof với rethrowing để chỉ xử lý lỗi mình biết.
6.4. Kết hợp nested try...catch
6.4.1. Nested try...catch là gì?
Nested try...catch là cách đặt 1 khối try...catch bên trong try...catch khác
Mục đích : xử lý ở nhiều cấp độ khác nhau
<!-- 
try {
  try {
    JSON.parse("{ invalid json }");
  } catch (err) {
    if (err instanceof SyntaxError) {
      console.log("JSON không hợp lệ");
    } else {
      throw err;
    }
  }
} catch (err) {
  console.log("Lỗi không mong muốn:", err);
}
 -->
6.4.2. Luồng xử lý
1. Khối try bên trong thực hiện JSON.parse().
2. JSON không hợp lệ nên phát sinh SyntaxError.
3. catch bên trong bắt được lỗi.
4. Vì là SyntaxError, lỗi được xử lý ngay tại đây.
5. Khối catch bên ngoài không được thực thi.
6.4.3. Khi nào lỗi được chuyển lên cấp bên ngoài?
Nếu lỗi không thuộc loại mà catch bên trong xử lý, nó sẽ được throw lại.
<!-- 
try {
  try {
    unknownFunction();
  } catch (err) {
    if (err instanceof SyntaxError) {
      console.log("JSON không hợp lệ");
    } else {
      throw err;
    }
  }
} catch (err) {
  console.log("Lỗi được xử lý ở cấp ngoài:", err.name);
}
 -->
Lỗi được xử lý ở cấp ngoài: ReferenceError
Giải thích:
- unknownFunction() gây ra ReferenceError.
- catch bên trong nhận được lỗi.
- Lỗi không phải SyntaxError, nên throw err chuyển lỗi ra ngoài.
- catch bên ngoài bắt và xử lý ReferenceError
Ghi nhớ:
- catch bên trong xử lý lỗi thuộc phạm vi của nó.
- throw err chuyển lỗi lên cấp bên ngoài.
- catch bên ngoài chỉ nhận lỗi nếu lỗi thoát khỏi khối bên trong.
Tổng kết phần 6 – Rethrowing
- catch có thể bắt nhiều loại lỗi.
- Dùng instanceof để xác định loại lỗi.
- Xử lý lỗi mà mình biết.
- Dùng throw err để chuyển lỗi không thuộc phạm vi xử lý lên cấp cao hơn.
- Có thể kết hợp nhiều try...catch để phân chia trách nhiệm xử lý lỗi.

- return trong try: finally chạy trước, sau đó trả kết quả của try.

8. Global catch
8.1. Global error handler là gì?
Nếu lỗi k được xử lý bằng try...catch nó có thể trở thành uncaught error
Thông thường , lỗi sẽ được môi trương thực thi nhận và hiển thị trong console
Tuy nhiên , trong ưng dụng chúng ta có thể cần 1 cơ chế để ghi nhận các lỗi chưa được xử lý trên toàn ứng dung
Cơ chế đó được gọi là Global error handler.
<!-- 
function doSomething() {
  unknownFunction();
}

doSomething();
 -->
Ở đây:
- unknownFunction() gây ra ReferenceError.
- Không có try...catch xử lý lỗi.
- Lỗi truyền lên các cấp gọi hàm.
- Nếu không có handler phù hợp, môi trường thực thi sẽ báo lỗi.
8.1.1. Global catch khác gì try...catch?
| Tiêu chí  | `try...catch`            | Global error handler     |
| --------- | ------------------------ | ------------------------ |
| Phạm vi   | Một khối code            | Toàn môi trường ứng dụng |
| Mục đích  | Xử lý lỗi cụ thể         | Ghi nhận lỗi chưa xử lý  |
| Kiểm soát | Chủ động tại vị trí code | Được môi trường gọi      |
Lưu ý theo javascript.info: Global error handling phụ thuộc vào môi trươngf chạy JS > Cách xử lý trên browser vad nodé k giống nhau

* Kiểm tra kiến thức 8.1
Một hàm phát sinh ReferenceError nhưng không có try...catch nào xử lý. Global error handler thường được sử dụng để làm gì?

A. Ngăn tất cả lỗi xảy ra.
B. Tự động sửa lỗi trong code.
C. Ghi nhận và báo cáo các lỗi chưa được xử lý.
D. Chuyển mọi lỗi thành SyntaxError.
Giải thích:
Global error handler thường được sử dụng để :
Ghi nhận lỗi chưa được xử ;lý
Thu thập thông tin lỗi để debug
Gửi lỗi đến hệ thống monitoring/logging.
Giúp developer phát hiện lỗi xảy ra trên production
8.2. window.onerror
Trên môi trương browser chúng ta có thể sử dụng window.onerror để đăng ký một global error handler.
8.2.1. Cú pháp
<!-- 
window.onerror = function(message, url, line, col, error) {
  // Xử lý thông tin lỗi
};
 -->
| Tham số   | Ý nghĩa                 |
| --------- | ----------------------- |
| `message` | Nội dung lỗi            |
| `url`     | URL của file xảy ra lỗi |
| `line`    | Số dòng xảy ra lỗi      |
| `col`     | Vị trí cột xảy ra lỗi   |
| `error`   | Error object            |
8.2.2. Ví dụ
<!-- 
window.onerror = function(message, url, line, col, error) {
  console.log("Error message:", message);
  console.log("File:", url);
  console.log("Line:", line);
  console.log("Column:", col);
  console.log("Error object:", error);
};

unknownFunction();
 -->
Khi unknownFunction() gây ra ReferenceError, handler có thể nhận thông tin lỗi và ghi nhận chúng.
8.2.3. Ứng dụng thực tế
Trong ứng dụng React, khi gặp lỗi JS chưa xử lý được , ta có thể ghi nhận thông tin để phục vụ debug production
<!-- 
window.onerror = function(message, url, line, col, error) {
  sendErrorToLoggingService({
    message,
    url,
    line,
    col,
    stack: error?.stack
  });
};
-->
Ở đây, sendErrorToLoggingService() đại diện cho hàm gửi thông tin đến hệ thống logging
Lưu ý quan trọng:
- window.onerror thuộc môi trường Browser, không phải cú pháp JavaScript chạy ở mọi môi trường.
- Nó không thay thế try...catch.
- Nó chủ yếu giúp ghi nhận lỗi toàn cục chưa được xử lý.
- Với Promise rejection không được xử lý, Browser còn có sự kiện unhandledrejection riêng.
Kiểm tra kiến thức 8.2
Trong đoạn code sau, tham số error của window.onerror có vai trò gì?
<!-- 
window.onerror = function(message, url, line, col, error) {
  console.log(error?.stack);
};
-->
Ghi nhớ: error.stack rất hữu ích khi debug vì cho biết chuỗi lời gọi dẫn đến lỗi.

Một ứng dụng React chạy production. Người dùng gặp lỗi nhưng developer không thể tái hiện trên máy local.

Giải pháp nào phù hợp nhất để hỗ trợ điều tra?

A. Chỉ sử dụng console.log() trên máy developer.
B. Gửi thông tin lỗi như message, stack, timestamp đến hệ thống error logging.
C. Xóa toàn bộ try...catch trong ứng dụng.

Vì trong production, developer không trực tiếp quan sát được môi trường của người dùng. Error logging giúp thu thập thông tin để điều tra.

Ví dụ các dữ liệu quan trọng:
- message: Nội dung lỗi.
- stack: Stack trace để tìm vị trí phát sinh lỗi.
- timestamp: Thời điểm xảy ra lỗi.
- url: Trang hoặc file xảy ra lỗi.
Liên hệ React/Next.js: Trong dự án thực tế, có thể tích hợp Sentry để theo dõi JavaScript errors, API errors và lỗi phía client.

          │      Cấp bên ngoài

                │
                ▼
           Tiếp tục luồng
9.1.3. Những điều cần đặc biệt nhớ
1. try...catch không bắt được lỗi cú pháp xảy ra khi parse code.
2. try...catch thông thường không bắt được lỗi từ callback bất đồng bộ chạy sau đó.
3. Không nên bắt mọi lỗi rồi bỏ qua.
<!-- 
catch (err) {
  if (err instanceof SyntaxError) {
    // Xử lý lỗi đã biết
  } else {
    throw err;
  }
} -->
4. finally vẫn chạy khi try hoặc catch có return.
5. Tránh return trong finally vì có thể ghi đè kết quả hoặc che mất lỗi ban đầu.
6. Global error handler dùng để ghi nhận lỗi chưa được xử lý, không thay thế xử lý lỗi tại từng vị trí.

10. Task
Đề bài: Hai đoạn code dưới đây có sự khác biệt gì? Tại sao cần finally?
Đoạn 1:
<!-- 
try {
  work();
} catch (err) {
  handleError(err);
} finally {
  cleanup();
}
 -->
 Luồng thực thi:
- Nếu work() thành công → chạy finally → cleanup().
- Nếu work() phát sinh lỗi → chạy catch → sau đó chạy finally → cleanup().
Dù có lỗi hay không, cleanup() vẫn được thực thi trong luồng xử lý thông thường.
Đoạn 2:
<!-- 
try {
  work();
} catch (err) {
  handleError(err);
}

cleanup();
 -->
 work() phát sinh lỗi và handleError() tiếp tục ném lỗi
 work()
  |
  ▼
Phát sinh lỗi
  |
  ▼
catch bắt lỗi
  |
  ▼
handleError(err)
  |
  ▼
Phát sinh lỗi mới
  |
  ▼
Thoát khỏi hàm
  |
  ▼
cleanup() KHÔNG chạy
Lý do: Khi handleError() ném lỗi mới, chương trình thoát khỏi luồng thực thi hiện tại. Vì vậy, câu lệnh cleanup() phía sau không được chạy.
Ngoài ra, nếu handleError() thực hiện return từ hàm chứa đoạn code này thì cleanup() cũng bị bỏ qua.
