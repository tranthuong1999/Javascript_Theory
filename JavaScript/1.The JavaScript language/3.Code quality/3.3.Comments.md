Mục 1 — Bad comments
1.1. Tránh comment giải thích điều code đã thể hiện
Bài gốc nhấn mạnh: code tốt nên dễ hiểu mà không cần quá nhiều comment
1.2. Tách logic thành function
Khi có nhiều đoạn code thực hiện những nhiệm vụ khác nhau, ta có thể tách chúng thành các hàm có tên thể hiện rõ nhiệm vụ
1. Vấn đề: Code dài, comment phải giải thích từng phần
2. Cách cải thiện: Tách thành function
3. Tại sao cách này tốt hơn?

Recipe: Create Functions
├── Khi code dài và comment phải giải thích từng đoạn
│   └── Cân nhắc tách đoạn code thành function
├── Đặt tên function thể hiện nhiệm vụ
├── Code chính gọi các function theo trình tự
└── Mục tiêu
    ├── Giảm comment giải thích thừa
    ├── Dễ đọc luồng xử lý
    └── Dễ bảo trì
Mục 2 — Good comments (Comment tốt)
2.1. Mô tả kiến trúc (Describe the architecture)
Khi một dự án có nhiều module, component hoặc service tương tác với nhau, comment có thể giúp người đọc hiểu bức tranh tổng thể mà không cần đọc từng file.
2.2. Document function bằng JSDoc
Good Comments
├── Describe the architecture
│   └── Mô tả kiến trúc và luồng tương tác
├── Document function usage
│   └── JSDoc: mục đích, tham số, giá trị trả về
└── Nguyên tắc
    └── Comment bổ sung thông tin hữu ích
        mà code chưa thể hiện rõ
    
Khi đọc code, bạn có thể hiểu code làm gì nhưng chưa biết tại sao tác giả lại chọn cách làm đó.

Good comments — Subtle features
├── Ghi chú hành vi khó hiểu hoặc phản trực giác
├── Giải thích lý do của quyết định đặc biệt
├── Cảnh báo trường hợp dễ bị sửa nhầm
└── Không lặp lại điều code đã thể hiện rõ

setTimeout(sendRequest, 300);
B. // Giảm nguy cơ gửi request trùng khi người dùng bấm liên tục.

RECAP

Ghi nhớ toàn bài:
- Tránh comment chỉ lặp lại điều code đã thể hiện.
- Tách logic thành function có tên rõ nghĩa để code tự mô tả.
- Dùng JSDoc để ghi rõ mục đích, tham số và giá trị trả về của hàm.
- Comment kiến trúc, lý do chọn giải pháp và các chi tiết khó hiểu hoặc phản trực giác.
