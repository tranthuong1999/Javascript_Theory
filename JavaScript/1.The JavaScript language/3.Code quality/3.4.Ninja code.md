Mục 1 — Brevity is the soul of wit
1. Ý chính
Đừng cố viết code ngắn nhất có thể chỉ để thể hiện mình giỏi. Code ngắn nhưng khó hiểu thường tốn nhiều thời gian bảo trì hơn.
*******************************

Mục 2 — One-letter variables (Biến chỉ có một chữ cái)
1. Ví dụ
Code khó hiểu:
function calculate(a, b) {
  let c = a * b;
  return c;
}

One-letter variables
├── Tránh tên một chữ cái trong logic nghiệp vụ
├── Ưu tiên tên mô tả ý nghĩa: price, quantity, total
├── Biến i, j vẫn phù hợp với vòng lặp ngắn, quen thuộc
└── Mục tiêu: đọc tên biến là hiểu dữ liệu đại diện cho gì

*******************************

Mục 3 — Use abbreviations (Sử dụng từ viết tắt)
Mục này châm biếm việc cố tình viết tắt tên biến để code ngắn hơn nhưng khó hiểu. 
Cách viết khó hiểu:
const lst = getUsers();
const ua = getUserAgent();
const brsr = getBrowser();
Cách viết dễ hiểu hơn:
const userList = getUsers();
const userAgent = getUserAgent();
const browser = getBrowser();

Mục 4 — Soar high. Be abstract (Bay cao, tư duy trừu tượng)
viết code quá trừu tượng, dùng những cách diễn đạt phức tạp không cần thiết thay vì viết rõ ràng.
function getValue(condition, a, b) {
  return condition ? a : b;
}

const result = getValue(true, 10, 20);

Reuse names

11. Side-effects everywhere! — Tác dụng phụ bất ngờ
Một hàm có tên checkPermission() thường được kỳ vọng là kiểm tra quyền. Nếu nó âm thầm sửa dữ liệu hoặc thay đổi trạng thái, người gọi sẽ khó đoán hành vi.
function checkPermission(user) {
  user.isAdmin = true; // Tác dụng phụ bất ngờ!
  return true;
}
12. Powerful functions! — Hàm làm quá nhiều việc
    Một hàm validateEmail() nên tập trung kiểm tra email. Nếu nó đồng thời hiện thông báo, mở hộp thoại và gửi yêu cầu API, việc tái sử dụng sẽ khó khăn.
