Mục 1.1 — Curly Braces {}
1. Curly braces là gì?
{} là cặp dấu ngoặc nhọn dùng để xác định 1 khối lệnh chẳng hạn trong if , for hoặc function
2. So sánh cách viết
if (condition) {
  // Các câu lệnh cần thực hiện
}
**********************************************************
Mục 1.2 — Line Length (Độ dài dòng code)
1. Ví dụ
Cách khó đọc:
if (id === 123 && moonPhase === "Waning Gibbous" && zodiacSign === "Libra") {
  startProcess();
}
Cách dễ đọc hơn:
if (
  id === 123 &&
  moonPhase === "Waning Gibbous" &&
  zodiacSign === "Libra"
) {
  startProcess();
}
2. Dòng code dài tối đa bao nhiêu ký tự?
Tối đa thường từ 80 đến 120 ký tự 
3. Ghi nhớ
Line Length
├── Tránh dòng code quá dài
├── Chia điều kiện dài thành nhiều dòng
└── Thống nhất giới hạn dòng trong dự án
    └── Thường là 80 hoặc 120 ký tự
**********************************************************
Mục 1.3 — Indents (Thụt lề)
1. Thụt lề ngang — Horizontal indents
Dùng khoảng trắng hoặc phím Tab để thể hiện code nào nằm bên trong khối lệnh.
Cách viết đúng:
function calculate(a, b) {
  let total = a + b;

  if (total > 10) {
    return total;
  }

  return 10;
}
2. Dùng 2 hay 4 dấu cách?
3. Thụt lề dọc — Vertical indents
Indents
├── Horizontal indents
│   ├── Thụt lề bằng 2 hoặc 4 dấu cách
│   └── Thể hiện cấu trúc lồng nhau
└── Vertical indents
    └── Dùng dòng trống để chia nhóm logic

Mục 1.5 — Nesting Levels (Mức độ lồng nhau)
Nên tránh lồng các khối lệnh quá nhiều dẫn đến code khó đọc 
1. Ví dụ: Lồng if trong vòng lặp
2. Ví dụ: Dùng return để thoát sớm
Nesting Levels
├── Tránh lồng if/else quá sâu
├── continue → Bỏ qua lần lặp hiện tại
└── return   → Kết thúc hàm ngay
    └── Giúp xử lý trường hợp đặc biệt trước
Xử lý trường hợp đặc biệt trước
          ↓
        return
          ↓
Viết logic chính ở phía dưới

Mục 2 — Function Placement (Vị trí đặt hàm)
2.1. Ba cách đặt hàm
Cách 1 — Khai báo hàm trước, code sử dụng sau
function createUser() {
  return { name: "Martin" };
}

function showUser(user) {
  console.log(user.name);
}

// Code sử dụng hàm
const user = createUser();
showUser(user);
Cách 2 — Code sử dụng trước, hàm phụ trợ phía sau
// Code chính
const user = createUser();
showUser(user);

// Các hàm phụ trợ
function createUser() {
  return { name: "Martin" };
}

function showUser(user) {
  console.log(user.name);
}
Cách 3 — Đặt hàm tại vị trí đầu tiên cần dùng
const user = createUser();

function createUser() {
  return { name: "Martin" };
}

showUser(user);

function showUser(user) {
  console.log(user.name);
}
Function Placement
├── Có thể đặt hàm trước code chính
├── Có thể đặt code chính trước hàm phụ trợ
├── Có thể đặt hàm gần nơi sử dụng
└── Bài gốc ưu tiên:
    Code chính trước → Helper functions sau

Mục 3 — Style Guides (Hướng dẫn quy chuẩn code)
1. Style Guide là gì?
Là bộ quy tắc thống nhất cách viết code trong một dự án hoặc team
Ví dụ :
const userName = "Martin";
const user_name = "Martin";
Nếu team thống nhất dùng cammelCase
2. Tại sao cần Style Guide?
Consistency: Code trong dự án có phong cách thống nhất.
Readability: Dễ đọc và hiểu code của đồng đội.
Maintainability: Dễ sửa đổi, bảo trì và review code.
| Quy tắc                                | Ví dụ                    |
| -------------------------------------- | ------------------------ |
| Đặt tên biến theo `camelCase`          | `userName`, `totalPrice` |
| Đặt tên hằng số theo quy ước của dự án | `MAX_RETRIES`            |
| Thống nhất cách dùng dấu `;`           | `const age = 25;`        |
| Thống nhất cách thụt lề                | 2 hoặc 4 spaces          |
| Thống nhất cách đặt dấu ngoặc          | Theo quy chuẩn của team  |

Mục 4 — Automated Linters (Công cụ kiểm tra code tự động)
* 1. Linter là gì?
Linter là công cụ tự đôngj phân tích code để phát hiện các vấn đề như :
1. Vi phạm coding style
2. Lỗi đánh máy trong tên hàm hoặc biến
3. Một số tiềm ẩn có thể ảnh hưởng đến chương trình
   
* 2. Phân biệt Linter và Formatter
  ESLint — Linter kiểm tra code có vi phạm quy tắc không
  Prettier — Formatter : tự định dạng code theo format đã định chẳng hạn dấu nháy , khoảng trắng , xuống dòng

Automated Linters
├── Linter
│   ├── Kiểm tra quy tắc code
│   ├── Phát hiện một số lỗi tiềm ẩn
│   └── Ví dụ: ESLint
├── Formatter
│   ├── Tự động định dạng code
│   └── Ví dụ: Prettier
└── Mục tiêu
    ├── Code nhất quán, dễ đọc
    └── Giảm một số lỗi thường gặp
