1.1. Reachability — Khi nào object còn được giữ trong bộ nhớ?
Một object đựơc xem là reachable khi chương trình vẫn có thể truy cập nó thông qua các tham chiếu còn tồn tại
JS sử dụng GC để thu hồi bộ nhớ của những object không còn reachable
1.2. Object được giữ trong bộ nhớ bởi Array
Gán biến tham chiếu thành null không có nghĩa là object chắc chắn còn reachable
<!-- 
let user = { name: "John" };

const users = [user];

user = null;

console.log(users[0].name); // "John"
Ban đầu : user và users[0] đều tham chiếu đến cùng 1 object
user = null chỉ xoá tham chiếu của biến user
Mảng user vẫn giữ tham chiếu đó
 -->
1.3. Object được giữ trong bộ nhớ bởi Map
Tương tự Array , Map thông thường cũng giữ tham chiếu đến object dùng làm key
<!-- 
let user = { name: "John" };

const map = new Map();
map.set(user, "Developer");

user = null;

console.log(map.size); // 1
console.log([...map.keys()][0].name); // "John"

Dù user = null nhưng Object vẫn được truy cập thông qua key trong map
 -->
1.4. WeakMap không ngăn Garbage Collection
Khác với Map , WeakMap không giữ object key đã tồn tại trong bộ nhớ vì object đó là key của nó
<!--
let user = { name: "John" };

const weakMap = new WeakMap();
weakMap.set(user, "Developer");

user = null;
Sau khi user bằng null nếu k còn tham chiếu nào đến object , object đó có thể được GC thu hồi . Khi ấy , entry tương ứng trong WeakMap
cũng tự động biến mất
Note : GC diễn ra tự động và không có thơi điểm nào chính xác được đảm bảo
-->
let product = { name: "Laptop" };

const weakMap = new WeakMap();
weakMap.set(product, 1000);

product = null;

2. WeakMap
2.1. WeakMap là gì?
WeakMap là 1 cấu trúc dữ liệu lưu các cặp key -value tương tự Map nhưng có điểm khác biệt quan trọng : key phải là object
và được tham chiếu yếu
<!-- 
const user = { name: "An" };

const weakMap = new WeakMap();

weakMap.set(user, "Developer");

console.log(weakMap.get(user)); // "Developer"
console.log(weakMap.has(user)); // true

user là object được dùng làm key
Develop là value tương ứng
get() lấy value còn has() kiểm tra key có tồn tại hay không
 -->
 | Đặc điểm                            | `Map` | `WeakMap`      |
 | ----------------------------------- | ----- | -------------- |
 | Key là object                       | Có    | Có             |
 | Key là primitive như string, number | Có    | Không          |
 | Có thể duyệt các phần tử            | Có    | Không          |
 | Giữ object key trong bộ nhớ         | Có    | Không giữ mạnh |

2.2. Key của WeakMap phải là object
<!-- 
const weakMap = new WeakMap();

weakMap.set({ id: 1 }, "An"); // Hợp lệ

const weakMap = new WeakMap();

weakMap.set("id", "An"); // TypeError
weakMap.set(1, "An");    // TypeError
 -->
 2.3. Object key được tự động loại bỏ khi không còn reachable
 <!--
 let user = { name: "An" };

const weakMap = new WeakMap();
weakMap.set(user, "Developer");

user = null;
Sau khi user null
1. Biến user không còn tham chiếu đến object
2. Nếu k có tham chiếu nào khác , object có thể bị GC thu hồi
3. Khi object key được thu hồi , entry tương ứng trong WeakMap cũng bị thu hồi
   -->

let user = { name: "An" };
const anotherRef = user;

const weakMap = new WeakMap();
weakMap.set(user, "Developer");

user = null;

console.log(weakMap.get(anotherRef)); // "Developer"

<!-- anotherRef vẫn tham chiếu đến object nên object chưa đủ điều kiện đê thu hồi -->
2.4. Các phương thức của WeakMap
WeakMap có 4 phương thức chính:
| Phương thức       | Chức năng                        |
| ----------------- | -------------------------------- |
| `set(key, value)` | Thêm hoặc cập nhật cặp key-value |
| `get(key)`        | Lấy value theo key               |
| `has(key)`        | Kiểm tra key có tồn tại không    |
| `delete(key)`     | Xóa entry theo key               |
<!-- 
const user = { name: "An" };
const weakMap = new WeakMap();

weakMap.set(user, "Developer");

console.log(weakMap.get(user));    // "Developer"
console.log(weakMap.has(user));    // true

weakMap.set(user, "Frontend");     // Cập nhật value
console.log(weakMap.get(user));    // "Frontend"

weakMap.delete(user);
console.log(weakMap.has(user));    // false
 -->
 set với cùng một key sẽ cập nhật value không tạo thêm emtry mới

 2.5. Vì sao WeakMap không hỗ trợ iteration?
 Khác với Map , WeakMap không hỗ trợ duyệt các phần tử và không có nhưng thuộc tính và phương thức sau:
 <!-- 
 weakMap.keys();
weakMap.values();
weakMap.entries();
weakMap.size;
weakMap.clear();

Giả sử WeakMap cho phép duyệt tất cả key. Trong lúc duyệt, Garbage Collection có thể thu hồi một object không còn reachable. Khi đó, kết quả duyệt và số lượng phần tử có thể thay đổi không xác định.

Vì vậy, JavaScript không cung cấp cơ chế iteration hoặc size cho WeakMap.

Lưu ý: weakMap.clear() cũng không tồn tại; nếu muốn xóa toàn bộ dữ liệu, bạn có thể tạo một WeakMap mới hoặc xóa từng key bằng delete().
  -->
2.6. Use case: lưu dữ liệu bổ sung cho object
Giả sử bạn quản lý thông tin người dùng và muốn lưu số mỗi người dùng truy cập 
<!-- 
let user = { name: "An" };

const visits = new WeakMap();

visits.set(user, 1);

console.log(visits.get(user)); // 1
 -->
 Visits lưu dữ liệu bổ sung bên ngoài object user , không cần sửa cấu trúc object

3. Use case — Caching
Cachinh là lưu kết quả đã tính toán để tái sử dụng , tránh thực hiện cùng 1 phép tính nhiều lần
<!-- 
function process(user) {
    console.log("Processing...");
    return user.name.toUpperCase();
}

const user = { name: "An" };

process(user); // Processing... → "AN"
process(user); // Processing... → "AN"
 -->
 Ta có thể lưu kết quả bằng Map
 <!-- 
 const cache = new Map();

function process(user) {
    if (cache.has(user)) {
        return cache.get(user);
    }

    console.log("Processing...");

    const result = user.name.toUpperCase();
    cache.set(user, result);

    return result;
}

const user = { name: "An" };

console.log(process(user)); // Processing... → "AN"
console.log(process(user)); // "AN" (lấy từ cache)
  -->
3.2. Vấn đề khi dùng Map để cache
Map giữ tham chiều mạnh đến object được dùng làm key . Vì vậy nếu obj không được dùng ở nơi khác nhưng vân đưuojc làm key 
trong cache , nó vẫn có thể được giữ trong bộ nhớ
3.3. Dùng WeakMap để cache theo object
<!-- 
const cache = new WeakMap();

function process(user) {
    if (cache.has(user)) {
        return cache.get(user);
    }

    const result = user.name.toUpperCase();
    cache.set(user, result);

    return result;
}
 -->
 Khi object không còn reacale từ nới khác , nó có thể được thu hồi và entry cache tương ứng cũng tự động biến mất
 Điểm cần nhớ: WeakMap phù hợp để cache dữ liệu được gắn với objetc

4. WeakSet
4.1. WeakSet là gì?
WeakSet tương tự như Set , nhưng chỉ lưu object và không giữ object tồn tại trong bộ nhớ vì object đó nằm trong tập hợp
<!-- 

const visitedUsers = new WeakSet();

const user1 = { name: "An" };
const user2 = { name: "Bình" };

visitedUsers.add(user1);
visitedUsers.add(user2);

console.log(visitedUsers.has(user1)); // true
console.log(visitedUsers.has(user2)); // true
 -->

 4.2. WeakSet chỉ lưu object
 <!-- 
 const weakSet = new WeakSet();

weakSet.add({ id: 1 }); // Hợp lệ
weakSet.add("An");      // TypeError
weakSet.add(100);       // TypeError
  -->
WeakSet được thiết kế để theo dõi vòng đời của object , chứ không lưu giá trị primitive như string hoặc number

4.3. Object được tự động loại bỏ khi không còn reachable
<!-- 

let user = { name: "An" };

const visitedUsers = new WeakSet();
visitedUsers.add(user);

console.log(visitedUsers.has(user)); // true

user = null;
 -->

 Nếu không còn tham chiếu đến object nó có thể bị GC thu hồi . Khi đó object cũng tự động k còn thuộc WeakSet
 4.4. Các phương thức của WeakSet
 | Phương thức     | Chức năng                        |
 | --------------- | -------------------------------- |
 | `add(value)`    | Thêm object vào tập hợp          |
 | `has(value)`    | Kiểm tra object có tồn tại không |
 | `delete(value)` | Xóa object khỏi tập hợp          |
 <!-- 
 const weakSet = new WeakSet();
const user = { name: "An" };

weakSet.add(user);

console.log(weakSet.has(user)); // true

weakSet.delete(user);

console.log(weakSet.has(user)); // false
  -->
WeakSet không hỗ trợ size , keys() , values() , entries() , interation hoặc clear();

const weakSet = new WeakSet();

 const visitedUsers = new WeakSet();

    if (visitedUsers.has(user)) {

5. Summary — Tổng kết WeakMap và WeakSet
   
5.1. WeakMap
- Lưu dữ liệu theo cặp key-value.
- Key là object (theo phạm vi bài học).
- Không giữ object key tồn tại trong bộ nhớ chỉ vì nó là key.
- Hỗ trợ set(), get(), has(), delete().
- Không hỗ trợ iteration, size hoặc clear().

5.2. WeakSet
- Lưu các object duy nhất, không lưu cặp key-value.
- Không giữ object tồn tại trong bộ nhớ chỉ vì nó thuộc tập hợp.
- Hỗ trợ add(), has(), delete().
- Không hỗ trợ iteration, size hoặc clear().
  
5.3. So sánh
| Đặc điểm                       | `Map`     | `Set`            | `WeakMap`          | `WeakSet`             |
| ------------------------------ | --------- | ---------------- | ------------------ | --------------------- |
| Lưu dữ liệu                    | Key-value | Giá trị duy nhất | Key-value          | Object                |
| Key/giá trị là primitive       | Có        | Có               | Không*             | Không                 |
| Duyệt phần tử                  | Có        | Có               | Không              | Không                 |
| Có `size`                      | Có        | Có               | Không              | Không                 |
| Có `clear()`                   | Có        | Có               | Không              | Không                 |
| Giữ tham chiếu mạnh đến object | Có        | Có               | Không giữ mạnh key | Không giữ mạnh object |

5.4. Khi nào sử dụng?
Map: cần lưu key-value và duyệt dữ liệu.
Set: cần tập hợp giá trị duy nhất và duyệt phần tử.
WeakMap: cần lưu dữ liệu bổ sung hoặc cache gắn với vòng đời của object.
WeakSet: cần đánh dấu object đã được xử lý, đã truy cập hoặc thuộc một trạng thái nào đó.
