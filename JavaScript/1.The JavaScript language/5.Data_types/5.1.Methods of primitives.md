Mục 1. Primitive và Object khác nhau thế nào?
1. Primitive là gì
Primitive là giá trị nguyên thuỷ.
avaScript có 7 primitive types:
Number , string , boolean , null , undefined , bigint , symbol
2. Object là gì?
Object có thể lưu nhiều giá trị thông qua các propety và có thể chứa function làm method
const user = {
    name: "Martin",
    age: 27,

    sayHi() {
        console.log("Hello!");
    }
};

user.sayHi(); // Hello!
3. So sánh nhanh
   | Primitive                                      | Object                                      |
   | ---------------------------------------------- | ------------------------------------------- |
   | Là một giá trị nguyên thủy                     | Có thể chứa nhiều property                  |
   | Ví dụ: `"Hello"`, `10`, `true`                 | Ví dụ: `{ name: "Martin" }`                 |
   | Không thể thêm property để lưu dữ liệu lâu dài | Có thể thêm, sửa, xóa property thông thường |
   | Thường nhẹ hơn object                          | Có thêm cơ chế quản lý property, method     |
4. Điểm dễ nhầm: Primitive vẫn có thể sử dụng method, chẳng hạn "hello".toUpperCase(). Điều này không có nghĩa chuỗi primitive đã trở thành object. Đây chính là nội dung chúng ta sẽ học ở mục tiếp theo.

Mục 2. A primitive as an object
1. Vấn đề JavaScript cần giải quyết
JS đôngg thời cần đáp ứng 2 yêu cầu 
* Primitive như string , number phải nhẹ và nhanh
* CHúng ta vẫn cần gọi method trên primiive : "hello".opUpperCase();
2. Cơ chế hoạt động
JS sử dụng wrapper object ( object bao bọc) tạm thời khi bạn truy cập property hoặc method của một số primitive
Dù gọi được toUpperCase(), biến str vẫn có kiểu string, không biến thành object.
3. Wrapper tương ứng với từng primitive
| Primitive | Wrapper   |
| --------- | --------- |
| `string`  | `String`  |
| `number`  | `Number`  |
| `boolean` | `Boolean` |
| `symbol`  | `Symbol`  |
| `bigint`  | `BigInt`  |

const n = 12.345;

console.log(n.toFixed(1));
console.log(typeof n);
console.log(typeof n.toFixed(1));

- n vẫn có kiểu number.
- Giá trị trả về của toFixed(1) có kiểu string -->

Mục 3. Wrapper objects — Vì sao không nên dùng new String(), new Number(), new Boolean()?
JS khuyến nghị dùng primitive thay vì tạo wrapper object bằng new
1. Khác nhau giữa primitive và wrapper object
const a = "hello";
const b = new String("hello");

console.log(typeof a); // "string"
console.log(typeof b); // "object"
2. Trường hợp dễ nhầm nhất: Boolean

const a = Boolean(false);
const b = new Boolean(false);

console.log(typeof a); // "boolean"
console.log(typeof b); // "object"

console.log(Boolean(a)); // false
console.log(Boolean(b)); // true

Vì b là 1 object . Trong JS mọi object đều là truethy kể cả object bao bọc 1 giá trị false
3. So sánh == và ===

const a = "hello";
const b = new String("hello");

console.log(a == b);  // true
console.log(a === b); // false

== có thể chuyển đổi kiểu để so sánh, nên kết quả là true.
=== không chuyển đổi kiểu; một bên là string, một bên là object, nên kết quả là false.

Mục 4. null và undefined không có methods
1. Quy tắc
Các primitive như string, number, boolean, symbol và bigint có thể sử dụng methods thông qua cơ chế wrapper tạm thời.
Nhưng null và undefined là ngoại lệ : bạn k thể truy cập thuộc tính hoặc method của chúng như các primitive khác
2. Phân biệt với optional chaining ?.
const user = null;

console.log(user?.name); // undefined
console.log(user.name);  // TypeError
user?.name: kiểm tra user; nếu là null hoặc undefined, dừng và trả về undefined.
user.name: truy cập trực tiếp nên gây lỗi.

// Primitive vẫn giữ kiểu nguyên thủy
const str = "hello";
console.log(typeof str); // "string"
console.log(str.toUpperCase()); // "HELLO"

// Wrapper object có kiểu object
const boxed = new String("hello");
console.log(typeof boxed); // "object"

// Object luôn truthy
console.log(Boolean(new Boolean(false))); // true

// null và undefined không có methods
console.log(null?.toString()); // undefined

Lưu ý: str.toUpperCase() hoạt động nhờ cơ chế wrapper tạm thời. Điều đó không có nghĩa primitive có thể lưu thêm property tùy ý.
