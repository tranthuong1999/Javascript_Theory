Phần 1 – Getters and setters
1.1. Có hai loại properties trong JavaScript
Data properties (thuộc tính dữ liệu)
Đây là proprty chúng ta sử dụng từ đầu :
<!-- 
let user = {
    name: "John",
    age: 25
};
 -->
1.2. Getter và Setter là gì?
Trong object literal, cú pháp như sau:
<!-- 
let obj = {
    get propName() {
        // Chạy khi đọc obj.propName
    },

    set propName(value) {
        // Chạy khi gán obj.propName = value
    }
};
 -->
 get : được gọi khi đọc property
 set : được gọi khi gán giá trị cho property.
 1.3. Ví dụ trong tài liệu gốc
Giả sử có object user:
<!-- 
let user = {
    name: "John",
    surname: "Smith"
};
 -->
 Chúng ta muốn có thêm property fullName , kết quả "John Smith"
 Thay vì lưu trữ và sao chép dữ liệu ,ta sử dụng getter
 <!-- 
 let user = {
    name: "John",
    surname: "Smith",

    get fullName() {
        return `${this.name} ${this.surname}`;
    }
};

console.log(user.fullName); // John Smith
  -->
Điểm cần hiểu:
user.fullName
không phải user.fullName();
Getter tự động chạy khi chúng ta đọc property
1.4. Getter-only
Nếu property chỉ có getter mà không có setter
<!-- 
let user = {
    get fullName() {
        return "John Smith";
    }
};

user.fullName = "Test"; // Error trong strict mode
 -->
Vì propety này chỉ cho phép đọc không cho phép gán
1.5. Thêm Setter
<!-- 
let user = {
    name: "John",
    surname: "Smith",

    get fullName() {
        return `${this.name} ${this.surname}`;
    },

    set fullName(value) {
        [this.name, this.surname] = value.split(" ");
    }
};

user.fullName = "Alice Cooper";

console.log(user.name);    // Alice
console.log(user.surname); // Cooper
 -->
 Đây được gọi là virtual property( thuộc tính ảo ) :không lưu giá trị fullName trực tiếp mà lấy từ name và surname
 Kiểm tra phần 1:
 <!-- 
 let user = {
    name: "John",
    surname: "Smith",

    get fullName() {
        return `${this.name} ${this.surname}`;
    },

    set fullName(value) {
        [this.name, this.surname] = value.split(" ");
    }
};

user.fullName = "Alice Cooper";

console.log(user.fullName);
console.log(user.name);
  -->
Giải thích luồng thực thi:
1. user.fullName = "Alice Cooper" kích hoạt setter.
2. value.split(" ") tạo mảng ["Alice", "Cooper"].
3. Destructuring gán user.name = "Alice" và user.surname = "Cooper".
4. Khi đọc user.fullName, getter ghép hai giá trị lại.

* Phần 2. Accessor descriptors
2.1. Descriptor của accessor properties
Ở bài trước, chúng ta đã học descriptor của data property:
<!-- 
{
    value: "John",
    writable: true,
    enumerable: true,
    configurable: true
}
 -->
Nhưng accessor property có descriptor khác.
Nó không có value hoặc writable , thay vào đó:
| Thuộc tính     | Ý nghĩa                                    |
| -------------- | ------------------------------------------ |
| `get`          | Function chạy khi đọc property             |
| `set`          | Function chạy khi gán property             |
| `enumerable`   | Có xuất hiện khi liệt kê không?            |
| `configurable` | Có thể xóa hoặc thay đổi descriptor không? |
2.2. Tạo accessor bằng Object.defineProperty()
Ví dụ trong tài liệu gốc :
<!-- 
let user = {
    name: "John",
    surname: "Smith"
};

Object.defineProperty(user, "fullName", {
    get() {
        return `${this.name} ${this.surname}`;
    },

    set(value) {
        [this.name, this.surname] = value.split(" ");
    }
});

console.log(user.fullName); // John Smith

for (let key in user) {
    console.log(key);
}
 -->
 Tại sao không có fullName ?
 Vì khi tạo propety bằng Object.defineProperty() , nếu không khai báo enumerable , mặc định nó là false
 2.3. Data property và Accessor property không thể kết hợp
 Một propety chỉ có thể là :
 Data property: có value
 Accessor property: có get và hoặc set
 Không thể vừa có get vừa có value trong cùng descriptor
 Ví dụ không hợp lệ:
 <!-- 
 Object.defineProperty({}, "prop", {
    get() {
        return 1;
    },

    value: 2
});
  -->
  Tốt! Trước khi sang phần 2, mình chốt lại kiến thức phần 1:
- writable: cho phép thay đổi giá trị.
- enumerable: cho phép property xuất hiện trong quá trình liệt kê.
- configurable: cho phép xóa property và thay đổi descriptor theo quy tắc của JavaScript.
- Object.getOwnPropertyDescriptor(): đọc descriptor.
- Object.defineProperty(): định nghĩa hoặc cấu hình property.
<!-- 

let user = {
    name: "John",
    surname: "Smith"
};

Object.defineProperty(user, "fullName", {
    get() {
        return `${this.name} ${this.surname}`;
    }
});

console.log(Object.keys(user));
console.log(user.fullName);
 -->
Giải thích:
- Object.keys(user) chỉ lấy các own properties có enumerable: true.
- fullName được tạo bằng Object.defineProperty() nhưng không khai báo enumerable, nên mặc định là false.
- user.fullName vẫn đọc được bình thường vì getter hoạt động.

*********************************************************************************************************************************

getter/setter có thể được sử dụng như 1 lớp wrapper bao quanh giá trị property thực tế , giúp kiểm soat thao tác các giá trị đó

Phần 3. Smarter getters/setters
3.1. Vấn đề cần giải quyết
<!-- 
let user = {
    name: "John"
};

user.name = "";
 -->
Hiện tại bất kỳ giá trị nào cũng có thể gán cho name , kể cả chuỗi rỗng 
Ta muốn đặt quy tắc:
1. Tên phải có ít nhất 4 kí tự 
2. Nếu không đủ 4 kí tự thì không chấp nhận giá trị

3.2. Sử dụng getter và setter
<!-- 
let user = {
    get name() {
        return this._name;
    },

    set name(value) {
        if (value.length < 4) {
            alert("Name is too short, need at least 4 characters");
            return;
        }

        this._name = value;
    }
};

user.name = "Pete";
alert(user.name); // Pete

user.name = ""; // Name is too short...
 -->
 3.3. Phân tích cách hoạt động
 1. Nhận "Pete" thông qua tham số value
 2. Kiểm tra value.length < 4
 3. Vì "Pete" có 4 kí tự nên hợp lệ 
 4. Lưu giá trị vào this._name

3.4. Tại sao sử dụng _name?
_name :là propety lưu giá trị thực tế
Còn name là ccessor property dùng để kiểm soát việc đọc và ghi

Phần 4. Using for compatibility
4.1. Vấn đề: Thay đổi cấu trúc dữ liệu
Giả sử ban đầu chungs ta xây dựng constructor User như sau :
<!-- 
function User(name, age) {
    this.name = name;
    this.age = age;
}

let john = new User("John", 25);

console.log(john.age); // 25
 -->
Sau 1 thơi gian chúng ta thay age bằng birthday , vì ngày sinh chính xác và hữu ích hơn
<!-- 
function User(name, birthday) {
    this.name = name;
    this.birthday = birthday;
}

let john = new User("John", new Date(1992, 6, 1));
 -->
 Nhưng vấn đề xuất hiện :
 Code cũ vẫn đang sử dụng : john.age;
 Nếu thay đổi cấu truc trên john.age trả về undefined
 Chúng ta pphair sửa tất cả code đang sử dụng age , điều này có vẻ tốn thời gian

4.2. Giải pháp: Sử dụng Getter
Thay vì lưu age , chúng ta tạo getter để tính tuổi từ birthday
<!-- 
function User(name, birthday) {
    this.name = name;
    this.birthday = birthday;

    Object.defineProperty(this, "age", {
        get() {
            let todayYear = new Date().getFullYear();
            return todayYear - this.birthday.getFullYear();
        }
    });
}

let john = new User("John", new Date(1992, 6, 1));

console.log(john.birthday);
console.log(john.age);
 -->
Cách hoạt động:
-birthday: lưu ngày sinh thực tế
- age : không lưu trực tiép , được tính toán thông qua get
- Code cũ vẫn có thể hoạt dộng như cũ
4.3. Ý nghĩa của Compatibility
Compatibility ở đây có nghĩa là duy trì khả năng tương thích với code cũ khi cấu trúc dữ liệu bên trong thay đổi
Ví dụ:
Trước đây:
User
├── name
└── age (lưu trực tiếp)

Sau khi thay đổi:
User
├── name
├── birthday (lưu trực tiếp)
└── age (getter tính từ birthday)

Nhờ vậy chúng ta có thê thay đổi cách dữ liệu bên trong mà không phải thay đổi code bên ngoài sủ dụng object

Tổng kết :
1. Getters and setters
Có hai loại properties:

| Tiêu chí      | Data properties        | Accessor properties                |
| ------------- | ---------------------- | ---------------------------------- |
| Cách lưu trữ  | Lưu giá trị trực tiếp  | Là các function                    |
| Descriptor    | Có `value`, `writable` | Có `get`, `set`                    |
| Cách truy cập | Đọc và ghi trực tiếp   | Đọc và ghi thông qua getter/setter |
<!-- 
let user = {
    get fullName() {
        return `${this.name} ${this.surname}`;
    },

    set fullName(value) {
        [this.name, this.surname] = value.split(" ");
    }
};
 -->
Ghi nhớ:
- get: chạy khi đọc property.
- set : chạy khi gán property
- Getter/setter được sử dụng như property thông thường, không gọi bằng ().
fullName là một virtual property vì giá trị được tạo từ name và surname, không lưu trực tiếp.

2. Accessor descriptors
Descriptor của accessor property:
<!-- 
Object.defineProperty(user, "fullName", {
    get() {
        return `${this.name} ${this.surname}`;
    }
});
 -->
| Thuộc tính     | Ý nghĩa                         |
| -------------- | ------------------------------- |
| `get`          | Function khi đọc                |
| `set`          | Function khi ghi                |
| `enumerable`   | Có xuất hiện khi liệt kê?       |
| `configurable` | Có thể xóa/thay đổi descriptor? |
Điểm quan trọng:
- Accessor property không có value hoặc writable.
- Data property có value và writable.
- Một property không thể đồng thời là data property và accessor property.
  
3. Smarter getters/setters
Sử dung getter/setter để kiểm soát dữ liệu 
<!-- 
let user = {
    get name() {
        return this._name;
    },

    set name(value) {
        if (value.length < 4) return;

        this._name = value;
    }
};
 -->
Ứng dụng:
1. Validation dữ liệu.
2. Kiểm soát giá trị được phép gán.
3. Tách property dùng bên ngoài (name) khỏi property lưu dữ liệu (_name).

Lưu ý: _name chỉ là quy ước biểu thị property nội bộ, không phải cơ chế private thực sự.
4. Using for compatibility
Sử dụng accessor để duy trì tương thích khi cấu trúc dữ liệu thay đổi.
Trước:
User
├── name
└── age

Sau:
User
├── name
├── birthday
└── age (getter)
