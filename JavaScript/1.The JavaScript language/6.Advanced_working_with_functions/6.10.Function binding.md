1. Losing this – Mất ngữ cảnh this
Mục tiêu cần hiểu:
- this được xác định như thế nào khi gọi function
- Tại sao gọi method thông qua object thì this đúng
- Tại sao truyền method làm callback thì mất this
- Phân biệt cách gọi trực tiếp và cách truyền function
  
1.1. this hoạt động như thế nào?
Trong JS , this thường được xác định dựa vào cách function được gọi , không phải nơi function được khai báo
<!--
let user = {
  firstName: "John",

  sayHi() {
    console.log(this.firstName);
  }
};

user.sayHi(); // John
  -->
user là obj gọi method
sayHi() được gọi thông qua user
this bên trong sayHi() tham chiếu đến user
this.firstName tương đương với user.sayHi()
1.2. Vấn đề: Losing this
Bây giờ chúng ta sẽ thay đổi cách gọi :
<!-- 
let user = {
  firstName: "John",

  sayHi() {
    console.log(`Hello, ${this.firstName}!`);
  }
};

let sayHi = user.sayHi;

sayHi(); // Hello, undefined!
 -->
let sayHi = user.sayHi;
Bởi vì chúng ta chỉ lấy funtion ra khỏi obj và gán vào biến sayHi
sayHi(); đây là gọi funtion độc lập , không phải lời gọi method thông qua user
Trong strict mode:
<!-- this === undefined; -->
Do đó , this.firstName trả về undefined trong trương hợp này sẽ gây ra lỗi truy cập 
1.3. Tình huống thực tế: Truyền method làm callback
<!-- 
let user = {
  firstName: "John",

  sayHi() {
    console.log(`Hello, ${this.firstName}!`);
  }
};

setTimeout(user.sayHi, 1000);
 -->
Sau 1s , callback được thực thi nhưng không còn được gọi thông qua user
Vì vậy, this không còn tham chiếu đến user
Đây là hiện tượng losing this.
| Cách gọi                       | `this`                        |
| ------------------------------ | ----------------------------- |
| `user.sayHi()`                 | `user`                        |
| `let f = user.sayHi; f()`      | `undefined` trong strict mode |
| `setTimeout(user.sayHi, 1000)` | Không phải `user`             |

Kiến thức cốt lõi: 1 function có thể lấy ra khỏi objeect và truyền đi độc lập . Khi đó , nó không tự động giữ lại this của object
ban đầu 
((f là function độc lập.

2. Solution 1: A wrapper
Chúng ta sẽ khắc phục this bằng :
- Function wrapper thông thường
- Arrow function
<!-- 
let user = {
  firstName: "John",

  sayHi() {
    console.log(`Hello, ${this.firstName}!`);
  }
};

setTimeout(function () {
  user.sayHi();
}, 1000);
 -->
 Ở đây callback không trực tiếp gọi sayHi , mà gọi user.sayHi() bên trong wrapper
 Vì vậy , this vẫn tham chiếu đến user


<!-- 
let user = {
    name: "Martin",
    sayHi() {
        console.log(this.name);
    }
};

setTimeout(() => user.sayHi(), 1000);
-->

this bên trong sayHi() được xác định theo object gọi method, nên this = user.
Tổng kết mục 2:
- Funcion wrapper giúp gọi lại method thông qua object
- Arrow function cũng có thể dùng làm wrapper
- Điều quan trọng là phải gọi user.sayHi() , không phải chỉ gọi user.sayHi

3. Solution 2: bind
3.1. Cú pháp bind(context)
JS cung cấp method bind() để tạo ra 1 function mới với this cố định
<!-- let boundFunction = func.bind(context); -->
Trong đó :
func : function gốc
context : object muốn cố định this
boundFunction : function mới có this luôn tham chiếu đến context
<!-- 
let user = {
  firstName: "John",

  sayHi() {
    console.log(`Hello, ${this.firstName}!`);
  }
};

let sayHi = user.sayHi.bind(user);

sayHi(); // Hello, John!
 -->
1. user.sayHi.bind(user) tạo function mới.
2. Function mới được cố định với this là user
3. Dù gọi sayHi() độc lập this vẫn là user
((: Điểm quan trọng: bind() không gọi function ngay lập tức . Nó trả về 1 function mới

3.2. Truyền method làm callback an toàn
<!-- 
setTimeout(user.sayHi, 1000);
// Mất this
 -->
 Sử dụng bind:
 <!-- 
 setTimeout(user.sayHi.bind(user), 1000);
// Hello, Martin!
 -->
 Ở đây , bind(user) tạo function mới đã cố định this , nên setTimeout có thể gọi function đó độc lập mà không làm mất this
 3.3. So sánh Wrapper và bind
 | Tiêu chí       | Wrapper                       | bind             |
 | -------------- | ----------------------------- | ---------------- |
 | Cách hoạt động | Gọi lại method                | Tạo function mới |
 | Giữ `this`     | Nhờ gọi qua object            | Cố định `this`   |
 | Code           | Phải viết function trung gian | Ngắn gọn hơn     |

Bài tập kiểm tra mục 3:
<!-- 
let user = {
  name: "Martin",

  sayHi() {
    console.log(this.name);
  }
};

let f = user.sayHi.bind(user);

let anotherUser = {
  name: "John"
};

f.call(anotherUser);
 -->
Thông thường, call() có thể truyền this mới cho function:
Nhưng với function đã được bind() this đã cố định 
Vì vậy :
f đã cố định this = user.
f.call(anotherUser) không thể thay đổi this.
- Kết quả vẫn là Martin.
Ghi nhớ : là bind có độ ưu tiên cao hơn call() và apply() trong việc xác định this của bound function

4. Partial functions
4.1. Cú pháp bind(context, ...args)
Ngoài việc cố định this , bind() còn cho phép chúng ta cố định trước một hoặc nhiểu argument của nhiều tham số
của funcion
Cú pháp:
<!-- let boundFunction = func.bind(context, arg1, arg2, ...); -->
Trong đó:
- context: giá trị this muốn cố định
- arg1 , arg2 : những arguments được truyền trước
- Args còn lại sẽ được truyền khi gọi funcion mới

<!-- 
function multiply(a, b) {
  return a * b;
}

let double = multiply.bind(null, 2);

console.log(double(5));  // 10
console.log(double(10)); // 20
 -->
Phân tích:
Bước 1:
<!-- let double = multiply.bind(null, 2); -->
Cố định argument đầu tiên :
a=2;
Bước 2:Argument còn lại được truyền vào:b = 5;

4.2. Khái niệm Partial function
Partial function là 1 funcion được tạo ra bằng cách cố định trước một số argument của một function ban đầu
Ví dụ:
<!-- 
function sum(a, b) {
  return a + b;
}

let addFive = sum.bind(null, 5);

console.log(addFive(10)); // 15
console.log(addFive(20)); // 25
 -->
 Thay vì mỗi lần gọi đều phải truyền cả 2 argument , chúng ta chỉ cần truyền argument chưa được cố định 
 Bài tập :
 <!-- 
 function calculate(a, b, c) {
  return a + b * c;
}

let result = calculate.bind(null, 10, 2);

console.log(result(5));
console.log(result(8));
  -->
4.3. Tổng kết Partial functions
-bind(): có thể cố định this
bind() cũng có thể cố định trước arguments.
Các argument chưa cố định sẽ được truyền khi gọi fucntion mới
Function mới được tạo ra nhưng function gốc không thay dổi

5. Going partial without context
5.1. Vấn đề
<!-- let result = calculate.bind(null, 10, 2); -->
Nhưng bind luôn tạo ra 1. bound function, nghĩa là nó cố định cả this ( ở đây là null) lẫn các argument đã truyền
Nếu chúng ta muốn có định argument mà k cố định this thì làm như thế nào ?
5.2. Xây dựng hàm partial()
<!-- 
function partial(func, ...argsBound) {
  return function (...args) {
    return func.call(this, ...argsBound, ...args);
  };
}
 -->
 func: function gốc.
 argsBound : những arguments muốn cố định trứóc
 args : những argument tryuyền thêm khi gọi function mới
 func.call(this, ...): giữ nguyên this của cách gọi fucntion mới
 <!-- 
 function say(time, phrase) {
  console.log(`[${time}] ${phrase}, ${this.name}`);
}

let partialSay = partial(say, "10:00");

let user = { name: "Martin" };

partialSay.call(user, "Hello");
  -->
Bài tập :
<!-- 
function partial(func, ...argsBound) {
  return function (...args) {
    return func.call(this, ...argsBound, ...args);
  };
}

function multiply(a, b) {
  return a * b;
}

let double = partial(multiply, 2);

console.log(double(5));
console.log(double(10));
 -->
Bạn hãy cho biết:
1. Kết quả của hai lần gọi?
2. argsBound chứa gì?
3. args chứa gì trong lần gọi double(5)?

Điểm quan trọng cần nhớ:
- bind() có thể cố định this và arguments.
- - partial() tự xây dựng ở trên chỉ cố định arguments, còn this được xác định khi gọi function mới.

6. Summary – Tổng kết Function binding

6.1. Losing this
<!-- 
let f = user.sayHi;
f(); // Mất this
 -->
 Nguyên nhân: function được gọi độc lập, không thông qua object.
 6.2. Wrapper function
 <!-- 
 setTimeout(() => user.sayHi(), 1000);
  -->
Gọi lại method thông qua object nên giữ được this.
6.3. bind(context)
<!-- 
let f = user.sayHi.bind(user);
f(); // this luôn là user
 -->
Tạo function mới với this cố định.
6.4. Partial functions
<!-- 
function multiply(a, b) {
  return a * b;
}

let double = multiply.bind(null, 2);

double(5); // 10
 -->
Cố định trước arguments.
6.5. Going partial without context
<!-- 
function partial(func, ...argsBound) {
  return function (...args) {
    return func.call(this, ...argsBound, ...args);
  };
}
 -->
Cố định arguments nhưng vẫn giữ this theo cách gọi function mới.
6.6. Bảng so sánh
| Phương pháp | Cố định `this`                            | Cố định arguments |
| ----------- | ----------------------------------------- | ----------------- |
| Wrapper     | Không, nhưng có thể gọi method qua object | Không             |
| `bind()`    | Có                                        | Có thể            |
| `partial()` | Không                                     | Có                |
