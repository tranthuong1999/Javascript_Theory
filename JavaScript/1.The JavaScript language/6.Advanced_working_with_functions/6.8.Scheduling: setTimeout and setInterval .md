1. setTimeout
1.1. Scheduling a call là gì?
Thông thường, khi gọi function:
<!-- 
function sayHi() {
    console.log("Hello");
}

sayHi();
console.log("World");
 -->
Hello
World
sayHi() được thực thi ngay khi JS gặp lời gọi 
Nhưng đôi khi chugngs ta không muốn thực thi functin ngay lập tức , mà muốn thực thi sau 1 khoảng thời gian
Giải thích:
1. JavaScript gặp setTimeout(sayHi, 2000).
2. Đăng ký lịch gọi sayHi sau khoảng 2000 milliseconds.
3. Không chờ đủ 2 giây, JavaScript tiếp tục chạy dòng tiếp theo.
4. console.log("World") được thực hiện.
5. Khi timer đến hạn và môi trường có thể thực thi callback, sayHi() được gọi.
Điểm cần nhớ : setTimeout() không làm chưong trình dừng lại để chờ . Nó chỉ lên lịch thực thi callback trơng tương lai
Lưu ý thêm: 2000ms là khoảng thời gian tối thiểu theo yêu cầu , không đảm bảo chính xác callback chạy chính xác ngay tại mốc 2s

1.2. Syntax và parameters
<!-- 
let timerId = setTimeout(
    func,
    delay,
    arg1,
    arg2,
    ...
);
 -->
| Parameter       | Ý nghĩa                               |
| --------------- | ------------------------------------- |
| `func`          | Function sẽ được thực thi             |
| `delay`         | Thời gian chờ, tính bằng milliseconds |
| `arg1, arg2...` | Các arguments truyền vào function     |
| `timerId`       | ID dùng để quản lý hoặc hủy timer     |
Ví dụ :
<!-- 
function sayHi() {
    console.log("Hello");
}

let timerId = setTimeout(sayHi, 3000);

console.log(timerId);
 -->
Sau khoảng 3s , sayHi() được thực thi
timerId là mã định danh của timer .Giá trị cụ thể phụ thuộc vào môi trường chạy : Browser thuơngf trả về số,
còn Nodejs/Bun có thể trả về timer object

4. "Martin" được truyền vào parameter name.
5. Sau thời gian chờ , function được gọi với 2 argument đó

setTimeout() là cơ chế bất đồng bộ (asynchronous).

| `arg1, arg2...` | Các arguments truyền vào function                              |
| `timerId`       | ID dùng để quản lý hoặc hủy interval                           |

let count = 1;

    count++;
}, 1000);
 -->

1
2
3
4
5
...

let count = 1;

let timerId = setInterval(() => {

3. Nested setTimeout
Nested setTimeout là kĩ thuật gọi setTimeout() bên trong chính callstack của nó để tạo ra 1 vòng lặp 
Thay vì dùng setInterval() chúng ta có thể dùng cách này để kiểm soát thời gian giữa các lần thực thi linh hoạt hơn
3.1. Cách hoạt động
Ví dụ sử dụng setInterval():
<!-- 
let count = 0;

let timerId = setInterval(() => {
    count++;
    console.log(count);

    if (count === 5) {
        clearInterval(timerId);
    }
}, 1000);
 -->
Cùng logic đó chúng ta sử dụng nested setTimeout():
<!-- 
let count = 0;

function run() {
    count++;
    console.log(count);

    if (count < 5) {
        setTimeout(run, 1000);
    }
}

setTimeout(run, 1000);
 -->
 Cách hoạt động :
 1. setTimeout(run , 1000) lên lịch gọi run() sau khoảng 1s
 2. run() thực thi và tăng count
 3. Nếu count < 5 nó tiếp tục lên lịch gọi run() sau 1s
 4. Khi count =5 điều kiện sai nên nó không tiếp tục tạo timer mới . Kết thúc vòng lặp

3.2. So sánh setInterval() và nested setTimeout()
Điểm khác biệt quan trọng nhất nằm ở  thời diểm nên lịch lần thực thi tiếp theo
<!-- 
setInterval(() => {
    doSomething();
}, 1000);
 -->
 Các lần gọi được nên lịch theo chu kì cố định . Nếu xử lý mất nhiều thời gian , callback có thể không bắt đầu đúng mỗi 1s
 * Nested setTimeout()
<!-- 
function run() {
    doSomething();
    setTimeout(run, 1000);
}

setTimeout(run, 1000);
 -->
 Lần tiếp theo được nên lịch sau khi lần hiện tại hoàn thành . Vì vậy khoảng cách giữa 2 lần bắt đầu thường bằng thời gian xử lý
 + 1s
  
Ví dụ doSomething() mất 500ms:
setInterval(..., 1000): chu kỳ được lên lịch mỗi 1000ms.
Nested setTimeout():khoảng cách giữa 2 lần bắt đầu sấp sỉ khoảng 1500ms
Ưu điểm của nested setTimeout():
- Kiểm soat được khonagr thời gian chờ giữa các lần thực thi
- Có thể thay đổi delay tuỳ theo kết quả xử lý
- Tránh nên lịch lần tiếp theo trước khi lần hiện tại hoàn thành
<!-- 
let count = 0;

function run() {
    count++;
    console.log(count);

    if (count < 3) {
        setTimeout(run, 1000);
    }
}

setTimeout(run, 1000);

console.log("Start");
 -->
Điểm cần nhớ: 
Nested setTimeout() chỉ tạo lần chạy tiếp theo khi cb hiện tại thực thi xong và đi đến lệnh setTimeout();
3.3. Điều chỉnh delay linh hoạt
Một ưu điểm của nested setTimeout() là có thể thay đổi thời gian chờ tuỳ theo kết quả của lần thực thi trước
<!-- 
let delay = 1000;

function run() {
    console.log("Running...");

    delay *= 2;

    if (delay <= 8000) {
        setTimeout(run, delay);
    }
}

setTimeout(run, delay);
 -->
| Lần chạy | Delay trước khi chạy |
| -------- | -------------------- |
| 1        | 1000ms               |
| 2        | 2000ms               |
| 3        | 4000ms               |
| 4        | 8000ms               |
Sau lần thứ 4 , delay tăng nên 1600ms nên không tạo ra timer mới
Ứng dụng thực tế: Khi gọi API thất bại , bạn có thể tăng thời gian chờ trước mỗi lần thử lại, tránh gửi request liên tục đến server

4. Zero delay setTimeout
Bạn có thể truyên 0 vào setTimeout();
<!-- 
setTimeout(() => {
    console.log("Hello");
}, 0);

console.log("World");
 -->
Kết quả:
World
Hello
Bởi vì setTimeout(fn, 0) không có nghĩa là thực thi ngay lập tức
Nó có nghĩa là callback được nên lịch thực thi ở cơ hội sớm nhất sau khi JS hoàn thành công việc hiện tại 
4.1. Cách hoạt động
<!-- 
console.log("Start");

setTimeout(() => {
    console.log("Timer");
}, 0);

console.log("End");
 -->
Thứ tự thực thi:
1. In Start.
2. Đăng ký timer với delay 0.
3. Tiếp tục in End.
4. Sau khi đoạn code hiện tại hoàn thành, callback được thực thi và in Timer.

4.2. So sánh với lời gọi hàm thông thường
<!-- 
function sayHi() {
    console.log("Hello");
}

sayHi();

setTimeout(sayHi, 0);

console.log("World");
 -->
sayHi() gọi hàm ngay lập tức.
setTimeout(sayHi, 0) lên lịch gọi hàm sau.
console.log("World") chạy trước callback của timer.
Ứng dụng: Có thể dùng setTimeout(fn, 0) để trì hoãn một công việc đến sau khi đoạn JavaScript hiện tại hoàn thành. Tuy nhiên, nó không đảm bảo callback chạy ngay lập tức.
<!-- 
console.log("A");

setTimeout(() => {
    console.log("B");
}, 0);

console.log("C");

setTimeout(() => {
    console.log("D");
}, 0);

console.log("E");
 -->
Bước 6: Khi đoạn code đồng bộ hoàn thành, các callback timer lần lượt được thực thi: B, rồi D.
Ghi nhớ
Trong ví dụ này:
- Code đồng bộ chạy trước.
- Callback của setTimeout(..., 0) chạy sau.
- - Các timer được đăng ký theo thứ tự sẽ được xử lý theo thứ tự tương ứng khi cùng đủ điều kiện chạy.

4. Garbage collection and timers
4.1. Timer giữ tham chiếu đến callback
Khi truyền 1 funtion đến setTimeout() hoặc setInterval() bộ lập lịch scheduler sẽ giữ 1 tham chiếu nội bộ đến function đó
Điều này không có nghĩa là functioon k bị GC thu hồi trong khi timer vẫn còn đó
Ví dụ :
<!-- 
setTimeout(function() {
    console.log("Hello");
}, 1000);
 -->
Mặc dù chúng ta không lưu function vào biến:
nhưng function vẫn tồn tại trong bộ nhớ vì schedule đang giữ tham chiếu đến nó
4.2. Ảnh hưởng đến Lexical Environment
Một function có thể tham chiếu đến các biến thuộc môi trường bên ngoiaf 
<!-- 
function createTimer() {
    let user = {
        name: "Martin",
        age: 27
    };

    setInterval(() => {
        console.log(user.name);
    }, 1000);
}

createTimer();
 -->
Sau khi createTimer() kết thúc, bạn có thể nghĩ rằng biến user sẽ bị giải phóng.
Nhưng thực tế :
1. createTimer() kết thúc.
2. Callback của setInterval() vẫn được schedule giữ lại
3. Callback vẫn truy cập được user.name.
4. Vì vậy , obj của user vẫn giữ trong memory

4.3. Vì sao cần clearInterval?
Với setInterval(), callback tiếp tục được scheduler giữ lại cho đến khi chúng ta gọi clearInterval().


<!-- 
function createTimer() {
    let user = {
        name: "Martin"
    };

    let timerId = setInterval(() => {
        console.log(user.name);
    }, 1000);

    return timerId;
}

const timerId = createTimer();

// Khi không cần timer nữa
clearInterval(timerId);
 -->
 Sau khi hủy interval, schedule không còn cần giữu cb đó nữa . Nếu không còn tham chiếu nào khác đến cb
 và môi trường liên quan, chúng có thể bị GC thu hồi
 Lưu ý: setTimeout() cũng giữ callback cho đến khi callback được thực thi hoặc timer bị hủy. Sau khi callback chạy xong, tham chiếu nội bộ của timer có thể được giải phóng.
****************************************************************************************************************************

| Nội dung              | Ghi nhớ                                                     |
| --------------------- | ----------------------------------------------------------- |
| `setTimeout()`        | Lên lịch chạy một lần                                       |
| `clearTimeout()`      | Hủy timeout                                                 |
| `setInterval()`       | Lên lịch chạy lặp lại                                       |
| `clearInterval()`     | Hủy interval                                                |
| Nested `setTimeout()` | Lên lịch lần tiếp theo sau khi callback hiện tại hoàn thành |
| `setTimeout(fn, 0)`   | Trì hoãn callback đến sau công việc đồng bộ hiện tại        |
