1. Code blocks
1.1. Block scope là gì?
Trước tiên hãy hiể scope
Scope ( phạm vi biến): là khu vực trong code mà tại đó chúng ta có thể truy cập và sử dụng 1 biến
Ví dụ :
<!-- 
{
    let message = "Hello JavaScript";
    console.log(message); // Hello JavaScript
}

console.log(message); // ReferenceError
 -->
 Vì message được khai báo bên trong {} nên chỉ có thể sử dụng bên trong block đó
 Đây gọi là block scope
 1.2. Nhiều block có thể sử dụng cùng tên biến
 <!-- 
 {
    let message = "Hello";
    console.log(message);
}

{
    let message = "Goodbye";
    console.log(message);
}
  -->
Hello
Goodbye
Không có lỗi vì mỗi block là 1 pham vi riêng
1.3. Block scope trong if, for và while
Các biến khai báo bằng let hoặc const bên trong những block này chỉ tồn tại trong phạm vi block tương ứng
Ví dụ với if:
<!-- 
if (true) {
    let user = "Martin";

    console.log(user); // Martin
}

console.log(user); // ReferenceError
 -->
Ví dụ với for:
<!-- 
for (let i = 0; i < 3; i++) {
    console.log(i);
}

console.log(i); // ReferenceError
 -->
 Biến i chỉ tồn tại trong phạm vi vòng lặp
1.4. Tại sao kiến thức này quan trọng?
Trong React bạn thường xuyên sử dụng block scope 
<!-- 
function UserProfile({ user }) {
    if (!user) {
        const message = "User not found";
        return <p>{message}</p>;
    }

    return <h1>{user.name}</h1>;
}
 -->
 Biến message chỉ cần thiết trong nhánh if  nên không cần tồn tại bên ngoài 
 Bài tập nhỏ 1
 <!-- 
 let name = "Martin";

if (true) {
    let name = "John";
    console.log(name);
}

console.log(name);
  -->
((Ghi nhớ: Khi có nhiều biến cùng tên trong các scope lồng nhau , JS ưu tiên biến ở scope gần nhất

2. Nested functions
2.1. Nested function là gì?
Nested function là 1 function đượuc khai báo bên trong 1 function khác
<!-- 
function sayHello() {
    let message = "Hello";

    function showMessage() {
        console.log(message);
    }

    showMessage();
}

sayHello();
 -->
Kết quả: Hello
Ở đây:
-sayHello() là outer function
-showMessage() là inner funtion
-showMessage() có thể truy cấp biến message của outer funcion
2.2.Function bên trong có thể truy cập biến bên ngoài
<!-- 
function outer() {
    let name = "Martin";

    function inner() {
        console.log(name);
    }

    inner();
}
outer();
 -->
 Kết quả : Martin
 Điểm quan trọng : inner() không khai báo biến name , nhưng vẫn có thể sử dụng biến đó từ scope bên ngoài
 Đây là nền tảng để hiểu Lecical Enviroment và Closure ở phần tiếp theo
 2.3.Nested function có thể trả về từ outer function
 <!-- 
 function makeCounter() {

const counter = makeCounter();

  -->
Hãy chú ý:
1. makeCounter() tạo biến count = 0;
2. Function increment được tạo bên trong makeCounter
3. makeCounter() trả về increment
4. Biến counter nhận function đó
5. Mỗi lần gọi counter() , biến count lại tăng nên
(( : Tại sao makeCounter chạy xong nhưng counter() vẫn truy cập và thay đổi biến count
Bài tập nhỏ 2:

outer();

3. Lexical Environment
Đây là phần quan trọng nhất của bài Closure
3.1. Lexical Enviroment là gì ?
Mỗi khi JS chạy code , nó sử dụng 1 cơ chế nội bộ là Lexical Environment để quản lý các biến và cách tìm kiếm chúng
Một Lexical scope bao gồm 2 thành phần :
Lexical Environment
│
├── Environment Record
│   └── Lưu trữ các biến và function trong phạm vi hiện tại
│
└── Outer Lexical Environment
    └── Tham chiếu đến môi trường bên ngoài
Ví dụ:
<!-- 
let name = "Martin";

function sayHello() {
    let message = "Hello";

    console.log(message, name);
}

sayHello();
 -->
Có thể hình dung môi trường như sau :
Global Lexical Environment
│
├── name = "Martin"
├── sayHello = function
│
└── sayHello() được gọi
    │
    └── Function Lexical Environment
        ├── message = "Hello"
        └── Outer → Global Lexical Environment
Khi sayHello() thực hiện:
1. JS tìm message trong môi trương của sayHello() => tìm thấy
2. JS tìm name trong môi trường sayHello() => không tìm thấy
3. Tiếp tục tìm môi trường bên ngoài (global) => tìm thấy Martin
((: Điểm cần nhớ : JS tìm biến từ phạm vi hiện tại ra phạm vi bên ngoài , chứ không tìm ngược từ bên ngoài vào trong
Bài tập nhỏ:
<!-- 
let a = 10;

function outer() {
    let b = 20;

    function inner() {
        let c = 30;

        console.log(a, b, c);
    }

    inner();
}

outer();
 -->
 | Biến | JavaScript tìm ở đâu?         | Giá trị |
 | ---- | ----------------------------- | ------- |
 | `a`  | Global Lexical Environment    | 10      |
 | `b`  | `outer()` Lexical Environment | 20      |
 | `c`  | `inner()` Lexical Environment | 30      |

Quy tắc tìm kiếm :
inner()
  │
  ├── Tìm c → thấy ngay trong inner
  │
  ├── Tìm b → không thấy, đi ra outer
  │
  └── Tìm a → không thấy, đi ra global
3.2.Function declaration trong Lexical Enviroment
Khi JS tạo Lexical Enviroment , các Function Declaration được khởi tạo ngay từ đầu môi trường
Ví dụ:
<!-- 
sayHello();

function sayHello() {
    console.log("Hello");
}
 -->
Vì JS đã khởi tạo sayHello khi tạo Lexical Enviroment , trước khi thực thi từng dòng code
Bài tập nhỏ:
<!-- 
function sayHello() {
    console.log("Hello");
}

function outer() {
    sayHello();

    function sayHello() {
        console.log("Hi");
    }
}

outer();
 -->
Vì khi gọi sayHello() bên trong outer(), JavaScript tìm biến theo thứ tự:
1. Tìm sayHello trong Lexical Environment của outer().
2. Tìm thấy function sayHello() được khai báo bên trong outer().
3. Gọi function đó và in ra Hi.

JS không đi ra global nữa vì đã tìm thấy trong function hiện tại
Đây là cơ chế Shadowing: biến hoặc function ở phạm vi bên trong che khuất tên tương ứng ở phạm vi bên ngoài
Global
│
└── sayHello() → "Hello"
    │
    └── outer()
        │
        └── sayHello() → "Hi"  ← được ưu tiên
3.3. Inner và Outer Lexical Environment
Bây giờ kết hợp 2 kiến thức :
Funtion có lexical Enviroment riêng khi được gọi 
Function tìm biến từ môi trường hiện tại ra môi trương bên ngoài 
Xem ví dụ :
<!-- 
let phrase = "Hello";

function say(name) {
    console.log(phrase + ", " + name);
}

say("Martin");
 -->
 Global Lexical Environment
│
├── phrase = "Hello"
├── say = function
│
└── say() Lexical Environment
    ├── name = "Martin"
    └── Outer → Global
Khi thực hiện console.log:
-phrase:không có trong môi trường say() => tìm global();
-name : có ngay trong môi trường say()
Kết quả: Hello, Martin.
((Lưu ý: Function tìm biến dựa trên nơi nó được khai báo , không phải nơi nó được gọi . Đây chính là nền tảng hiểu closure
* Bài tập :
<!-- 
let name = "Global";

function outer() {
    let name = "Outer";

    function inner() {
        console.log(name);
    }

    return inner;
}

let fn = outer();

fn();
 -->
Giải thích:
1. outer() tạo biến name = "Outer".
2. inner() được khai báo bên trong outer(), nên nó ghi nhớ môi trường nơi nó được tạo.
3. outer() trả về inner và kết thúc.
4. fn() gọi lại inner().
5. Khi tìm name, JavaScript tìm trong môi trường của inner, không thấy, sau đó tìm trong môi trường của outer và tìm thấy "Outer".
Điểm quan trọng: inner() vẫn truy cập được biến name của outer() dù outer() đã kết thúc
Đây chính là hiện tượng chúng ta sẽ tìm hiểu sâu hơn ở phần tiếp theo.
3.4. Returning a function – Closure
<!-- 
function makeCounter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}

let counter = makeCounter();

console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
 -->
Thông thường bạn có thể nghĩ răngf makeCounter() kết thúc thì biến count cũng sẽ mất
Nhưng thực tế , function trả về vẫn cần sử dụng biến count , nên JS giữ lại môi trường cần thiết để funtion đó hoạt động 
[[Environment]] là gì?
Khi function được tạo , JS gắn nó với 1 tham chiếu nội bộ có tên [[Environment]].
Tham chiếu này trỏ đến Lexical Environment tại nơi function được khai báo
<!-- 
function outer() {
    let name = "Martin";

    function inner() {
        console.log(name);
    }

    return inner;
}

let fn = outer();
 -->
Có thể hình dung:
Global
│
├── outer
│
└── fn
    │
    └── inner function
        │
        └── [[Environment]]
            │
            └── outer Lexical Environment
                └── name = "Martin"
Khi gọi fn() , function vẫn có thể tìm thấy name
Closure là gì?
Closure là sự kết hợp giữa một function và môi trường Lexical Environment mà function đó ghi nhớ
Nói đơn giản:
Closure cho phép 1 function tiếp tục truy cập vào các biến thuộc phạm vi bên ngoài , ngay cả khi function bên ngoài đã kết thúc
Bài tập nhỏ :
<!-- 
function createUser() {
    let name = "Martin";

    return function () {
        name = "John";
        console.log(name);
    };
}

const user = createUser();

user();
user();
 -->
 Giải thích thêm một điểm quan trọng:
- Lần 1: user() tìm thấy name = "Martin" trong môi trường của createUser(), sau đó đổi thành "John".
- Lần 2: user() vẫn truy cập cùng môi trường đó. name đã mang giá trị "John" từ lần gọi trước nên tiếp tục in "John".
((Chú ý : Closure không tạo bản sao biến mỗi lần gọi . Nó giữ quyền truy cập vào cùng binding(biến) trong Lexical Enviroment
Tổng kết phần 3 – Lexical Environment
LEXICAL ENVIRONMENT
│
├── 1. Environment Record
│   └── Lưu các biến và function trong phạm vi
│
├── 2. Outer Lexical Environment
│   └── Tham chiếu đến phạm vi bên ngoài
│
├── 3. [[Environment]]
│   └── Function ghi nhớ môi trường nơi nó được tạo
│
└── 4. Closure
    └── Function + môi trường bên ngoài mà nó truy cập

4. Garbage collection
4.1. Lexical Environment được giải phóng khi nào?
<!-- 
function sayHello() {
    let message = "Hello";
    console.log(message);
}

sayHello();
 -->
Sau khi sayHello() kết thúc :
Không còn functioon nào cần truy cập message
Môi trường sayHello() không còn được sử dụng 
Nó có thể được GC thu hồi bộ nhớ
Nhưng với Closure:
<!-- 
function makeCounter() {
    let count = 0;

    return function () {
        count++;
        console.log(count);
    };
}

const counter = makeCounter();

counter(); // 1
counter(); // 2
 -->
 makeCounter() đã kết thúc
 Nhưng counter vẫn tham chiếu đến function bên trong nó
Function bên trong vẫn dùng count
Vì vậy môi trường count vẫn cần giữ lại 
Quy tắc: Một Lexical Environment chỉ có thể được Garbage Collector thu hồi khi không còn được tham chiếu và không thể truy cập được nữa.
Bài tập nhỏ :
<!-- 
function createMessage() {
    let message = "Hello";

    return function () {
        console.log(message);
    };
}

let fn = createMessage();

fn();

fn = null;

 -->
 Lưu ý: GC không nhất thiết chạy ngay tại dòng fn = null. JavaScript sẽ thu hồi khi cần và khi môi trường không còn được sử dụng.
 4.2. Closure giữ biến trong bộ nhớ
 <!-- 
 function f() {
    let value = 123;

    return function () {
        console.log(value);
    };
}

let g = f();

g(); // 123
  -->
Ở đây:
- f() kết thúc.
- g giữ function bên trong.
- Function bên trong cần value.
- Vì vậy, value vẫn được giữ lại.
Nhưng nếu không còn g:
g = null;
Thì môi trường chưa value có thể được giải phóng nếu không còn tham chiếu khác
<!-- 
function makeFunctions() {
    let a = 10;
    let b = 20;

    return function () {
        console.log(a);
    };
}

let fn = makeFunctions();
Theo bạn, khi fn còn tồn tại:
1. Biến a có cần được giữ lại không?
2. Biến b có cần được giữ lại không? Vì sao?
 -->
Bạn hiểu đúng ý chính:
- a = 10: Function bên trong sử dụng a, nên giá trị này cần được giữ lại để function hoạt động.
- b = 20: Function bên trong không sử dụng b, nên JavaScript Engine có thể tối ưu và không cần giữ nó trong bộ nhớ.

4.3. Real-life optimizations
JavaScript Engine có thể tối ưu bộ nhớ bằng cách loại bỏ những biến không cần thiết
<!-- 
function f() {
    let value = 123;
    let anotherValue = 456;

    return function () {
        console.log(value);
    };
}

let g = f();
 -->
Function trả về chỉ sử dụng value, không sử dụng anotherValue.
Vì vậy, Engine có thể tối ưu để không giữ anotherValue.
Lưu ý: Đây là tối ưu nội bộ của JavaScript Engine. Không nên dựa vào việc một biến không được hiển thị trong DevTools để kết luận chính xác thời điểm nó bị giải phóng.

* 6.1. Does a function pickup latest changes?
<!-- 
let name = "John";

function sayHi() {
    console.log("Hi, " + name);
}

name = "Pete";

sayHi();
 -->
 Theo bạn:
1. Kết quả in ra là gì?
2. Tại sao function sayHi() lại in giá trị đó?

Bước 1: Khai báo biến:
let name = "John";

Bước 2: Khai báo function sayHi().

Function ghi nhớ môi trường nơi nó được khai báo, trong đó có biến name.

Bước 3: Thay đổi giá trị:
name = "Pete";

Bước 4: Gọi function:
sayHi();
Khi chạy, function truy cập binding name hiện tại và nhận giá trị "Pete".
* 6.2. Which variables are available?
<!-- 
function makeWorker() {
    let name = "Pete";

    return function () {
        console.log(name);
    };
}

let name = "John";

let work = makeWorker();

work();
 -->
Theo bạn:
1. Kết quả là John hay Pete?
2. Tại sao function work() không lấy biến name ở Global Scope?
Global Lexical Environment
│
├── name = "John"
├── makeWorker
└── work
    │
    └── Inner Function
        │
        └── [[Environment]]
            │
            └── makeWorker Lexical Environment
                └── name = "Pete"
Khi work() chạy:
1. Tìm name trong môi trường của function bên trong.
2. Không tìm thấy.
3. Đi ra môi trường makeWorker().
4. Tìm thấy name = "Pete".
5. Dừng tìm kiếm, không cần tìm đến Global.
Ghi nhớ: Lexical Scope phụ thuộc vào nơi function được khai báo, không phụ thuộc vào nơi function được gọi.

* 6.3. Are counters independent?
<!-- 
function makeCounter() {
    let count = 0;

    return function () {
        return count++;
    };
}

let counter1 = makeCounter();
let counter2 = makeCounter();

console.log(counter1());
console.log(counter1());

console.log(counter2());
console.log(counter2());
 -->
Câu hỏi:
1. Kết quả của 4 lần gọi là gì?
2. Tại sao counter1 và counter2 có thể có giá trị count riêng biệt dù cùng được tạo từ makeCounter()?
   
Mỗi lần gọi makeCounter() là một lần tạo ra Lexical Environment mới.
let counter1 = makeCounter(); // count = 0 (môi trường 1)
let counter2 = makeCounter(); // count = 0 (môi trường 2)

Kiến thức phỏng vấn: Mỗi lần gọi một function tạo ra một execution context và môi trường từ vựng tương ứng. Nếu function trả về một closure, closure đó có thể giữ lại môi trường riêng của lần gọi ấy.

- down() giảm giá trị đếm đi 1.
- Giá trị ban đầu là 0.
Yêu cầu: Dùng Closure để quản lý biến count, không cho phép truy cập trực tiếp từ bên ngoài.

Điểm quan trọng: Đây là một ứng dụng thực tế của Closure: đóng gói dữ liệu và kiểm soát cách dữ liệu được truy cập hoặc thay đổi (Data Privacy).

6.7. Is variable visible?
<!--

    console.log(x);

 -->
Theo bạn:
1. Kết quả là 1, 2 hay lỗi?
2. Tại sao JavaScript không lấy x = 1 ở Global Scope?

Khi gọi func():
1. JavaScript tạo Lexical Environment cho func().
2. Biến x cục bộ được tạo nhưng chưa được khởi tạo.
3. JavaScript chạy console.log(x).
4. Nó tìm thấy x trong phạm vi func(), nhưng x đang trong TDZ.
5. JavaScript báo ReferenceError, không tiếp tục tìm x ở Global Scope.
Ghi nhớ:
- let và const được tạo khi Lexical Environment được thiết lập.
- Nhưng chỉ được khởi tạo khi luồng thực thi đi đến dòng khai báo.
- Trước thời điểm đó, biến nằm trong TDZ.

6.9. Sort by field
Bài tiếp theo yêu cầu viết hàm byField(field) để sắp xếp object theo một thuộc tính bất kỳ.
<!-- 
let users = [
    { name: "John", age: 20 },
    { name: "Pete", age: 18 },
    { name: "Mary", age: 25 }
];

users.sort(byField("name"));
// Mary, John, Pete

users.sort(byField("age"));
// Pete, John, Mary
 -->
 function byField(field) {
    return function (a, b) {
        return a[field] > b[field] ? 1 : -1;
    };
}

let users = [
    { name: "John", age: 20 },
    { name: "Pete", age: 18 },
    { name: "Mary", age: 25 }
];

users.sort(byField("name"));
console.log(users);

users.sort(byField("age"));
console.log(users);
