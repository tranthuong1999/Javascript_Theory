1. "var" has no block scope
1.1. Ôn lại block scope
let và const : có phạm vi trong block scope {}
var: không có block scope mà có function scope hoặc function scope
<!-- 
if (true) {
    let message = "Hello";
}

console.log(message); // ReferenceError
 -->
Vì message chỉ tồn tại bên trong block if
Bây giờ thử thay bằng var:
<!-- 
if (true) {
    var message = "Hello";
}

console.log(message); // Hello
 -->
Vì var không bị giới hạn bởi block scope của if . Biến vẫn có thể được truy cập bên ngoài scope đó
1.2. So sánh trực quan
<!-- 
function test() {
    if (true) {
        let a = 10;
        var b = 20;
    }

    console.log(a); // ReferenceError
    console.log(b); // 20
}

test();
 -->
 | Biến        | Phạm vi               |
 | ----------- | --------------------- |
 | `a` (`let`) | Chỉ trong block `if`  |
 | `b` (`var`) | Trong function `test` |
 Lưu ý : không có nghĩa là biến luôn trở thành global .Nếu khai báo bên trong function , nó thuộc pham vi của function đó
 1.3. Bài tập nhỏ
 <!-- 
 function test() {
    if (true) {
        var name = "Martin";
        let age = 27;
    }

    console.log(name);
    console.log(age);
}

test();
  -->
var name có function scope nên vẫn truy cập được bên ngoài block if nhưng bên trong function test
let age: có block scope , chỉ tồn tại bên trong {} của if
function test()
│
├── var name = "Martin"  ← function scope
│
└── if (true)
    └── let age = 27     ← block scope
1.4. Thử thêm một trường hợp
<!-- 
function test() {
    if (true) {
        var a = 10;
    }

    if (true) {
        var a = 20;
    }

    console.log(a);
}

test();
 -->
 Cả 2 lần khai báo biến a đều nằm trong cùng function test . Vì var có function scope nên chúng cùng tham chiếu đến biến a
 Diễn biến:
 <!-- 
 function test() {
    if (true) {
        var a = 10; // a = 10
    }

    if (true) {
        var a = 20; // a được gán lại thành 20
    }

    console.log(a); // 20
}
  -->
Lưu ý: var a = 20 ở đây không tạo ra biến a mới . Nó khai báo lại cùng biến và gán giá trị mới
1.5. Sang phần tiếp theo: var trong vòng lặp
<!-- 
for (var i = 0; i < 3; i++) {
    console.log(i);
}

console.log(i);
 -->
 | Bước | Điều kiện / hành động        | Giá trị `i` |
 | ---- | ---------------------------- | ----------- |
 | 1    | Khởi tạo `var i = 0`         | 0           |
 | 2    | `i < 3` đúng → in ra         | 0           |
 | 3    | Tăng `i++`                   | 1           |
 | 4    | `i < 3` đúng → in ra         | 1           |
 | 5    | Tăng `i++`                   | 2           |
 | 6    | `i < 3` đúng → in ra         | 2           |
 | 7    | Tăng `i++`                   | 3           |
 | 8    | `i < 3` sai → thoát vòng lặp | 3           |

Sau khi thoát vòng lặp i vẫn có giá trị 3 vì var không có block scope
Kiểm tra thêm: Nếu đổi var thành let?
<!-- 
for (let i = 0; i < 3; i++) {
    console.log(i);
}

console.log(i);
 -->

2. "var" tolerates redeclarations
2.1.var cho phép khai báo lại biến
Với var , bạn có thể khai báo 1 biến nhiều lần trong cùng scope mà không bị lỗi 
<!-- 
var user = "Martin";
var user = "John";

console.log(user); // John
 -->
 JS không báo lỗi . Lần khai bá thứ 2 chỉ đơn giản gán lại giá trị biến cho user
 2.2. Nhưng let thì không
 <!-- 
 let user = "Martin";
let user = "John"; // SyntaxError
  -->
Let không cho phép khai báo lại 1 biến trong cùng scope
Tuy nhiên, bạn vẫn có thể thay đổi giá trị:
<!-- 
let user = "Martin";
user = "John";

console.log(user); // John
 -->
Redeclaration: Khai báo lại biến.
Reassignment: Gán lại giá trị cho biến.
<!-- 
function test() {
    var a = 10;
    var a = 20;

    let b = 30;
    b = 40;

    console.log(a);
    console.log(b);
}

test();
 -->

Đây là phần quan trọng nhất của bài : Hoisting
3.1. Thử một ví dụ
<!-- 
console.log(name);
var name = "Martin";
 -->
 JS xử lý var theo cơ chế hoisting 
 tức là đưa phần khai báo biến var được đưa nên đầu phạm vi (scope) trước khi thực thi code
 Có thể hình dung JS xử lý như sau:
 <!-- 
 var name; // Khai báo được đưa lên đầu

console.log(name); // undefined

name = "Martin"; // Gán giá trị
  -->
3.2. Phân biệt Declaration và Assignment
Thực chất có 2 hành động :
| Thành phần        | Ý nghĩa                     |
| ----------------- | --------------------------- |
| `var name`        | Declaration – khai báo biến |
| `name = "Martin"` | Assignment – gán giá trị    |
3.3. So sánh với let
<!-- 
console.log(name);

let name = "Martin";
 -->
Vì let được hoisting nhưng k được khỏi tạo giá trị undefined như var . Biến nằm trong vùng TDZ cho đến khi dòng khai báo được thực thi
Ghi nhớ:
-var: được hoisting và được khỏi tại với giá trị undefined
let / const : Hoisting nhưng chưa được khỏi tạo , truy cập trước sẽ gây báo lỗi ReferenceError
Bài tập:
<!-- 

console.log(a);
console.log(b);

var a = 10;
var b = 20;

console.log(a);
console.log(b);
 -->
Điểm cần nhớ: Chỉ có phần khai báo var a, var b được hoisting, không phải giá trị gán 10, 20.
3.4. Một trường hợp dễ nhầm lẫn
<!-- 

function sayHi() {
    console.log("Hello");

    var message = "Martin";
}

sayHi();

console.log(message);
 -->
Điểm quan trọng:Hoisting k làm biến var thoát khỏi scope của nó . Nó chỉ đưa phần khai báo lên đầu scope tương ứng
3.5. Kiểm tra thêm về Hoisting
<!-- 
function test() {
    console.log(a);

    if (false) {
        var a = 10;
    }

    console.log(a);
}

test();
 -->
 cách xử lý như sau:
 function test() {
    var a; // Hoisting, khởi tạo undefined

    console.log(a); // undefined

    if (false) {
        a = 10; // Không chạy vì điều kiện false
    }

    console.log(a); // undefined
}
Ghi nhớ
- var được hoisting lên đầu function.
- var bên trong if, for vẫn thuộc function scope.
- Dù khai báo nằm trong if (false), biến vẫn được hoisting.
- Nhưng phép gán a = 10 không chạy vì điều kiện false.
<!-- - 
function test() {
    var x; // undefined

    if (false) {
        x = 100; // Không chạy
    }

    console.log(x); // undefined
}
 -->
 Hoisting chỉ đưa phần khai báo lên đầu scope , không đưa cả phép gán nên đầu scope

4. IIFE (Immediately Invoked Function Expressions)
4.1. IIFE là gì?
IIFE là 1 function đượuc khai báo dưới dạng expression và được gọi ngay sau khi tạo 
Ví dụ:
<!-- 
(function () {
    console.log("Hello Martin!");
})();
 -->
 Hello Martin!
 Phân tích:
 <!-- 
 (function () {
    // Function body
})();
  -->
(function() { ... }) biến function declaration thành function expression.
() cuối cùng: gọi function ngay lập tức
4.2. Tại sao trước đây cần IIFE?
Trước khi let , const xuất hiện  JS chủ yếu sử dụng var
Vì var không có block scope nên người ta dùng IIFE để tạo 1 function scope riêng , tránh làm ảnh hườnge đến
các biến bên ngoài
VÍ dụ :
<!--  
(function () {
    var message = "Hello";
    console.log(message);
})();

console.log(message); // ReferenceError
-->
Biến message chỉ tồn tại bên trong IIFE 
Ngày nay thuơngf dùng {} kết hợp với let hoặc const để tạo block scope riêng thay vì IIFE
Bài tập nhỏ:
<!-- 
let name = "Martin";

(function () {
    let name = "John";
    console.log(name);
})();

console.log(name);
 -->
Giải thích:
- let name = "Martin" thuộc Global Scope.
- IIFE tạo một function scope riêng.
- let name = "John" bên trong IIFE là biến cục bộ, không ghi đè biến bên ngoài.
- Khi IIFE kết thúc, biến name = "John" không còn được truy cập từ bên ngoài.
Minh họa:
<!-- 
Global Scope
│
├── name = "Martin"
│
└── IIFE
    └── name = "John"
 -->
4.3. Một cách viết IIFE khác
IIFE có thể viết bằng nhiều cách:
<!-- 
(function () {
    console.log("Hello");
})();
hoặc 
(function () {
    console.log("Hello");
}());
 -->
Chú ý : IIFE tạo một function scope riêng và thực thi ngap lập tức
****************************************************************************************************************************
5. Summary – Tổng kết bài The old "var"
   
   | Đặc điểm                 | `var`                    | `let`   | `const` |
   | ------------------------ | ------------------------ | ------- | ------- |
   | Block scope              | Không                    | Có      | Có      |
   | Function scope           | Có                       | Có      | Có      |
   | Redeclaration cùng scope | Có                       | Không   | Không   |
   | Reassignment             | Có                       | Có      | Không   |
   | Hoisting                 | Có, khởi tạo `undefined` | Có, TDZ | Có, TDZ |
Những điểm quan trọng cần nhớ:
1. var không có block scope
2. var cho phép khai báo lại trong cùng scope
3. var được hoisting và khởi tạo bằng undefined
4. let và const cũng được hoisting nhưng trong TDZ khi khái báo thực thi
5. IIFE dùng để tạo function scope và thực thi function ngay lập tức
