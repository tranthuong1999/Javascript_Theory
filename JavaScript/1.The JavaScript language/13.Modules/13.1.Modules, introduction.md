4.1. What is a module?
4.1.1. Tại sao cần Module?
Khi ứng dụng phát triển lớn hơn , chúng ta muốn chia code thành nhiều file , gọi là Modules
Một module có thể chứa :
- Một class
- Một thư viện các function để phục vụ mục đích cụ thể
4.1.2. Module là gì?
Một module đơn giản là 1 file . Một script tương ứng với một module
Các module có thể tải lẫn nhau và sử đụng hai từ khoá
export : đánh dấu biến hoặc function muốn cho phép sử dụng bên ngoài của module hiện tại 
import : nhập chức năng hoặc export từ module khác
4.1.3. Ví dụ trong tài liệu gốc
Giả sử có file sayHi.js:
<!-- 
// sayHi.js
export function sayHi(user) {
    alert(`Hello, ${user}!`);
}
 -->
File khác là main.js:
<!-- 
// main.js
import { sayHi } from './sayHi.js';

alert(sayHi);
sayHi('John');
 -->
Giải thích :
- export cho phép function sayHi được truy cập từ module khác.
- import nhập function đó vào main.js.
- './sayHi.js' là đường dẫn tương đối đến file module.
- Sau khi import, chúng ta có thể sử dụng sayHi() như một function bình thường.

4.1.4. Vì sao phải có type="module"?
Với trình duyệt , nếu muốn sử dung import/export , chúng ta phải thông báo rằng script là Module bằng thuộc tính
Ví dụ:
<!-- 
<script type="module">
    import { sayHi } from './say.js';

    document.body.innerHTML = sayHi('John');
</script>
 -->
Nếu không khai báo type="module" , trình duyệt sẽ không xử lý script theo cơ chế Module như ví dụ trên
Module chỉ hoặt động qua HTTP(S), không hoạt động trực tiếp qua giao thức file://.
Nếu mở file trực tiếp từ máy tính , các lệnh import/export có thể không hoạt động
4.1.5. Bổ sung ngoài tài liệu gốc – trường hợp dễ nhầm
Trường hợp 1: Import phải đúng đường dẫn
<!--

 -->
./: thư mục hiện tại.
../: thư mục cha.
Đường dẫn tương đối trong ví duj trình duyệt phải xác định được file cần tải

Trường hợp 2: export không tự động đưa biến thành global
<!-- let user = 'John'; -->

Trường hợp 3: type="module" và công cụ build
bạn thường viết import/export trực tiếp trong file JavaScript. Công cụ build với moii trường chạy sẽ xử lý các module cho ứng dụng . Không nên nhầm ví dụ HTML thuần trong bài với toàn bộ quy trình

4.2. Core module features
Trong module, giá trị this ở cấp cao nhất (top-level this) là undefined.
1. Ví dụ trong tài liệu gốc
Tài liệu so sánh regular script với module script
Regular script:
<!-- 
<script>
  alert(this); // window
</script>
 -->
Kết quả : this là đối tượng global window
Module script:
<!-- 

<script type="module">
  alert(this); // undefined
</script>
 -->
 Kết quả : this là undefined
 2. So sánh
| Đặc điểm                  | Regular script               | Module script |
| ------------------------- | ---------------------------- | ------------- |
| Top-level `this`          | `window` (trong browser)     | `undefined`   |
| Strict mode mặc định      | Không                        | Có            |
| Phạm vi biến cấp cao nhất | Global scope (trong browser) | Module scope  |

Bổ sung ngoài tài liệu gốc – trường hợp dễ nhầm
Không nên nhầm top-level this với this bên trong function hoặc method.
<!-- 
// module.js
console.log(this); // undefined

const user = {
  name: "John",
  sayHi() {
    console.log(this.name);
  }
};

user.sayHi(); // John
 -->
this trong sayHi() vẫn là object user , vì nó phụ thuộc vào cách gọi funcion , không phải vì module hay regular script

4.3. Browser-specific features
Module scripts are deferred
Mục tiêu : Hiểu thời điểm trình duyệt thực thi module script và sự khác biệt so với regular script.

1. Module scripts được defer mặc định
Khi trình duyệt gặp:
<!-- <script type="module" src="./main.js"></script> -->
Trình duyệt sẽ:
1. Tải module script song song với quá trình phân tích HTML , không chặn HTML parsing
2. Chờ cho đến khi tài liệu HTML được phân tích xong
3. Thực thi module script
4. Giữ thứ tự thực thi theo thứ tự xuất hiện trong HTML đối với các module script thông thường.
Điểm quan trọng: Module script mặc định có hành vi tương tự defer của regular script 

2. So sánh với regular script
Regular script không có defer:
<!-- <script src="./main.js"></script> -->
Trình duyêt dùng phân tích HTML để tải và thực thi script
Nếu script truy cập đến một phần tử HTML nằm phía sau nó phần tử đó có thể chưa tồn tại 

Module script:
<!-- <script type="module" src="./main.js"></script> -->
Không chặn HTML parsing trong lúc tải.
Chờ HTML parsing hoàn tất mới thực thi.
Có thể truy cập các phần tử HTML nằm phía sau thẻ script.
3. Lưu ý từ tài liệu
Vì module script được thực thi sau khi HTML parsing được hoàn tất , trang web của có thể hiển thị nội dung HTML
trước khi JS của ứng dụng chạy song
Do đó, nếu ứng dụng cần JavaScript để hiển thị nội dung chính, có thể cần hiển thị trạng thái loading trong thời gian chờ.

* Kiểm tra kiến thức
Giả sử HTML:
<head>
  <script type="module" src="./main.js"></script>
</head>
<body>
  <div id="app">Hello</div>
</body>


Trong main.js:
const app = document.querySelector("#app");

console.log(app.textContent);

Kết quả nào đúng?

A. Lỗi vì #app chưa được tạo khi trình duyệt gặp thẻ script.

B. In ra Hello, vì module script mặc định được defer cho đến khi HTML parsing hoàn tất.

C. Không chạy vì module script bắt buộc phải đặt trong body.

D. Chạy ngay khi tải xong, bất kể HTML parsing đã hoàn tất hay chưa.

Module script mặc định có hành vi defer:
1. Trình duyệt tiếp tục phân tích HTML trong lúc tải module.
2. HTML parsing hoàn tất.
3. Module script mới được thực thi.
4. Lúc này #app đã tồn tại nên querySelector() tìm thấy phần tử.
Bạn nhớ quy tắc này nhé: Module script mặc định defer, nhưng không có nghĩa là tải xong thì chạy ngay.

4.3. Browser-specific features
Tiếp theo là đặc điểm async đối với module script.
1. Regular script và async
Với regular script, async thường được sử dụng trên script bên ngoài:
<!-- <script async src="./script.js"></script> -->
script sẽ được thực thi ngay khi tải xong , không cần chở HTML parsing hoàn tất
2. Module script hỗ trợ async trên cả inline script
Với module script , bạn có thể sử dụng async ngay cả khi viết code bên trong thẻ script
<!-- 
<script type="module" async>
  import { loadData } from "./data.js";

  loadData();
</script>
 -->
Khi sử dụng async:
- Module script và các dependency của nó tải được 
- Script thực thi ngay khi tất cả depeendecy đã sẵn sàng
- Không chờ HTML parsing hoàn tất
- Không đảm bảo thứ tự thực thi với script khác

3. Khi nào sử dụng?
Theo tài liệu, async phù hợp với những module độc lập, không phụ thuộc vào HTML hoặc các script khác
Ví dụ:
- Bộ đếm (counter).
- Quảng cáo (advertisement).
- Các chức năng độc lập khác.

4. So sánh defer và async
| Đặc điểm               | Module mặc định               | Module có `async`                      |
| ---------------------- | ----------------------------- | -------------------------------------- |
| Tải script             | Song song với HTML parsing    | Song song với HTML parsing             |
| Thời điểm chạy         | Sau khi HTML parsing hoàn tất | Ngay khi module và dependency sẵn sàng |
| Thứ tự với script khác | Giữ thứ tự trong HTML         | Không đảm bảo                          |
Bổ sung ngoài tài liệu gốc – trường hợp dễ nhầm
async không có nghĩa là chạy song song với script khác , JS trên cùng 1 thread vẫn thực thi theo lần lượt ,
async ở đây quyết định thời điểm script được phép bắt đầu thực thi 
<!-- 
<script type="module" src="./app.js"></script>

<script type="module" async src="./analytics.js"></script>
 -->
Giả sử analytics.js tải xong trước app.js. Điều gì có thể xảy ra?

A. analytics.js phải chờ app.js vì mọi module đều giữ thứ tự HTML.
B. analytics.js có thể thực thi trước app.js.
C. Cả hai luôn thực thi đồng thời.
D. async chỉ hoạt động với regular script, không hoạt động với module script.
Ghi nhớ :
- Module mặc định: defer, giữ thứ tự.
- Module có async: chạy khi sẵn sàng, không đảm bảo thứ tự.

Phần này giải thích tại sao trình duyệt yêu cầu đường dẫn cụ thể khi import module.
1. Bare module specifier là gì?
<!-- import { sayHi } from "sayHi"; -->
"sayHi" được gọi là bare module specifier : tên module không có đường dẫn tương đối hoặc tuyệt đối

2. Cách viết được trình duyệt hỗ trợ
Relative path:
<!-- import { sayHi } from "./sayHi.js"; -->
Absolute path:
<!-- import { sayHi } from "/modules/sayHi.js"; -->
Full URL:
<!-- import { sayHi } from "https://example.com/modules/sayHi.js"; -->

<!-- import React from "react"; -->

HTML cung cấp thuộc tính nomodule để xử lý trường hợp này.

4.5. Summary
Theo phần Summary của tài liệu gốc, cần nắm 4 ý chính:
1. Module là một file: Trong browser cần khai báo type="module". Module có những đặc điểm riêng như defer mặc định, hỗ trợ async và yêu cầu CORS khi tải từ origin khác.
2. Module có scope riêng: Biến và function ở cấp cao nhất không tự động truy cập được từ module khác. Muốn chia sẻ phải dùng export và import.
3. Module luôn chạy ở strict mode: Không cần khai báo "use strict".
4. Module chỉ được đánh giá một lần: Những lần import tiếp theo sử dụng lại module đã được khởi tạo và các exports được chia sẻ.

Ngoài ra, browser tự động tải và xử lý các module được import . Trong production, dự án thường sử dụng bundler như Webpack
