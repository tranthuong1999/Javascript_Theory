4. The import() expression
4.1. Vì sao cần Dynamic Import?
Trong bài trước, chúng ta đã học các cú pháp:
<!-- 
import { sayHi } from './say.js';
 -->
export { sayHi };
Tài liệu gọi những câu lệnh này là Static Import và Static Export.
Chúng có cú pháp đơn giản và nghiêm ngặt , nhưng có 2 hạn chế :
Hạn chế 1: Không thể tạo đường dẫn import một cách động.
Ví dụ sau không hợp lệ:
<!-- import ... from getModuleName(); // Error -->
Lý do: Đường dẫn module phải là một chuỗi primitive, ko thể là kết quả gọi function
Ví dụ hợp lệ:
<!-- import { sayHi } from './say.js'; -->
Hạn chế 2: Không thể import có điều kiện hoặc tại thời điểm chạy (runtime).
Ví dụ không hợp lệ:
<!-- 
if (condition) {
  import { sayHi } from './say.js'; // Error
}
 -->
Hoặc:
<!-- 
{
  import { sayHi } from './say.js'; // Error
}
-->
4.2. Tại sao Static Import lại có những hạn chế này?
import và export được thiết kế để tạo cấu trúc nền tảng cho code.
Nhờ cấu trúc import/export cố định, các công cụ có thể:
- Phân tích cấu trúc code
- Gom các module thành một file bằng công cụ build
- Loại bỏ những export k đượuc sử dụng (Tree-shaking).

4.3. Sử dụng biểu thức import()
Tài liệu giới thiệu cú pháp:
<!-- import(module) -->
Biểu thức này :
1. Tải module được chỉ định 
2. Trả về một Promise
3. Promise resolve thành một module object chứa tất cả các export trong module đó

Điểm quan trọng: có thể gọi import() ở bất kỳ vị trí nào trong code
Ví dụ:
<!-- 
let modulePath = prompt('Which module to load?');

import(modulePath)
  .then(obj => {
    // obj là module object
  })
  .catch(err => {
    // Xử lý lỗi tải module
  });
 -->
Trong đó:
- modulePath : đường dẫn module cần tải
- .then(obj => ...): nhận module object khi tải thành công.
- .catch(err => ...): xử lý lỗi, ví dụ module không tồn tại 

Tài liệu cũng cho phép sử dụng await nếu đang ở bên trong 1 async function
<!-- let module = await import(modulePath); -->
4.4. Import Named Export bằng import()
Giả sử có file say.js
<!-- 
// say.js
export function hi() {
  alert('Hello');
}

export function bye() {
  alert('Bye');
}
-->
Có thể Dynamic import như sau :
<!-- 
let { hi, bye } = await import('./say.js');

hi();
bye();
 -->
Giải thích:
- import('./say.js') tải module và trả về Promise
- await chờ Promise hoàn thành
- Kết qủa là module object chứa các export 
- Destructuring lấy hi và bye từ object đó

4.5. Import Default Export bằng import()
Nếu say.js có Default Export:
<!-- 
// say.js
export default function() {
  alert('Module loaded (export default)!');
}
-->
Để truy cập Default Export , sử dụng thuộc tính Default của module object
<!-- 
let obj = await import('./say.js');

let say = obj.default;

say();
 -->
Hoặc viết ngắn hơn bằng destructuring:
<!-- 
let { default: say } = await import('./say.js');

say();
 -->
Điểm cần nhớ: Dynamic Import trả về module object , nên Default export được truy cập thông qua thuộc tính default

4.6. Ví dụ hoàn chỉnh trong tài liệu
File say.js:
<!-- 
export function hi() {
  alert('Hello');
}

export function bye() {
  alert('Bye');
}

export default function() {
  alert('Module loaded (export default)!');
}
 -->
File index.html:
<!-- 
<!doctype html>
<script>
  async function load() {
    let say = await import('./say.js');

    say.hi();
    say.bye();
    say.default();
  }
</script>

<button onclick="load()">Click me</button>
 -->
Khi người dùng click button:
1. Hàm load() được gọi 
2. import('./say.js') tải module.
3. await chờ module được tải xong
4. Sử dụng các export thông qua object say

Kết quả:
- say.hi() → Hello!
- say.bye() → Bye!
- say.default() → Module loaded (export default)!

4.7. Những lưu ý cuối cùng trong tài liệu
Lưu ý 1: Dynamic Import hoạt động trong regular script.
Không bắt buộc phải sử dụng :
<!-- <script type="module"> -->
Dynamic Import vẫn hoạt động trong regular script:
<!--  
<script>
  async function load() {
    const module = await import('./say.js');
    module.hi();
  }
</script>
 -->
Lưu ý 2: import() không phải function thông thường
Mặc dù nhìn giống function call
<!-- import('./say.js'); -->
Nhưng đây là một special syntax sủ dụng dấu ngoặc đơn , tương tụ super()
Vì vậy, không thể:
- Gán import vào 1 biến
- Sử dụng call() hoặc apply() với import.
Ví dụ không hợp lệ:
<!-- 
const load = import; // Không hợp lệ

import.call(null, './say.js'); // Không hợp lệ
 -->
Bổ sung ngoài tài liệu gốc — các trường hợp dễ nhầm
1. Static Import và Dynamic Import khác nhau về thời điểm sử dụng
<!-- 
// Static Import
import { hi } from './say.js';
// Dynamic Import
const module = await import('./say.js');
module.hi();
 -->
 Static Import được khai báo cố định trong cấu trúc module  Dynamic import có thể được gọi khi chương trình cần tải module
2. Không nhầm Promise với module object
<!-- const result = import('./say.js'); -->
result ở đây là Promise, chưa phải module object
Muốn lấy module object:
<!-- const module = await import('./say.js'); -->
3. Dynamic Import không cần đặt trong async function nếu dùng .then()
<!-- 
import('./say.js').then(module => {
  module.hi();
});
 -->
chỉ sử dụng await trong regular function thì function đó phải dược khai báo trong async
* Kiểm tra hiểu bài
Giả sử file user.js:
<!-- 
export const name = 'John';

export default class User {}

async function loadUser() {
  const module = await import('./user.js');

  console.log(module.name);
  console.log(module.default);
}
 -->
B. module là module object; module.name truy cập Named Export và module.default truy cập Default Export.
Giải thích :
import('./user.js') trả về Promise.
await chờ Promise hoàn thành và nhận module object
module.name truy cập Named export
module.default truy cập default export
Bạn đã nắm được phần quan trọng nhất của import().

5. Summary
| Nội dung          | Cần nhớ                                              |
| ----------------- | ---------------------------------------------------- |
| Static Import     | Không hỗ trợ đường dẫn động hoặc import có điều kiện |
| Dynamic Import    | `import(modulePath)`                                 |
| Giá trị trả về    | Promise                                              |
| Kết quả Promise   | Module object                                        |
| Named Export      | `module.name`                                        |
| Default Export    | `module.default`                                     |
| Sử dụng với await | `await import('./module.js')`                        |
| Sử dụng với then  | `import('./module.js').then(...)`                    |

 - Phù hợp với những module không cần thiết ngay khi ứng dụng khởi chạy.
| Ưu điểm             | Ý nghĩa                                              |
| ------------------- | ---------------------------------------------------- |
| Conditional loading | Chỉ tải module khi điều kiện được đáp ứng            |
| Lazy loading        | Chỉ tải module khi cần sử dụng                       |
| Giảm tải ban đầu    | Không phải tải tất cả module ngay từ đầu             |
| Tách code           | Có thể giúp bundler chia ứng dụng thành nhiều chunks |

Ví dụ: Chỉ tải chức năng xuất báo cáo khi người dùng bấm nút.
<!-- 
button.addEventListener('click', async () => {
    const module = await import('./report.js');

    module.exportReport();
});
 -->
Nếu người dùng không bấm nút , module report.js không cần tải thông qua lời gọi dynamic import này
3. Khi nào nên sử dụng?
| Trường hợp                              | Nên dùng       |
| --------------------------------------- | -------------- |
| Module luôn cần thiết khi ứng dụng chạy | Static Import  |
| Module chỉ dùng khi người dùng bấm nút  | Dynamic Import |
| Module chỉ dùng ở một route nhất định   | Dynamic Import |
| Module lớn, ít khi sử dụng              | Dynamic Import |
| Dependency cốt lõi của ứng dụng         | Static Import  |

4. Ví dụ thực tế trong React
Giả sử ứng dụng có trang Dashboard và chức năng xem biểu đồ chỉ xuất hiện khi người dùng mở tab Analytics.
Có thể dùng dynamic import thông qua React.lazy:
<!-- 
import { lazy, Suspense } from 'react';

const Analytics = lazy(() => import('./Analytics'));

function Dashboard() {
    return (
        <Suspense fallback={<p>Loading...</p>}>
            <Analytics />
        </Suspense>
    );
}
-->
React có thể tải component Analytics khi cần render nó thay vì đưa component vào phần tải ban đầu
5. Những điểm cần nhớ
- Dynamic Import không thay thế hoàn toàn Static Import.
- Dynamic Import trả về Promise nên cần xử lý bất đồng bộ.
- Dynamic Import có thể giúp giảm lượng JavaScript cần tải ban đầu, nhưng không có nghĩa tổng dung lượng ứng dụng giảm.
- Dynamic Import chỉ thực sự có lợi khi module được tải muộn hoặc không cần thiết ngay từ đầu.
Cách ghi nhớ:
- Static Import: Tôi biết chắc mình cần module này.
- Dynamic import : Tôi chỉ tải module này khi thực sự cần
