- export ... from không làm cho thành phần được re-export khả dụng trong chính file hiện tại.

1. Export before declarations
Mỗi module có phạm bi riêng . Module khác không thể tự truy cập biến , function hoặc class trong module đó
export giải quyết vấn đề này : cho phép 1 module công khai những thành phần mà module khác có thể import và sử dụng 
Cú pháp:
Theo tài liệu có thể đặtt ừ khoá export ngay trước khai báo:
- export let hoặc export const để xuất biến.
- export function để xuất function
- - export class để xuất class.

Ví dụ trong file say.js:
<!-- 
// Export an array
export let months = [
  'Jan', 'Feb', 'Mar', 'Apr', 'Aug',
  'Sep', 'Oct', 'Nov', 'Dec'
];

// Export a constant
export const MODULES_BECAME_STANDARD_YEAR = 2015;

// Export a class
export class User {
  constructor(name) {
    this.name = name;
  }
}

// Export a function
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}
 -->
 Khi một module có thể export , module khác có thể sử dụng 
 Ví dụ trong file main.js:
 <!-- 
 import { User, sayHi } from './say.js';

const user = new User('John');

sayHi(user.name);
  -->
Lưu ý : đây là name export . Tên được import phải khớp với tên đã export , trừ khi sử dụng tên alias ở phần sau
Điểm cần lưu ý trong tài liệu
export đặt trước function hoặc class không làm thay đổi cách khai báo của chúng. CHúng vẫn là function decalaration
và class declaration
Ví dụ:
<!-- export function sayHi(user) {
  alert(`Hello, ${user}!`);
} -->
Không cần dấu chấm phẩy sau dấu } kết thúc function decalaration
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
export k có nghĩa là gọi hoặc thực thi funtion ngay lập tức
<!-- 
export function sayHi() {
  console.log('Hello');
}
 -->
Đoạn code trên chỉ công khai function sayHI() để module khác có thể import . Function chỉ chạy khi được goi lại
Kiểm tra hiểu bài
Trong user.js có đoạn code:
<!-- 
export class User {
  constructor(name) {
    this.name = name;
  }
}
-->
Giải thích:
- export class User là Named Export.
- Khi import Named Export, phải đặt tên trong {}.
- Tên User phải khớp với tên được export.
Phân biệt:
<!-- 
// Named Export
export class User {}
import { User } from './user.js';

// Default Export
export default class User {}
import User from './user.js';
 -->
 Đây là khác biệt quan trọng : Named Export dùng {} , default Export không dùng {} trong cú pháp import thông thường

2. Export apart from declarations
Ở phần trước, chúng ta đặt export trực tiếp trước khai báo.
Tài liệu  giới thiệu 1 cách khác : khai báo các thành phần trước , sau đó export chúng bằng 1 danh sách riêng
Cú pháp
Ví dụ file say.js:
<!-- 
function sayHi(user) {
  alert(`Hello, ${user}!`);
}

function sayBye(user) {
  alert(`Bye, ${user}!`);
}

export { sayHi, sayBye };
 -->
 Trong ví dụ này :
1.  Khai báo sayHi() và sayBye() như bình thường
2.  Sau khi khai báo , sử dụng export { sayHi, sayBye } để export cả hai.

Module khác có thể impport
<!-- 
import { sayHi, sayBye } from './say.js';

sayHi('John');
sayBye('John');
 -->
So sánh hai cách export
Cách 1 — Export trước khai báo:
<!-- 
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}
-->
Cách 2 — Export riêng sau khai báo:
<!-- 
function sayHi(user) {
  alert(`Hello, ${user}!`);
}

export { sayHi };
 -->
 Cả 2 cách đều export sayHi với tên sayHi
 Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
 export { sayHi } không gọi function và cũng k tạo ra 1 bản sao của function. Nó công khai bindidng sayHi
 để module khác có thể import 
 Kiểm tra hiểu bài
 Cho file math.js:
 <!-- 
 const PI = 3.14;

function calculateArea(radius) {
  return PI * radius * radius;
}

export { PI, calculateArea };
  -->
import { PI, calculateArea } from './math.js';

Giải thích:
- PI và calculateArea đều là Named Export.
- Vì vậy, khi import phải đặt tên trong {}.
- './math.js' là đường dẫn tương đối đến module

3. Import *
Mục đích
Ở hai phần trước, chúng ta đã biết cách export và import từng thành phần.
Tài liệu giới thiệu thêm cách import tất cả các export của một module vào một object duy nhất , thay vì phải liêtj kê từng tên
3.1. Import từng thành phần
Ví dụ file say.js:
<!-- 
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}

export function sayBye(user) {
  alert(`Bye, ${user}!`);
}
 -->
Trong file main.js:
<!-- 
import { sayHi, sayBye } from './say.js';

sayHi('John');
sayBye('John');
 -->
Chúng ta import tưng thành phần bằng tên tương ứng

3.2. Import tất cả bằng *
Thay vì liệt kê tưng export , có thể sử dụng :
<!-- 
import * as say from './say.js';

say.sayHi('John');
say.sayBye('John');
 -->
Giải thích:
- *: import tất cả các export của module.
- as say : gom chúng vào object có tên say
- Truy cập các thành phần thông qua say.sayHi , say.sayBye

3.3. Nên sử dụng cách nào?

Cách 1 — Import cụ thể
<!-- import { sayHi, sayBye } from './say.js'; -->
Ưu điểm :
Code ngắn hơn khi sử dụng các function đã import
Nhìn vào import có thể biết module đang sử dụng những thành phần nào
Hỗ trợ việc phân tích và refactor code

Cách 2 — Import tất cả
<!--
 import * as say from './say.js';
say.sayHi('John');
 -->
Ưu điểm:
Gom các thành phần cùng 1 module vào 1 object
Tránh phải liệt kê nhiều tên khi muốn sử dụng nhiều export

3.4. Don't worry about importing too much
Không cần lo lắng khi import nhiều thành phần
Các build tools như Webpack có thể tối ưu việc bundler và loại bỏ những export không được sử dụng (Tree-shaking),
giúp giảm kích thươcs bundle trong những trường hợp phù hợp 
Ví dụ:
<!-- 
// say.js
export function sayHi() {
  console.log('Hi');
}

export function sayBye() {
  console.log('Bye');
}
 -->
 <!-- 
 // main.js
import { sayHi } from './say.js';

sayHi();
  -->
Trong quá trình tối ưu phù hợp,build tool có thể loại bỏ phần sayBye không được sử dụng khỏi bundler
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
import * as say không có nghĩa là import một default export vào object say dưới tên bất kỳ . Nếu module có default export,
nó được truy cập qua :
<!-- say.default -->
Chúng ta sẽ tìm hiểu kỹ hơn ở phần Export default.
Kiểm tra hiểu bài
Cho module user.js
<!-- 
export const name = 'John';

export function sayHi() {
  console.log('Hi');
}

export default class User {}
 -->
Kiểm tra hiểu bài
Cho module user.js:
<!-- 
export const name = 'John';

export function sayHi() {
  console.log('Hi');
}

export default class User {}
 -->
import * as user from './user.js';
Object user chứa tất cả các export 
- user.name: truy cập Named Export name.
- user.sayHi(): gọi Named Export sayHi.
- user.default: truy cập Default Export.

4. Import "as"
Mục đích
Khi import 1 thành phần , đôi khi tên export không còn phù hợp vơi cách đặt tên trong module hiện tại hoặc bị trùng
với 1 biến khác
as cho phép đổi tên thành phần khi import , mà không cần thay đổi tên export trong file module gốc
4.1. Cú pháp
Ví dụ file say.js:
<!-- 
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}

export function sayBye(user) {
  alert(`Bye, ${user}!`);
}
 -->
Trong file main.js:
<!-- 
import {
  sayHi as hi,
  sayBye as bye
} from './say.js';

hi('John');
bye('John');
 -->
Giải thích:
- sayHi() : tên được export từ module gốc
- hi : tên mới sử dụng trong module hiện tại 
- sayBye as bye : tương tự , đổi tên sayBye thành bye

Sau khi import bằng alias, sử dụng tên mới:
<!-- 
hi('John');
bye('John');
 -->
không sử dụng tên cũ sayHi() hoặc sayBye() trong module hiện tại nếu không import chúng bằng tên đó
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
Alias chỉ thay đổi tên binding trong module đang import, không thay đổi tên export của module gốc.
Ví dụ :
<!-- 
// say.js
export function sayHi() {}
 -->

 <!-- 
 // main.js
import { sayHi as hi } from './say.js';

hi();     // Đúng
sayHi();  // ReferenceError nếu không có binding sayHi khác
  -->

5. Export "as"
Mục đích 
Ở phần trước , chúng ta dùng as để đổi tên khi import
Ở phần này, tài liệu giới thiệu chiều ngược lại : đổi tên thành phần khi export , để module khác nhìn thấy và sử dung tên mới
5.1. Cú pháp
Ví dụ file say.js:
<!-- 
function sayHi(user) {
  alert(`Hello, ${user}!`);
}

function sayBye(user) {
  alert(`Bye, ${user}!`);
}

export {
  sayHi as hi,
  sayBye as bye
};
 -->
Giải thích:
- sayHi : tên function bên trong module
- hi : tên được export ra bên ngoài
- sayBye : tên functio bên trong module
- bye : tên được export ra bên ngoài

5.2. Import và sử dụng
Trong file main.js:
<!-- 
import * as say from './say.js';

say.hi('John');
say.bye('John');
 -->
Lưu ý: Module bên ngoài phải sử dụng tên export mới hi, bye), không phải tên nội bộ ( sayHi, sayBye)
So sánh Import "as" và Export "as"
| Đặc điểm | Import `as`            | Export `as`              |
| -------- | ---------------------- | ------------------------ |
| Thay đổi | Tên sử dụng khi import | Tên công khai khi export |
| Ví dụ    | `sayHi as hi`          | `sayHi as hi`            |
| Tác động | Module hiện tại        | Các module import nó     |
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
Có thể kết hợp cả 2 cách đổi tên :
<!-- 
// say.js
function sayHi() {}

export { sayHi as hi };
 -->
<!-- 
// main.js
import { hi as greeting } from './say.js';

greeting();
 -->

6. Export default
Mục đích
Ở các phần trước , chúng ta sử dụng Named Export để export một hoặc nhiều thành phần bằng tên cụ thể.
Tài liệu gioiws thiệu 1 cách khác : Default Export.

Cách này thường sử dụng khi module chủ yếu muốn cung cấp 1 thành phần duy nhất , chẳng hạn module user.js
chỉ export class User
6.1. Export default là gì?
Ví dụ file user.js:
<!-- 
export default class User {
  constructor(name) {
    this.name = name;
  }
}
 -->
Ở đây:
- export default : khai báo thành phần export mặc định 
- class User: class được export mặc định
- Mỗi module chỉ có 1 export default
6.2. Import Default Export
Trong file main.js:
<!-- 
import User from './user.js';

const user = new User('John');
 -->
Điểm khác biệt so với Named Export:
<!-- 
// Named Export
export class User {}
import { User } from './user.js';

// Default Export
export default class User {}
import User from './user.js';
 -->
 Named Export: import bằng {}
 Default Export: import trực tiếp không cần {}

6.3. Default Export có thể không cần tên
Tài liệu cũng chỉ ra rằng Default Export có thể export một khai báo ẩn danh.
<!-- 
export default class {
  constructor() {}
}
-->
Hoặc:
<!-- 
export default function(user) {
  alert(`Hello, ${user}!`);
}
-->
Cũng có thể export một giá trị:
<!-- export default ['Jan', 'Feb', 'Mar']; -->
Lý do: Default Export không yêu cầu người viết phải đặt tên cho thành phần được export.
So sánh trường hợp dễ nhầm:
<!-- 
// Hợp lệ: Default Export không cần tên
export default class {
  constructor() {}
}

// Không hợp lệ: Named Export cần tên class
export class {
  constructor() {}
}
 -->
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
Tên biến khi import Default Export không bắt buộc phải giống tên class trong file gốc.
Ví dụ:
<!-- 
// user.js
export default class User {}
 -->
<!-- 
// main.js
import MyUser from './user.js';

const user = new MyUser();
 -->
Đoạn code vẫn hợp lệ .MyUser là tên binding được đặt tại module import, không làm thay đổi class User trong module gốc
Kiểm tra hiểu bài :
<!-- 
export default class User {
  constructor(name) {
    this.name = name;
  }
}
 -->
B đúng, nhưng chưa đủ. Câu này có hai đáp án hợp lệ: B và C.
- B đúng: Cú pháp import Default Export thông thường.
- C cũng đúng: Import Default Export thông qua tên default.
<!-- 
// B
import User from './user.js';

// C
import { default as User } from './user.js';
 -->

6. Export default
The "default" name
Ở phần trước, chúng ta đã biết export default có thể export một class, function hoặc giá trị mà không cần tên export cụ thể.
Tài liệu tiếp tục giới thiệu 1 cách sử dụng khác : sử dụng tên default trong cú pháp export thông thường.

1. Export một thành phần có tên dưới dạng default
Ví dụ file say.js:
<!-- 
function sayHi(user) {
  alert(`Hello, ${user}!`);
}

export { sayHi as default };
 -->
Giải thích:
- sayHi là tên function được khai báo trong module.
- as default biến nó thành Default Export.
- Module khác có thể import function này mà không cần {}
Ví dụ:
<!-- 
import sayHi from './say.js';

sayHi('John');
 -->
2. Một module có thể có cả Default Export và Named Export
Ví dụ file user.js:
<!-- 
export default class User {
  constructor(name) {
    this.name = name;
  }
}

export function sayHi(user) {
  alert(`Hello, ${user}!`);
}
-->
Trong ví dụ này có hai loại export:
- User: Default Export.
- sayHi: Named Export.

3. Import Default Export cùng Named Export
Có thể import cả 2 trong cùng 1 câu lệnh :
<!-- 
import { default as User, sayHi } from './user.js';

const user = new User('John');

sayHi(user.name);
 -->
Giải thích:
- default as User: lấy Default export và đặt tên local là User
- sayHi : import Named Export bằng tên tương ứng

4. Import tất cả bằng *
Tài liệu cũng chỉ ra cách import toàn bộ module:
<!-- 
import * as user from './user.js';

const User = user.default;

const instance = new User('John');

user.sayHi(instance.name);
 -->
Diểm quan trọng :
- Named Export được truy cập bằng tên tương ứng, ví dụ user.sayHi.
- Default Export được truy cập thông qua thuộc tính user.default.
Bổ sung ngoài tài liệu gốc — trường hợp dễ nhầm
<!-- 
// Import default + named
import User, { sayHi } from './user.js';

// Import tất cả
import * as user from './user.js';

user.default;
user.sayHi;
 -->
Cả 2 đều có thể lấy Default Export và Named Export, nhưng cách truy cập khác nhau:

Bài tập thực hành:
<!-- 
export default class User {}

export function sayHi() {
  console.log('Hi');
}
 -->
Tất cả export được gom vào object user:
- user.default: Default Export (class User).
- user.sayHi: Named Export (function sayHi).
Vì User là tên class được khai báo, nhưng nó không phải tên export. Class được export dưới tên default.

* A word against default exports
1. Vấn đề của Default Export
Tài liệu phân tích sự khác biệt giữa Named Export và Default Export.
Named Export:
<!--
 // user.js
export class User {}
 -->
Khi import:
<!-- import { User } from './user.js'; -->
Tên import phải khớp với tên đã export (User).

Default Export:
<!-- 
// user.js
export default class User {}
 -->
Khi import, người dùng có thể tự đặt tên:
<!-- 
import User from './user.js';

import MyUser from './user.js';

import Anything from './user.js';
 -->
 Cả ba cách đều hợp lệ.

 2. Nhược điểm của Default Export
Vì người import được tự đặt tên nên cùng một module có thể được đặt nhiều tên khác nhau trong dự án.
<!-- import User from './user.js'; -->
Ở file khác:
<!-- import MyUser from './user.js'; -->
Ở file khác nữa:
<!-- import Account from './user.js'; -->
Điểu này có thể khiến code thiếu nhất quán và khó nhận biết các thành phần đang được import từ cùng 1 module
3. Cách hạn chế vấn đề
Tài liệu đề cập một số nhóm phát triển đặt quy ước:
Tên biến import phải tương ứng với tên file.
<!--
 // user.js
export default class User {}
 -->
Các file khác thống nhất:
<!-- import User from './user.js'; -->
Một số nhóm còn chọn không sử dụng Default Export, chỉ sử dụng Named Export để tên import luôn rõ ràng.
Bổ sung ngoài tài liệu gốc — góc nhìn thực tế
Trong dự án React, bạn có thể gặp cả hai cách:
<!-- 
// Named Export
export function UserProfile() {}
import { UserProfile } from './UserProfile.js';

// Named Export
export function UserProfile() {}
import { UserProfile } from './UserProfile.js';
 -->
Không có quy tắc rằng 1 cách luôn tốt hơn cách còn lại . Điều quan trọng là thống nhất convention trong dự án
Kiểm tra bài tập :
<!-- export default class User {} -->
B. Có thể import bằng nhiều tên khác nhau vì Default Export không yêu cầu tên import phải khớp tên class.
Vì sao :
Default Export không yêu cầu tên binding khi import phải khớp với tên class hoặc function trong module gốc.

7. Re-export
Mục đích
Trong các phần trước, chúng ta đã biết cách export thành phần từ một module và import chúng ở module khác.
Nhưng trong dự án thưucj tế , đôi khi một module muốn export lại thành phần được export từ module khác

7.1. Cú pháp Re-export
Giả sử có hai file:
say.js:
<!-- 
export function sayHi(user) {
  alert(`Hello, ${user}!`);
}
 -->
user.js:
<!-- 
export default class User {
  constructor(name) {
    this.name = name;
  }
}
-->
Một file khác có thể export lại các thành phần này:
<!-- 
// index.js
export { sayHi } from './say.js';
export { default as User } from './user.js';
 -->
Giải thích:
- export { sayHi } from './say.js': export lại Named Export sayHi.
-  export { default as User } from './user.js': lấy Default Export từ user.js và export lại dưới tên User.
  
Sau đó cac module khác chỉ cần import từ index.js
<!-- 
import { sayHi, User } from './index.js';

sayHi('John');

const user = new User('John');
 -->
Như vậy người sử dụng không cần biết sayHi và User nằm trong những file riêng nào

7.3. Điểm đặc biệt cần nhớ
Dễ nhầm
Re-export không tự động tạo binding trong module hiện tại.
Vi dụ :
<!-- 
// index.js
export { login } from './helpers.js';

login(); // ReferenceError
 -->
Tại sao?
export { login } from './helpers.js' chỉ export lại login cho module khác. Nó không import login vào phạm vi của index.js.
Nếu muốn vừa sử dụng vừa export lại, phải import riêng:
<!-- 
// index.js
import { login } from './helpers.js';

login();

export { login };
 -->

Bổ sung ngoài tài liệu gốc — liên hệ thực tế

components/
├── Button/
│   └── Button.jsx
├── Input/
│   └── Input.jsx
└── index.js

index.js có thể đóng vai trò điểm export tập trung:
<!-- 
export { default as Button } from './Button/Button.jsx';
export { default as Input } from './Input/Input.jsx';
 -->
Module khác sử dụng:
<!-- 
import { Button, Input } from './components';
 -->
Ghi nhớ:
- export ... from: chỉ Re-export.
- import ... + export ...: vừa sử dụng vừa export.

* Re-exporting the default export
Tài liệu lưu ý rằng Re-export Default Export có một số cú pháp đặc biệt, dễ nhầm với Named Export.

1. Không thể Re-export Default Export theo cách thông thường
Giả sử file user.js:
<!-- export default class User {} -->
Trong index.js, cách viết sau không hợp lệ:
<!-- export User from './user.js'; // SyntaxError -->
Lý do: Cú pháp Re-export không hỗ trợ viết trực tiếp tên User như vậy để lấy Default Export.

2. Cách Re-export Default Export đúng
Phải sử dụng default:
<!-- // index.js
export { default as User } from './user.js';
 -->
Giải thích:
- default : lấy Default Export từ user.js
- as User: đặt tên export công khai là User
Module khác có thể sử dụng:
<!-- 
import { User } from './index.js';

const user = new User();
 -->
3. export * không Re-export Default Export
Đây là trường hợp đặc biệt quan trọng :
Giả sử user.js:
<!-- 
export default class User {}

export function sayHi() {
  console.log('Hi');
}
 -->
Trong index.js:
<!-- export * from './user.js'; -->
Kết quả:
- sayHi được Re-export.
- - User không được Re-export vì đây là Default Export.
Muốn Re-export cả Named Export và Default Export:
<!-- 
// index.js
export * from './user.js';
export { default } from './user.js';
 -->
Hoặc muốn đặt tên cho Default Export:
<!-- 
// index.js
export * from './user.js';
export { default as User } from './user.js';
 -->
| Cú pháp                                       | Kết quả                                     |
| --------------------------------------------- | ------------------------------------------- |
| `export * from './user.js'`                   | Chỉ Re-export Named Export                  |
| `export { default } from './user.js'`         | Re-export Default Export dưới tên `default` |
| `export { default as User } from './user.js'` | Re-export Default Export dưới tên `User`    |

Đặc biệt: export * không bao gồm Default Export.

8. Summary

8.1. Export
1. Export trước khai báo
<!-- 
export let name = 'John';

export const PI = 3.14;

export function sayHi() {}

export class User {}
 -->
2. Export riêng sau khai báo
<!-- 
function sayHi() {}

class User {}

export { sayHi, User };
 -->
3. Export với alias
<!-- export { sayHi as hi }; -->
4. Default Export
<!-- export default class User {} -->
Hoặc:
<!-- export { sayHi as default }; -->

8.2. Import
1. Import Named Export
<!-- import { sayHi, User } from './module.js'; -->
2. Import và đổi tên
<!-- import { sayHi as hi } from './module.js'; -->
3. Import Default Export
<!-- import User from './user.js'; -->
Hoặc:
<!-- import { default as User } from './user.js'; -->
4. Import tất cả
<!-- 
import * as module from './module.js';

module.sayHi();
 -->


| Nội dung               | Cú pháp cần nhớ                   |
| ---------------------- | --------------------------------- |
| Named Export           | `export { x }`                    |
| Default Export         | `export default x`                |
| Named Import           | `import { x }`                    |
| Default Import         | `import x`                        |
| Import alias           | `import { x as y }`               |
| Export alias           | `export { x as y }`               |
| Import tất cả          | `import * as obj`                 |
| Re-export              | `export { x } from './module.js'` |
| Re-export tất cả       | `export * from './module.js'`     |
| Import chỉ để thực thi | `import './module.js'`            |
