3. Nội dung chi tiết
3.1. WeakRef
Trước khi tìm hiểu WeakRef, cần nhớ lại nguyên tắc Reachability trong Garbage Collection.
Strong reference là gì?
Strong reference là tham chiếu thông thường giữ cho object còn được truy cập . Khi object vẫn còn trong reference, GC không thể thu hồi object đó
Ví dụ theo tài liệu:
<!-- 
let user = { name: "John" };

// user đang giữ Strong reference tới object
user = null;

// Không còn tham chiếu mạnh tới object
// Object có thể được GC thu hồi
 -->
Một trường hợp khác có hai Strong references:
<!-- 
let user = { name: "John" };

let admin = user;

user = null;
 -->
Lúc này object vẫn chưa thể bị thu hồi vì admin vẫn giữ tham chiếu tới đó
<!-- admin = null; -->
Khi cả hai Strong references đều mất , object trở thành không còn reachable và có thể bị GC thu hồi

* Weak reference là gì?
Weak reference là tham chiếu không ngăn GC thu hồi Object
JS cung cấp WeakRef để loại tham chiếu này
<!-- 
let user = { name: "John" };

let admin = new WeakRef(user);
 -->
Ở đây:
- user : giữ Strong reference
- admin giữ 1 WeakRef tới object mà user đang tham chiếu

Nếu sau đó:
<!-- user = null; -->
GC có thể thu hồi object, dù biến admin vẫn còn tồn tại 
Điểm quan trọng: WeakRef không giữ object sống trong bộ nhớ.
Lấy object bằng deref()
<!-- 
let user = { name: "John" };

let admin = new WeakRef(user);

user = null;

let ref = admin.deref();

if (ref) {
  console.log(ref.name);
} else {
  console.log("Object đã bị Garbage Collector thu hồi");
}
 -->
 Những trường hợp dễ nhầm
1. Có WeakRef không có nghĩa object chắc chắn còn tồn tại.
<!-- 
let user = { name: "John" };
let admin = new WeakRef(user);

user = null;

console.log(admin.deref());
 -->
Không thể khẳng định kết quả luôn là object hay undefined. Điều đó phụ thuộc vào hoạt động của GC.

2. GC không chạy ngay khi mất Strong reference.
<!-- 
let user = { name: "John" };
let admin = new WeakRef(user);

user = null;
 -->
Không có nghĩa object lập tức bị xoá khỏi bộ nhớ . GC quyết định thời điểm thu hồi.

3. Không nên dùng WeakRef để quản lý dữ liệu bắt buộc phải tồn tại.
Ví dụ: thông tin đơn hàng, thông tin đăng nhập hoặc dữ liệu nghiệp vụ quan trọng không nên chỉ được giữ bằng WeakRef.
Bổ sung ngoài tài liệu gốc: Ứng dụng React và Backend
- React: Khi component unmount, bạn cần chủ động cleanup subscription, event listener và timer. Không nên dùng WeakRef để thay thế cleanup.
- Backend: WeakRef có thể hữu ích khi xây dựng cache chứa object lớn, nhưng k nên dùng để lưu dữ liệu nghiệp vụ cần đảm bảo tồn tại 

### **Tổng kết 3.1**

| Khái niệm          | Ý nghĩa                          |
| ------------------ | -------------------------------- |
| Strong reference   | Giữ object không bị GC thu hồi   |
| Weak reference     | Không ngăn GC thu hồi object     |
| `new WeakRef(obj)` | Tạo WeakRef tới object           |
| `deref()`          | Lấy object hoặc nhận `undefined` |

3.2. WeakRef use cases
WeakRef thương được sử dụng để xây cacche hoặc associative array chứa những object tốn tài nguyên
Mục đích: cho phép chương trình tái sử dụng object nếu nó vẫn còn trong bộ nhớ , nhưng không bắt GC phải giữ object đó
chỉ vì cache đang lưu tham chiếu đến đó
Vì sao cần WeakRef?
Giả sử ứng dụng tải nhiều ảnh và lưu chúng vào cache:
<!-- 
const imageCache = new Map();

imageCache.set("avatar.png", imageObject);
 -->
Vấn đề là Map giữ tham chiếu mạnh đến imageObject
Dù ứng dụng không còn sử dụng ảnh đó, object vẫn có thể không được Garbage Collector thu hồi vì cache vẫn giữ tham chiếu.

Tại sao không dùng WeakMap?
WeakMap có tham chiếu yếu đối với key là object, chứ không phải value.
Trong trường hợp này, chúng ta muốn:
- Key: tên ảnh dạng string.
- Value : object ảnh hưởng có thể được GC thu hồi
Vì vậy, WeakMap không phù hợp với cấu trúc này.
Cách giải quyết bằng WeakRef
Sử dụng Map kết hợp với WeakRef:
<!-- 
const imageCache = new Map();

imageCache.set(
  "avatar.png",
  new WeakRef(imageObject)
);
-->
Lúc này:
- Map vẫn giữ key "avatar.png".
- Value là WeakRef, không giũ object ảnh sống trong bộ nhớ
- Nếu object ảnh vẫn còn được sử dụng ở nơi khác, cache có thể lấy lại nó
- Nếu object đã bị GC thu hồi, cache phải tải hoặc tạo lại ảnh.
Ví dụ kiểm tra:
<!-- 
const cachedImage = imageCache.get("avatar.png");

const image = cachedImage?.deref();

if (image) {
  console.log("Sử dụng ảnh từ cache");
} else {
  console.log("Ảnh không còn trong bộ nhớ");
}
 -->
Điểm cần nhớ: WeakRef không đảm bảo object luôn tồn tại trong cache. Nó chỉ cho phép truy cập object nếu object chưa bị GC thu hồi.
Bổ sung ngoài tài liệu gốc — Case dễ nhầm
WeakRef không tự xóa key khỏi Map.
Ví dụ:
<!-- 
imageCache.set("avatar.png", new WeakRef(imageObject));
 -->
Khi imageObject bị GC thu hồi, key "avatar.png" vẫn có thể tồn tại trong Map.
Do đó, nếu sử dụng cách này, cần cơ chế dọn những entry không còn giá trị , chẳng hạn kiểm tra deref() hoặc sử dung FinalizationRegistry
Áp dụng trong React và Backend
- React: Có thể cân nhắc khi quản lý cache object lớn, nhưng không nên dùng WeakRef để thay thế cleanup trong useeffect
- Backend Node.js: Có thể cân nhắc với cache object có thể tái tạo lại,nhưng k phù hợp với dữ liệu nghiệp vụ cần đảm bảo tồn tại 

3.3. Example №1: using WeakRef for caching
xây dựng cache ảnh bằng Map kết hợp với WeakRef.
Mục tiêu là tận dụng lại ảnh nếu object ảnh vẫn còn trong bộ nhớ . Nếu GC đã thu hồi object , chương trình sẽ tải ảnh lại thay vì 
cố giữ nó sống mãi trong cache
Ví dụ trong tài liệu gốc
fetchImg() là hàm giả định dùng để tải ảnh:
<!-- 
function fetchImg() {
  // abstract function for downloading images...
}
 -->
Tài liệu xây dựng hàm weakRefCache() như sau:
<!-- 
function weakRefCache(fetchImg) {
  const imgCache = new Map();

  return (imgName) => {
    const cachedImg = imgCache.get(imgName);

    if (cachedImg?.deref()) {
      return cachedImg?.deref();
    }

    const newImg = fetchImg(imgName);
    imgCache.set(imgName, new WeakRef(newImg));

    return newImg;
  };
}

const getCachedImg = weakRefCache(fetchImg);
 -->
Phân tích từng phần
1. Tạo cache
<!-- const imgCache = new Map(); -->
Map lưu dữ liệu theo cấu trúc:
<!-- 
Key             Value
"avatar.png"    WeakRef(imageObject)
"banner.png"    WeakRef(imageObject)
 -->
Key là tên ảnh, còn value là WeakRef trỏ đến object ảnh

2. Kiểm tra ảnh trong cache
<!-- 
const cachedImg = imgCache.get(imgName);

if (cachedImg?.deref()) {
  return cachedImg?.deref();
}
-->
Có hai trường hợp:
- cachedImg không tồn tại : ảnh chưa có trong cache.
- - cachedImg tồn tại nhưng deref() trả về undefined: object ảnh đã bị GC thu hồi.

sử dụng WeakRef để theo dõi một DOM element mà không giữ element đó sống trong bộ nhớ
Ý tưởng của ví dụ:
<!-- 
<div class="window__body">
  Window content
</div>
 -->
 Chúng ta muốn theo dõi elemnet này  TUy nhiên , nếu trực tiếp element vào 1 biến thông thường , biến đó sẽ giữ strong reference đến DOM Object
 Thay vào đó, sử dụng WeakRef:
 <!-- 
 const element = document.querySelector(".window__body");

const weakElement = new WeakRef(element);
  -->
Theo dõi DOM object
Có thể gọi deref() để kiểm tra element còn tồn tại trong bộ nhớ hay không :
<!-- 
const element = weakElement.deref();

if (element) {
  console.log("Element is still available");
} else {
  console.log("Element was garbage collected");
}
 -->
Hai trường hợp:
- deref() trả về DOM object: object vẫn còn trong bộ nhớ
- deref() trả về undefined: object đã bị GC thu hồi.

Điểm quan trọng: Xóa DOM không đồng nghĩa với GC ngay lập tức
Ví dụ:
<!-- element.remove(); -->
Lệnh này chỉ loại bỏ element khỏi DOM tree:
Nó không đảm bảo object được GC ngay lập tức vì:
- Có thể vẫn còn strong reference từ biến khác.
- GC không chạy ngay tại thời điểm gọi remove().
- THời điểm thu hồi bộ nhớ do JS enginee quyết định 

Bổ sung ngoài tài liệu gốc — Áp dụng trong React
Trong React, khi component unmount, bạn thường cần sử dụng cleanup những tài nguyên đã tạo 
Ví dụ:
<!-- 
useEffect(() => {
  const timer = setInterval(() => {
    console.log("Running...");
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);
 -->
Không nên thay clearInterval() bằng WeakRef.
Tương tự, event listener cần được gỡ bỏ 
<!-- 
useEffect(() => {
  const handleResize = () => {
    console.log("Resized");
  };

  window.addEventListener("resize", handleResize);

  return () => {
    window.removeEventListener("resize", handleResize);
  };
}, []);
 -->
**Phân biệt:**

| Cơ chế                  | Mục đích                                           |
| ----------------------- | -------------------------------------------------- |
| `WeakRef`               | Không giữ object sống chỉ vì có tham chiếu yếu     |
| `clearInterval()`       | Dừng timer                                         |
| `removeEventListener()` | Gỡ event listener                                  |
| React cleanup           | Chủ động giải phóng tài nguyên khi effect kết thúc |

3.5. FinalizationRegistry
WeakRef cho phép tham chiếu đến object mà không giữ object sống trong bộ nhớ
Nhưng có một vấn đề:
Khi object bị Garbage Collector thu hồi, làm sao chúng ta biết để thực hiện một hành động dọn dẹp liên quan?
JavaScript cung cấp FinalizationRegistry để đăng ký callback được goi khi một Object được GC thu hồi
Cách tạo FinalizationRegistry
<!-- const registry = new FinalizationRegistry(callback); -->
Trong đó:
- callback : hàm được đăng ký để thực hiện khi object mục tiêu được GC thu hồi
- registry : đối tượng quản lý các đăng ký này
Ví dụ:
<!-- 
const registry = new FinalizationRegistry((value) => {
  console.log(`${value} was garbage collected`);
});

let user = {
  name: "John"
};

registry.register(user, "User John");

user = null;
 -->
Giải thích:
1. Tạo FinalizationRegistry với callback.
2. Tạo object user.
3. Đăng ký object với registry.register().
4. Bỏ strong reference bằng user = null.
5. Nếu object được GC thu hồi, callback có thể được gọi.

Phương thức register()
Cú pháp:
<!-- registry.register(target, heldValue, unregisterToken); -->
| Tham số           | Ý nghĩa                                                  |
| ----------------- | -------------------------------------------------------- |
| `target`          | Object muốn theo dõi                                     |
| `heldValue`       | Giá trị được truyền vào callback khi target được thu hồi |
| `unregisterToken` | Token tùy chọn dùng để hủy đăng ký                       |
Ví dụ:
<!-- 
const registry = new FinalizationRegistry((value) => {
  console.log("Cleanup:", value);
});

let user = { name: "John" };

registry.register(user, "John data");

user = null;
 -->
Điểm cần nhớ: registry không giữ strong reference đến target, nếu không object sẽ không thể được GC thu hồi.
Tuy nhiên, heldValue được registry giữ strong reference. Vì vậy, không nên truyền chính target làm heldValue , vì điều đó khiến
object không được thu hồi

Phương thức unregister()
Có thể hủy đăng ký trước khi object bị GC:
<!-- 
const registry = new FinalizationRegistry((value) => {
  console.log("Cleanup:", value);
});

let user = { name: "John" };

registry.register(user, "John data", user);

// Hủy đăng ký
registry.unregister(user);

user = null;
 -->
Sau khi unregister(user) thành công, callback sẽ không được gọi cho đăng ký đó.
Bổ sung ngoài tài liệu gốc — Những điểm dễ nhầm
1. FinalizationRegistry không phải cơ chế cleanup đảm bảo
Không dùng nó để đảm bảo đóng database, file hoặc socket.
Những tài nguyên này cần được giải phóng chủ động, ví dụ close() hoặc finally.
2. Không nhầm target với heldValue
- target: object được theo dõi, không bị registry giữ strong reference
- heldValue : dữ liệu được truyền cho callback , được registry giữ strong reference.
3. Không dựa vào thứ tự callback
Nếu nhiều object bị thu hồi, không nên giả định callback chạy theo thứ tự đăng ký hoặc theo thứ tự object bị mất reference.
Áp dụng trong React và Backend
- React: Không dùng FinalizationRegistry để thay thế cleanup trong useEffect
- Backend Node.js: có thể dùng cho 1 số tác vụ dọn metadata hoặc cache phụ trợ, nhưng không dùng cho cleanup nghiệp vụ quan trọng 

Áp dụng trong React / Backend
React: Có thể nghiên cứu cơ chế này khi xây dựng cache object phụ trợ, nhưng không dùng để quản lý vòng đời component.
Backend Node.js: Có thể hỗ trợ dọn metadata của cache, nhưng nếu cần kiểm soát dung lượng và thời gian sống thì TTL/LRU vẫn dễ dự đoán hơn.

3.7. Using WeakRef and FinalizationRegistry in practice
WeakRef và FinalizationRegistry là những công cụ đặc biệt, không nên sử dụng tùy tiện.
Khi nào nên sử dụng?
Có thể cân nhắc khi:
- Muốn cache những object lớn, tốn tài nguyên.
- Object có thể được tạo lại hoặc tải lại khi cần.
- Việc object bị GC thu hồi không ảnh hưởng đến tính đúng đắn của ứng dụng.
- Chấp nhận được rằng thời điểm object bị thu hồi và callback chạy không thể đoán chính xác
Ví dụ: ứng dụng lưu cache thumbnail ảnh để sử dụng lại khi người dùng mở nhiều album ảnh.
Nếu thumbnail vẫn còn trong bộ nhớ, có thể tái sử dụng. Nếu đã bị GC thu hồi, ứng dụng tạo hoặc tải lại thumbnail.

Áp dụng trong React và Backend
React

Ví dụ một ứng dụng có cache dữ liệu ảnh:
- Có thể sử dụng cache thông thường nếu cần kiểm soát thời gian lưu.
- Có thể nghiên cứu WeakRef nếu object lớn, có thể tái tạo và không bắt buộc tồn tại.
- Vẫn phải cleanup event listener, timer và subscription bằng cơ chế chủ động.

Backend Node.js
Ví dụ một service xử lý ảnh:
- Cache thumbnail có thể tái tạo.
- Cache object phục vụ xử lý tạm thời.
- Không dùng WeakRef để lưu dữ liệu quan trọng như thông tin đơn hàng , tải khoản hoặc trang thái thanh toán

3.8. Summary
Theo nội dung tổng kết của tài liệu, cần ghi nhớ:
- WeakRef tạo tham chiếu yếu đến object.
- deref() trả về object nếu nó vẫn còn tồn tại, ngược lại trả về undefined.
- FinalizationRegistry đăng ký callback có thể được gọi khi object bị GC thu hồi.
- Không thể đảm bảo thời điểm GC hoặc callback chạy.
- Hai cơ chế này có thể hỗ trợ xây dựng cache, nhưng cần cân nhắc kỹ trước khi sử dụng.
