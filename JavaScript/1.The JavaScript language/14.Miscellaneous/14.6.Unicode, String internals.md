3. Nội dung chi tiết
3.1. Unicode
Unicode là gì?
Unicode là tiêu chuẩn quy định mã số cho các ký tự trong nhiều hệ thống chữ viết trên thế giới :
| Ký tự | Unicode |
| ----- | ------- |
| `A`   | U+0041  |
| `z`   | U+007A  |
| `©`   | U+00A9  |
| `😍`   | U+1F60D |
Theo tài liệu, JavaScript cho phép đưa ký tự Unicode vào chuỗi bằng ba cách biểu diễn.
Cách 1: \xXX
- XX gồm đúng 2 chữ số hexadecimal.
- Giá trị từ 00 đến FF.
- Chỉ biểu diễn được 256 ký tự đầu tiên.
<!-- 
console.log("\x7A"); // z
console.log("\xA9"); // ©
 -->
Cách 2: \uXXXX
- XXXX gồm đúng 4 chữ số hexadecimal.
- Biểu diễn các mã Unicode từ U+0000 đến U+FFFF.
- Nếu ký tự có mã lớn hơn U+FFFF , cần sử dụng surrogate pair.
<!-- 
console.log("\u00A9"); // ©
console.log("\u044F"); // я
console.log("\u2191"); // ↑
 -->
Cách 3: \u{X…XXXXXX}
- Nhận mã hexadecimal từ 1 đến 6 chữ số.
- Giá trị từ 0 đến 10FFFF.
- - Có thể biểu diễn tất cả Unicode code point hiện có.

Bổ sung ngoài tài liệu gốc: Điều dễ nhầm
Hexadecimal là hệ thập lục phân, sử dụng các ký tự 0–9 và A–F.
<!-- 
console.log("\x41");     // A
console.log("\u0041");   // A
console.log("\u{41}");   // A
 -->
Cả ba cách đều tạo ra ký tự A, nhưng phạm vi biểu diễn khác nhau.
Ứng dụng trong React và Backend
Thông thường bạn không cần tự viết Unicode escape khi làm React hoặc Node.js.
Tuy nhiên, hiểu Unicode giúp bạn:
- Đọc và xử lý dữ liệu API có ký tự đặc biệt.
- Debug chuỗi có emoji hoặc ký tự hiếm.
- Tránh giả định rằng mỗi ký tự hiển thị tương ứng với một đơn vị length.

3.2. Surrogate pairs
Đây là phần quan trọng nhất để hiểu vì sao trong JavaScript, 1 kí tự emoji có thể có lenght === 2
Vì sao cần Surrogate pairs?
| Phương thức              | Chức năng                                        |
| ------------------------ | ------------------------------------------------ |
| `charCodeAt()`           | Lấy code unit tại vị trí chỉ định                |
| `codePointAt()`          | Lấy Unicode code point, nhận diện surrogate pair |
| `String.fromCharCode()`  | Tạo ký tự từ code unit                           |
| `String.fromCodePoint()` | Tạo ký tự từ Unicode code point                  |

Ví dụ :
<!-- 
const symbol = "𝒳";

console.log(symbol.charCodeAt(0).toString(16));
// d835

console.log(symbol.codePointAt(0).toString(16));
// 1d4b3
 -->
charCodeAt(0) chỉ lấy phần đầu của surrogate pair.
codePointAt(0) nhận diện cả 2 phần và trả về code point đầy đủ
Tương tự, khi tạo ký tự:
<!-- 
console.log(String.fromCharCode(0x1f60d));
// Không tạo đúng emoji 😍

console.log(String.fromCodePoint(0x1f60d));
// 😍
 -->
Cả hai phần riêng lẻ đều không biểu diễn đúng ký tự ban đầu.
Điều này cũng ảnh hưởng đến slice();
<!-- 
const str = "hi 😂";

console.log(str.length);      // 5
console.log(str.slice(0, 4)); // Có thể chứa nửa emoji
 -->
Bởi vì slice() tính vị trí theo UTF-16 code units, không phải theo ký tự Unicode hoàn chỉnh.
Bổ sung ngoài tài liệu gốc: Ứng dụng thực tế
React – giới hạn độ dài nội dung
Ví dụ bạn muốn giới hạn nội dung người nhập gõ 10 kí tự 
<!-- 
const message = "Hello 😂";

console.log(message.length); // 8
 -->
 Ở đây emoji chiếm 2 đơn vị length, dù người dùng nhìn thấy nó như một ký tự.

Nếu cần đếm theo Unicode code point:
Nếu cần đếm theo Unicode code point:
<!-- 
const count = [...message].length;

console.log(count); // 7
 -->
Lưu ý: Cách này xử lý tốt surrogate pairs, nhưng chưa đảm bảo đếm đúng mọi kí tự người dùng nhìn thâý.
Một emoji có thể được tạo từ nhiều code point.
Tổng kết 3.2
- JavaScript sử dụng UTF-16 code units để biểu diễn chuỗi.
- Ký tự có code point lớn hơn U+FFFF cần hai code units.
- Đó là lý do một số emoji có length === 2.
- charCodeAt() lấy code unit; codePointAt() có thể lấy toàn bộ code point.
- fromCharCode() và fromCodePoint() cũng có sự khác biệt tương ứng.
- slice() có thể cắt giữa một surrogate pair.

3.3. Diacritical marks and normalization
Phần này giải thích : 2 chuỗi được xem là giống hệt nhau nhưng JS được xem chungs là khác nhau
Đặc biệt hữu ích khi xử lý tiếng Việt, tìm kiếm, so sánh tên người dùng và dữ liệu nhập từ API.
Diacritical marks là gì?
Diacritical marks là các dấu được kết hợp vơi chữ cái để tạo thành ký tự có dấu
Ví dụ, ký tự é có thể được biểu diễn theo hai cách:
Cách 1: Một Unicode code point
<!-- 
const str1 = "\u00E9";

console.log(str1); // é
console.log(str1.length); // 1
 -->
Đây là ký tự é được biểu diễn trực tiếp bằng mã U+00E9.
Cách 2: Hai Unicode code points
<!-- 
const str2 = "e\u0301";

console.log(str2); // é
console.log(str2.length); // 2
 -->
Gồm:
- e: U+0065.
- Dấu sắc kết hợp: U+0301.
Hai chuỗi nhìn giống nhau nhưng cấu trúc bên trong khác nhau
Vì sao so sánh lại cho kết quả khác?
<!-- 
const str1 = "\u00E9";
const str2 = "e\u0301";

console.log(str1 === str2); // false
 -->
JavaScript so sánh dựa trên các đơn vị trong mã chuỗi , không tự động chuẩn hoá Unicode trước khi so sánh
Vì vậy, hai chuỗi hiển thị giống nhau chưa chắc có cùng biểu diễn.

* Unicode normalization
Để giải quyết vấn đề này, JavaScript cung cấp phương thức normalize().
| Dạng   | Ý nghĩa                            |
| ------ | ---------------------------------- |
| `NFC`  | Chuẩn hóa theo dạng kết hợp chuẩn  |
| `NFD`  | Chuẩn hóa theo dạng phân rã chuẩn  |
| `NFKC` | Chuẩn hóa tương thích dạng kết hợp |
| `NFKD` | Chuẩn hóa tương thích dạng phân rã |

<!-- 
const str1 = "\u00E9";
const str2 = "e\u0301";

console.log(str1 === str2); // false

console.log(str1.normalize() === str2.normalize());
// true
 -->
normalize() mặc định sử dụng NFC.
Bạn cũng có thể chỉ định rõ:
Phân biệt NFC/NFD và NFKC/NFKD
- NFC và NFD xử lý tương đương chuẩn (canonical equivalence).
- NFKC và NFKD còn xử lý tương đương tương thích (compatibility equivalence).
Ví dụ, một số ký tự có dạng trình bày đặc biệt có thể được chuyển về dạng thông thường khi dùng NFKC hoặc NFKD.
Bổ sung ngoài tài liệu gốc: Ứng dụng trong React và Backend
1. React – so sánh dữ liệu nhập vào
Giả sử người dùng nhập tên có dấu:
<!-- 
const input = "é";
const stored = "e\u0301";

console.log(input === stored); // false
 -->
Nếu ứng dụng cần so sánh 2 chuỗi theo dạng Unicode tương đương :
<!-- 
const isSame =
  input.normalize("NFC") === stored.normalize("NFC");

console.log(isSame); // true
 -->
2. Backend – tìm kiếm và kiểm tra dữ liệu
Khi nhận dữ liệu từ nhiều nguồn khác nhau, có thể chuẩn hoá trước khi so sánh hoặc tìm kiếm
<!-- 
function normalizeText(value) {
  return value.normalize("NFC");
}

const username1 = "é";
const username2 = "e\u0301";

console.log(
  normalizeText(username1) === normalizeText(username2)
); // true
 -->
3. Lưu ý riêng với tiếng Việt
Unicode normalization giúp xử lý những cách biểu diễn khác nhau của cùng 1 ký tự có dấu .Tuy nhiên, nó không tự động biến tiếng Việt có dấu thành không dấu.
<!-- 
const text = "Tiếng Việt";

console.log(text.normalize("NFC")); // Tiếng Việt
 -->
Nếu muốn tìm kiếm không phân biệt dấu, đó là một yêu cầu xử lý khác, không chỉ đơn giản là normalize().
Tổng kết 3.3
- Một ký tự có thể có nhiều cách biểu diễn Unicode.
- Hai chuỗi nhìn giống nhau vẫn có thể cho kết quả === false.
- normalize() giúp đưa chuỗi về dạng Unicode chuẩn hóa.
- NFC, NFD xử lý tương đương chuẩn.
- NFKC, NFKD xử lý thêm tương đương tương thích.
- Với React và Backend, normalization hữu ích khi so sánh, tìm kiếm và xử lý dữ liệu Unicode.


4. Tổng kết toàn bài Unicode
1. Unicode : có nhiều cách biểu diễn ký tự bằng escape sequence.
2. Surrogate pairs: 1 code point có thể cần hai UTF-16 code units.
3. Normalization : 2 chuỗi nhìn giống nhau chưa chắc có cùng biểu diễn bên trong
