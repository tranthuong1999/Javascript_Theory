Ví dụ, theo dõi việc ghi dữ liệu:
<!-- 
const user = new Proxy({}, {

    }
});

user.name = 'Martin';
// Update name: Martin
 -->
Đây là ví dụ minh họa một pattern có thể sử dụng trong Node.js, không phải yêu cầu phải dùng Proxy trong mọi backend project.

*******************************************************************************************************************
Proxy and Reflect
Proxy
1. Proxy là gì?
Proxy là 1 object đóng vai trò trung gian , bao bọc 1 object khác và có thể can thiệp vào những thao tác thực hiện trên object đó
Ví dụ bình thương khi đọc hoăcj ghi object
<!-- 
const user = {
    name: 'Martin'
};

console.log(user.name); // Martin

user.name = 'John';
 -->
JS thực hiện các thao tác trực tiếp trên user
Nhưng với Proxy, chúng ta có thể đứng ở giữa để kiểm soát những thao tác đó
2. Cú pháp
<!-- let proxy = new Proxy(target, handler); -->
Có hai thành phần:
| Thành phần | Ý nghĩa                                                     |
| ---------- | ----------------------------------------------------------- |
| `target`   | Object gốc được bao bọc. Có thể là object hoặc function.    |
| `handler`  | Object chứa các trap để can thiệp vào thao tác trên target. |
Trap là các method trong handler, được gọi khi 1 thao tác tương ứng xảy ra
Ví dụ:
- get: đọc property.
- set: ghi property.
- has: sử dụng toán tử in.
- deleteProperty: sử dụng toán tử delete.
3. Ví dụ đầu tiên trong tài liệu gốc
Tạo Proxy không có trap:
<!-- 
let target = {};

let proxy = new Proxy(target, {});

proxy.test = 5;

console.log(target.test); // 5
console.log(proxy.test);  // 5

for (let key in proxy) {
    console.log(key); // test
}
 -->
Điều gì xảy ra?
Vì handler là object rỗng {} , không có trap nào can thiệp 
Do đó , tât cả các thao tác trên Proxy được chuyển tiếp đến target
Vì vậy:
<!-- console.log(target.test); // 5 -->
Proxy không tự động tạo ra 1 bản sao của target . Khi không có trap , nó chuyển tiếp thao tác đến target

4. Proxy traps và Internal methods
Đây là phần quan trọng tiếp theo trong tài liệu.
Trong JavaScript Specification, các thao tác trên object được mô tả bằng những internal methods ( phương thức nội bộ)
Ví dụ:
- [[Get]]: đọc property.
- [[Set]]: ghi property.
- [[HasProperty]]: kiểm tra property.
- [[Delete]]: xóa property.

Đây là tên gọi đặc tả của JS , chúng ta không thể trực tiếp gọi các internal methods này bằng cú pháp thông thường.
Proxy traps cho phép can thiệp vào những thao tác tương ứng
Bảng trong tài liệu gốc:
| Internal method       | Proxy trap       | Khi nào được gọi?  |
| --------------------- | ---------------- | ------------------ |
| `[[Get]]`             | `get`            | Đọc property       |
| `[[Set]]`             | `set`            | Ghi property       |
| `[[HasProperty]]`     | `has`            | Toán tử `in`       |
| `[[Delete]]`          | `deleteProperty` | Toán tử `delete`   |
| `[[Call]]`            | `apply`          | Gọi function       |
| `[[Construct]]`       | `construct`      | Toán tử `new`      |
| `[[OwnPropertyKeys]]` | `ownKeys`        | Lấy danh sách keys |
Ngoài ra còn có getPrototypeOf, setPrototypeOf, defineProperty, getOwnPropertyDescriptor và một số trap khác.
5. Invariants
Invariants là những quy tắc mà JS bắt buộc Proxy traps phải tuân thủ
Ví dụ:
- [[Set]] phải trả về true nếu ghi thành công, ngược lại trả về false.
- [[Delete]] phải trả về true nếu xóa thành công, ngược lại trả về false.
- Một số thao tác còn có những quy tắc ràng buộc khác, ví dụ liên quan đến prototype.
Ví dụ:
<!-- 
const user = new Proxy({}, {
    set(target, property, value) {
        target[property] = value;
        // Quên return true
    }
});

user.name = 'Martin';
 -->
Trong strict mode, thao tác ghi này sẽ gây TypeError vì trap set trả về undefined, không phải true.
Không phải trap nào cũng trả về cùng một kiểu dữ liệu  CHẳng hạn :
- get trả về giá trị của property.
- set trả về boolean.
- has trả về boolean.
- ownKeys trả về danh sách keys.
Đừng nhầm tất cả các trap phải trả về return true ;
6. Kiểm tra hiểu bài
Câu hỏi: Khi tạo Proxy với handler rỗng:
<!-- 
const target = {};
const proxy = new Proxy(target, {});

proxy.name = 'Martin';

console.log(target.name);
 -->
Vì handler rỗng nên không có trap nào can thiệp. Thao tác:
Ghi nhớ: Proxy không tạo bản sao của target. Khi không có trap, thao tác được chuyển tiếp đến object gốc.

2. Default value with “get” trap
1. Mục đích
Trong phần trước , chúng ta đã biết Proxy có thể can thiệp vào thao tác đọc property thông qua get
Tài liệu sử dụng get để giải quyết tình huống:
Khi đọc một property không tồn tại, thay vì nhận underdined , chúng ta muốn trả về 1 giá trị mặc định 
2. Cú pháp get
<!-- 
let proxy = new Proxy(target, {
    get(target, property, receiver) {
        // Trả về giá trị mong muốn
    }
});
 -->
 Ba tham số:
| Tham số    | Ý nghĩa                                   |
| ---------- | ----------------------------------------- |
| `target`   | Object gốc                                |
| `property` | Tên property đang được đọc                |
| `receiver` | Object nhận thao tác đọc, thường là Proxy |
<!-- 
const user = {
    name: 'Martin'
};

const proxy = new Proxy(user, {
    get(target, property, receiver) {
        return target[property];
    }
});

console.log(proxy.name); // Martin
console.log(proxy.age);  // undefined
 -->
Khi gọi proxy.name, trap get được kích hoạt.
- target là user.
- propety là name
- receiver là proxy

3. Default value – Giá trị mặc định
Bây giờ chúng ta thay đổi cách xử lý propety không tồn tại :
<!-- 
const user = {
    name: 'Martin'
};

const proxy = new Proxy(user, {
    get(target, property) {
        if (property in target) {
            return target[property];
        }

        return 'Unknown';
    }
});

console.log(proxy.name); // Martin
console.log(proxy.age);  // Unknown
 -->
Giải thích :
- proxy.name: property tồn tại nên trả về 'Martin'.
- proxy.age: property không tồn tại nên trả về 'Unknown'.
4. Case dễ nhầm cần chú ý
Case 1: Property tồn tại nhưng giá trị là undefined.
<!-- 
const user = {
    name: undefined
};

const proxy = new Proxy(user, {
    get(target, property) {
        if (property in target) {
            return target[property];
        }

        return 'Unknown';
    }
});

console.log(proxy.name); // undefined
 -->
Vì name in target trả về true , nên kết qủa vẫn là undefined , không phải "Unknown"
Nếu dùng:
<!-- if (target[property] !== undefined) -->
thì sẽ không phân biệt được property không tồn tại và property tồn tại nhưng có giá trị là undefined

Case 2: in kiểm tra cả prototype chain.
<!-- 
const user = {
    name: 'Martin'
};

const proxy = new Proxy(user, {
    get(target, property) {
        if (property in target) {
            return target[property];
        }

        return 'Unknown';
    }
});

console.log(proxy.toString); // Function toString()
 -->
toString không được khai báo trực tiếp trong user , nhưng tồn tại trên prototype cảu object
Do đó , toString in target vẫn là true.
Nếu muốn chỉ kiểm tra property trực tiếp trên object , có thể dùng :
<!-- Object.hasOwn(target, property); -->
Lưu ý: đây là cách kiểm tra bổ sung, không phải cách tài liệu dùng trong ví dụ trên.

* Validation with “set” trap
1. Mục đích
bạn đã học get để kiểm soát thao tác đọc property.
Phần này sủ dụng set để kiểm soát thao tác ghi propety
Ví dụ: Một object user có property age.Chúng ta muốn đảm bảo age luôn là số nguyên không âm 
Thay vì để code ghi dữ liệu tùy ý, Proxy cho phép kiểm tra dữ liệu trước khi cập nhật object
<!-- 
let proxy = new Proxy(target, {
    set(target, property, value, receiver) {
        // Kiểm tra và xử lý dữ liệu
    }
});
 -->
Có 4 tham số :
| Tham số    | Ý nghĩa                                   |
| ---------- | ----------------------------------------- |
| `target`   | Object gốc                                |
| `property` | Tên property được ghi                     |
| `value`    | Giá trị mới                               |
| `receiver` | Object nhận thao tác ghi, thường là Proxy |

Điểm quan trọng : set phải trả về booleann
true : thao tác ghi thành công
false : thao tác ghi thất bại 

3. Ví dụ theo tài liệu gốc
Tạo Proxy để kiểm tra age:
<!-- 
let user = {
    name: "John",
    age: 30
};

user = new Proxy(user, {
    set(target, property, value) {
        if (property === "age") {
            if (!Number.isInteger(value)) {
                throw new TypeError("Age must be an integer");
            }

            if (value < 0) {
                throw new TypeError("Age must be a positive number");
            }
        }

        target[property] = value;
        return true;
    }
});

user.age = 25;

console.log(user.age); // 25
 -->
Giải thích:
1. Khi thực hiện user.age = 25 , trap set được gọi 
2. Kiểm tra property có phải age hay không
3. Kiểm tra giá trị có phải số nguyên không.
4. Kiểm tra giá trị có nhỏ hơn 0 không
5. Nếu hợp lệ ghi dữ liệu vào target 
6. trả về true

Nếu dữ liệu không hợp lệ, chương trình ném TypeError và không thực hiện ghi dữ liệu.
4. Vì sao cần return true?
trap set không trả về gì , tức là trả về undefined
Trong strict mode, phép gán này sẽ gây TypeError vì set không trả về true
Cách viết đúng :
<!-- 
const user = new Proxy({}, {
    set(target, property, value) {
        target[property] = value;
        return true;
    }
}); -->
5. Bổ sung ngoài tài liệu gốc – Các trường hợp dễ nhầm
Trường hợp 1: Number.isInteger() và typeof không giống nhau.
<!-- 
typeof 25.5 === "number";       // true
Number.isInteger(25.5);        // false

Number.isInteger(25);          // true
Number.isInteger("25");        // false
 -->
Nếu yêu cầu số tuổi là nguyên , chỉ kiểm tra typeof value === 'number' là chưa đủ
Trường hợp 2: set có thể từ chối ghi dữ liệu bằng false.
<!-- 
const user = new Proxy({}, {
    set(target, property, value) {
        if (property === "age" && value < 0) {
            return false;
        }

        target[property] = value;
        return true;
    }
});

user.age = -1;
 -->
Trường hợp 3: set không tự động kiểm tra toàn bộ object.
Ví dụ:
<!-- user.age = 25; -->
Sẽ kích hoạt set , nhưng nếy bạn ghi trực tiếp:
<!-- target.age = -1; -->
thì không đi qua Proxy và không kích hoạt trap.
Vì vậy , Proxy chỉ kiểm soát những thao tác thực hiện thông qua Proxy

7. Kiểm tra hiểu bài
<!-- 
const user = new Proxy({}, {
    set(target, property, value) {
        if (property === "age" && value < 0) {
            return false;
        }

        target[property] = value;
        return true;
    }

user.age = 25;

console.log(user.age);

 Giải thích theo từng bước :
 <!-- 
 user.age = 25;  // set trả về true → ghi thành công

user.age = -1;  // set trả về false → từ chối ghi
  -->
Trong strict mode, khi trap set trả về false, JavaScript ném TypeError ngay tại phép gán thứ hai.
Điểm cần nhớ :
return true: cho phép thao tác ghi 
return false : tư chối thao tác ghi 
throw new TypeError(...): chủ động ném lỗi với thông báo cụ thể
Lưu ý: Nếu không ở strict mode, phép gán bị từ chối nhưng không ném lỗi; khi đó user.age vẫn là 25.

* Iteration with “ownKeys” and “getOwnPropertyDescriptor”
1. Mục đích

Ơ phần trước ,bạn đã học cách set và get để kiểm soát thao tác đọc và ghi property
Phần này giải quyết một vấn đề khác:
Làm thế nào để kiểm soát danh sách Propety được trả về khi duyệt hoặc lấy keys của 1 object
Proxy cung cấp trap ownKeys để can thiệp vào thao tác lấy danh sách property keys của object.

2. ownKeys trap
ownKeys được gọi khi JS cần lấy danh sách các property keys của object.
Cú pháp :
<!-- 
const proxy = new Proxy(target, {
    ownKeys(target) {
        // Trả về danh sách property keys
    }
});
 -->
Theo tài liệu, các phương thức và thao tác sau sử dụng internal method [[OwnPropertyKeys]], được can thiệp bởi ownKeys:
- Object.getOwnPropertyNames()
- Object.getOwnPropertySymbols()
- Object.keys(), Object.values(), Object.entries()
- for...in
Các phương thức này có cách xử lý khác nhau sau khi lấy danh sách keys
3. Ví dụ gốc: Ẩn property bắt đầu bằng _
Giả sử object có thông tin :
 <!--
 let user = {
    name: "John",
    age: 30,
    _password: "***"
};
-->
Chúng ta muốn khi duyệt object thỉ bỏ qua property bắt đầu bằng _.
Sủ dụng Proxy :
<!-- 
user = new Proxy(user, {
    ownKeys(target) {
        return Object.keys(target).filter(
            key => !key.startsWith('_')
        );
    }
});
 -->
Kết quả:
<!-- 
for (let key in user) {
    console.log(key);
}
// name
// age

console.log(Object.keys(user));
// ['name', 'age']

console.log(Object.values(user));
// ['John', 30]
 -->
Giải thích:
1. ownKeys lấy danh sách keys từ object gốc
2. filter() loại bỏ những key bằng _
3. Trả về danh sách key đã lọc 
4. Các thao tác duyệt object sử dụng dang sách key này

4. Vì sao chỉ dùng ownKeys đôi khi chưa đủ?
Đây là điểm quan trọng nhất của phần này.
Tài liệu đưa ra ví dụ:
<!-- 
let user = {};

user = new Proxy(user, {
    ownKeys(target) {
        return ['a', 'b', 'c'];
    }
});

console.log(Object.keys(user));
// []
 -->
Tại sao ownKeys trả về ['a', 'b', 'c'] nhưng Object.keys() lại trả về mảng rỗng?
Lý do: Object.keys() không chỉ lấy danh sách keys.
Nó còn kiểm tra property có tồn tại và có enumerable: true hay không.
Trong ví dụ trên, object gốc không có các property a, b, c, nên không có descriptor tương ứng để xác định chúng có enumerable hay không.
Do đó, chúng bị bỏ qua.
5. getOwnPropertyDescriptor trap
Cú pháp:
<!-- 
const proxy = new Proxy(target, {
    getOwnPropertyDescriptor(target, property) {
        // Trả về property descriptor
    }
});
 -->
 Ví dụ theo tài liệu:
 <!-- 
 let user = {};

user = new Proxy(user, {
    ownKeys(target) {
        return ['a', 'b', 'c'];
    },

    getOwnPropertyDescriptor(target, prop) {
        return {
            enumerable: true,
            configurable: true
        };
    }
});

console.log(Object.keys(user));
// ['a', 'b', 'c']
  -->
Điều gì xảy ra?
- ownKeys : cung cấp danh sách a ,b,c
- getOwnPropertyDescriptor : được gọi để lấy descriptor của từng property
- Trả về enumerable: true , vì vậy Object.keys() có thể liệt kê các keys này.
Tài liệu lưu ý: Chúng ta chỉ cần can thiệp vào [[GetOwnProperty]] khi property không tồn tại trong object gốc.


6. Bổ sung ngoài tài liệu gốc – Những điểm dễ nhầm
Trường hợp 1: Object.keys() và Object.getOwnPropertyNames() khác nhau.
<!-- 
const user = {};

Object.defineProperty(user, 'name', {
    value: 'Martin',
    enumerable: false
});

console.log(Object.keys(user));
// []

console.log(Object.getOwnPropertyNames(user));
// ['name']
 -->
Object.keys() chỉ lấy own enumerable string keys.
Object.getOwnPropertyNames() lấy tất cả own string keys, kể cả non-enumerable.

Trường hợp 2: ownKeys không chỉ trả về string.
Nó cũng có thể trả về Symbol keys.
<!-- 
const key = Symbol('id');

const proxy = new Proxy({}, {
    ownKeys() {
        return ['name', key];
    }
});

console.log(Reflect.ownKeys(proxy));
// ['name', Symbol(id)]
 -->
Trường hợp 3: Proxy có invariants đối với ownKeys.
Không thể tuỳ ý ẩn mọi property.
Ví dụ, một property non-configurable trên target bắt buộc phải xuất hiện trong danh sách do ownKeys trả về .
Nếu vi phạm, JavaScript sẽ ném TypeError.

7. Liên hệ thực tế
Trong frontend/backend, hai trap này có thể hữu ích khi:
- Tạo object có danh sách property được kiểm soát.
- Ẩn các trường nội bộ khỏi thao tác liệt kê.
- Xây dựng object giả lập hoặc object có hành vi đặc biệt.
- Tạo lớp trung gian để kiểm soát cách dữ liệu được truy xuất.
Bài tập thức hành :
<!-- 
const user = {};

const proxy = new Proxy(user, {
    ownKeys() {
        return ['name'];
    },

    getOwnPropertyDescriptor() {
        return {
            enumerable: true,
            configurable: true
        };
    }
});

console.log(Object.keys(proxy));
 -->
Hai trap phối hợp với nhau:
1. ownKeys() trả về danh sách ['name'].
2. getOwnPropertyDescriptor() trả về enumerable: true.
3. Object.keys() lấy key có enumerable là true.

*******************************************************************************************************************
* Protected properties with “deleteProperty” and other traps
Phần này giải quyết vấn đề : làm thế nào để ngăn người dùng xóa những property được xem là cẩn bảo vệ của 1 object ?
Ví dụ, object có các property bắt đầu bằng _ là property nội bộ.Ta muốn đọc được chúng , nhưng không cho phép xoá 
thông qua Proxy
1. Quy ước property bắt đầu bằng _
JS có 1 quy ước phổ biến : property hoặc method bắt đầu bằng _ được xem là thành phần nội bộ , không nên truy cập từ bên ngoài object
<!-- 
let user = {
  name: "John",
  _password: "secret"
};

console.log(user._password); // secret
 -->
Nhưng đây chỉ là quy ước đặt tên, không phải cơ chế bảo mật thực sự . JS vẫn cho phép truy cập _password
Tài liệu sử dụng Proxy để chặn bốn loại thao tác:
| Trap             | Thao tác bị kiểm soát  |
| ---------------- | ---------------------- |
| `get`            | Đọc property           |
| `set`            | Ghi property           |
| `deleteProperty` | Xóa property           |
| `ownKeys`        | Lấy danh sách property |
2. Ví dụ trong tài liệu
<!-- 
let user = {
  name: "John",
  _password: "***"
};

user = new Proxy(user, {
  get(target, prop) {
    if (prop.startsWith('_')) {
      throw new Error("Access denied");
    }

    let value = target[prop];

    return (typeof value === 'function')
      ? value.bind(target)
      : value;
  },

  set(target, prop, val) {
    if (prop.startsWith('_')) {
      throw new Error("Access denied");
    } else {
      target[prop] = val;
      return true;
    }
  },

  deleteProperty(target, prop) {
    if (prop.startsWith('_')) {
      throw new Error("Access denied");
    } else {
      delete target[prop];
      return true;
    }
  },

  ownKeys(target) {
    return Object.keys(target).filter(
      key => !key.startsWith('_')
    );
  }
});
 -->
Kết quả:
<!-- 
user._password;          // Error: Access denied
user._password = "test"; // Error: Access denied
delete user._password;   // Error: Access denied

Object.keys(user);       // ["name"]
 -->
Điểm cần hiểu:
- get: chặn việc đọc propety bắt đầu bằng _
- set : chặn việc ghi property bắt đầu bằng _
- deleteProperty : chặn việc xóa property bắt đầu bằng _.
- ownKeys: loại bỏ property bắt đầu bằng _ khỏi danh sách key.

Lưu ý: ownKeys chỉ kiểm soát danh sách key được liệt kê . Nó không tự chặn việc đọc , ghi hay xoá property

3. Tại sao phải dùng value.bind(target)?
Tài liệu đặt ra tình huống: method bên trong object cần truy cập _password của chính object đó.
Ví dụ :
<!-- 
let user = {
  _password: "secret",

  checkPassword(value) {
    return value === this._password;
  }
};
 -->
 Nếu lấy method thông qua Proxy và gọi:
 <!-- user.checkPassword("secret"); -->
 Khi method chạy :
 <!-- this._password -->
Nó kích hoạt get trap, bị chặn bởi điều kiện :
<!-- 
if (prop.startsWith('_')) {
  throw new Error("Access denied");
}
 -->
Kết quả: method checkPassword() không thể kiểm tra mật khẩu.
Cách giải quyết của tài liệu :
<!-- 
let value = target[prop];

return (typeof value === 'function')
  ? value.bind(target)
  : value;
 -->
bind(target) tạo một function mới có this cố định là object gốc target
Vì vậy :
<!-- user.checkPassword("secret"); // true -->
Khi method truy cập this._password, nó truy cập trực tiếp object gốc , không đi qua Proxy
4. Hạn chế của cách dùng bind(target)
Method có thể truyền object gốc target ra bên ngoài, khiến nơi khác có thể truy cập object mà không qua Proxy.
Một object có thể được bọc bởi nhiều Proxy khác nhau. Việc truyền object gốc thay vì Proxy có thể gây ra hành vi không mong muốn.
Vì vậy, không nên sử dụng kiểu Proxy này một cách tùy tiện ở mọi nơi.
5. Private properties of a class
JS hiện đại đã hỗ trợ private properties trong class bằng ký hiệu #.
<!-- 
class User {
  #password = "secret";

  checkPassword(value) {
    return value === this.#password;
  }
}

const user = new User();

user.checkPassword("secret"); // true

user.#password; // SyntaxError nếu truy cập từ bên ngoài class
 -->
Khác với _password, #password được JavaScript bảo vệ bằng cơ chế private thực sự.
Và hiểu được lý do bind(target) xuất hiện trong get: giữ cho method sử dụng object gốc làm this, tránh việc truy cập property nội bộ lại đi qua Proxy.

*******************************************************************************************************************
Hểu cách sử dụng has trap để kiểm soát toán tử in

* “In range” with “has” trap
1. Mục đích
Toán tử in để kiểm tra một property có tồn tại trong object hay không , bao gồm cả propety được kế thừa từ prototype
<!-- 
const user = {
  name: "John",
  age: 25
};

console.log("name" in user); // true
console.log("email" in user); // false
 -->
Với Proxy, ta có thể thay đổi kết quả kiểm tra này thông qua has trap
2. Cú pháp has
<!-- 
const proxy = new Proxy(target, {
  has(target, property) {
    // Trả về true hoặc false
  }
});
 -->
- target : object gốc
- property : tên property đang được kiểm tra
- Giá trị trả về: true hoặc false.
Trap này được gọi khi sử dụng toán tử in
3. Ví dụ “In range”
Tài liệu sử dụng Proxy để tạo một object đại diện cho một khoảng số.
<!-- 
let range = {
  start: 1,
  end: 10
};

range = new Proxy(range, {
  has(target, property) {
    return property >= target.start &&
           property <= target.end;
  }
});

console.log(5 in range);  // true
console.log(50 in range); // false
 -->
4. Điểm cần chú ý
has không kiểm tra property theo cách thông thường nữa
Trong ví dụ trên:
<!-- "start" in range; -->
Kết quả là false , bởi vì "start" không nằm trong khoảng từ 1 đến 10
Đây là hành vi do ta tự định nghĩa trong has trap.
Bổ sung ngoài tài liệu gốc – Case dễ nhầm
in luôn truyền tên property dưới dạng string hoặc symbol vào trap
<!-- 
const proxy = new Proxy({}, {
  has(target, property) {
    console.log(typeof property);
    return true;
  }
});

console.log(5 in proxy);
 -->
Ngoài ra , has trap có các invariant : không được tùy ý trả về false để che dấu nhưungx own property không configurable hoặc những property không thể bị xóa khỏi target theo quy định của Proxy.
<!-- 
const range = new Proxy(
  { start: 1, end: 10 },
  {
    has(target, property) {
      return property >= target.start &&
             property <= target.end;
    }
  }
);

console.log(8 in range);
console.log("start" in range);
 -->
Điểm cần nhớ: has trap nhận tên property , nhưng ta có thể tự định nghĩa cách kiểm tra property đó

*******************************************************************************************************************
* Wrapping functions: "apply"
TÌm hiểu cách dùng Proxy để bọc 1 function và kiểm soát cách function được gọi 
Ta đã học các trap dành cho object như : get , set ,deleteProperty , ownKeys ,has . Với function , JS còn trap là apply
1. Mục đích
function cũng là một object đặc biệt có thể gọi được.
Ta có thể tạo Proxy cho function để can thiệp vào quá trình gọi function đó
Ví dụ:
<!-- 
function sayHi(name) {
  return `Hello, ${name}`;
}

const proxy = new Proxy(sayHi, {});

console.log(proxy("Martin")); // Hello, Martin
 -->
Vì handler chưa khai báo trap nên chuyển đến funtion gốc
2. apply trap
Cú pháp:
<!-- 
const proxy = new Proxy(target, {
  apply(target, thisArg, args) {
    // Xử lý trước hoặc sau khi gọi function
  }
});
 -->
 | Tham số   | Ý nghĩa                              |
 | --------- | ------------------------------------ |
 | `target`  | Function gốc                         |
 | `thisArg` | Giá trị `this` khi function được gọi |
 | `args`    | Mảng các đối số truyền vào           |

apply được kích hoạt khi Proxy function được gọi bằng cách như :
<!-- 
proxy();
proxy.call(thisArg, arg1);
proxy.apply(thisArg, [arg1]);
 -->
Lưu ý: target phải là 1 functio có thể gọi được thì mới sử dụng được apply trap

3. Ví dụ trong tài liệu: delay(f, ms)
Tài liệu nhắc lại bài Decorators and forwarding, call/apply.
Mục tiêu: tạo function delay(f, ms) để trì hoãn việc thực thi function f trong ms 

Cách 2: Dùng Proxy với apply
<!-- 
function delay(f, ms) {
  return new Proxy(f, {
    apply(target, thisArg, args) {
      setTimeout(() => target.apply(thisArg, args), ms);
    }
  });
}

function sayHi(user) {
  console.log(`Hello, ${user}!`);
}

sayHi = delay(sayHi, 3000);

console.log(sayHi.length); // 1

sayHi("John"); // Hello, John! sau 3 giây
 -->
Điểm khác biệt:
- apply trap can thiệp vào lúc gọi funcion
- Các thao tác như đọc sayHi.length vẫn được Proxy chuyển đến function gốc
- - Vì vậy, sayHi.length vẫn là 1.
4. Điều cần hiểu về apply
Trong ví dụ:
<!--
apply(target, thisArg, args) {
  setTimeout(() => {
    target.apply(thisArg, args);
  }, ms);
}
-->
Có 3 thành phần quan trọng :
- target: function gốc cần gọi.
- thisArg : gía trị this của lần gọi ban đầu
- args : các đối số được truyền vào 
Ta dùng:
<!-- target.apply(thisArg, args); -->
để gọi function gốc với đúng this và sanh sách đối số ban đầu
Lưu ý dễ nhầm: apply trap không bắt buộc phải trả về fucntion gốc .Trong ví dụ delay, nó lên lịch thực thi bằng setTimeout ,
nên kết quả của lời gọi Proxy là undefined

Bổ sung ngoài tài liệu gốc – Liên hệ React và Backend
- React : có thể gặp Proxy trong các thư viện quản lý state hoặc theo dõi thay đổi dữ liệu . Tuy nhiên, không cần tự viết apply 
trap khi phát triển component thông thường
- Backend : có thể dùng apply để ghi lời gọi function , đo thời gian thực thi hoặc kiểm soát việc gọi function
Ví dụ minh họa logging:
<!-- 
function logCalls(fn) {
  return new Proxy(fn, {
    apply(target, thisArg, args) {
      console.log("Function called:", target.name);
      return Reflect.apply(target, thisArg, args);
    }
  });
}
 -->
Ở đây Reflect.apply sẽ được học trong phần tiếp theo của tài liệu.
Tổng kết:
Bạn cần nhớ:
1. Function cũng có thể kiểm soát bằng Proxxy
2. apply trap kiểm soát thao tác gọi function
3. Wrapper function không tự động chuyển tiếp các property của function gốc.
4. Proxy chuyển tiếp những thao tác không có trap tương ứng đến target.

Bài tập kiểm tra :
<!-- 
function multiply(a, b) {
  return a * b;
}

const proxy = new Proxy(multiply, {
  apply(target, thisArg, args) {
    console.log("Calling function");
    return target.apply(thisArg, args);
  }
});

console.log(proxy(2, 3));
 -->
Giải thích:
1. proxy(2, 3) kích hoạt apply trap
2. console.log("Calling function") in ra thông báo
3. target.apply(thisArg, args) gọi function gốc multiply(2, 3).
4. return trả kết quả 6 về bên ngoài

Điểm quan trọng: Nếu không có return trước target.apply(...), kết quả của proxy(2, 3) sẽ là undefined.

*******************************************************************************************************************
* Reflect
Phần này giải quyết một vấn đề quan trọng khi làm việc với Proxy : làm thế nào thực hiện thao tác mặc định của JS bên trong trap
mà vẫn giữ đúng hành vi gốc
1. Reflect là gì?
Reflect là 1 built in object cung cấp các method tương ứng với nhiều internal operation của JS
Ví dụ:
<!-- 
const user = {
  name: "John"
};

console.log(Reflect.get(user, "name")); // John
console.log(Reflect.set(user, "age", 25)); // true
console.log(Reflect.has(user, "name")); // true
console.log(Reflect.deleteProperty(user, "name")); // true
 -->
Điểm cần nhớ: Reflect không phải là 1 Proxy và cũng k tự tạo Proxy . Nó cung cấp các mehthod để thực hiện 
những thao tác tương ứng với internal operations.

2. Dùng Reflect bên trong Proxy
Xét ví dụ:
<!-- 
const user = {
  name: "John"
};

const proxy = new Proxy(user, {
  get(target, property, receiver) {
    console.log(`Getting ${property}`);

    return Reflect.get(target, property, receiver);
  }
});

console.log(proxy.name);
 -->
 1. Truy cập proxy.name.
 2. JS kích hoạt get trap
 3. Trap ghi log 
 4. Reflect.get() thực hiện thao tác đọc property theo hành vi mặc định 
 5. Giá trị John được trả về
Nếu chỉ viết:
<!-- return target[property]; -->
Khi muốn trap thực hiện hành vi mặc định trên target, ta có thể dùng Reflect để chuyển tiếp thao tác.
4. Ví dụ trong tài liệu: Chuyển tiếp thao tác với Reflect
<!-- 
let user = {
  name: "John"
};

user = new Proxy(user, {
  get(target, prop, receiver) {
    alert(`GET ${prop}`);
    return Reflect.get(target, prop, receiver); // (1)
  },

  set(target, prop, val, receiver) {
    alert(`SET ${prop}=${val}`);
    return Reflect.set(target, prop, val, receiver); // (2)
  }
});

let name = user.name; // GET name
user.name = "Pete";   // SET name=Pete
 -->
Giải thích :
Reflect.get(target, prop, receiver): đọc property theo hành vi mặc định 
Reflect.set(target, prop, val, receiver) : ghi property theo hành vi mặc định 
Reflect.set() trả về true nếu ghi thành công, false nếu không thành công.

Tại sao cần receiver?
5. Proxying a getter
Phần này giải quyết một lỗi tinh tế: khi object kế thừa từ Proxy , getter có thể nhận sai giá trị this 
nếu ta dùng target[prop].
Xét object:
<!-- 
let user = {
  _name: "Guest",

  get name() {
    return this._name;
  }
};
 -->
Getter name trả về this._name.
Bây giờ bọc object bằng Proxy:
<!-- 
let userProxy = new Proxy(user, {
  get(target, prop, receiver) {
    return target[prop];
  }
});
 -->
 Khi đọc:
 <!-- console.log(userProxy.name); // Guest -->
 Nhưng xet nếu trường hợp kế thừa :
 Trường hợp lỗi trong tài liệu:
 <!-- 
 let user = {
  _name: "Guest",

  get name() {
    return this._name;
  }
};

let userProxy = new Proxy(user, {
  get(target, prop, receiver) {
    return target[prop];
  }
});

let admin = {
  __proto__: userProxy,
  _name: "Admin"
};

console.log(admin.name); // Guest (?!)
  -->
1. admin không có property name, nên JS tìm kiếm trong prototype
2. Prototype của admin là userProxy.
3. get trap được kích hoạt 
4. Trap thực hiện target[prop].
5. Vì name là getter, target[prop] gọi getter với this = target tức object user
6. Getter đọc user._name, nhận "Guest".
Vấn đề nằm ở chỗ getter nhận sai this.
Cách sửa bằng Reflect:
<!-- 
let userProxy = new Proxy(user, {
  get(target, prop, receiver) {
    return Reflect.get(target, prop, receiver);
  }
});
 -->
 receiver trong trường hợp này là admin 
 Reflect.get(target, prop, receiver) giúp getter nhận đúng receiver làm this , thay vì mặc định dùng target
Vì Reflect sử dụng cùng tên và tham số tương ứng với Proxy trap.

Bổ sung ngoài tài liệu gốc – Những điểm dễ nhầm
1. target[prop] không phải lúc nào cũng tương đương Reflect.get().
Với property thông thường , 2 cách này thường cho kết quả giống nhau . Nhưng khi có getter và prototype inheritance, receiver có thể làm thay đổi giá trị this.
2. Reflect.set() không giống phép gán về giá trị trả về.
<!-- 
const result = Reflect.set({}, "name", "John");

console.log(result); // true
 -->
Reflect.set() trả về Boolean , không trả về object hoặc giá trị vừa gán
3. Reflect không tự động làm cho Proxy an toàn hơn
Nó giúp chuyển tiếp thao tác đúng hành vi theo mặc định , đặc biệt khi cần giữ receiver
Ứng dụng trong React và Backend
- React: Hiểu Reflect giúp đọc được cách các thư viện dùng Proxy để theo dõi thao tác trên object. Không cần tự viết Reflect trong component thông thường.
- Backend: Có thể dùng Proxy + Reflect để logging, monitoring hoặc kiểm soát thao tác gọi và truy cập object mà vẫn giữ hành vi gốc.

* Proxy limitations
Không phải object nào cũng có thể đọc bằng Proxy mà vẫn hoạt động giống hết object gốc
Đặc biệt, cần chú ý khi làm việc với:
- Built-in objects như Map, Set.
- Private field trong class
- So sánh Proxy với target
Roadmap của phần này:
Proxy limitations
│
├── Built-in objects: Internal slots
│
├── Private fields
│
└── Proxy != target
Mục tiêu cần nắm và áp dụng :
1. HIểu tại sao Proxy có thể làm hỏng hoạt động của một số built in object
2. HIểu lỗi khi Proxy truy cập private field
3. Phân biệt object gốc và Proxy , đặc biệt khi so sánh bằng ===
4. Biết khi nào cần tránh bọc object bằng Proxy

1. Built-in objects: Internal slots
1.1. Internal slots là gì?
Nhiều built-in objects của JavaScript như Map, Set, Date, Promise sủ dụng internal slots
Internal slots giống như vùng dữ liệu nội bộ của object nhưng:
- Không phải property thông thường. 
- Không thể truy cập trực tiếp bằng JS
- Được các built-in methods sử dụng để thực hiện các chức năng của chúng
Ví dụ: Map lưu dữ liệu bên trong internal slot [[MapData]].

1.2. Vấn đề khi dùng Proxy với Map
Xét ví dụ trong tài liệu:
<!-- 
let map = new Map();

let proxy = new Proxy(map, {});

proxy.set('test', 1); // Error
 -->
Tại sao lại lỗi?
Khi gọi :
<!-- proxy.set('test', 1); -->
Luồng thực thi:
1. JS đọc proxy.set
2. Proxy chuyển tiếp các thao tác đọc đến map, , lấy được method set
3. Method được gọi này với this = proxy
4. Bên trong Map.prototype.set, JS cần truy cập internal slot this.[[MapData]].
5. Nhưng Proxy không có internal slot [[MapData]]
6. Kết quả : TypeError
Lỗi quan trọng
Proxy không tự động sở hữu internal slots của target.

1.3. Cách giải quyết trong tài liệu
Dùng get trap kết hợp với Reflect.get() và bind(target)
<!-- 
let map = new Map();

let proxy = new Proxy(map, {
  get(target, prop, receiver) {
    let value = Reflect.get(...arguments);

    return typeof value == 'function'
      ? value.bind(target)
      : value;
  }
});

proxy.set('test', 1);

console.log(proxy.get('test')); // 1
 -->
Giải thích :
<!-- let value = Reflect.get(...arguments); -->
Lấy property theo hành vi mặc định , giữ đúng receiver

Nếu property là function, bind this về object gốc target
Khi gọi:
<!-- proxy.set('test', 1); -->
Thực tế method được gọi với :
<!-- map.set('test', 1); -->
Vì this lúc này là map , nên method được truy cập [MapData]].
1.4. Ngoại lệ: Array không gặp vấn đề này
Array không sử dụng internal slot theo cách gây ra vấn đề như Map
Vì vậy, Proxy cho Array vẫn hoạt động bình thường với các thao tác như :
<!-- 
let arr = [1, 2, 3];

let proxy = new Proxy(arr, {});

proxy.push(4);

console.log(proxy); // [1, 2, 3, 4]
 -->
Ứng dụng thực tế
- React : khi làm việc với state chưa Map hoặc Set ., cần hiểu sự khác biệt giữa object gốc và Proxy nếu thư viện 
sử dụng Proxy để theo dõi dữ liệu
- Backend : Nếu dùng proxy để logging hoặc monitoring các object như Map , cần chú ý this của built in method

2. Private fields
Proxy không thể truy cập private field của object gốc thông qua chính Proxy đó
2.1. Ví dụ trong tài liệu
<!-- 
class User {
  #name = "Guest";

  getName() {
    return this.#name;
  }
}

const user = new User();

console.log(user.getName()); // Guest
 -->
Private field #name chỉ có thể truy câp bên trong class User
Bây giờ bọc object bằng Proxy:
<!-- 
const user = new User();

const proxy = new Proxy(user, {});

console.log(proxy.getName()); // TypeError
 -->
Tại sao lại lỗi?
Luồng thực thi:
1. Gọi proxy.getName().
2. Proxy chuyển tiếp việc đọc method getName đến user
3. Method được gọi với this = proxy.
4. Bên trong method, this.#name được thực thi.
5. Proxy không phải object đã được class User khởi tạo private field #name
6. JavaScript ném TypeError. 

2.2. Cách giải quyết
Giống vấn đề với Map, ta có thể bind method về object gốc.
<!-- 
class User {
  #name = "Guest";

  getName() {
    return this.#name;
  }
}

const user = new User();

const proxy = new Proxy(user, {
  get(target, prop, receiver) {
    const value = Reflect.get(target, prop, receiver);

    return typeof value === "function"
      ? value.bind(target)
      : value;
  }
});

console.log(proxy.getName()); // Guest
 -->
3. Proxy != target
Proxy và target là 2 object khác nhau , dù Proxy đại diện cho target
3.1. Ví dụ cơ bản
<!-- 
const target = {};

const proxy = new Proxy(target, {});

console.log(proxy === target); // false
 -->
Tại sao?
- target : object gốc
- proxy : object mới được tạo bởi new Proxy()
- Proxy chuyển tiếp các thao tác đến target , nhưng không phải chính target
3.2. Ảnh hưởng khi so sánh object
<!-- 
const target = { name: "Martin" };
const proxy = new Proxy(target, {});

console.log(target === proxy); // false
 -->
Hai object có thể truy cập cùng dữ liệu , nhưng phép so sánh vẫn là false
3.3. Ảnh hưởng khi dùng object làm Map key
<!-- 
const target = {};
const proxy = new Proxy(target, {});

const map = new Map();

map.set(target, "Original");
map.set(proxy, "Proxy");

console.log(map.get(target)); // Original
console.log(map.get(proxy));  // Proxy
console.log(map.size);        // 2
 -->
Tại sao có hai phần tử?
target và proxy là hai object khác nhau nên được xem là hai key khác nhau.
3.4. Ảnh hưởng khi dùng WeakMap
Tương tự Map, WeakMap cũng xem target và proxy là hai key khác nhau.
<!-- 
const target = {};
const proxy = new Proxy(target, {});

const weakMap = new WeakMap();

weakMap.set(target, "Original");
weakMap.set(proxy, "Proxy");

console.log(weakMap.get(target)); // Original
console.log(weakMap.get(proxy));  // Proxy
 -->
3.5. Tại sao điều này quan trọng?
Khi 1 thư viện sử dụng Proxy để theo dõi Object , cps thể xuát hiên tình huống :
<!-- 
const original = {};
const reactive = new Proxy(original, {});

console.log(original === reactive); // false
 -->
Nếu một phần code sử dụng original, phần khác sử dụng reactive, việc tra cứu theo object identity có thể cho kết quả khác nhau
Bổ sung ngoài tài liệu gốc – Liên hệ React
Một số thư viện quản lý state dùng Proxy để tạo object reactive.
Ba điều cần nhớ:
1. Proxy không tự sở hữu internal slots của target.
2. Private fields yêu cầu truy cập từ đúng instance.
3. Proxy và target không bằng nhau khi so sánh bằng ===
<!-- 
const target = { name: "Martin" };
const proxy = new Proxy(target, {});

const map = new Map();

map.set(target, 100);

console.log(map.get(proxy)); -->

Kết quả là gì?

A. 100 vì Proxy đại diện cho target.

B. undefined vì Proxy và target là hai object khác nhau.

C. null vì Proxy không thể làm Map key.

D. TypeError vì Map không hỗ trợ Proxy.

* Revocable proxies
tạo Proxy có thể bị vô hiệu hóa sau khi sử dụng.
Thông thương sau khi tạo Proxy bằng new Proxy() , ta không có phương thức trực tiếp để tắt Proxy đó
JS cung cấp Proxy.revocable() để giải quyết vấn đề này

1. Proxy.revocable()
<!-- const { proxy, revoke } = Proxy.revocable(target, handler); -->
Phương thức trả về một object gồm hai thành phần:
| Thành phần | Ý nghĩa                            |
| ---------- | ---------------------------------- |
| `proxy`    | Proxy được tạo ra                  |
| `revoke`   | Function dùng để vô hiệu hóa Proxy |
2. Ví dụ
<!-- 
const target = {
  name: "Martin"
};

const { proxy, revoke } = Proxy.revocable(target, {});

console.log(proxy.name); // Martin

revoke();

console.log(proxy.name); // TypeError
 -->
Giải thích:
1. Proxy.revocable() tạo Proxy và function revoke.
2. Trước khi gọi revoke(), Proxy hoạt động bình thường.
3. Gọi revoke() để vô hiệu hóa Proxy.
4. Sau đó, mọi thao tác tương tác với Proxy đều gây TypeError.
Lưu ý: revoke() không xoá object gốc target . Nó chỉ vô hiệu hoá Proxy
3. Trường hợp sử dụng trong tài liệu
có một resource chứa dữ liệu quan trọng và muốn chia sẻ quyền truy cập cho nơi khác , nhưng vẫn có khả năng đóng quyền truy cập 
bất cứ lúc nào
<!-- 
let object = {
  data: "Valuable data"
};

let { proxy, revoke } = Proxy.revocable(object, {});

// Truyền proxy cho nơi khác thay vì truyền object gốc
console.log(proxy.data); // Valuable data

// Sau đó đóng quyền truy cập
revoke();

console.log(proxy.data); // TypeError
 -->
 Ý tưởng:
- Nơi nhận chỉ được cung cấp proxy.
- Code quản lý resource giữ lại revoke.
- Khi không muốn cho phép truy cập nữa, gọi revoke().
4. Điều gì xảy ra sau khi gọi revoke()?
revoke() loại bỏ các tham chiếu nội bộ từ Proxy đến target và handler
Điều này có nghĩa:
- Proxy không còn hoạt động.
- Proxy không còn kết nối với target.
- Nếu target không còn được tham chiếu ở nơi khác, nó có thể bị GC thu hồi
- Gọi revoke() lần nữa không gây lỗi, cũng không khôi phục Proxy
<!-- 
const target = { name: "Martin" };

const { proxy, revoke } = Proxy.revocable(target, {});

revoke();
revoke(); // Không có lỗi

console.log(proxy.name); // TypeError
 -->
Lưu ý: biến target vẫn có thể truy cập bình thường nếu còn tham chiếu đến nó:
5. Lưu trữ revoke bằng WeakMap
Tài liệu giới thiệu thêm một cách quản lý nhiều revocable proxies.
<!-- 
let revokes = new WeakMap();

let object = {
  data: "Valuable data"
};

let { proxy, revoke } = Proxy.revocable(object, {});

revokes.set(proxy, revoke);

// Ở một nơi khác trong chương trình
revoke = revokes.get(proxy);
revoke();

console.log(proxy.data); // Error
 -->
Tại sao dùng WeakMap thay vì Map?
Nếu dùng Map, key là proxy sẽ giữ tham chiếu mạnh đến Proxy . Điều này có thể khiến Proxy không đựic GC thu hồi khi k còn được sử dụng ở nơi khác
Bổ sung ngoài tài liệu gốc – Case dễ nhầm
1. Revoke không xóa target
<!-- 
revoke();

console.log(target.name); // Vẫn truy cập được
 -->
2. Revoke không thể khôi phục
Muốn sử dụng lại, phải tạo một Proxy mới.
3. typeof proxy vẫn hoạt động
<!-- 
revoke();

console.log(typeof proxy); // "object"
 -->
Vì typeof không kích hoạt thao tác thông qua Proxy trap
Ứng dụng thực tế
- React: Ít khi cần tự tạo revocable Proxy trong component. Có thể gặp khái niệm này khi nghiện cứu thư viện hoặc quản lý vòng đởi resource
- Backend : có thể giới hạn truy câp object được chia sẻ cho mdule hoặc hoằn thành phần khác . Tuy nhiên, đây không phải cơ chế thay thế authorization.
<!-- 
const target = { name: "Martin" };

const { proxy, revoke } = Proxy.revocable(target, {});

revoke();

console.log(target.name);
console.log(proxy.name);
 -->
Ghi nhớ : revoke chỉ vô hiệu hoá Proxy , không xoá hoặc vô hiệu hoá target

* Summary

Các nội dung chính bạn vừa học:
- Proxy : tạo đối tượng đại diện cho target
- get, set: kiểm soát đọc và ghi property.
- ownKeys, getOwnPropertyDescriptor: kiểm soát viêc liệt kê property
- deleteProperty : kiểm soát xoá property
- has: kiểm soát toán tử in.
- apply: kiểm soát việc gọi function.
- Reflect : thực hiện các internal operations theo hành vi mặc định 
- Proxy limitations: các giới hạn internal slots, private fields và object identity.

1. Proxy
Proxy cho phép tạo 1 đối tượng đại diện cho object hoặc function khác , từ đó can thiệp vào các thao tác tương ứng
<!-- const proxy = new Proxy(target, handler); -->
1. Các traps cần nhớ
| Trap                       | Chức năng                   |
| -------------------------- | --------------------------- |
| `get`                      | Đọc property                |
| `set`                      | Ghi property                |
| `has`                      | Kiểm tra property bằng `in` |
| `deleteProperty`           | Xóa property                |
| `ownKeys`                  | Lấy danh sách keys          |
| `getOwnPropertyDescriptor` | Lấy property descriptor     |
| `defineProperty`           | Định nghĩa property         |
| `apply`                    | Gọi function                |
| `construct`                | Khởi tạo object bằng `new`  |
1. Reflect
Reflect cung cấp các method tương ứng với nhiều internal operations.
<!-- 
Reflect.get(target, property, receiver);
Reflect.set(target, property, value, receiver);
Reflect.has(target, property);
Reflect.deleteProperty(target, property);
Reflect.apply(target, thisArg, args);
 -->
Đặc biệt chú ý receiver khi làm việc với getter/setter và prototype inheritance.
1. Proxy limitations
Ba giới hạn quan trọng:
- Built-in objects: internal slots có thể không hoạt động khi this là Proxy.
- Private fields: yêu cầu truy cập từ đúng instance.
- Proxy != target: hai object có identify khác nhau

1. Revocable proxies
<!-- 
const { proxy, revoke } = Proxy.revocable(target, handler);
revoke();
 -->
Sau khi gọi revoke(), Proxy không thể tiếp tục được sử dung , nhưng target vẫn còn tồn tại nếu còn tham chiếu

1. Error on reading non-existent property

<!-- 
const user = {

Đề bài yêu cầu tạo một Proxy để nem lỗi khi propety không tồn tại  thay vì trả về undefined
Mục đích : phát hiện lỗi lập trình sớm hơn

2. Accessing array[-1]
2.1. Yêu cầu bài tập
Trong JavaScript, khi truy cập phần tử bằng index âm:
<!-- 
const array = [1, 2, 3];

console.log(array[-1]); // undefined
console.log(array[-2]); // undefined
 -->
Thông thường JS không hiểu index âm từ vị trị cuối mảng
Bài tập yêu cầu sử dụng Proxy để hỗ trợ:
array[-1] → phần tử cuối cùng.
array[-2] → phần tử kế cuối.
Các chức năng khác của Array vẫn hoạt động bình thường.
3. Observable
3.1. Yêu cầu bài tập
Bài tập yêu cầu tạo hàm makeObservable(target) để biến 1 object thành object có khả năng theo dõi sự thay đổi propety
1. makeObservable(target) trả về một Proxy.
2. Object trả về có phương thức observe(handler) để đăng ký một callback.
3. Khi propety được thay đổi , callback được gọi với 2 tham số:
- key: tên property thay đổi.
- value: giá trị mới.
Ví dụ kết quả mong muốn:
<!-- 
let user = {
    name: "John",
    age: 30
};

user = makeObservable(user);

user.observe((key, value) => {
    console.log(`SET ${key}=${value}`);
});

user.name = "Pete"; // SET name=Pete
user.age = 31;      // SET age=31
 -->
3.2. Gợi ý kiến thức cần áp dụng
