Sau bài học, bạn cần có thể:

2. Hiểu prototype chain khi kế thừa class.
3. Ghi đè method của class cha.

1. The "extends" keyword
1.1. Basic inheritance
Kế thừa (Inheritance) là cơ chế cho phép một class mở rộng 1 class khác , sử dụng lại chức năng và thuộc tính 
dông thời bổ sung tính năng khác
<!-- 
class Animal {
    constructor(name) {
        this.speed = 0;
        this.name = name;
    }

    run(speed) {
        this.speed = speed;
        console.log(`${this.name} runs with speed ${this.speed}.`);
    }

    stop() {
        this.speed = 0;
        console.log(`${this.name} stands still.`);
    }
}
 -->
Thỏ cũng là động vật nên có thể sử dụng lại các chức năng của Animal.
Ta viết:
<!-- 
class Rabbit extends Animal {
    hide() {
        console.log(`${this.name} hides!`);
    }
}
 -->
 const rabbit = new Rabbit("White Rabbit");

rabbit.run(5);
rabbit.hide();
Giải thích:
-Giải thích:
extends Animal: khai báo Rabbit kế thừa Anial
rabbit.run(5) : sủ dụng method được kế thừa từ animal
rabbit.hide(): sử duungj method do chính Rabbit khai báo

1.2. Prototype inheritance with extends
JS sử dung cơ chế prototype inheritance phía bên dưới
Khi viết:
<!-- class Rabbit extends Animal {} -->
JavaScript thiết lập quan hệ:
<!-- Rabbit.prototype.__proto__ === Animal.prototype;
// true -->
Điều đó có nghĩa là Rabbit.prototype kế thừa Animal.prototype.
Khi gọi :
<!-- rabbit.run(5); -->
JavaScript tìm method run theo thứ tự:
1. Tìm trong object rabbit
2. Không thấy tìm trong Rabbit.prototype.
3. Không thấy, tiếp tục tìm trong Animal.prototype.
4. Tìm thấy run() và thực thi

Bài tập thực hành :
<!-- 
class Animal {
    run() {
        console.log("Animal runs");
    }
}

class Rabbit extends Animal {
    hide() {
        console.log("Rabbit hides");
    }
}

const rabbit = new Rabbit();

console.log(rabbit.hasOwnProperty("run"));
console.log(rabbit.hasOwnProperty("hide"));
console.log(Rabbit.prototype.__proto__ === Animal.prototype);
 -->
run() nằm trong Animal.prototype, không nằm trực tiếp trên rabbit.
hide() nằm trong Rabbit.prototype, không nằm trực tiếp trên rabbit.
Rabbit.prototype kế thừa từ Animal.prototype.

Lưu ý : hasOwnProperty() chỉ kiểm tra thuộc tính có nằm trên object hay không ,không kiểm tra thuộc tính được kế thữa
1.3. Any expression after extends
Sau extend không nhất thiết phải thêm 1 class cụ thể . Bạn có thể sử dụng biểu thức sau và trả về class
<!-- 
function f(phrase) {
    return class {
        sayHi() {
            console.log(phrase);
        }
    };
}

class User extends f("Hello") {}

new User().sayHi(); // Hello
 -->
Method sayHi() được kế thừa và sử dụng biến phrase có giá trị "Hello".
Ứng dụng: cách viết này cho phép tạo class cha 1 cách linh hoạt dựa trên kết quả của biểu thức
Phân biệt hai quan hệ quan trọng:
<!-- 
Rabbit.prototype.__proto__ === Animal.prototype; // true
Rabbit.__proto__ === Animal; // true
 -->
Quan hệ thứ nhất : kế thừa các method của instance
Quan hệ thứ hai : kế thừa các thuộc tính và method tĩnh (static) của class cha

2. Overriding a method
2.1. Overriding methods
Overriding (ghi đè phương thức) là việc class con định nghĩa lại một method là tồn tại trong class cha
Mục đích: thay đổi cách hoạt động của method được kế thừa mà không cần sửa class cha.
   <!-- 
   class Animal {
    run() {
        console.log("Animal runs");
    }
}

class Rabbit extends Animal {
    run() {
        console.log("Rabbit runs");
    }
}

const rabbit = new Rabbit();

rabbit.run(); // Rabbit runs
    -->
Khi gọi :
rabbit.run(); JS sẽ tìm theo prototype chain:
1. Tìm run trong rabbit nếu không có 
2. Tìm run() trong Rabbit.prototype: tìm thấy.
3. Thực thi Rabbit.prototype.run() và dừng tìm kiếm.

Vì vậy method run của animal không được gọi 
Ghi nhớ: Khi class con có method trùng tên với class cha, method của class con sẽ được ưu tiên khi truy cập từ instance của class con.
<!-- 
class Animal {
    speak() {
        console.log("Animal");
    }
}

class Dog extends Animal {
    speak() {
        console.log("Dog");
    }
}

const dog = new Dog();

dog.speak();
 -->
Vì Dog.prototype có method speak(), nên JavaScript tìm thấy method này trước khi tìm đến Animal.prototype.
2.2. super.method()
Khi ghi đè method, đôi khi chúng ta không muôn thay thế hoàn toàn của logic của class cha mà muộn mở rộng logic cũ
JS cung cấp từ khoá super() để gọi method cúa class cha
<!-- 
class Animal {
    run() {
        console.log("Animal runs");
    }
}

class Rabbit extends Animal {
    run() {
        super.run();
        console.log("Rabbit runs");
    }
}

const rabbit = new Rabbit();

rabbit.run();
 -->
Giải thích:
- super.run() gọi method run() của class cha
- console.log("Rabbit runs") thực hiệnlogic bổ sung của class con
Một điểm rất quan trọng: super.method() vẫn sử dụng this của instance hiện tại
<!-- 
class Animal {
    constructor(name) {
        this.name = name;
    }

    introduce() {
        console.log(`I am ${this.name}`);
    }
}

class Rabbit extends Animal {
    introduce() {
        super.introduce();
        console.log(`${this.name} is a rabbit`);
    }
}

const rabbit = new Rabbit("Bunny");

rabbit.introduce();
 -->
Mặc dù introduce() được định nghĩa trong animal nhưng this vẫn trỏ đến instance rabbit
Bài tập :
<!-- 
class Animal {
    constructor(name) {
        this.name = name;
    }

    speak() {
        console.log(`${this.name} speaks`);
    }
}

class Dog extends Animal {
    speak() {
        super.speak();
        console.log(`${this.name} barks`);
    }
}

const dog = new Dog("Lucky");

dog.speak();
 -->
2.3. Arrow functions have no super
Arrow function không có super riêng . Nó lấy super từ lexical enviroment
tương tự như arrow funtion lấy this 
<!-- 
class Animal {
    speak() {
        console.log("Animal speaks");
    }
}

class Dog extends Animal {
    speak() {
        const say = () => super.speak();

        say();
    }
}

new Dog().speak();
 -->
Ở đây:
- say là arrow function.
- Arrow function không tự tạo super.
- Nó sử dụng super từ method speak() của class Dog.
Lưu ý: k nên hiểu rằng arrow function không thể sử dụng super . Nó có thể sử dụng super nếu phạm vi bên ngoài có super hợp lệ 
<!-- 
class Animal {
    speak() {
        console.log("Animal speaks");
    }
}

class Dog extends Animal {
    speak() {
        function say() {
            super.speak(); // SyntaxError
        }

        say();
    }
}
-->
Đoạn code trên bị lỗi cú pháp vì function thông thường không có super riêng và không thể sử dụng super theo cách này.
Bạn cần nắm 3 nội dung:
1. Overriding methods:Class con định nghĩa lại method của class cha
2. super.method(): gọi method của class cha , nhưng this vẫn trỏ đến instace hiện tại 
3. Arrow functions have no super : arrow function kế thừa super từ lexical enviroment , không tự tạo super riêng

3. Overriding constructor
Đây là kiến thức quan trọng để hiểu extends, super() và cách khởi tạo object trong JS
3.1. Default constructor in derived classes
<!-- 
class Animal {
    constructor(name) {
        this.name = name;
    }
}

class Rabbit extends Animal {
}

const rabbit = new Rabbit("White Rabbit");

console.log(rabbit.name); // White Rabbit
 -->
Rabbit không khai báo constructor nhưng vẫn nhận name
Tại sao?
Khi class con kế thừa class cha mà không khai báo constructor riêng , JS tự cung cấp một constructor mặc định tương đương
<!-- 
constructor(...args) {
    super(...args);
}
 -->
Luồng hoạt động:
1. Gọi new Rabbit("White Rabbit").
2. Constructor mặc định của Rabbit nhận đối số.
3. super(...args) gọi constructor của Animal.
4. Constructor Animal khởi tạo this.name.

3.2. Why super() must be called before this
<!-- 
class Animal {
    constructor(name) {
        this.name = name;
    }
}

class Rabbit extends Animal {
    constructor(name, earLength) {
        this.name = name;
        this.earLength = earLength;
    }
}

const rabbit = new Rabbit("White Rabbit", 10);
 -->
Tại sao lại xảy ra lỗi?
constructor của class kế thừa có cách khỏi tạo this khác constructor thông thường
Constructor thông thường:JS tạo oject và gắn object đó vào this khi gọi bằng new
Derived constructor: k tự tạo this theo cách đó . Nó chờ cha constructor cha thực hiện viẹc khởi tạo
<!--
class Animal {
    constructor(name) {
        this.name = name;
    }
}

class Rabbit extends Animal {
    constructor(name, earLength) {
        super(name);

        this.earLength = earLength;
    }
}

const rabbit = new Rabbit("White Rabbit", 10);

console.log(rabbit.name);      // White Rabbit
console.log(rabbit.earLength); // 10
  -->
Luồng thực thi:
1. new Rabbit("White Rabbit", 10) gọi constructor của Rabbit.
2. super(name) gọi constructor của Animal.
3. Constructor Animal khởi tạo object và thiết lập this.name.
4. Quay lại constructor Rabbit.
5. Tiếp tục thiết lập this.earLength.

3.3. ConstructorKind: "derived"
super() bắt buộc phải đươc gọi 
<!-- [[ConstructorKind]]: "derived" -->
Constructor của class con có một internal property:
Khi gọi super(), constructor cha được thực thi và object được khởi tạo. Sau đó class con mới có thể sử dụng this.
<!-- 
class Child extends Parent {
    constructor() {
        super(); // Bắt buộc trước khi dùng this

        this.value = 10;
    }
}
-->
Bài tập :
<!-- 
class Person {
    constructor(name) {
        this.name = name;
    }
}

class Developer extends Person {
    constructor(name, language) {
        super(name);
        this.language = language;
    }
}

const dev = new Developer("Martin", "JavaScript");

console.log(dev.name);
console.log(dev.language);
 -->
Giải thích:
1. new Developer("Martin", "JavaScript") gọi constructor của Developer.
2. super(name) gọi constructor của Person.
3. Person thiết lập this.name = "Martin".
4. Quay lại Developer, thiết lập this.language = "JavaScript".
5. Hai thuộc tính đều được lưu trên instance dev.
Tổng kết mục 3 – Overriding constructor
Bạn cần nhớ 3 điểm:
- Không khai báo constructor ở class con: JavaScript tự tạo constructor mặc định gọi super(...args).
- Có constructor ở class con: Phải gọi super() trước khi sử dụng this.
- Derived constructor: Constructor của class con cần constructor cha khởi tạo this thông qua super().

4. Overriding class fields: a tricky note
4.1. Overriding class fields
Khi class con ghi đè 1 field của class cha , kết quả có thể khác với những gì bạn dự đoán
<!-- 
class Animal {
    name = 'animal';

    constructor() {
        console.log(this.name);
    }
}

class Rabbit extends Animal {
    name = 'rabbit';
}

new Animal(); // animal
new Rabbit(); // animal
 -->
 JavaScript thực hiện theo thứ tự:
1. Bắt đầu khởi tạo instance Rabbit.
2. Gọi constructor của Animal thông qua super().
3. Constructor Animal chạy và đọc this.name.
4. Lúc này field name = 'rabbit' của Rabbit chưa được khởi tạo.
5. Sau khi constructor cha hoàn thành, field của Rabbit mới được khởi tạo.
Vì vậy, trong constructor của Animal, this.name vẫn là 'animal'.
4.2. Difference between fields and methods
Trường hợp 1: Sử dụng field
<!-- 
class Animal {
    name = 'animal';

    constructor() {
        console.log(this.name);
    }
}

class Rabbit extends Animal {
    name = 'rabbit';
}

new Rabbit(); // animal
 -->
Trường hợp 2: Sử dụng method
<!-- 
class Animal {
    showName() {
        console.log('animal');
    }

    constructor() {
        this.showName();
    }
}

class Rabbit extends Animal {
    showName() {
        console.log('rabbit');
    }
}

new Rabbit(); // rabbit
 -->
Field: Field của class con chưa được khởi tạo khi constructor cha chạy.
- Method: Method của class con đã nằm trên prototype trước khi instance được tạo. Vì vậy, khi constructor cha gọi this.showName(), JavaScript tìm thấy method ghi đè của class con.

4.3. Field initialization order
| Loại class    | Thời điểm khởi tạo field                |
| ------------- | --------------------------------------- |
| Base class    | Trước khi constructor của chính nó chạy |
| Derived class | Ngay sau khi `super()` hoàn thành       |
<!-- 
class Parent {
    value = 10;

    constructor() {
        console.log(this.value);
        this.show();
    }

    show() {
        console.log("Parent");
    }
}

class Child extends Parent {
    value = 20;

    show() {
        console.log("Child");
    }
}
new Child();
 -->
 B1: Khi thực hiện new Child() khởi tạo filed của parent value: 10
 B2: Chạy constructor của parent
 Lúc này filed Child.value = 20 chưa được khởi tạo nên this.value vẫn là 10
 B3: Gọi method show()
 JS thìm theo mehtod prototype chain . Child.prototupe có show() nên method child được gọi 
 Bước 4 – Sau khi super() hoàn thành
 Filed của child mới được khỏi tạo
 Tổng kết mục 4
 | Nội dung           | Thời điểm / kết quả                                |
 | ------------------ | -------------------------------------------------- |
 | Field của Parent   | Khởi tạo trước constructor Parent                  |
 | Constructor Parent | Chạy trước khi field Child khởi tạo                |
 | Method overriding  | Có hiệu lực ngay khi constructor Parent gọi method |
 | Field của Child    | Khởi tạo sau khi `super()` hoàn thành              |

5. Super: internals, [[HomeObject]]
5.1. Why this.__proto__ does not work
<!-- 
const animal = {
    name: "Animal",

    eat() {
        console.log(`${this.name} eats.`);
    }
};

const rabbit = {
    __proto__: animal,
    name: "Rabbit",

    eat() {
        this.__proto__.eat.call(this);
    }
};

rabbit.eat(); // Rabbit eats.
 -->
Ở đây:
- rabbit.__proto__ trỏ đến animal
- this..__proto__.eat : lấy method eat() của animal
- .call(this) đảm bảo method của cha vẫn sử dụng rabbit làm this
  
5.2. [[HomeObject]]
Để giải quyết vấn đề trên JS sủ dụng một internal property gọi là [[HomeObject]].
[[HomeObject]] là gì?
Là thuộc tính nội bộ giúp JS biết method được định nghĩa bên trong object nào
<!-- 
const animal = {
    eat() {
        console.log("Animal eats");
    }
};

const rabbit = {
    __proto__: animal,

    eat() {
        super.eat();
    }
};

rabbit.eat(); // Animal eats
 -->
 Khi khai báo:
 <!-- 
 eat() {
    super.eat();
}
  -->
JavaScript ghi nhận:
<!-- rabbit.eat.[[HomeObject]] = rabbit -->
khi chạy super.eat() JS biết cần tìm method cha dựa trên prototype của rabbit thay vì dựa trên this.__proto__.
Lưu ý: [[HomeObject]] là intternal property , không thể truy cập trực tiếp bằng cú pháp JS thông thường
Giả sử:
<!-- 
const animal = {
    eat() {
        console.log("Animal eats");
    }
};

const rabbit = {
    __proto__: animal,

    eat() {
        super.eat();
    }
};

const longEar = {
    __proto__: rabbit,

    eat() {
        super.eat();
    }
};
 -->
Khi gọi longEar.eat();
JavaScript xử lý:
1. longEar.eat() có [[HomeObject]] là longEar.
2. super.eat() tìm method trên prototype của longEar, tức rabbit
3. rabbit.eat() có [[HomeObject]] là rabbit.
4. super.eat() bên trong rabbit.eat() tìm method trên prototype của rabbit , tức là animal
5. Gọi animal.eat().
Điểm quan trọng: super được xác định dựa trên [[HomeObject]], còn this vẫn là object ban đầu đang thực hiện lời gọi.
Bài tập thực hành :
<!-- 
const parent = {
    show() {
        console.log("Parent");
    }
};

const child = {
    __proto__: parent,

    show() {
        super.show();
    }
};

const instance = {
    __proto__: child
};

instance.show();
 -->
Khi gọi instance.show():
1. JavaScript tìm show() trong instance → không có.
2. Tìm trong child => tìm thấy show()
3. Method child.show() có [[HomeObject]] là child.
4. super.show() tìm method trên prototype của child, tức parent.
5. Gọi parent.show().

Ghi nhớ:
- this : object đang thực hiện lời gọi 
- super : tìm method dựa trên prototype của [[HomeObject]].

5.3. Methods are not "free"
Một method sử dụng super không thể dược xem như 1 funcion độc lập hoàn toàn , vì nó mang theo [[HomeObject]]
<!-- 
const parent = {
    show() {
        console.log("Parent");
    }
};

const child = {
    __proto__: parent,

    show() {
        super.show();
    }
};

const anotherParent = {
    show() {
        console.log("Another Parent");
    }
};

Object.setPrototypeOf(child, anotherParent);

child.show(); // Another Parent
 -->
 Bởi vì :
 1. child.show vẫn có [[HomeObject]] là child.
 2. super.show() tìm method trên prototype hiện tại của child.
 3. Object.setPrototypeOf() đã thay prototype của child thành anotherParent.
   Do đó, super.show() gọi anotherParent.show().
   Điểm cần nhớ: [[HomeObject]] không thay đổi khi prototype thay đổi, nhưng prototype mà super tra cứu có thể thay đổi.
Bài tập kiểm tra :
<!-- 
const A = {
    show() {
        console.log("A");
    }
};

const B = {
    __proto__: A,

    show() {
        super.show();
    }
};

const C = {
    show() {
        console.log("C");
    }
};

Object.setPrototypeOf(B, C);

B.show();
 -->
5.4. Methods, not function properties
super chỉ hoạt động trong method short hand không hoạt động tương tụ trong function property thông thường
Trường hợp 1: Method shorthand – hợp lệ
<!-- 
const parent = {
    show() {
        console.log("Parent");
    }
};

const child = {
    __proto__: parent,

    show() {
        super.show();
    }
};

child.show(); // Parent
 -->
Trường hợp 2: Function property – không hợp lệ
<!-- 
const child = {
    show: function() {
        super.show();
    }
};
 -->
Đoạn code này gây SyntaxError ,vì function thông thường k có [[HomeObject]] để xác định super()
Lưu ý: Arrow function không tự tạo [[HomeObject]], nhưng có thể sử dụng super được kế thừa từ method bên ngoài, như mục 2.3 đã học.
Tổng kết mục 5. Super: internals, [[HomeObject]]
1. Không dùng this.__proto__ để thay thế super: Vì this có thể trỏ đến instance khác với object định nghĩa method, dẫn đến đệ quy ngoài ý muốn.
2. [[HomeObject]]: Là liên kết nội bộ xác định object nơi method được định nghĩa, giúp JavaScript tìm đúng prototype khi gọi super.
3. Methods are not "free": super dựa vào prototype của [[HomeObject]], không dựa vào prototype của this.
4. Methods, not function properties: Method shorthand hỗ trợ super; function property thông thường không có cơ chế này.

6. Summary — Class inheritance
6.1. Kế thừa class bằng extends
<!-- 
class Parent {
    sayHello() {
        console.log("Hello");
    }
}

class Child extends Parent {}

const child = new Child();

child.sayHello(); // Hello
 -->
Child kế thừa từ Parent.
Child.prototype có prototype là Parent.prototype.
Instance của Child sử dụng được các method kế thừa từ Parent.
6.2. Override constructor
Khi class con tự khai báo constructor, phải gọi super() trước khi sử dụng this.
<!-- 
class Parent {
    constructor(name) {
        this.name = name;
    }
}

class Child extends Parent {
    constructor(name, age) {
        super(name);
        this.age = age;
    }
}
-->
Ghi nhớ: super() gọi constructor của class cha và khởi tạo this cho class con.
6.3. Override method
Sử dụng super.method() để gọi method của class cha.
<!-- 
class Parent {
    show() {
        console.log("Parent");
    }
}

class Child extends Parent {
    show() {
        super.show();
        console.log("Child");
    }
}
 -->
6.4. Internals — [[HomeObject]]
1. Method trong class hoặc object ghi nhớ object nơi nó được định nghĩa thông qua [[HomeObject]].
2. super sử dụng [[HomeObject]] để xác định prototype cần tìm method cha.
3. Không nên copy method có sử dụng super sang object khác vì [[HomeObject]] không thay đổi.
Ngoài ra ,arrow function không có this và super riêng mà sử dụng ngữ cảnh bên ngoài
