1. Extending built-in classes
JS cho phép chúng ta kế thưà cac class có sẵn như :
Array
Map
Set
Date
Ví dụ chúng ta muốn tạo loại array có thêm method như isEmpty() để kiểm tra mảng có rỗng hay là không
1.1. Kế thừa Array
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 5, 10, 50);

console.log(arr.isEmpty()); // false
console.log(arr.length);    // 5
 -->
Giải thích:
- PowerArray extends Array: PowerArray kế thừa từ Array.
- PowerArray có toàn bộ chức năng thông thường của Array.
- isEmpty() là method do chúng ta tự bổ sung.
- - this.length truy cập thuộc tính length được kế thừa từ Array.
Vì vậy  , PowerArray vừa có thể sử dụng các method như push(), pop(), map(), filter(), vừa có method riêng isEmpty().
1.2. Sử dụng method của Array
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 5, 10, 50);

const filteredArr = arr.filter(item => item >= 10);

console.log(filteredArr);           // [10, 50]
console.log(filteredArr.isEmpty()); // false
 -->
filter() vồn là method của Array , nhưng khi được gọi từ PowerArray, kết qủa vẫn là một PowerArray
Câu hỏi kiểm tra 1:
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);

const result = arr.filter(item => item > 1);

console.log(result.isEmpty());
 -->
1.3. arr.constructor
Mỗi instnce đều có thể truy cập thuộc tính constructor thông qua prototype chain
Ví dụ:
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);

console.log(arr.constructor === PowerArray); // true
console.log(arr.constructor === Array);      // false
 -->
Giải thích:
- arr.constructor tìm thấy PowerArray thông qua PowerArray.prototype.
- Vì vậy, arr.constructor tham chiếu đến class PowerArray.
JS sử dụng thông tin này để xác định constructor phù hợp khi tạo kết quả từ 1 số mehtod của built-in classes.
Ví dụ:
<!-- 
const result = arr.filter(item => item > 1);
console.log(result.constructor === PowerArray); // true
 -->
Ghi nhớ : constructor là một propety tham chiếu đến hàm / class constructor , không phải bản thân prototype
<!-- 
class MyArray extends Array {}

const arr = new MyArray(1, 2, 3);

console.log(arr.constructor === MyArray);
 -->
Vì arr được tạo từ MyArray, nên arr.constructor tham chiếu đến MyArray.
1.4. Kết quả của map() và filter()
Khi gọi map() hoặc filter() trên 1 instance của class kế thừa Array , kết quả mặc định vẫn là instance của class con
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);

const mapped = arr.map(item => item * 2);
const filtered = arr.filter(item => item > 1);

console.log(mapped instanceof PowerArray);   // true
console.log(filtered instanceof PowerArray); // true
 -->
Tại sao lại như vậy?
JS sử dụng constructor của mảng ban đầu để tạo kết quả
<!-- const result = new arr.constructor(...); -->
Đây là cách minh hoạ ý tưởng , k phải cách triển khai map() và filter()
Vì arr.constructor là PowerArray, kết quả tiếp tục là PowerArray.
Bài tập :
<!-- 
class PowerArray extends Array {
    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);
const result = arr.map(x => x * 2);

console.log(result.isEmpty());
console.log(result instanceof Array);
 -->

2. Symbol.species

Đây là phần giải thích cách kiẻm soát kiểu constructor được sử dụng khi các mehtod như map() và filter() tạo ra kết quả mới
2.1. Symbol.species là gì?
Symbol.species là một well-known symbol được sử dụng để xác định constructor mà một số method của built in class dùng để tạo object mới
<!-- 
class PowerArray extends Array {}

const arr = new PowerArray(1, 2, 3);

const result = arr.map(x => x * 2);

console.log(result instanceof PowerArray); // true
 -->
Nhưng giả sử chúng ta muốn:
- Mảng ban đầu vẫn là PowerArray.
- - Kết quả từ map() chỉ là Array thông thường.
Khi đó, Symbol.species cho phép tùy chỉnh hành vi này.
2.2. Static getter Symbol.species
Ta khai báo 1 static getter trả về constructor mong muốn
<!-- 
class PowerArray extends Array {
    static get [Symbol.species]() {
        return Array;
    }

    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);

const result = arr.map(x => x * 2);

console.log(result instanceof PowerArray); // false
console.log(result instanceof Array);      // true
 -->
Giải thích:
<!-- 
static get [Symbol.species]() {
    return Array;
}
 -->
static: getter thuộc về class.
[Symbol.species]: khai báo static getter bằng computed property name.
return Array: yêu cầu các method sử dụng species tạo kết quả bằng constructor Array.
Vì vậy result là aray thông thường , không còn là PowerArray
Ghi nhớ: Symbol.species không thay đổi class của object ban đầu. Nó ảnh hưởng đến constructor được sử dụng để tạo ra một số kết quả mới.
<!-- 
class MyArray extends Array {
    static get [Symbol.species]() {
        return Array;
    }
}

const arr = new MyArray(1, 2, 3);
const result = arr.filter(x => x > 1);

console.log(result instanceof MyArray);
 -->
Vì Symbol.species trả về Array, nên filter() tạo kết quả bằng constructor Array, không phải MyArray.
2.3. Tùy chỉnh kiểu dữ liệu trả về
Trường hợp 1: Không khai báo Symbol.species
<!-- 
class PowerArray extends Array {}

const arr = new PowerArray(1, 2, 3);
const result = arr.map(x => x * 2);

console.log(result instanceof PowerArray); // true
 -->
Trường hợp 2: Ghi đè Symbol.species
<!-- 
class PowerArray extends Array {
    static get [Symbol.species]() {
        return Array;
    }
}

const arr = new PowerArray(1, 2, 3);
const result = arr.map(x => x * 2);

console.log(result instanceof PowerArray); // false
console.log(result instanceof Array);      // true
 -->
Kết quả trở thành Array thông thường.

### Bảng ghi nhớ:

| Cách khai báo                      | Constructor của kết quả |
| ---------------------------------- | ----------------------- |
| Không có `Symbol.species`          | `PowerArray`            |
| `Symbol.species` trả về `Array`    | `Array`                 |
| `Symbol.species` trả về class khác | Class được trả về       |
Lưu ý: Symbol.species chỉ ảnh hưởng đến những method có sử dụng cơ chế species, không phải mọi method của Array.
<!-- 
class PowerArray extends Array {
    static get [Symbol.species]() {
        return Array;
    }

    isEmpty() {
        return this.length === 0;
    }
}

const arr = new PowerArray(1, 2, 3);
const result = arr.filter(x => x > 1);
 -->
Điều gì xảy ra khi chạy result.isEmpty()?
<!-- 
Symbol.species trả về Array.
Vì vậy, filter() tạo ra một Array thông thường, không phải PowerArray.
result không có method isEmpty().
 -->
JavaScript sẽ báo TypeError vì result.isEmpty không phải function.

3. No static inheritance in built-ins
Sau phần này, bạn cần hiểu:
- Sự khác nhau giữa kế thừa instance method và static method.
- Vì sao Array kế thừa Object.prototype nhưng lại không kế thừa static method của Object.
- Prototype chain của Date và Object.

Ý 1: Built-in classes có static methods riêng
Các built-in object có những static method riêng, ví dụ:
<!-- 
Object.keys({});
Array.isArray([]);
Date.now();
 -->
Thông thưòng khi 1 class kế thừa class khác bằng extend , nó kế thừa cả :
- Instance methods: method dành cho instance.
- Static methods: method gọi trực tiếp trên class.
<!-- 
class Animal {
    static info() {
        return "Animal";
    }

    eat() {
        return "Eating";
    }
}

class Rabbit extends Animal {}

console.log(Rabbit.info()); // "Animal"

const rabbit = new Rabbit();
console.log(rabbit.eat()); // "Eating"
 -->
Rabbit kế thừa static method info() từ Animal.
Instance rabbit kế thừa method eat()

Ý 2: Built-in classes là ngoại lệ
built-in classes không kế thừa static methods của nhau theo cách extend thông thường
Ví dụ:
<!-- 
console.log(Array.isArray([])); // true
console.log(Object.keys({ a: 1 })); // ["a"]

console.log(Array.keys); // undefined
console.log(Date.keys);  // undefined
 -->
Mặc dù Array và Date đều kế thừa từ Object theo quan hệ prototype của instance , chúng k kế thừa static method Object.keys()

Ý 3: Prototype chain của Date và Object
Instance date có thể sử dụng các method từ Object.prototype, chẳng hạn toString().
Nhưng prototype chain của chính constructor Date lại khác:
<!-- 
Object.getPrototypeOf(Date) === Function.prototype; // true
Object.getPrototypeOf(Array) === Function.prototype; // true
 -->


<!-- 
const date = new Date();

console.log(date.toString());
console.log(Date.keys);
 -->
date.toString(): hoạt động vì instance date kế thừa toString() từ Object.prototype.
Date.keys: undefined vì constructor Date không kế thừa static method Object.keys()
Điểm cần nhớ: Kế thừa instance method và kế thừa static method là hai quan hệ prototype khác nhau
