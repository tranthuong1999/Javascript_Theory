1. Static methods
1.1. Khai báo static method
A. Static method là gì?
Chúng ta có thể khai báo một method thuộc về toàn bộ class thay vì thuộc về từng instance
Những method này thuộc về static method
Để khai báo , sử dụng từ khoá static trước tên method
Ví dụ:
<!-- 
class User {
    static staticMethod() {
        console.log("Hello");
    }
}

User.staticMethod(); // Hello
 -->
Ở đây:
- static là từ khoá khai báo static method
- staticMethod() thuộc về class User
- Có thể gọi trực tiếp thông qua User.staticMethod()
- Không cần tạo instance bằng new User()
B. Static method thực chất được lưu ở đâu?
<!-- 
class User {
    static staticMethod() {
        console.log("Hello");
    }
}
 -->
Static method tương đương với việc gán trực tiếp một function vào class
<!-- 
class User {}

User.staticMethod = function() {
    console.log("Hello");
};
 -->
Vì vậy, khi khai báo:
<!-- User.staticMethod(); -->
Lưu ý : static method k nằm trong User.prototype.
C. Phân biệt Static method và Instance method
<!-- 
class User {
    // Instance method
    sayHello() {
        console.log("Hello");
    }

    // Static method
    static createGuest() {
        return new User();
    }
}

const user = new User();
 -->
Lý do:
- sayHello() thuộc về User.prototype , instance có thể truy cập thông qua prototype chain.
- createGuest() thuộc trực tiếp class User , khôg thuộc instance
  
D. Ghi nhớ
Instance method : user.sayHello();
Static method : User.createGuest();

Instance mehtod : xử lý hành vi của 1 đối tượng cụ thể 
Static method: xử lý chức năng thuộc về class nói chung
Bài tập :
<!-- 
class Product {
    constructor(name) {
        this.name = name;
    }

    static createDefault() {
        return new Product("Laptop");
    }

    getName() {
        return this.name;
    }
}

const product = Product.createDefault();
 -->
1.2. this trong static method
* 
* A. this trong static method là gì?
Trong static method , this tham chiếu đến class constructor , không phải instance được tạo từ class
<!-- 
class User {
    constructor(name) {
        this.name = name;
    }

    static showClass() {
        console.log(this);
    }
}

User.showClass(); // class User {...}
 -->
Thì this bên trong class chính là User
* B. Sử dụng this để gọi static method khác
<!-- 
class User {
    static sayHello() {
        console.log("Hello");
    }

    static welcome() {
        this.sayHello();
    }
}

User.welcome(); // Hello
 -->
Giải thích:
1. Gọi User.welcome().
2. this bên trong welcome () tham chiếu đến user
3. this.sayHello() tương đương với User.sayHello()
4. Kết quả in ra Hello
* C. Static method không truy cập trực tiếp instance property
<!-- 
class User {
    constructor(name) {
        this.name = name;
    }

    static showName() {
        console.log(this.name);
    }
}

const user = new User("Martin");
User.showName(); // undefined
 -->
Tại sao?
- name được lưu trên instance user
- Static method được gọi trên class User.
- this ở đây là User, không phải user.

Muốn truy cập user.name, bạn cần truyền instance vào static method:
<!-- 
class User {
    constructor(name) {
        this.name = name;
    }

    static showName(user) {
        console.log(user.name);
    }
}

const user = new User("Martin");

User.showName(user); // Martin
 -->
1.3. Use cases
Static method thương được sử dụng trong các trường hợp như comparison method và factory method
A. Comparison method
Comparison method là method dùng để so sánh các đối tượng cùng class
<!-- 
class Article {
    constructor(title, date) {
        this.title = title;
        this.date = date;
    }

    static compare(articleA, articleB) {
        return articleA.date - articleB.date;
    }
}

const articles = [
    new Article("HTML", new Date(2024, 1, 1)),
    new Article("CSS", new Date(2023, 1, 1)),
    new Article("JavaScript", new Date(2025, 1, 1))
];

articles.sort(Article.compare);

console.log(articles.map(article => article.title));
 -->
 Result : ["CSS", "HTML", "JavaScript"]
Giải thích:
1. Article.compare() nhận hai instance articleA và articleB.
2. So sánh ngày tháng của 2 article
3. Trả về kết quả so sánh.
4. sort() sử dụng kết quả đó để sắp xếp mảng

Tại sao compare() là static method?
Vì chức năng so sánh cần làm việc 2 đối tượng , không phụ thuộc vào instace cu thẻ

B. Factory method
Factory method là static method dùng để tạo và trả về instance của class
Ví dụ theo tài liệu:
<!-- 
class Article {
    constructor(title, date) {
        this.title = title;
        this.date = date;
    }

    static createTodays() {
        return new this("Today's digest", new Date());
    }
}

const article = Article.createTodays();

console.log(article.title); // Today's digest
console.log(article.date);  // Current date
 -->
Giải thích:
- createTodays() là static method.
- new this(...) tạo instace của class hiện tại 
- Method trả về 1 đối tượng Article

Tại sao sử dụng factory method?
Thay vì phải viết:
<!-- const article = new Article("Today's digest", new Date()); -->
Chúng ta có thể viết :
<!-- const article = Article.createTodays(); -->
Cách này đóng gói logic khởi tạo đối tượng vào trong class
C. So sánh hai use cases
Bài tập :
<!--
class User {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }

    static createGuest() {
        return new this("Guest", 18);
    }

    static compareAge(userA, userB) {
        return userA.age - userB.age;
    }
}

const user1 = new User("Martin", 25);
const user2 = new User("Alex", 20);
  -->
Mẹo ghi nhớ:
- Factory = Nhà máy → tạo đối tượng.
- Comparison = So sánh → so sánh các đối tượng.

1.4. Static methods aren't available for individual objects.
A. Static method không thuộc instance
Static method được gán cho chính class constructor , không nằm trong prototype của class
<!-- 
class User {
    static staticMethod() {
        console.log("Static method");
    }

    instanceMethod() {
        console.log("Instance method");
    }
}

const user = new User();
 -->
Bởi vì staticMethod được định nghĩa trên User, không phải User.prototype.
B. Kiểm tra bằng prototype
<!-- 
class User {
    static sayHello() {
        console.log("Hello");
    }

    sayHi() {
        console.log("Hi");
    }
}

const user = new User();

console.log(User.hasOwnProperty("sayHello")); 
// true

console.log(User.prototype.hasOwnProperty("sayHello"));
// false

console.log(User.prototype.hasOwnProperty("sayHi"));
// true
 -->
| Method       | Nằm ở đâu?       |
| ------------ | ---------------- |
| `sayHello()` | `User`           |
| `sayHi()`    | `User.prototype` |

Instance user có thể tìm thấy sayHi() thông qua prototype chain ,nhưng không thể tìm thấy sayHello()
C. Liên hệ thực tế
<!-- 
class Message {
    constructor(content, senderId) {
        this.content = content;
        this.senderId = senderId;
    }

    static createSystemMessage(content) {
        return new Message(content, "SYSTEM");
    }

    getContent() {
        return this.content;
    }
}

const message = Message.createSystemMessage("User joined");

console.log(message.getContent()); // User joined
 -->
createSystemMessage() là static method vì tạo một loại message theo quy tắc chung của class.
getContent() là instance method vì đọc dữ liệu của một message cụ thể.
Bài tập kiểm tra :
<!-- 
class Car {
    static brand = "Toyota";

    static getBrand() {
        return this.brand;
    }

    getModel() {
        return "Camry";
    }
}

const car = new Car();
 -->

2. Static properties
2.1. Khai báo static property
A. Static property là gì?
Tương tự static method, static proprty là thuộc tính về class , không thuộc về tưng instance
Khai báo bằng từ khóa static.
<!-- 
class Article {
    static publisher = "javascript.info";
}

console.log(Article.publisher); // javascript.info
 -->
 Ở đây:
- publisher là static property
- Thuộc class Article
- Truy cập bằng Article.publisher
- Không cần tạo instance

B. Phân biệt static property và instance property
<!-- 
class User {
    static role = "ADMIN";

    constructor(name) {
        this.name = name;
    }
}

const user1 = new User("Martin");
const user2 = new User("Alex");

console.log(User.role);  // ADMIN
console.log(user1.name); // Martin
console.log(user2.name); // Alex

console.log(user1.role); // undefined
console.log(user2.role); // undefined
 -->
| Tiêu chí      | Static property                  | Instance property             |
| ------------- | -------------------------------- | ----------------------------- |
| Cách khai báo | `static role`                    | `this.name`                   |
| Thuộc về      | Thuộc class                      | Thuộc instance                |
| Cách truy cập | Truy cập `User.role`             | Truy cập `user1.name`         |
| Đặc điểm      | Không tự xuất hiện trên instance | Mỗi instance có dữ liệu riêng |

C. Static property thực chất nằm ở đâu?
<!-- 
class User {
    static role = "ADMIN";
}

console.log(User.hasOwnProperty("role")); // true
console.log(User.prototype.hasOwnProperty("role")); // false
 -->
Static property nằm trực tiếp trên class constructor , không nmằ trên User.prototype
D. Ứng dụng thực tế
Ví dụ class quản lý thông tin tin nhắn:
<!-- 
class Message {
    static MAX_LENGTH = 5000;
    static SYSTEM_SENDER_ID = "SYSTEM";

    constructor(content, senderId) {
        this.content = content;
        this.senderId = senderId;
    }
}
 -->
Sử dụng:
<!-- 
console.log(Message.MAX_LENGTH); // 5000

const message = new Message(
    "Hello",
    Message.SYSTEM_SENDER_ID
);
 -->
Các giá trị mang tính cấu hình hoặc quy tắc chung của class có thể khai báo dưới dạng static property.
Bài tập :
<!-- 
class Product {
    static category = "Electronics";

    constructor(name) {
        this.name = name;
    }
}

const product1 = new Product("Laptop");
const product2 = new Product("Phone");

product1.name = "MacBook";

console.log(Product.category);
console.log(product1.category);
console.log(product2.name);
 -->
Giải thích:
- Product.category: static property thuộc class Product.
- product1.category: undefined vì static property không nằm trong Product.prototype.
- product2.name: "Phone" vì mỗi instance có name riêng.

3. Inheritance of static properties and methods
3.1. Kế thừa static method
A. Static method có được kế thừa không?
Có . Khi class con kế thừa class cha bằng extends , class con cũng có thể truy cập static method của class cha
Ví dụ:
<!-- 
class Animal {
    static compare(a, b) {
        return a.speed - b.speed;
    }
}

class Rabbit extends Animal {}

console.log(Rabbit.compare); // function
 -->
Mặc dù Rabbit không khai báo compare(), nhưng vẫn có thể gọi:
<!-- 
Rabbit.compare(
    { speed: 10 },
    { speed: 20 }
); // -10
 -->
B. Tại sao class con truy cập được static method của class cha?
class Rabbit extends Animal {}
JS thiết lập 2 mối quan hệ prototype:
<!-- 
Rabbit.prototype.__proto__ === Animal.prototype; // true
Rabbit.__proto__ === Animal; // true
 -->
Đối với static method mối quan hệ quan trọng là :
<!-- Rabbit.__proto__ === Animal; -->
Vì vậy, khi gọi:
<!-- Rabbit.compare(); -->
JavaScript tìm compare:
1. Tìm trực tiếp trên Rabbit.
2. Không tìm thấy.
3. Đi lên prototype của Rabbit, tức Animal.
4. Tìm thấy Animal.compare().

C. Ví dụ thực tế
<!-- 
class User {
    static createGuest() {
        return new this("Guest");
    }

    constructor(name) {
        this.name = name;
    }
}

class Admin extends User {}

const admin = Admin.createGuest();

console.log(admin.name); // Guest
console.log(admin instanceof Admin); // true
 -->
Chú y: return new this("Guest");
Khi gọi Admin.createGuest():
- this là Admin
- new this("Guest") tương đương new Admin("Guest").
- Kết quả là một instance của Admin, không phải User.
Đây là một ứng dụng quan trọng của static method kết hợp với kế thừa.

Bài tập :
<!-- 
class Animal {
    static showType() {
        return this.name;
    }
}

class Rabbit extends Animal {}

console.log(Rabbit.showType());
 -->

1. Rabbit kế thừa static method showType() từ Animal.
2. Khi gọi Rabbit.showType(), this tham chiếu đến Rabbit.
3. this.name trả về tên class là "Rabbit".
Ghi nhớ: static method được kế thừa , nhưng this phụ thuộc vào class gọi method , không cố định là class khai báo method
3.2. Kế thừa static property
A. Static property có được kế thừa không?
Tưong tự như static method, static propety cũng được class con kế thừa thông qua quan hệ prototype giữa các class constructor
<!-- 
class Animal {
    static planet = "Earth";
}

class Rabbit extends Animal {}

console.log(Rabbit.planet); // Earth
 -->
Mặc dù Rabit không khai báo planet , vẫn có thể truy cập Animal.planet
B. JavaScript tìm static property như thế nào?
Khi chạy : Rabbit.planet;
JavaScript thực hiện tìm kiếm:
1. Tìm property planet trực tiếp trên Rabbit.
2. Không tìm thấy.
3. Đi lên prototype của Rabbit, tức Animal.
4. Tìm thấy Animal.planet.
<!--  Rabbit.__proto__ === Animal; // true -->
C. Static property không được sao chép sang class con
Đây là điểm cần phân biệt : kế thừa không có nghĩa là property được sao chép
<!-- 
class Animal {
    static planet = "Earth";
}

class Rabbit extends Animal {}

console.log(Rabbit.hasOwnProperty("planet")); // false
console.log(Animal.hasOwnProperty("planet")); // true
console.log(Rabbit.planet);                   // Earth
 -->
Rabbit.planet truy cập thông qua prototype chain , nhưng planet không phải own property của Rabbit
D. Khi class con khai báo static property cùng tên
<!-- 
class Animal {
    static planet = "Earth";
}

class Rabbit extends Animal {
    static planet = "Moon";
}

console.log(Animal.planet); // Earth
console.log(Rabbit.planet); // Moon
 -->
Rabbit có static property riêng tên planet nên property này che khuất property cùng tên được kế thừa từ Animal.
Ghi nhớ:
- Static property được kế thừa thông qua prototype chain.
- Không được sao chép sang class con.
- Class con có thể khai báo property cùng tên để che khuất property của class cha.
Bài tập thực hành :
<!-- 
class Animal {
    static type = "Animal";
}

class Rabbit extends Animal { }

Rabbit.type = "Rabbit";

console.log(Animal.type);
console.log(Rabbit.type);
console.log(Rabbit.hasOwnProperty("type"));
 -->
Giải thích:
1. Animal.type vẫn là "Animal" vì chúng ta không thay đổi property của class cha.
2. Rabbit.type = "Rabbit" tạo own property trên class con.
3. Rabbit.hasOwnProperty("type") trả về true vì type hiện được khai báo trực tiếp trên Rabbit
Ghi nhớ : Khi gán một static property được kế thừa thông qua class con , JS tạo propety mới trên class con , không sửa property của class cha
3.3. Hai prototype references của extends
Đây là cơ chế kế thừa static và method trong JS
A. extends thiết lập hai quan hệ prototype
<!-- 
class Animal {
    constructor(name) {
        this.name = name;
    }

    run() {
        console.log(`${this.name} is running`);
    }

    static compare(a, b) {
        return a.name.localeCompare(b.name);
    }
}

class Rabbit extends Animal {
    hide() {
        console.log(`${this.name} is hiding`);
    }
}
 -->
Khi viết:
<!-- class Rabbit extends Animal {} -->
Kiêmt tra

<!--
Rabbit.prototype.__proto__ === Animal.prototype; // true
Rabbit.__proto__ === Animal; // true
 -->
C. Hai quan hệ giải quyết hai nhiệm vụ khác nhau
| Quan hệ                               | Mục đích                          |
| ------------------------------------- | --------------------------------- |
| `Rabbit.prototype → Animal.prototype` | Kế thừa instance method           |
| `Rabbit → Animal`                     | Kế thừa static method và property |
<!-- 
const rabbit = new Rabbit("White Rabbit");

// Instance method
rabbit.run();
rabbit.hide();

// Static method
Rabbit.compare(
    { name: "A" },
    { name: "B" }
);
 -->
D. Kiểm tra bằng instanceof
<!-- 
const rabbit = new Rabbit("White Rabbit");

console.log(rabbit instanceof Rabbit); // true
console.log(rabbit instanceof Animal); // true
console.log(rabbit instanceof Object); // true
 -->
Vì prototype chain của instance rabbit đi qua:
<!-- 
rabbit
  → Rabbit.prototype
  → Animal.prototype
  → Object.prototype
 -->
Lưu ý: instanceof kiểm tra prototype chain của instance, không kiểm tra quan hệ kế thừa static giữa hai class constructor.
<!-- 
class Animal {
    run() {
        console.log("Running");
    }

    static compare() {
        console.log("Comparing");
    }
}

class Rabbit extends Animal {}

const rabbit = new Rabbit();
 -->

run() được kế thừa qua Rabbit.prototype, còn compare() được kế thừa qua Rabbit.__proto__.

Mẹo ghi nhớ:
- Rabbit.prototype: Dùng để tìm kiếm method/property cho object được tạo từ Rabbit.
- Rabbit.__proto__: Dùng để tìm kiếm method/property cho chính class Rabbit.

4. Summary

1. Static methods
- Khai báo bằng từ khóa static.
- Thuộc về class, không thuộc instance.
- this trong static method tham chiếu đến class gọi method.
- Use cases: Comparison method và Factory method.
2. Static properties
- Static property thuộc về class.
- Truy cập bằng Class.property.
- Không được lưu trên Class.prototype.
- Instance không thể truy cập static property thông qua prototype.
3. Inheritance of static properties and methods
Khi sử dụng extends, JavaScript thiết lập hai prototype chain:
Instance chain:
rabbit
  → Rabbit.prototype
  → Animal.prototype
  → Object.prototype

Class chain:
Rabbit
  → Animal
  → Function.prototype
  → Object.prototype
  ### Ghi nhớ:

| Cú pháp                         | Ý nghĩa                                |
| ------------------------------- | -------------------------------------- |
| `Rabbit.prototype`              | Prototype dành cho instance của Rabbit |
| `Rabbit.__proto__`              | Prototype của chính class Rabbit       |
| `Rabbit.prototype.__proto__`    | Prototype của `Rabbit.prototype`       |
| `Object.getPrototypeOf(Rabbit)` | Cách kiểm tra prototype của class      |
