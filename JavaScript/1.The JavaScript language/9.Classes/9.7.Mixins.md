1.1. Mixins là gì?
1. Khái niệm
Mixin là 1 object hoặc class chứa các phương thức có thể đựco sử dụng để bổ sụng chức năng cho những class khác 
mà k cần kế thừa trực tiếp từ nó
Hiểu đơn giản:
- Inheritance: 1 class kế thừa từ class cha
- Mixin : 1 class có thể nhận thêm các chức năng từ nhiều nguồn khác
Ví dụ, ta có:
- User : Quản lý thông tin người dùng
- EventEmitter : cung cấp chức năng phát và lắng nghe sự kiện 
  Ta muốn User vừa quản lý thông tin người dùng , vừa có thể phát sự kiện login
  Thay vì băts user kế thừa EventEmitter , ta có thể sử dụng mixin để bổ sung chức năng này
2. Ví dụ đơn giản
<!-- 
const sayHiMixin = {
    sayHi() {
        console.log(`Hello ${this.name}`);
    },

    sayBye() {
        console.log(`Bye ${this.name}`);
    }
};

class User {
    constructor(name) {
        this.name = name;
    }
}

Object.assign(User.prototype, sayHiMixin);

const user = new User("Martin");

user.sayHi();  // Hello Martin
user.sayBye(); // Bye Martin
 -->
1. sayHiMixin chứa 2 method sayHi() và sayBe()
2. User không khai báo method này
3. Object.assign() sao chép các method từ sayHiMixin vào User.prototype.
4. Instance user có thể sử dụng 2 method này thông qua prototype chain

3. Điều cần ghi nhớ
Mixin không tạo quan hệ kế thừa
<!-- 
user instanceof User;       // true
user instanceof Object;     // true
 -->
Không có class SayHiMixin nào được kế thừa ở đây
Mixin chỉ bổ sụng behavior vào User.prototype
Bàit tập :
<!-- 
const sayMixin = {
    say() {
        console.log("Hello");
    }
};

class User {}

Object.assign(User.prototype, sayMixin);

const user = new User();

console.log(user instanceof User);
console.log(user instanceof sayMixin);
console.log(typeof user.say);
 -->
Object.assign() đã sao chép method say vào User.prototype, nên user sử dung được phương thức này
Ghi nhớ : Mixin bổ sung chức năng , không tạo mối quan hệ kế thừa giữa class và mixin

1.2. Vấn đề multiple inheritance trong JavaScript
Trong lập trình hướng đối tượng , multiple inheritance ( đa kế thừa ) là khả năng 1 class kế thừa trực tiếp từ nhiều class cha
Ví dụ về ý tưởng đa kế thừa:
<!-- 
class User extends Person, EventEmitter {
  // ...
}
 -->
Tuy nhiên , JS không hỗ trợ cú pháp 1 class kế thừa nhiều class , extend chỉ cho phép 1 class cha
<!-- 
class User extends Person {
  // ...
}
 -->
Vậy nếu User cần cả:
- Các thuộc tính , phương thúc từ Person
- Khả năng phát và lắng nghe sự kiện từ EventEmitter

Ta không thể viết extend Person, EventEmitter
Đây là 1 trng nhũng lý do mixin hữu ích : thay vì kế thừa nhiều class , ta có thể kết hợp các phương thức từ nhiều object mixin
vào prôttye của class
Ví dụ đúng theo ý tưởng của bài:
<!-- 
const canEat = {
  eat() {
    console.log(`${this.name} is eating`);
  }
};

const canWalk = {
  walk() {
    console.log(`${this.name} is walking`);
  }
};

class Person {
  constructor(name) {
    this.name = name;
  }
}

Object.assign(Person.prototype, canEat, canWalk);

const person = new Person("Martin");

person.eat();  // Martin is eating
person.walk(); // Martin is walking
 -->
 Person vẫn chỉ có 1 prototype chain kế thừa từ prototype chain , nhưng có thể nhận nhiều nhóm phương thức từ các mixin khác nhau
.Đó chính là mixin giải quyết nhu cầu kết hợp nhiều hành vi 
<!-- 
console.log(person instanceof Person);
console.log(typeof person.eat);
console.log(typeof person.walk);
 -->
Ghi nhớ: Mixin không tạo ra multiple inheritance thực sự. Nó chỉ giúp kết hợp nhiều hành vi bằng cách sao chép methods vào object hoặc prototype.
1.3. Tạo mixin bằng object
Trong JS , mixin thường được tạo bằng 1 object chứa các method
<!-- 
let sayHiMixin = {
  sayHi() {
    console.log(`Hello ${this.name}`);
  },

  sayBye() {
    console.log(`Bye ${this.name}`);
  }
};
 -->
Ở đây:
- sayHiMixin là 1 object
- sayHi() và sayBye() là các methods.
- this tham chiếu đến object đang gọi method
Sử dụng mixin với class
<!-- Object.assign(User.prototype, sayHiMixin); -->
Điều gì xảy ra?
1. User.prototype là nơi chứa các method dùng chung cho instance của User
2. Object.assign() sao chép sayHi và sayBye từ sayHiMixin sang User.prototype
3. Instance user được truy cập được các method thông qua prototype chain

<!-- 


const loggerMixin = {
    log() {
        console.log(this.name);
    }
};

class User {
    constructor(name) {
        this.name = name;
    }
}

Object.assign(User.prototype, loggerMixin);

const user = new User("Martin");
user.log();
 -->

Giải thích:
- Object.assign(User.prototype, loggerMixin) thêm method log() vào prototype của User.
- user.log() gọi method thông qua prototype chain.
- this bên trong log() là user.
- user.name có giá trị "Martin".

1.4. Object.assign() để thêm methods vào prototype
<!-- Object.assign(User.prototype, sayHiMixin); -->
Cú pháp
<!--  Object.assign(target, ...sources); -->
Trong đó :
target : object nhận các thuộc tính
sources : 1 hoặc nhiều object cung cấp thuộc tính
Kết quả: trả về chính target.
Ví dụ: 
<!-- 
const mixinA = {
  eat() {
    console.log("Eating");
  }
};

const mixinB = {
  walk() {
    console.log("Walking");
  }
};

class Person {}

Object.assign(Person.prototype, mixinA, mixinB);

const person = new Person();

person.eat();  // Eating
person.walk(); // Walking
 -->
Điều gì xảy ra?
1. mixinA cung cấp method eat().
2. mixinB cung cấp method walk().
3. Object.assign() copy cả hai method vào Person.prototype.
4. person truy cập được chúng thông qua prototype chain.

Lưu ý quan trọng
Object.assign() chỉ sao chép các thuộc tính riêng (own properties) có thể enumerable của source object
Nó k thiết lập prototype chain của target theo source
<!-- 
const parent = {
  hello() {
    console.log("Hello");
  }
};

const child = Object.create(parent);

const target = {};

Object.assign(target, child);

console.log(target.hello); // undefined
 -->
Vì hello() nằm trên prototype của child, không phải own property của child.
Câu hỏi kiểm tra 1.4
<!-- 
const mixin = {
  eat() {
    console.log("Eating");
  }
};

class Animal {}

const result = Object.assign(Animal.prototype, mixin);

const animal = new Animal();

console.log(result === Animal.prototype);
console.log(typeof animal.eat);
 -->
 1.5. Mixins kết hợp với inheritance
 Mixin k thay thế cơ chế kế thừa extends . Chúng có thể kết hợp với inheritance để 1 class vừa kế thừa class cha , vừa nhận thêm các method từ mixin
 Ví dụ
Giả sử chúng ta có class Animal:
<!-- 
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() {
    console.log(`${this.name} is eating`);
  }
}
 -->
Tạo một mixin cung cấp khả năng di chuyển:
<!-- 
const walkMixin = {
  walk() {
    console.log(`${this.name} is walking`);
  }
};
 -->
Tạo class Rabbit kế thừa Animal và sử dụng mixin:
<!-- 
class Rabbit extends Animal {
  jump() {
    console.log(`${this.name} is jumping`);
  }
}

Object.assign(Rabbit.prototype, walkMixin);

const rabbit = new Rabbit("Bunny");

rabbit.eat();  // Bunny is eating
rabbit.walk(); // Bunny is walking
rabbit.jump(); // Bunny is jumping
 -->
Điểm cần nhớ: 1 class có thể kết hơp inheritance để tái sử dụng cấ trúc / hành vi từ class cha và mixin bổ sung các hành vi độc lâp
Câu hỏi kiểm tra 1.5
<!-- 
class Animal {
  eat() {
    console.log("Eating");
  }
}

const flyMixin = {
  fly() {
    console.log("Flying");
  }
};

class Bird extends Animal {}

Object.assign(Bird.prototype, flyMixin);

const bird = new Bird();

console.log(bird instanceof Animal);
console.log(typeof bird.eat);
console.log(typeof bird.fly);

 -->
 Giải thích:
- bird instanceof Animal → true: Bird kế thừa Animal.
- typeof bird.eat → "function": lấy method từ Animal.prototype.
- typeof bird.fly → "function": lấy method từ Bird.prototype, được bổ sung bởi mixin.
  
1.6. Mixins có thể kế thừa từ mixin khác
Mixin k nhất thiết phải hoạt đôgj độc lập , . Một mixin có thể tái sử dụng lại method của mixin khác thông qua prototype chain
Ví dụ, ta có mixin sayMixin:
<!-- 
let sayMixin = {
  say(phrase) {
    console.log(phrase);
  }
};
 -->
 Tạo mixin sayHiMixin kế thừa từ sayMixin:
 <!-- 
 let sayHiMixin = {
  __proto__: sayMixin,

  sayHi() {
    this.say(`Hello ${this.name}`);
  },

  sayBye() {
    this.say(`Bye ${this.name}`);
  }
};
-->
Ở đây:
- sayMixin cung cấp method say().
- sayHiMixin cung cấp sayHi() và sayBye().
- sayHiMixin truy cập được say() thông qua prototype chain.

Kiểm tra quan hệ kế thừa:
<!-- 
console.log(Object.getPrototypeOf(sayHiMixin) === sayMixin);
// true

console.log(typeof sayHiMixin.say);
// "function"
 -->
Điều cần phân biệt
Object.assign() chỉ sao chép own properties, không sao chép các method được kế thừa từ prototyoe của mixin
Vì vậy , khi kết hợp mixin kế thừa từ mixin khác , cần xử lý thêm vấn đềnayf
<!-- 
const parentMixin = {
  say() {
    console.log("Hello");
  }
};

const childMixin = {
  __proto__: parentMixin,

  walk() {
    console.log("Walking");
  }
};

console.log(typeof childMixin.say);
console.log(typeof childMixin.walk);

class Person {}

Object.assign(Person.prototype, childMixin);

const person = new Person();

console.log(typeof person.say);
console.log(typeof person.walk);
 -->

say() được truy cập thông qua prototype parentMixin.
walk() là own method của childMixin.
<!-- Object.assign(Person.prototype, childMixin); -->Chỉ có own enumerable properties được copy:
- walk() được copy.
- say() không được copy vì nó nằm trên prototype của childMixin.
Ghi nhớ: Truy cập được một property không đồng nghĩa property đó là own property.
1.7. super trong mixin và [[HomeObject]]
Đây là phần quan trọng nhất mixins ví nó giải thích cách super hoạt động khi method được lấy từ 1 mixin
1.7.1. Vấn đề khi sử dụng super
Giả sử có hai mixin:
<!-- 
const sayMixin = {
  say(phrase) {
    console.log(phrase);
  }
};

const sayHiMixin = {
  __proto__: sayMixin,

  sayHi() {
    super.say(`Hello ${this.name}`);
  }
};
 -->
Ở đây:
- sayMixin có method say().
- sayHiMixin có method sayHi().
- super.say() gọi method say() từ prototype của object chứa method sayHi().
Ta có thể kiểm tra:
<!-- 
const user = {
  name: "Martin"
};

Object.assign(user, sayHiMixin);

user.sayHi(); // TypeError
 -->
Bởi vì Object.assign() chỉ copy method sayHi() sang user , k copy prototype chain của sayHiMixin.
Mặc dù vậy, super không tự động tìm prototype của user.
Mình cần đính chính ví dụ vừa rồi: user.sayHi() thực tế vẫn chạy thành công, không gây TypeError.
Lý do nằm ở [[HomeObject]].

1.7.2. [[HomeObject]] là gì?
Khi khai báo method bằng cú pháp method shorthand , JS gắn cho method một internal property là [[HomeObject]]
Property này ghi nhớ object mà method được khai báo bên trong.
<!-- 
const sayHiMixin = {
  __proto__: sayMixin,

  sayHi() {
    super.say(`Hello ${this.name}`);
  }
};
 -->
Method sayHi() có:
<!-- [[HomeObject]] → sayHiMixin -->
Vì vậy, khi gọi:
<!-- super.say(...) -->
JavaScript tìm say trong prototype của sayHiMixin, tức sayMixin.
Điểm quan trọng:
- super được xác định dựa trên [[HomeObject]].
- this vẫn phụ thuộc vào object thực tế gọi method.
- Khi copy method bằng Object.assign(), [[HomeObject]] không thay đổi.
1.7.3. Ví dụ hoàn chỉnh
<!-- 
const sayMixin = {
  say(phrase) {
    console.log(phrase);
  }
};

const sayHiMixin = {
  __proto__: sayMixin,

  sayHi() {
    super.say(`Hello ${this.name}`);
  }
};

class User {
  constructor(name) {
    this.name = name;
  }
}

Object.assign(User.prototype, sayHiMixin);

const user = new User("Martin");

user.sayHi(); // Hello Martin
 -->
 B. Hello Martin vì [[HomeObject]] vẫn tham chiếu đến childMixin, còn this là user.
### Phân biệt để tránh nhầm:

| Thành phần | Xác định bởi     |
| ---------- | ---------------- |
| `super`    | `[[HomeObject]]` |
| `this`     | Cách gọi method  |

2. EventMixin
Ý tưởng là bổ sung khả năng phát và lắng nghe sự kiện cho bất kỳ object nào mà không cần tạo class kế thừa riêng
Ví dụ, trong ứng dụng chat:
- Khi có tin nhắn mới → phát sự kiện messageReceived.
- Khi người dùng đăng nhập → phát sự kiện login.
- Các thành phần khác có thể lắng nghe sự kiện này 
2.1. Ý tưởng EventMixin
Ta tạo một object eventMixin chứa các phương thức quản lý sự kiện :
<!-- 
let eventMixin = {
  // Các methods quản lý sự kiện sẽ được bổ sung ở đây
};
 -->
Mixin này sẽ cung cấp ba phương thức chính:
| Method                        | Ý nghĩa                   |
| ----------------------------- | ------------------------- |
| `on(eventName, handler)`      | Đăng ký lắng nghe sự kiện |
| `off(eventName, handler)`     | Hủy đăng ký lắng nghe     |
| `trigger(eventName, ...args)` | Phát sự kiện              |
Ví dụ cách sử dụng mà chúng ta hướng tới:
<!-- 
user.on("login", () => {
  console.log("User logged in");
});

user.trigger("login");
 -->
Điểm cần nắm: EventMixin giúp tách biệt nơi phát sự kiện và nơi xử lý sự kiện . Object phát sự kiện không cần biết ai đang lắng nghe nó.

2.2. Phương thức on()
on() dùng để đăng ký 1 handler ( cb function) để xử lý 1 sự kiện xảy ra
Cú pháp :
<!-- object.on(eventName, handler); -->
Trong đó :
- eventName: tên sự kiện cần lắng nghe.
- handler: callback được thực thi khi sự kiện được phát.
Cài đặt on()
<!-- 
let eventMixin = {
  on(eventName, handler) {
    if (!this._eventHandlers) {
      this._eventHandlers = {};
    }

    if (!this._eventHandlers[eventName]) {
      this._eventHandlers[eventName] = [];
    }

    this._eventHandlers[eventName].push(handler);
  }
};
 -->
Phân tích từng bước
Bước 1: Khởi tạo nơi lưu trữ handlers
<!-- 
if (!this._eventHandlers) {
  this._eventHandlers = {};
}
 -->
_eventHandlers là object lưu danh sách callback theo từng tên sự kiện.
Ví dụ:
<!-- 
this._eventHandlers = {
  login: [],
  logout: []
};
 -->
Bước 2: Kiểm tra danh sách handler của sự kiện
<!-- 
if (!this._eventHandlers[eventName]) {
  this._eventHandlers[eventName] = [];
}
 -->
Nếu sự kiện chưa tồn tại thì tạo một mảng mới.
Bước 3: Thêm handler
<!-- this._eventHandlers[eventName].push(handler); -->
Thêm callback vào danh sách của sự kiện tương ứng.
Ví dụ sử dụng
<!-- 
const user = {};

Object.assign(user, eventMixin);

user.on("login", () => {
  console.log("User logged in");
});

user.on("login", () => {
  console.log("Send welcome notification");
});
 -->

 Lúc này, user._eventHandlers có dạng:
 <!-- 
 {
  login: [
    () => console.log("User logged in"),
    () => console.log("Send welcome notification")
  ]
}
  -->
Lưu ý: Hai callback đã được đăng ký nhưng chưa chạy. Chúng chỉ chạy khi sự kiện login được phát bằng trigger().

2.3. Phương thức off()
off() dùng để huỷ đăng ký một handler đã được đăng ký trước đó bằng on().
Cú pháp
<!-- object.off(eventName, handler); -->
Trong đó:
- eventName: tên sự kiện.
- handler: callback cần hủy đăng ký.
Cài đặt off()
Theo ví dụ EventMixin trong javascript.info:
<!-- 
let eventMixin = {
  // on() được giữ nguyên

  off(eventName, handler) {
    let handlers = this._eventHandlers?.[eventName];

    if (!handlers) return;

    for (let i = 0; i < handlers.length; i++) {
      if (handlers[i] === handler) {
        handlers.splice(i--, 1);
      }
    }
  }
};
 -->
 2.4. Phương thức trigger()
 trigger() dùng để phát 1 sự kiện và thực thi tất cả các handler đã đăng ký bằng on
 <!-- object.trigger(eventName, ...args); -->
 Trong đó:
- eventName : tên sự kiện cần phát
- ...args: các tham số bổ sung truyền cho handler
<!-- 
let eventMixin = {
  // on() và off() được giữ nguyên

  trigger(eventName, ...args) {
    if (!this._eventHandlers?.[eventName]) {
      return;
    }

    this._eventHandlers[eventName].forEach(handler => {
      handler.apply(this, args);
    });
  }
};
 -->
2.5. Kết hợp EventMixin với class
Sau khi xây dựng được ba phương thức on(), off() và trigger(), chúng ta cs thể kêt hợp EventMixin với class để bổ sung khả năng xử lý
sự kiện cho các object.
Ví dụ hoàn chỉnh
<!-- 
let eventMixin = {
  on(eventName, handler) {
    if (!this._eventHandlers) {
      this._eventHandlers = {};
    }

    if (!this._eventHandlers[eventName]) {
      this._eventHandlers[eventName] = [];
    }

    this._eventHandlers[eventName].push(handler);
  },

  off(eventName, handler) {
    let handlers = this._eventHandlers?.[eventName];

    if (!handlers) return;

    for (let i = 0; i < handlers.length; i++) {
      if (handlers[i] === handler) {
        handlers.splice(i--, 1);
      }
    }
  },

  trigger(eventName, ...args) {
    if (!this._eventHandlers?.[eventName]) {
      return;
    }

    this._eventHandlers[eventName].forEach(handler => {
      handler.apply(this, args);
    });
  }
};
 -->
Tạo class Menu:
<!-- 
class Menu {
  choose(value) {
    this.trigger("select", value);
  }
}

Object.assign(Menu.prototype, eventMixin);

const menu = new Menu();

menu.on("select", function(value) {
  console.log(`Selected: ${value}`);
});

menu.choose("Start");
 -->
Phân tích luồng hoạt động
1. Object.assign() thêm ba phương thức của EventMixin vào Menu.prototype.
2. menu.on() đăng ký callback cho sự kiện select.
3. menu.choose("Start") gọi this.trigger().
4. trigger() tìm các callback đã đăng ký và thực thi chúng.
5. Callback nhận được giá trị "Start".

Điểm cần nhớ: Class Menu không cần tự viết lại logic quản lý sự kiện. Nó chỉ cần sử dụng EventMixin.
2.6. Luồng hoạt động của EventMixin
Phần này tổng hợp cách ba phương thức on(), off() và trigger() phối hợp với nhau.
2.6.1. Luồng đăng ký sự kiện
<!-- 
chat.on("message", handlerA);
chat.on("message", handlerB);
 -->
EventMixin lưu trữ:
<!-- 
chat._eventHandlers = {
  message: [handlerA, handlerB]
}
 -->
2.6.2. Luồng phát sự kiện
<!-- chat.trigger("message", "Hello"); -->
EventMixin duyệt danh sách handler và thực thi từng callback:
<!-- 
handlerA.apply(chat, ["Hello"]);
handlerB.apply(chat, ["Hello"]);
 -->
2.6.3. Luồng hủy đăng ký
<!-- chat.off("message", handlerA); -->
Danh sách còn lại:
<!-- 
chat._eventHandlers = {
  message: [handlerB]
};
 -->
Khi phát sự kiện lần tiếp theo:
<!-- 
chat.trigger("message", "Hi again");
 -->
2.6.4. Tổng hợp ba phương thức
| Method      | Nhiệm vụ     | Thao tác                |
| ----------- | ------------ | ----------------------- |
| `on()`      | Đăng ký      | `push()`                |
| `off()`     | Hủy đăng ký  | `splice()`              |
| `trigger()` | Phát sự kiện | `forEach()` + `apply()` |

Liên hệ với React và ứng dụng chat:
Trong ứng dụng chat, tư duy EventMixin giúp bạn hiểu cơ chế event-driven:
- Có tin nhắn mới → phát event.
- Thành phần cần nhận tin nhắn → đăng ký listener.
- Thành phần không còn cần nhận → hủy listener.
Lưu ý: EventMixin là ví dụ minh họa cơ chế event trong JavaScript, không phải cách thay thế trực tiếp cho WebSocket hoặc Socket.IO.

3. Summary
3.1. Tổng kết Mixins
1. Mixin
- Là object chứa các methods có thể bổ sung cho object hoặc class khác.
- Có thể kết hợp nhiều mixin bằng Object.assign().
- Có thể kết hợp mixin với extends.
- Có thể thiết lập prototype giữa các mixin.
- super trong method mixin hoạt động dựa trên [[HomeObject]].
2. EventMixin
Method	Chức năng
on()	Đăng ký sự kiện
off()	Hủy đăng ký sự kiện
trigger()	Phát sự kiện
3.2. Ưu điểm và hạn chế
Ưu điểm
1. Tái sử dụng hành vi
Nhiều class có thể sử dụng chung một mixin mà không cần viết lại methods.
<!-- 
const timestampMixin = {
  getTimestamp() {
    return Date.now();
  }
};

class User {}
class Message {}

Object.assign(User.prototype, timestampMixin);
Object.assign(Message.prototype, timestampMixin);
 -->
Cả User và Message đều có thể sử dụng getTimestamp().
2. Kết hợp nhiều hành vi
Một class có thể nhận methods từ nhiều mixin:
<!-- 
Object.assign(
  User.prototype,
  sayMixin,
  eventMixin,
  timestampMixin
);
 -->
3. Giảm phụ thuộc vào inheritance
Không cần tạo một hệ thống class cha phức tạp chỉ để chia sẻ một vài methods.
Hạn chế
1. Xung đột tên method
Nếu hai mixin có cùng tên method, mixin được truyền sau sẽ ghi đè mixin trước.
<!-- 
const mixinA = {
  say() {
    console.log("A");
  }
};

const mixinB = {
  say() {
    console.log("B");
  }
};

class User {}

Object.assign(User.prototype, mixinA, mixinB);

new User().say(); // B
 -->
2. Khó theo dõi nguồn gốc method
Khi một class sử dụng nhiều mixin, việc xác định method đến từ đâu có thể trở nên khó khăn.
3. Phụ thuộc vào cấu trúc this
Mixin có thể giả định object sử dụng nó phải có những properties nhất định.
<!-- 
const sayMixin = {
  say() {
    console.log(this.name);
  }
};
 -->
3.3.2. Liên hệ với ReactJS
Trong React hiện đại, bạn thường không cần sử dụng mixin theo cách trên.

Thay vào đó, có thể tái sử dụng logic bằng:
- Custom Hooks.
- Utility functions.
- Composition.
- Context API.

Ví dụ Custom Hook:
<!-- 
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setIsOnline(true);
    const handleOffline = () => setIsOnline(false);

    window.addEventListener("online", handleOnline);
    window.addEventListener("offline", handleOffline);

    return () => {
      window.removeEventListener("online", handleOnline);
      window.removeEventListener("offline", handleOffline);
    };
  }, []);

  return isOnline;
}
 -->
Hai component có thể sử dụng chung logic:
<!-- 
function Header() {
  const isOnline = useOnlineStatus();

  return <div>{isOnline ? "Online" : "Offline"}</div>;
}

function ChatRoom() {
  const isOnline = useOnlineStatus();

  return <div>{isOnline ? "Connected" : "Disconnected"}</div>;
}
 -->
Đây là tư duy tái sử dụng logic tương tự mục đích của mixin, nhưng phù hợp với kiến trúc React hiện đại hơn.
Custom Hooks giúp:
- Tái sử dụng logic giữa các component.
- Tách biệt logic và giao diện.
- Dễ kiểm thử và bảo trì.
- Không cần kế thừa class hoặc sửa prototype.
