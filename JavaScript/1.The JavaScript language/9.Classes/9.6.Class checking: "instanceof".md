1. The instanceof operator

* 1.1. Cú pháp và ý nghĩa
1. instanceof là gì?
instanceof là toán tử để kiểm tra 1 object có thuộc về 1 class nhất định hay không
Cú pháp :
<!-- object instanceof Class -->
Kết quả trả về là boolean:
- true : Object thuộc class đó hoặc 1 class kế thừa từ nó
- false : Object khôg thuộc class đó
<!-- 
class Rabbit {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit); // true
console.log(rabbit instanceof Array);  // false
 -->
 Ở đây :
rabbit được taoj từ class Rabbit
Vì vậy rabbit instanceof Rabbit trả về true.
rabbit không thuộc Array , nên trả về false
2. instanceof có tính đến kế thừa
<!-- 
class Animal {}

class Rabbit extends Animal {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit); // true
console.log(rabbit instanceof Animal); // true
 -->
Tại sao rabbit instanceof Animal cũng trả về true?
Vì Rabbit kế thừa từ Animal . Do dó instance của Rabbit cũng được xem là instace của Animal
Ghi nhớ: instanceof không chỉ kiểm tra class trực tiếp tạo ra object mà còn xét cả quan hệ kế thừa
3. Câu hỏi kiểm tra
<!-- 
class Animal {}

class Rabbit extends Animal {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit);
console.log(rabbit instanceof Animal);
console.log(rabbit instanceof Array);
 -->
* 1.2. instanceof với class và constructor function
 1. Với class
<!-- 
class Rabbit {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit); // true
 -->
2. Với constructor function
Trước khi có class, JS thường sử dụng constructor function để tạo object
<!-- 
function Rabbit() {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit); // true
 -->
Tại sao?
Khi sử dụng new Rabbit(), JS tạo object và thiết lập prôttype của object đó trỏ đến Rabbit.prototype.
3. Với built-in classes
instanceof cũng hạot động với các class có sẵn của JS
<!-- 
const arr = [1, 2, 3];

console.log(arr instanceof Array);  // true
console.log(arr instanceof Object); // true
 -->
Tại sao arr instanceof Object cũng trả về true?
Vì Array.prototype kế thừa từ Object.prototype.
Do đó , cả Array.prototype và Object.prototype dều nằm trong prôttype chain của arr
<!--
function User() {}

const user = new User();

console.log(user instanceof User);
console.log(user instanceof Object);
console.log(user instanceof Array); 
 -->
Giải thích:
- User: user được tạo bằng new User().
- Object: User.prototype mặc định kế thừa từ Object.prototype.
- Array: Không nằm trong prototype chain của user.

Ghi nhớ: Constructor function và class đều có thể sử dụng với instanceof.

* 1.3. instanceof với built-in classes
instanceof cũng có thể kiểm tra object được tạo từ các built-in classes có sẵn trong JavaScript như Array , Date , Map ,
Set 
1. Ví dụ với built-in classes
<!-- 
const arr = [1, 2, 3];
const date = new Date();
const map = new Map();

console.log(arr instanceof Array); // true
console.log(date instanceof Date); // true
console.log(map instanceof Map);   // true
 -->
Các kết quả đều là true vì prototype tương ứng nằm trong prototype chain của từng object.
2. Kiểm tra cả class cha
<!-- 
const arr = [1, 2, 3];

console.log(arr instanceof Array);  // true
console.log(arr instanceof Object); // true
 -->
arr instanceof Object cũng trả về true vì:Object.prototype nằm trong chain của arr
Ghi nhớ : 1 object có thể là instance của nhiều object thông qua quan hệ kế thừa
* 1.4. Symbol.hasInstance
instanceof kiểm tra prototype chain . Tuy nhiên , JS cho phép chúng ta tuỳ chỉnh logic kiểm tra thông qua static method
1. Cơ chế mặc định
<!-- 
class Animal {}

const obj = {};

console.log(obj instanceof Animal); // false
 -->
JS kiểm tra prototype chain của obj để xác định có chưa Animal.prototype hay không.
2. Tùy chỉnh bằng Symbol.hasInstance
<!-- 
class Animal {
    static [Symbol.hasInstance](obj) {
        return Boolean(obj.canEat);
    }
}

const rabbit = {
    canEat: true
};

console.log(rabbit instanceof Animal); // true
 -->
Điều đặc biệt ở đây:
- rabbit không được tạo bằng new Animal().
- Animal.prototype cũng không nằm trong prototype chain của rabbit.
- Nhưng kết quả vẫn là true.
3. Ứng dụng thực tế
Ta có thể kiểm tra object dựa trên cấu trúc hoặc đặc điểm của nó thay vì yêu cầu object phải được tạo từ một class cụ thể.
Ví dụ, kiểm tra một object có khả năng ăn:
<!-- 
class Animal {
    static [Symbol.hasInstance](obj) {
        return Boolean(obj.canEat);
    }
}

const rabbit = { canEat: true };
const rock = { isHard: true };

console.log(rabbit instanceof Animal); // true
console.log(rock instanceof Animal);   // false
 -->
Điểm quan trọng: Khi class định nghĩa Symbol.hasInstance, ta có thể thay đổi hoàn toàn logic kiểm tra mặc định của instanceof.

* 1.4. Cơ chế kiểm tra prototype chain
Mặc định, instanceof kiểm tra xem Class.prototype có nằm trong prototype chain của object hay không.
1. Cách kiểm tra từng bước
<!-- 
class Animal {}

class Rabbit extends Animal {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Animal); // true
 -->
JavaScript lần lượt kiểm tra:
<!-- 
rabbit.__proto__ === Animal.prototype;
// false

rabbit.__proto__.__proto__ === Animal.prototype;
// true
 -->
Vì tìm thấy Animal.prototype trong prototype chain nên kết quả là true.

2. Minh họa prototype chain
rabbit
  │
  ▼
Rabbit.prototype
  │
  ▼
Animal.prototype  ← Tìm thấy!
  │
  ▼
Object.prototype
  │
  ▼
null
instanceof không chỉ kiểm tra prototype trực tiếp mà kiểm tra toàn bộ chuỗi cho đến khi tìm thấy kết quả hoặc đến null.
<!-- 
class A {}

class B extends A {}

const obj = new B();

console.log(obj instanceof A);
console.log(obj instanceof B);
console.log(A.prototype.isPrototypeOf(obj));
 -->
Giải thích:
- obj instanceof A: A.prototype nằm trong prototype chain của obj.
- obj instanceof B: B.prototype nằm trong prototype chain của obj.
- A.prototype.isPrototypeOf(obj): kiểm tra trực tiếp xem A.prototype có nằm trong prototype chain của obj không.
Ghi nhớ: isPrototypeOf() là một cách kiểm tra prototype chain, có thể giúp hiểu rõ cơ chế mặc định của instanceof.

* 1.6. isPrototypeOf()
isPrototypeOf() là method có sẵn của Object.prototype , dùng để kiểm tra 1 object có nằm trong prototype chain của object khác hay không
1. Cú pháp
<!-- prototypeObject.isPrototypeOf(object); -->
prototypeObject: Object cần kiểm tra.
object: Object cần kiểm tra prototype chain.
2. Ví dụ
 <!--
 class Animal {}

class Rabbit extends Animal {}

const rabbit = new Rabbit();

console.log(Rabbit.prototype.isPrototypeOf(rabbit)); // true
console.log(Animal.prototype.isPrototypeOf(rabbit)); // true
console.log(Array.prototype.isPrototypeOf(rabbit));  // false
   -->
Giải thích:
- Rabbit.prototype nằm trong prototype chain của rabbit.
- Animal.prototype cũng nằm trong prototype chain vì Rabbit kế thừa Animal.
- Array.prototype không nằm trong prototype chain của rabbit.
  
3. So sánh với instanceof
<!-- 
rabbit instanceof Animal;

// Tương đương:
Animal.prototype.isPrototypeOf(rabbit);
 -->
Cả hai đều kiểm tra prototype chain.

Tuy nhiên, có một điểm khác biệt quan trọng: instanceof có thể bị tùy chỉnh bằng Symbol.hasInstance, còn isPrototypeOf() vẫn kiểm tra prototype chain thực tế.
<!-- 
class Animal {
    static [Symbol.hasInstance](obj) {
        return obj.canEat === true;
    }
}

const rabbit = { canEat: true };

console.log(rabbit instanceof Animal); // true

console.log(
    Animal.prototype.isPrototypeOf(rabbit)
); // false
 -->
Vì rabbit không có Animal.prototype trong prototype chain, nhưng Symbol.hasInstance đã tùy chỉnh kết quả của instanceof.
<!-- 
class Animal {}

class Dog extends Animal {}

const dog = new Dog();

console.log(Animal.prototype.isPrototypeOf(dog));
console.log(Object.prototype.isPrototypeOf(dog));
console.log(Array.prototype.isPrototypeOf(dog));
 -->
1.7. Thay đổi prototype sau khi tạo object
1. Điều gì xảy ra khi thay đổi prototype?
instanceof không kiểm tra constructor function nào đẵ trực tiếp tạo ra object
Nó kiểm tra Class.prototype hiện tại có nằm trong prototype chain của object hay không.
Ví dụ theo tài liệu gốc:
<!-- 
function Rabbit() {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Rabbit); // true

// Thay đổi prototype
Rabbit.prototype = {};

console.log(rabbit instanceof Rabbit); // false
 -->
2. Tại sao kết quả thay đổi?
Trước khi thay đổi:
<!-- Object.getPrototypeOf(rabbit) === Rabbit.prototype;
// true -->
Khi gọi new Rabbit(),prototype của rabbit được thiết lập bằng  Rabbit.prototype tại thời điểm tạo object. 
Sau khi thay đổi:
<!-- Rabbit.prototype = {}; -->
Ta đã gán 1 object mới cho Rabbit.prototype.
Nhưng prototype của rabbit vẫn trỏ đến object cũ.
<!-- Object.getPrototypeOf(rabbit) === Rabbit.prototype;
// false -->

2. Bonus: Object.prototype.toString for the type
2.1. Object.prototype.toString()
Trong JS chugns ta thường sử dụng typeof để kiểm tra dữ liệu
Tuy nhiên, typeof có một số hạn chế khi kiểm tra object.
<!-- 
console.log(typeof {});        // "object"
console.log(typeof []);        // "object"
console.log(typeof new Date()); // "object"
console.log(typeof new Map());  // "object"
 -->
Các kết quả đều là "object", nên typeof không giúp phân biệt cụ thể những loại object này.
1. Object.prototype.toString() là gì?
Đây là method có sẵn trong Object.prototype, có thể trả về chuỗi mô tả loại dữ liệu
<!-- 
const obj = {};

console.log(obj.toString()); // [object Object]
 -->
 Với các kiểu dữ liệu khác, kết quả sẽ khác:
 <!-- 
 console.log(Object.prototype.toString.call([]));
// [object Array]

console.log(Object.prototype.toString.call(new Date()));
// [object Date]

console.log(Object.prototype.toString.call(new Map()));
// [object Map]

console.log(Object.prototype.toString.call(123));
// [object Number]
  -->
2. Tại sao lại có Object và Array?
<!-- [object Type] -->
Trong đó:
- object : Phần cố định
- Type : loại dữ liệu JavaScript nhận diện được 
| Giá trị     | Kết quả              |
| ----------- | -------------------- |
| `{}`        | `[object Object]`    |
| `[]`        | `[object Array]`     |
| `123`       | `[object Number]`    |
| `true`      | `[object Boolean]`   |
| `null`      | `[object Null]`      |
| `undefined` | `[object Undefined]` |
Ghi nhớ: Object.prototype.toString() có thể phân biệt nhiều loại dữ liệu mà typeof chỉ trả về "object".

3. Câu hỏi kiểm tra
<!-- 
console.log(typeof []);
console.log(Object.prototype.toString.call([]));

console.log(typeof new Date());
console.log(Object.prototype.toString.call(new Date()));
 -->
Tại sao cần call()?
Object.prototype.toString là method của Object.prototype. Ta dùng call() để gọi method đó với this là object cần kiểm tra 
<!-- Object.prototype.toString.call([]); -->
Ở đây, this bên trong toString() chính là mảng [].
Ghi nhớ:
- typeof: Kiểm tra kiểu dữ liệu ở mức cơ bản.
- Object.prototype.toString.call(): Nhận diện loại object cụ thể.
  
2.2. Sử dụng call() để kiểm tra kiểu
1. Vấn đề khi gọi trực tiếp toString()
<!-- 
const arr = [1, 2, 3];

console.log(arr.toString()); // "1,2,3"
 -->
Tại sao không trả về [object Array]?
Vì Array.prototype đã định nghĩa method toString() riêng , ghi đè method được kế thừa từ Object.prototype.
Do đó, khi gọi:arr.toString();
JavaScript sử dụng Array.prototype.toString(), không phải Object.prototype.toString().
2. Gọi trực tiếp method của Object
Ta có thể lấy method gốc từ Object.prototype:
<!-- 
const arr = [1, 2, 3];

console.log(
    Object.prototype.toString.call(arr)
); // "[object Array]"
 -->
Ở đây:
- Object.prototype.toString: Lấy method gốc.
- .call(arr): Gọi method với this trỏ đến arr.
3. Ví dụ với nhiều kiểu dữ liệu
<!-- 
const values = [
    [],
    {},
    new Date(),
    new Map(),
    new Set(),
    /hello/,
    function () {}
];

values.forEach(value => {
    console.log(Object.prototype.toString.call(value));
});
 -->
Kết quả:
<!-- 
[object Array]
[object Object]
[object Date]
[object Map]
[object Set]
[object RegExp]
[object Function]
 -->
Ghi nhớ: Dùng Object.prototype.toString.call(value) khi muốn gọi chính method gốc của Object, tránh bị method cùng tên ở object hoặc prototype ghi đè.
2.3. Symbol.toStringTag
1. Symbol.toStringTag là gì?
Symbol.toStringTag là một well-known symbol cho phép tùy chỉnh phần tên kiểu dữ liệu được trả về bởi Object.prototype.toString().
<!-- 
const user = {
    [Symbol.toStringTag]: "User"
};

console.log(
    Object.prototype.toString.call(user)
); // "[object User]"
 -->
Thay vì trả về:
<!-- [object Object] -->
JavaScript trả về:
<!--  [object User] -->

Vì object đã định nghĩa sẵn Symbol.toStringTag với giá trị "User"
2. Ví dụ với class
<!-- 
class User {
    get [Symbol.toStringTag]() {
        return "User";
    }
}

const user = new User();

console.log(
    Object.prototype.toString.call(user)
); // "[object User]"
 -->
Ở đây, getter [Symbol.toStringTag] trả về "User".
3. Built-in objects cũng sử dụng Symbol.toStringTag
<!-- 
console.log(
    Object.prototype.toString.call(new Map())
); // "[object Map]"

console.log(
    Object.prototype.toString.call(new Set())
); // "[object Set]"

console.log(
    Object.prototype.toString.call(new Date())
); // "[object Date]"
 -->

3. Summary
3.1. So sánh typeof, toString() và instanceof
| Cách kiểm tra                      | Mục đích                     | Ví dụ                          |
| ---------------------------------- | ---------------------------- | ------------------------------ |
| `typeof`                           | Kiểm tra kiểu dữ liệu cơ bản | `typeof []` → `"object"`       |
| `Object.prototype.toString.call()` | Nhận diện nhãn kiểu dữ liệu  | `"[object Array]"`             |
| `instanceof`                       | Kiểm tra prototype chain     | `[] instanceof Array` → `true` |

<!-- 
const arr = [];

console.log(typeof arr);
// "object"

console.log(Object.prototype.toString.call(arr));
// "[object Array]"

console.log(arr instanceof Array);
// true

console.log(Array.prototype.isPrototypeOf(arr));
// true
 -->
Những điểm cần nhớ:
1. instanceof mặc định kiểm tra prototype chain.
2. Symbol.hasInstance cho phép tùy chỉnh kết quả của instanceof.
3. isPrototypeOf() kiểm tra prototype chain thực tế.
4. Object.prototype.toString.call() giúp nhận diện loại object.
5. Symbol.toStringTag cho phép tùy chỉnh nhãn kiểu dữ liệu.

Câu hỏi tổng hợp
<!-- 
class Animal {}

class Rabbit extends Animal {}

const rabbit = new Rabbit();

console.log(rabbit instanceof Animal);
console.log(Animal.prototype.isPrototypeOf(rabbit));
console.log(Object.prototype.toString.call(rabbit));
 -->
Tại sao không phải [object Animal] hoặc [object Rabbit]?
Vì rabbit không định nghĩa Symbol.toStringTag. JavaScript mặc định nhận diện nó là object thông thường.
Lưu ý: instanceof Animal trả về true không có nghĩa Object.prototype.toString() sẽ trả về [object Animal].
