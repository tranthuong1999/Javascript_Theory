1. The "class" syntax
1.1. Basic syntax
JS sử dụng class để khai báo class
<!-- 
class MyClass {
  prop = value;

  constructor(...) {
    // ...
  }

  method(...) {
    // ...
  }

  get something() {
    // ...
  }

  set something(value) {
    // ...
  }

  [Symbol.iterator]() {
    // ...
  }
}
 -->
Đây là cú pháp tổng quát trong bài viết, bao gồm:
- prop: thuộc tính của instance (class field).
- constructor: phương thức khởi tạo.
- method: phương thức của class.
- get / set: getter và setter.
-  [Symbol.iterator]: computed method name.
1.2. Creating objects with new
Để sử dụng class, chúng ta tạo object bằng từ khóa new.
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    alert(this.name);
  }
}

// Usage:
let user = new User("John");

user.sayHi(); // John
 -->
1. class User: khai báo class tên User.
2. constructor(name): nhận tham số khi tạo object.
3. this.name = name: lưu name vào instance đang được tạo.
4. sayHi(): phương thức của class.
5. new User("John"): tạo instance user.
6. user.sayHi(): gọi phương thức và hiển thị John.
Điểm cần nhớ: constructor() được JS gọi tự động khi sử dụng new() . Bạn không cần gọi trực tiếp
1.3. No comma between class methods
Trong class, các method được phân tách bằng dấu ngoặc nhọn, không sử dụng dấu phẩy.
<!-- 
class User {
  sayHi() {
    alert("Hello");
  }

  sayBye() {
    alert("Goodbye");
  }
}
 -->
Không viết dấu phẩy sau method như khi khai báo object literal.
Bài tập :
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    return `Hello ${this.name}`;
  }
}

let user = new User("Martin");

console.log(user.name);
console.log(user.sayHi());
 -->
Giải thích:
- new User("Martin") tạo instance mới.
- constructor(name) nhận "Martin".
- this.name = name lưu giá trị vào instance.
- user.sayHi() sử dụng this.name để tạo chuỗi "Hello Martin".

2. What is a class?
2.1. Class is a kind of function
Trong JS , class thực chất là 1 function đặc biệt
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    alert(this.name);
  }
}
 -->
 console.log(typeof User); // "function"
 Tại sao?
 Class trong JS được xây dựng trên cơ chế function và prototype mà chúng ta đã học ở bài trước
 Điều này có nghĩa:
- Class tạo ra một constructor function đặc biệt.
- Khi gọi new User(), JavaScript tạo instance.
- Các methods của class được lưu trong User.prototype.

2.2. Class declaration creates a constructor function
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    alert(this.name);
  }
}
 -->
typeof User trả về "function".
Khi khai báo class User , JS thực hiện 2 việc :
1. Tạo function tên User
- Function này trở thành kết quả của class declaration.
- Code của function được lấy từ phương thức constructor().
- Nếu không khai báo constructor(), JavaScript sử dụng constructor rỗng.
  
2. Lưu các class methods vào User.prototype
  <!-- 
  class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    alert(this.name);
  }
}
   -->
Có thể kiểm tra bằng cách :
console.log(typeof User);
// "function"

console.log(User === User.prototype.constructor);
// true

console.log(User.prototype.sayHi);
// Function sayHi
Giải thích:
- User: constructor function được tạo từ class.
- User.prototype.constructor: tham chiếu ngược về User.
- User.prototype.sayHi: phương thức sayHi được lưu trên prototype.
Khi tạo instance:
<!-- 
let user = new User("Martin");

console.log(user.name); // "Martin"
console.log(user.sayHi); // function
 -->
JavaScript tìm sayHi() trong user. Không tìm thấy thì tiếp tục tìm trên User.prototype.
Đây chính là cơ chế prototype inheritance chúng ta đã học ở các bài trước.
Bài tập :
<!-- 
class Product {
  constructor(name) {
    this.name = name;
  }

  getName() {
    return this.name;
  }
}

let product = new Product("Laptop");

console.log(product.hasOwnProperty("getName"));
console.log(Product.prototype.hasOwnProperty("getName"));
 -->
product.hasOwnProperty("getName") → false: getName không nằm trực tiếp trên instance product.
Product.prototype.hasOwnProperty("getName") → true: method getName được lưu trên Product.prototype.

Đây là điểm quan trọng: Class methods nằm trên prototype, không nằm trực tiếp trên instance.
Bạn cần nhớ:
1. typeof User trả về "function".
2. Class declaration tạo ra constructor function.
3. constructor() chứa logic khởi tạo instance.
4. Các methods được lưu trên User.prototype.
5. Instance truy cập methods thông qua prototype chain.

3. Not just a syntactic sugar
3.1. Class và constructor function
Theo tài liệu gốc, class không đơn thuần chỉ là cú pháp viết ngắn hơn của constructor function. Class có một số khác biệt quan trọng về hành vi.
Xét hai cách viết:
Cách 1: Constructor function
<!-- 
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function() {
  console.log(this.name);
};
 -->
Cách 2: Class
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    console.log(this.name);
  }
}
 -->
Cả hai đều có thể tạo instance bằng new và sử dụng prototype để chia sẻ method.
Tuy nhiên, chúng không hoàn toàn giống nhau. Tài liệu sẽ phân tích những khác biệt đó trong các phần tiếp theo.
3.2. Class must be called with new
Theo javascript.info, một điểm khác biệt quan trọng giữa class và constructor function thông thường là:
Class bắt buộc phải được gọi bằng new.
1. Với class
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }
}

let user = User("Martin"); // TypeError
 -->
 Code gây lỗi vì chúng ta gọi User() mà không có new.
 2. Với constructor function
Function thông thường vẫn có thể được gọi mà không cần new:
<!-- 
function User(name) {
  this.name = name;
}

User("Martin"); // Không tự động báo lỗi chỉ vì thiếu new
 -->
Tuy nhiên, việc gọi constructor function không có new có thể dẫn đến lỗi logic, đặc biệt khi this không trỏ đến object mong muốn.
3. Tại sao class bắt buộc dùng new?
JavaScript thiết kế class để việc tạo instance phải thông qua new, tránh gọi nhầm class như một function thông thường.

3.3. Class methods are non-enumerable
Theo javascript.info, các method được khai báo trong class sẽ có thuộc tính descriptor enumerable: false.
Điều này có nghĩa là chúng không xuất hiện khi liệt kê các property enumerable.
1. Ví dụ
<!-- 
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    console.log("Hello");
  }
}

console.log(Object.keys(User.prototype));
 -->
Tại sao không có sayHi?

Vì method sayHi có enumerable: false.
2. Kiểm tra property descriptor
<!-- 
console.log(
  Object.getOwnPropertyDescriptor(User.prototype, "sayHi")
);
 -->
{
  value: [Function: sayHi],
  writable: true,
  enumerable: false,
  configurable: true
}

Kiểm tra kiến thức – câu hỏi luyện tập do mình tạo
<!-- 
class Product {
  getName() {
    return "Laptop";
  }
}

console.log(
  Object.getOwnPropertyDescriptor(
    Product.prototype,
    "getName"
  ).enumerable
);
 -->
3.4. Classes always use strict mode
Theo javascript.info, toàn bộ code bên trong class luôn chạy ở chế độ strict mode, kể cả khi bạn không khai báo "use strict".
1. Strict mode là gì
Là chế độ JS áp dụng các quy tắc nghiêm ngặt hơn , giúp phát hiện lỗi mà 1 só chế độ thông thương bỏ qua
<!-- 
"use strict";

function test() {
  x = 10; // ReferenceError
}

test();
 -->
Vì x chưa được khai báo bằng let, const hoặc var, JavaScript báo lỗi.
2. Strict mode trong class
Bạn không cần viết "use strict" bên trong class:
<!-- 
class User {
  sayHi() {
    x = 10;
  }
}

let user = new User();

user.sayHi(); // ReferenceError
 -->
3. So sánh
| Code                       | Strict mode       |
| -------------------------- | ----------------- |
| Function thông thường      | Không tự động bật |
| Function có `"use strict"` | Có                |
| Code bên trong class       | Luôn có           |
Điểm cần nhớ: Strict mode chỉ là một trong những khác biệt về hành vi giữa class và function thông thường.

Điểm quan trọng: class không chỉ là cách viết ngắn gọn của constructor function. Nó còn có những quy tắc riêng về cách gọi, thuộc tính method và strict mode.

4. Class Expression
4.1. Class expression
Ngoài cách khai báo class bằng class User {...}, JavaScript còn cho phép tạo class thông qua một biểu thức và gán nó vào biến.
<!-- 
class User {
  sayHi() {
    console.log("Hello");
  }
}
 -->

Class expression:
<!-- 
const User = class {
  sayHi() {
    console.log("Hello");
  }
};

const user = new User();
user.sayHi(); // Hello
 -->
Điểm khác biệt:
- Class declaration: khai báo class trực tiếp bằng tên class.
- Class expression: tạo class như một biểu thức rồi gán kết quả cho biến.
Class expression cũng có thể được sử dụng như giá trị trả về của một function.
<!-- 
function createClass() {
  return class {
    sayHi() {
      console.log("Hello");
    }
  };
}

const User = createClass();
const user = new User();

user.sayHi(); // Hello
 -->
Cần nhớ: Class expression tạo ra một class và có thể được gán vào biến, truyền vào function hoặc trả về từ function.
<!-- 
const User = class {
  sayHi() {
    return "Hello";
  }
};

console.log(typeof User);
 -->
4.2. Named Class Expression
Theo javascript.info, Class Expression có thể có tên riêng. Đây được gọi là Named Class Expression.
<!-- 
const User = class MyClass {
  sayHi() {
    console.log("Hello");
  }
};

const user = new User();
user.sayHi(); // Hello
 -->
User: tên biến bên ngoài, dùng để truy cập class.
MyClass: tên nội bộ của class expression.
2. Phạm vi sử dụng tên class
Tên MyClass chỉ có thể được sử dụng bên trong chính class expression đó.
<!-- 
const User = class MyClass {
  sayHi() {
    console.log(MyClass);
  }
};

const user = new User();

user.sayHi(); // class MyClass { ... }

console.log(MyClass); // ReferenceError
 -->
Giải thích:
- Bên trong class, MyClass có thể tham chiếu đến chính class đó.
- Bên ngoài class, không thể truy cập MyClass.
- - Bên ngoài, ta sử dụng biến User.

3. Khi nào hữu ích?
Named Class Expression hữu ích khi class cần tham chiếu đến chính nó, chẳng hạn trong một số trường hợp đệ quy hoặc tạo instance bên trong class.
Kiểm tra kiến thức – câu hỏi luyện tập do mình tạo
<!-- 
const User = class MyClass {
  getName() {
    return MyClass.name;
  }
};

const user = new User();

console.log(user.getName());
console.log(User.name);
console.log(MyClass);
 -->
4.3. Making classes dynamically
JS cho phép tạo class 1 cách linh hoạt bằng cách sử dụng class expression kết hợp với điều kiện hoặc biểu thức
1. Tạo class dựa trên điều kiện
   <!-- 
    function createClass(phrase) {
  return class {
    sayHi() {
      console.log(phrase);
    }
  };
<!-- } -->

<!-- const User = createClass("Hello"); -->

<!-- new User().sayHi(); // Hello -->
    -->
Giải thích:
- createClass() nhận tham số phrase.
- Function trả về một class.
- Method sayHi() sử dụng biến phrase từ phạm vi bên ngoài.
- - Mỗi lần gọi createClass() có thể tạo ra một class khác nhau.
2. Ứng dụng
Có thể sử dụng khi muốn tạo class dựa trên cấu hinhf hoặc điều kiện tại runtime
<!-- 
function createUserClass(isAdmin) {
  if (isAdmin) {
    return class {
      role() {
        return "Admin";
      }
    };
  }

  return class {
    role() {
      return "User";
    }
  };
}

const Admin = createUserClass(true);
const User = createUserClass(false);

console.log(new Admin().role()); // Admin
console.log(new User().role());  // User

 -->
 Cần nhơ : class expression cho phép tạo và trả về class tai runtime , thay vì phải khai báo cố dịnh class từ đầu
 Bài tập vận dụng :
 <!-- 
 function createClass(name) {
  return class {
    getName() {
      return name;
    }
  };
}

const UserA = createClass("Martin");
const UserB = createClass("Alex");

console.log(new UserA().getName());
console.log(new UserB().getName());
  -->
Điểm cần nhớ: Class Expression có thể được tạo động tại runtime và sử dụng closure để giữ dữ liệu từ phạm vi bên ngoài.

5. Getters/setters
5.1. Getters in class
Class hỗ trợ get và set để định nghĩa getter và setter cho thuộc tính
Getter là một method được gọi khi đọc thuộc tính
Setter là 1 method được gọi khi gán giá trị cho thuộc tính
1. Cú pháp
   <!-- 
   class User {
  constructor(name) {
    this._name = name;
  }

  get name() {
    return this._name;
  }

  set name(value) {
    this._name = value;
  }
}

const user = new User("Martin");

console.log(user.name);

user.name = "Alex";

console.log(user.name); 
   
    -->
2. Cách hoạt động
Khi đọc:
<!-- console.log(user.name); -->
JS tự động gọi 
<!-- 
get name() {
  return this._name;
}
 -->
Khi gán :
<!-- user.name = "Alex"; -->
JavaScript tự động gọi:
<!-- 
set name(value) {
  this._name = value;
}
 -->
Lưu ý :: _name chỉ là quy ước đătj tên để thể hiện thuộc tính nội bộ , không phải là private field thực sự 
3. Khi nào sử dụng?
Getter/setter hữu ích khi bạn muốn:
- Kiểm soát cách đọc thuộc tính.
- Kiểm tra dữ liệu trước khi gán.
- Tính toán giá trị thay vì lưu trực tiếp.

5.2. Setters in class
1. Setter dùng để làm gì?
Setter cho phép kiểm soát gía trị được gán vào 1 thuộc tính
<!-- 
class User {
  set age(value) {
    if (value < 18) {
      throw new Error("You must be at least 18");
    }

    this._age = value;
  }
}

const user = new User();

user.age = 20; // Hợp lệ
user.age = 15; // Error
 -->
2. Setter không phải method thông thường
<!-- 
class User {
  set age(value) {
    this._age = value;
  }

  updateAge(value) {
    this._age = value;
  }
}

const user = new User();

user.age = 20;       // Gọi setter
user.updateAge(25);  // Gọi method thông thường
 -->
Khác biệt:
- Setter được gọi thông qua phép gán thuộc tính
- Method thông thường phải được gọi bằng cú pháp gọi hàm

3. Lưu ý quan trọng
Không nên gán lại chính thuộc tính đang có setter bên trong setter:
<!-- 
class User {
  set age(value) {
    this.age = value; // Gây gọi setter liên tục
  }
}
 -->
Điều này gây đệ quy vô hạn và dẫn đến RangeError.
Thay vào đó, sử dụng thuộc tính khác như _age để lưu dữ liệu.
5.3. Getters/setters in User.prototype
Getter và setter không chỉ được dịnh nghĩa bên trong class mà còn có thể định nghĩa trực tiếp tên prototype của construction
1. Ví dụ với constructor function
<!-- 
function User(name) {
  this._name = name;
}

Object.defineProperty(User.prototype, "name", {
  get() {
    return this._name;
  },

  set(value) {
    this._name = value;
  }
});

const user = new User("Martin");

console.log(user.name); // Martin

user.name = "Alex";

console.log(user.name); // Alex
 -->
2. Phân tích cách hoạt động
Bước 1: Tạo object bằng constructor:
<!-- const user = new User("Martin"); -->
Object user có thuộc tính _name.
Bước 2: Getter và setter được định nghĩa trên User.prototype
<!-- 
Object.defineProperty(User.prototype, "name", {
  get() {
    return this._name;
  },
  set(value) {
    this._name = value;
  }
});
 -->
Bước 3: Khi đọc:user.name;
Cần nhớ: Getter/setter là property accessor được định nghĩa trên prototype, không phải dữ liệu được lưu trực tiếp trên từng object.

Bài tập :
<!-- 
function User(name) {
  this._name = name;
}

Object.defineProperty(User.prototype, "name", {
  get() {
    return this._name;
  }
});

const user = new User("Martin");

console.log(user.hasOwnProperty("name"));
console.log(user.hasOwnProperty("_name"));
 -->
Giải thích:
- name được đingj nghĩa trên User.prototype, không nằm trực tiếp trong object user
- _name được tạo bằng this._name = name bên trong constructor , nên là thuộc tính riêng của user

6. Computed names […]
6.1. Computed method names
Class cho phép sử dụng bên trong đấu ngoặc [] để xác đinhj tên method
1. Cú pháp
<!-- 
class User {
  sayHi() {
    console.log("Hello");
  }
}
 -->
 Với computed method names:
 <!-- 
 const methodName = "sayHi";

class User {
  [methodName]() {
    console.log("Hello");
  }
}

const user = new User();

user.sayHi(); // Hello
  -->
JavaScript sẽ đánh giá biểu thức [methodName] và sử dụng kết quả làm tên method.
2. Sử dụng biểu thức
Không chỉ biến, bạn có thể sử dụng biểu thức JavaScript bên trong [].
<!-- 
class User {
  ["say" + "Hi"]() {
    console.log("Hello");
  }
}

const user = new User();

user.sayHi(); // Hello
 -->
Ở đây 
<!-- "say" + "Hi" -->
Trả về "sayHi", vì vậy method được tạo ra có tên là sayHi
3. Lưu ý
Computed method names cũng áp dugnj được với getter và setter
<!-- 
const propertyName = "name";

class User {
  constructor(name) {
    this._name = name;
  }

  get [propertyName]() {
    return this._name;
  }
}

const user = new User("Martin");

console.log(user.name); // Martin
 -->
Cần nhớ:
- methodName(): tên method cố định.
- [methodName](): tên method được xác định bằng biểu thức.
- Biểu thức bên trong [] được đánh giá khi class được định nghĩa.
Tổng kết 6. Computed names
- Sử dụng [] để xác định tên method bằng biểu thức.
- Biểu thức được đánh giá khi class được định nghĩa.
- Có thể áp dụng cho method, getter và setter.

7. Class fields.
7.1. Class fields syntax
class fields cho phép khai báo thuộc trực tiếp bên trong class mà không cần phải khai báo chúng trong constructor
1. Cách khai báo truyền thống
Trước khi có class fields, chúng ta thường khai báo thuộc tính trong constructor
<!-- 
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

const user = new User("Martin", 27);

console.log(user.name); // Martin
console.log(user.age);  // 27
 -->
2. Sử dụng class fields
Có thể viết ngắn gọn hơn:
<!-- 
class User {
  name = "Martin";
  age = 27;
}

const user = new User();

console.log(user.name); // Martin
console.log(user.age);  // 27
 -->
Ở đây:
- name = "Martin" là class field.
- age = 27 là class field.
- Mỗi object được tạo từ class sẽ có các field riêng.

3. Class fields kết hợp với constructor
Bạn có thể khơi tạo constuctor để khởi tạo những giá trị truyền từ bên ngoài
<!-- 
class User {
  role = "Developer";

  constructor(name) {
    this.name = name;
  }
}

const user = new User("Martin");

console.log(user.name); // Martin
console.log(user.role); // Developer
 -->
4. Phân biệt class fields và methods
<!-- 
class User {
  name = "Martin";

  sayHi() {
    return "Hello";
  }
}
 -->
| Thành phần | Vị trí           |
| ---------- | ---------------- |
| `name`     | Mỗi object       |
| `sayHi()`  | `User.prototype` |
Điểm này rất quan trọng: class field là thuộc tính riêng của từng instance , còn method thông thường được chia sẻ thông qua prototype
Bài tập 
<!-- 
class User {
  name = "Martin";

  constructor(age) {
    this.age = age;
  }

  sayHi() {
    return "Hello";
  }
}

const user = new User(27);

console.log(user.hasOwnProperty("name"));
console.log(user.hasOwnProperty("sayHi"));
 -->
Giải thích:
- name là class field nên được tạo trực tiếp trên từng instance user.
- sayHi() là method thông thường nên nằm trên User.prototype, không nằm trực tiếp trên user

| Thành phần          | Vị trí lưu trữ               |
| ------------------- | ---------------------------- |
| Class field         | Instance                     |
| Constructor         | `User.prototype.constructor` |
| Method thông thường | `User.prototype`             |

7.2. Fields belong to individual objects
class fields thuộc về từng object được tạo ra, không đựọc chia sẻ thông qua prototype như các mehtod thông thường
1. Mỗi object có field riêng
<!-- 
class User {
  name = "Martin";
}

const user1 = new User();
const user2 = new User();

user1.name = "Alex";

console.log(user1.name); // Alex
console.log(user2.name); // Martin
 -->
Giải thích:
user1 có thuộc tính name riêng
user2 có thuộc tính name riêng
Thay đổi user1.name không ảnh hưởng đến user2.name
2. So sánh với prototype method
<!-- 
class User {
  name = "Martin";

  sayHi() {
    console.log("Hello");
  }
}

const user1 = new User();
const user2 = new User();

console.log(user1.sayHi === user2.sayHi); // true
console.log(user1.name === user2.name);   // true
 -->
Cả hai kết quả đều là true, nhưng bản chất khác nhau:
- sayHi : 2 object đều tham chiếu đến cùng 1 method trên prototype
- name : 2 object có 2 thuộc tính riêng , tình cờ đang chứa cùng giá trị "Martin"
3. Kiểm tra vị trí lưu trữ
<!-- 
class User {
  name = "Martin";

  sayHi() {}
}

const user = new User();

console.log(Object.hasOwn(user, "name")); // true
console.log(Object.hasOwn(user, "sayHi")); // false

console.log(Object.hasOwn(User.prototype, "sayHi")); // true
 -->
user
├── name: "Martin"
└── [[Prototype]]
    └── User.prototype
        ├── constructor: User
        └── sayHi: function

Cần nhớ:
- Class fields thuộc từng instance.
- Method thông thường nằm trên prototype
- Các instance có filed riêng nhưng chia sẻ method thông qua prototype
  
Bài tập :
<!-- 
class Counter {
  count = 0;

  increase() {
    this.count++;
  }
}

const a = new Counter();
const b = new Counter();

a.increase();
a.increase();

console.log(a.count);
console.log(b.count);
 -->
b.count không thay đổi vì mỗi instance có field count riêng.
Tổng kết 7.2
- Class field được khởi tạo riêng cho mỗi instance.
- Thay đổi field của object này không ảnh hưởng object khác.
- Method thông thường vẫn được chia sẻ qua prototype.
7.3. Expressions and function calls in fields
Class field không chỉ nhận giá trị cố định mà cón có thể sử dụng biểu thức và fucntion call để khởi tạo gia strij 
1. Sử dụng biểu thức
<!--

3. Mỗi instance thực hiện khởi tạo riêng

Giải thích:
Mỗi lần tạo instance, class field id gọi lại function getValue():

8. Making bound methods with class fields
8.1. Losing this
Khi truyền method làm callback , chúng ta có thể mất ngữ cảnh this
1. Method hoạt động bình thường
<!-- 
class Button {
  constructor(value) {
    this.value = value;
  }

  click() {
    console.log(this.value);
  }
}

const button = new Button("Hello");

button.click(); // Hello
 -->
 2. Vấn đề khi truyền method làm callback
<!-- 
class Button {
  constructor(value) {
    this.value = value;
  }

  click() {
    console.log(this.value);
  }
}

const button = new Button("Hello");

const callback = button.click;

callback(); // TypeError hoặc undefined tùy môi trường
 -->
 Tai sao :
 const callback = button.click;
 chúng ta chỉ lấy function ra khỏi object  , không giữ lại ngữ cảnh button
 Khi gọi : callback()
 this không còn tham chiếu đến button
Trong strict mode, this sẽ là undefined, nên truy cập this.value gây TypeError.
3. Trường hợp thực tế với setTimeout
<!--

 -->
 Sau 1s callback mới được gọi nhưng không còn ngữ cảnh button , dẫn đến lỗi truy cập this.value
 Cần nhớ:
- button.click() → this là button.
- const callback = button.click → chỉ lấy functioon không giữ lại this
- Truyền method trực tiếp làm callback có thể khiến this bị mất.

8.4. Class fields with arrow functions
Theo javascript.info, có một cách khác để giải quyết vấn đề mất this: sử dụng arrow function làm class field.
1. Cách viết
Thay vì khai báo method thông thường:
<!-- 
class Button {
  constructor(value) {
    this.value = value;
  }

  click() {
    console.log(this.value);
  }
}
 -->
2. Tại sao không mất this?
Arrow function không có this riêng.
Nó lấy this từ phạm vi bên ngoài tại thời điểm được tạo.
3. So sánh method thông thường và arrow function field
<!-- 
class User {
  name = "Martin";

  sayHi() {
    console.log(this.name);
  }

  sayHello = () => {
    console.log(this.name);
  };
}
 -->
| Tiêu chí                       | Method thông thường | Arrow function field |
| ------------------------------ | ------------------- | -------------------- |
| Vị trí                         | `User.prototype`    | Instance             |
| Có `this` riêng                | Có                  | Không                |
| Mất `this` khi truyền callback | Có thể              | Không                |
| Chia sẻ giữa các instance      | Có                  | Không                |
5. Lưu ý quan trọng
Arrow function field có một nhược điểm:
- Mỗi instance tạo một function riêng.
- Không được chia sẻ trên prototype như method thông thường.
Vì vậy, không phải lúc nào cũng nên chuyển tất cả method thành arrow function.

Cần nhớ:
- Arrow function không có this riêng.
- Class field tạo arrow function riêng cho từng instance.
- Arrow function giữ this của instance khi được tạo.
- Có thể dùng trực tiếp làm callback mà không cần bind().

9. Summary
Theo nội dung bài Classes – javascript.info, cần ghi nhớ những điểm chính sau:
1. Class syntax: class cung cấp cú pháp để tạo constructor và các phương thức cho object.

8. Class fields: Field được tạo trên từng instance, khác với method thông thường được lưu trên prototype.
