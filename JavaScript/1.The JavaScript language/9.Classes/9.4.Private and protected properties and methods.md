1. A real-life example
Hãy tưởng tượng một chiếc máy pha cà phê:
- Bên ngoài: nút bật/tắt, màn hình, vòi lấy cà phê.
- Bên trong: bộ phận đun nước, đường ống, cảm biến nhiệt, hệ thống điều khiển.
Khi sử dụng máy, bạn chỉ cần thao tác với các nút bên ngoài. Bạn không cần biết cách bộ phận đun nước hoạt động.
Tại sao phải thiết kế như vậy?
1. Người dùng không vô tình thay đổi các thành phần bên trong.
2. Nhà sản xuất có thể thay đổi cấu trúc bên trong mà không ảnh hưởng cách sử dụng.
3. Người dùng không phải hiểu toàn bộ sự phức tạp của hệ thống.
Trong lập trình OOP cũng tương tự:
- Người sử dụng class chỉ cần biết cách gọi những chức năng được cung cấp
- Những dữ liệu và phương thức phục vụ hoạt động nôi bộ có thể được ẩn đi
  
Đây chính là ý tưởng nền tảng của Encapsulation (tính đóng gói).
Liên hệ với ứng dụng chat:
Ví dụ class ChatRoom có chức năng gửi tin nhắn . Người sủ dụng chỉ cần gửi sendMessage() , không nhất thiết phải can thiếp trực tiếp
vào cách hệ thống kiểm tra nội dung , cập nhật trạng thái hoặc dữ liệu xử lý nội bộ 
Ẩn các thành phần nội bộ giúp:
- Bảo vệ dữ liệu và logic bên trong
- Tránh việc can thiệp bên ngoài k đúng cách
- Đơn giản hoá cách sử dụng class
- Cho phép thay đổi implementation bên trong mà không ảnh hươngr đến interface bên ngoài

2. Internal and external interface
Internal interface là tập hợp các thuộc tính và phương thức bên trong class , được sử dụng để triển khai logic hoạt động 
của class 
<!-- 
class CoffeeMachine {
    waterAmount = 0;

    checkWater() {
        return this.waterAmount > 0;
    }

    makeCoffee() {
        if (this.checkWater()) {
            console.log("Making coffee...");
        }
    }
}
 -->
Trong ví dụ:
- waterAmount: dữ liệu nội bộ.
- checkWater(): logic kiểm tra nội bộ.
- makeCoffee(): chức năng sử dụng logic nội bộ.

2.2. External interface
External interface là tập hợp các thuộc tính và phương thức mà bên ngoiaf class có thể sử dụng để tương tác với class
<!-- 
class CoffeeMachine {
    waterAmount = 0;

    checkWater() {
        return this.waterAmount > 0;
    }

    makeCoffee() {
        if (this.checkWater()) {
            console.log("Making coffee...");
        }
    }
}

const machine = new CoffeeMachine();

machine.waterAmount = 100;
machine.makeCoffee();
 -->
Bên ngoài có thể:
- Truy cập waterAmount.
- Gọi makeCoffee().
Trong khi đó , checkWater() được thiết kế để phục vụ logic nội bộ 
Lưu ý: Trong ví dụ này , cả ba đang đều là public . Việc một method được dùng nội bộ hông khiến nó trở thành private
| Internal interface    | External interface         |
| --------------------- | -------------------------- |
| **Mục đích**          | Triển khai logic bên trong | Tương tác từ bên ngoài |
| **Đối tượng sử dụng** | Chính class                | Code bên ngoài         |
| **Ví dụ**             | Kiểm tra nước, tính toán   | Bật máy, pha cà phê    |

2.3. Public fields
Public là những thuộc tính và phương thức có thể truy cập từ bên ngoài class
Trong JS , mặc định các field và method được khai báo trong class đều là public
<!-- 
class User {
    name = "Martin";

    sayHello() {
        console.log(`Hello ${this.name}`);
    }
}

const user = new User();

console.log(user.name); // Martin
user.sayHello();        // Hello Martin
 -->
Bên ngoài có thể:
- Đọc user.name
- Thay đổi user.name.
- Gọi user.sayHello().
<!-- 
user.name = "Alex";

console.log(user.name); // Alex
 -->
Đặc điểm:
- Public field có thể truy cập được trực tiếp
- Public method có thể được gọi trực tiếp.
- Đây là phần class cung cấp cho bên ngoài sử dụng
<!-- 
class User {
    name = "Martin";
}

const user = new User();
user.name = "Alex";
 -->
2.4. Private fields
Private là những thuộc tính và phương thức chỉ có thể truy cập bên trong class khi khai báo chúng
JavaScript sử dụng ký tự # để khai báo private.
<!-- 
class CoffeeMachine {
    #waterAmount = 0;

    makeCoffee() {
        console.log(this.#waterAmount);
    }
}

const machine = new CoffeeMachine();

machine.makeCoffee();       // 0
console.log(machine.#waterAmount); // SyntaxError
 -->
Có hai điểm cần nhớ:
1. Khai báo private filed bằng # trước thuộc tính
2. Private field chỉ được khai báo bên trong class đó 
Nếu thử truy cập machine.#waterAmount từ bên ngoài class, JavaScript sẽ báo lỗi cú pháp.
| Public                   | Private                                  |
| ------------------------ | ---------------------------------------- |
| `name`                   | `#name`                                  |
| Truy cập từ bên ngoài    | Chỉ truy cập bên trong class             |
| Có thể đọc/ghi trực tiếp | Phải thông qua logic được class cung cấp |
Ví dụ trong ứng dụng chat:
<!-- 
class ChatRoom {
    #messages = [];

    sendMessage(message) {
        this.#messages.push(message);
    }

    getMessages() {
        return this.#messages;
    }
}

const room = new ChatRoom();

room.sendMessage("Hello!");

console.log(room.getMessages()); // ["Hello!"]
// console.log(room.#messages);  // SyntaxError
 -->
Câu hỏi :
<!-- 
class User {
    #password = "123456";

    checkPassword() {
        return this.#password;
    }
}
-->
2.5. Protected fields
Protected là những thuộc tính và phương thức được thiết kế để sử dụng bên trong class và các class kế thừa nó
JavaScript hiện không có cú pháp protected chính thức như TypeScript.
JavaScript sử dụng _ phía trước thuộc tính
<!-- 
class CoffeeMachine {
    _waterAmount = 0;

    makeCoffee() {
        console.log(this._waterAmount);
    }
}

const machine = new CoffeeMachine();

machine._waterAmount = 100; // Vẫn truy cập được
console.log(machine._waterAmount); // 100
 -->
Điểm quan trọng: _waterAmount không thực sự được bảo vệ. Đây chỉ là quy ước để lập trình viên hiểu rằng không nên truy cập trực tiếp từ bên ngoài.
Ví dụ kế thừa:
<!-- 

class CoffeeMachine {
    _waterAmount = 0;
}

class SmartCoffeeMachine extends CoffeeMachine {
    checkWater() {
        return this._waterAmount > 0;
    }
}
 -->
Class con SmartCoffeeMachine có thể truy cập _waterAmount
So sánh Public, Protected và Private
| Loại      | Cú pháp | Truy cập bên ngoài                  | Class con       |
| --------- | ------- | ----------------------------------- | --------------- |
| Public    | `name`  | Có                                  | Có              |
| Protected | `_name` | Có về mặt kỹ thuật, nhưng không nên | Có              |
| Private   | `#name` | Không                               | Không trực tiếp |

Lưu ý quan trọng:
- _name: chỉ là quy ước , không có cơ chế bảo vệ thực sự 
- #name :được JS bảo vệ bằng cơ chế private fields.
- JavaScript : không có từ khoá protected chính thức

Đoạn code sau có chạy được không?
<!--

    _name = "Dog";
}

class Rabbit extends Animal {
    showName() {
        return this._name;

}

const rabbit = new Rabbit();

console.log(rabbit.showName());
 -->

3. Protecting "waterAmount"
3.1. Public property ban đầu
<!-- 
class CoffeeMachine {
    waterAmount = 0;

    constructor(power) {
        this.power = power;
    }
}

const coffeeMachine = new CoffeeMachine(100);

coffeeMachine.waterAmount = 200;
coffeeMachine.waterAmount = -10;
 -->
Hiện tại, cả waterAmount và power đều là public property.
Điều này có ý nghĩa là bên ngoài có thể tự do thay đổi giá trị 
<!-- coffeeMachine.waterAmount = -10; -->
Nhưng trong thực tế , lượng nước k thể âm
3.2. Protected property với dấu _
Tài liệu đề xuất sử dụng _waterAmount để thể hiện rằng property này không nên được truy cập trực tiếp từ bên ngoài
<!-- 
class CoffeeMachine {
    _waterAmount = 0;

    constructor(power) {
        this.power = power;
    }
}

const coffeeMachine = new CoffeeMachine(100);

coffeeMachine._waterAmount = -10;

console.log(coffeeMachine._waterAmount); // -10
 -->
Vậy tại sao vẫn sử dụng dấu _?
Đây là quy ước thiết kế dành cho lập trình viên:
1. Không nên thay đổi _waterAmount trực tiếp từ bên ngoài.
2. Nên tương tác thông qua các phương thức được class cung cấp
3. Class có thể kiểm soat cách dữ liệu thay đổi 

Điểm quan trọng: Đổi từ waterAmount sang _waterAmount không tự động bảo vệ dữ liệu.
3.3. Kiểm soát giá trị bằng getter/setter
Để kiểm soát dữ liệu thực sự theo cách tiếp cận của tài liệu, ta tạo setter để kiểm tra giá trị trước khi cập nhật.
<!-- 
class CoffeeMachine {
    _waterAmount = 0;

    constructor(power) {
        this.power = power;
    }

    set waterAmount(value) {
        if (value < 0) {
            value = 0;
        }

        this._waterAmount = value;
    }

    get waterAmount() {
        return this._waterAmount;
    }
}

const coffeeMachine = new CoffeeMachine(100);

coffeeMachine.waterAmount = -10;

console.log(coffeeMachine.waterAmount); // 0
 -->
Giải thích:
- set waterAmount(value): được gọi khi bên ngoài gán coffeeMachine.waterAmount = ....
- Setter kiểm tra giá trị đầu vào.
- Nếu giá trị nhỏ hơn 0, chuyển thành 0.
- get waterAmount(): được gọi khi đọc coffeeMachine.waterAmount.

Lưu ý:  waterAmount lúc này là accessor property , còn __waterAmount là nơi lưu giá trị thực tế
### Phân biệt getter và setter

| Thành phần               | Khi nào được gọi? | Chức năng                    |
| ------------------------ | ----------------- | ---------------------------- |
| `get waterAmount()`      | Khi đọc property  | Trả về giá trị               |
| `set waterAmount(value)` | Khi gán property  | Kiểm tra và cập nhật giá trị |

4. Read-only "power"
Trong ví dụ máy pha cà phê , power là công suất cua máy
Công suất được xác định khi khỏi tạo máy và k nên thay đổi sau đó
<!-- 
class CoffeeMachine {
    constructor(power) {
        this.power = power;
    }
}

const machine = new CoffeeMachine(100);

machine.power = 200;

console.log(machine.power); // 200
 -->
Vấn đề : power đang là public protety nên vẫn có thể được thay đổi
4.1. Getter không có setter
getter để cho phép đọc nhưng không cung cấp setter để thay đổi thông qua accessor.
<!-- 
class CoffeeMachine {
    constructor(power) {
        this._power = power;
    }

    get power() {
        return this._power;
    }
}

const machine = new CoffeeMachine(100);

console.log(machine.power); // 100
 -->
Ở đây:
- _power : lưu giá trị thực tế
- get power() cho phép đọc giá trị 
- - Không có set power().
Tuy nhiên cần chú ý : _power vẫn là public theo mặt lkỹ thuật nên người dùng vẫn có thể sửa trực tiếp machine._power. Đây chưa phải cơ chế bảo vệ tuyệt đối.
Tại sao?
- get power() cho phép đọc giá trị.
- Không có set power() nên không thể gán giá trị thông qua accessor power.
- Code bên trong class mặc định chạy ở strict mode.
- Vì vậy, phép gán machine.power = 200 gây TypeError.
Như vây : getter không có setter  chỉ ngăn việc ghi qua power, chưa bảo vệ hoàn toàn dữ liệu _power
4.2. Getter/setter và get/set methods
Trong JS có 2 cách phổ biến để cung cấp quyền đọc và ghi dữ liệu 
Cách 1: Getter/setter (Accessor)
<!-- 
class CoffeeMachine {
    constructor(power) {
        this._power = power;
    }

    get power() {
        return this._power;
    }

    set power(value) {
        if (value < 0) {
            throw new Error("Power must be positive");
        }

        this._power = value;
    }
}

const machine = new CoffeeMachine(100);

console.log(machine.power); // 100

machine.power = 200;
console.log(machine.power); // 200
 -->
 Cách sử dụng:
 <!-- 
 machine.power;       // Gọi getter 
machine.power = 200; // Gọi setter
  -->
Cách 2: Get/set methods (Method thông thường)
<!-- 
class CoffeeMachine {
    constructor(power) {
        this._power = power;
    }

    getPower() {
        return this._power;
    }

    setPower(value) {
        if (value < 0) {
            throw new Error("Power must be positive");
        }

        this._power = value;
    }
}

const machine = new CoffeeMachine(100);

console.log(machine.getPower()); // 100

machine.setPower(200);
console.log(machine.getPower()); // 200
 -->
Cách sử dụng:
<!-- 
machine.getPower();
machine.setPower(200);
 -->
### So sánh

| Tiêu chí         | Getter/setter         | Get/set methods         |
| ---------------- | --------------------- | ----------------------- |
| Cú pháp khai báo | `get power()`         | `getPower()`            |
| Đọc dữ liệu      | `machine.power`       | `machine.getPower()`    |
| Ghi dữ liệu      | `machine.power = 200` | `machine.setPower(200)` |
| Cách gọi         | Giống property        | Giống method            |
Điểm cần nhớ: Getter/setter giúp thao tác với dữ liệu giống như property, nhưng vẫn có thể kiểm soát logic đọc và ghi.

5. Private "#waterLimit"
5.1. Khai báo private field bằng #
Giả sử máy pha cà phê có giới hạn nước tối đa là 200
Ta muốn giới hạn này không bị thay đổi từ bên ngoài.
<!-- 
class CoffeeMachine {
    #waterLimit = 200;

    setWaterAmount(value) {
        if (value < 0) {
            value = 0;
        }

        if (value > this.#waterLimit) {
            value = this.#waterLimit;
        }

        this._waterAmount = value;
    }
}

const machine = new CoffeeMachine();

machine.setWaterAmount(300);

console.log(machine._waterAmount); // 200
 -->
Ở đây:
- #waterLimit là private field.
- Chỉ có thể truy cập bên trong class CoffeeMachine.
- Bên ngoài không thể đọc hoặc thay đổi trực tiếp.
- setWaterAmount() là public method cho phép bên ngoài tương tác với dữ liệu thông qua logic kiểm soát.
Điểm quan trọng: Khác với _waterLimit, dấu # tạo ra cơ chế private thực sự của JavaScript.
5.2. Private method
Không chỉ property, JavaScript còn cho phép khai báo private method bằng dấu #.
<!-- 
class CoffeeMachine {
    #waterAmount = 0;

    #checkWater() {
        return this.#waterAmount > 0;
    }

    makeCoffee() {
        if (this.#checkWater()) {
            console.log("Making coffee...");
        } else {
            console.log("Not enough water!");
        }
    }
}

const machine = new CoffeeMachine();

machine.makeCoffee(); // Not enough water!
 -->
Giải thích:
- #waterAmount: private field.
- #checkWater(): private method.
- makeCoffee(): public method.
| Loại             | Cú pháp  | Phạm vi truy cập       |
| ---------------- | -------- | ---------------------- |
| Public property  | `name`   | Bên ngoài và bên trong |
| Private property | `#name`  | Bên trong class        |
| Public method    | `run()`  | Bên ngoài và bên trong |
| Private method   | `#run()` | Bên trong class        |

Lưu ý: Private field/method được kiểm tra ngay ở thời điểm phân tích cú pháp, nên việc truy cập sai có thể khiến cả đoạn code không chạy.
5.3. Private fields và inheritance
Private field của class cha không thể được truy cập trực tiếp từ class con
<!-- 
class Animal {
    #name = "Dog";
}

class Rabbit extends Animal {
    showName() {
        return this.#name;
    }
}

const rabbit = new Rabbit();

rabbit.showName(); // SyntaxError
 -->
Tại sao?
- #name được khai báo bên trong Animal
- Rabbit kế thừa Animal
- Nhưng private field được không dược phép truy cập từ class con
Nếu muốn class con sử dụng dữ liệu private của class cha , có thể cung cấp public hoặc protected-style method để truy cập.
<!-- 
class Animal {
    #name = "Dog";

    getName() {
        return this.#name;
    }
}

class Rabbit extends Animal {
    showName() {
        return this.getName();
    }
}

const rabbit = new Rabbit();

console.log(rabbit.showName()); // Dog
 -->
Ở đây, Rabbit không truy cập trực tiếp #name, mà gọi getName() được cung cấp bởi Animal.
Ghi nhớ :
- extends cho phép kế thừa public và protected-style properties/methods
- Private fields vẫn thuộc phạm vi riêng của class khai báo chúng
- Class con không thể truy cập trực tiếp private field của class cha.

5.4. Private fields không truy cập bằng this[name]
Với public property, bạn có thể truy cập bằng cú pháp bracket notation:
<!-- 
class User {
    name = "Martin";
}

const user = new User();

const property = "name";

console.log(user[property]); // Martin
 -->
 Nhưng private field thì không thể:
 <!--
 class User {
    #name = "Martin";

    getName() {
        const property = "#name";

        return this[property];
    }
}

const user = new User();

console.log(user.getName()); // undefined 
  -->
Tại sao?
- this[property] tìm một property thông thường có tên "#name".
- Private field #name không phải property thông thường.
- Private field được JavaScript quản lý bằng cơ chế riêng.
Muốn truy cập private field, phải viết trực tiếp:
<!-- getName() {
    return this.#name;
} -->
### Ghi nhớ:

| Cách truy cập    | Public        | Private             |
| ---------------- | ------------- | ------------------- |
| `this.name`      | Có            | Không               |
| `this["name"]`   | Có            | Không               |
| `this.#name`     | Không áp dụng | Có, bên trong class |
| `this[property]` | Có            | Không               |
Bài tập :
<!-- 
class User {
    #name = "Martin";

    getName() {
        return this["#name"];
    }
}

const user = new User();

console.log(user.getName());
 -->
Tại sao không phải SyntaxError?
Vì this["#name"] là cú pháp JavaScript hợp lệ. Nó tìm một property thông thường có tên chuỗi "#name".
Trong khi đó, private field #name là một cơ chế riêng, không phải property thông thường có tên "#name"
<!-- 
this.#name       // Truy cập private field
this["#name"]    // Tìm property thông thường "#name"
 -->

6. Summary

1. A real-life example
- Encapsulation giúp ẩn các chi tiết triển khai bên trong.
- Bên ngoài chỉ cần sử dụng những chức năng được cung cấp.
2. Internal and external interface
| Khái niệm          | Ý nghĩa                                  |
| ------------------ | ---------------------------------------- |
| Internal interface | Phục vụ hoạt động bên trong class        |
| External interface | Cung cấp chức năng cho bên ngoài sử dụng |
3. Protecting "waterAmount"
Public property có thể bị thay đổi trực tiếp.
_waterAmount là quy ước Protected, không có bảo vệ thực sự.
Getter/setter giúp kiểm soát quá trình đọc và ghi dữ liệu.

1. Read-only "power"
- Getter không có setter cho phép đọc nhưng không thể gán qua accessor trong strict mode.
- Có thể sử dụng getter/setter hoặc các method getPower() / setPower().
1. Private "#waterLimit"
- #property: private field.
- #method(): private method.
- Private chỉ truy cập được bên trong class khai báo.
- Class con không thể truy cập trực tiếp private field của class cha.
- Không thể truy cập private field bằng this[name].
