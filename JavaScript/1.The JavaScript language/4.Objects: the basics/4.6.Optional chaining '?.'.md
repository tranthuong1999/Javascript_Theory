Mục 1. The “non-existing property” problem
1.1. Vấn đề cần giải quyết

1.2. Cách xử lý trước khi có ?.
const user = {};

const street = user.address
    ? user.address.street
    : undefined;

console.log(street); // undefined
const street =
    user.address && user.address.street;

console.log(street); // undefined
Bài tập thực hành :

const product = {
    name: "Laptop"
};

console.log(product.category.name);
1. product tồn tại.
2. product.category không tồn tại nên trả về undefined.
3. JavaScript tiếp tục truy cập undefined.name → phát sinh TypeError.
Phân biệt quan trọng:
- Truy cập thuộc tính không tồn tại trên object hợp lệ: thường trả về undefined.
- Tiếp tục truy cập thuộc tính của undefined hoặc null: gây TypeError.

Mục 2. Optional chaining ?.
2.1. ?. là gì?
?. (optional chaining) cho phép truy cập thuộc tính an toàn phía trước nó là null hoặc undefined
2.2. Cú pháp và cách hoạt động
object?.property

const user = null;
console.log(user?.name); // undefined
JavaScript dừng tại ?., không phát sinh TypeError.
2.3. Khi truy cập nhiều cấp, phải đặt ?. đúng vị trí
const user = {};
console.log(user?.address.street);   // TypeError
console.log(user?.address?.street);  // undefined
2.4. Không nên lạm dụng ?.

const user = {
    profile: null
};

console.log(user?.profile?.name);

Mục 3. Short-circuiting — Dừng thực thi giữa chừng
3.1. Short-circuiting là gì?
Short-circuiting nghĩa là JavaScript nghĩa là JS dùng đánh giá phần còn lại của biểu thức khi ?. gặp 
gía trị null hoặc undefined
let user = null;
let x = 0;

user?.sayHi(x++);

console.log(x); // 0
1. user là null.
2. user?. dừng thực thi.
3. JavaScript không gọi sayHi().
4. Biểu thức x++ cũng không được thực hiện.
Nếu users tồn tại , JS mới tiếp tục đánh giá phần còn lại
3.2. So sánh hai trường hợp
3.3. Điểm dễ nhầm
?. không có nghĩa là bỏ qua toàn bộ biểu thức trong mọi trường hợp. Nó chỉ dừng khi giá trị ngay bên trái nó là null hoặc undefined.

Bài tập tự luyện :
let product = null;
let count = 10;

product?.buy(count++);

console.log(count);

Mục 4. Other variants: ?.(), ?.[]
4.1. ?.() — Gọi một hàm có thể không tồn tại
Giả sử mỗi user có thể có hoặc không có phương thức admin().
const userAdmin = {
    admin() {
        console.log("I am admin");
    }
};

const userGuest = {};

userAdmin.admin?.(); // "I am admin"
userGuest.admin?.(); // Không có gì xảy ra
Lưu ý quan trọng : userGuest.admin?.(); chỉ bảo vệ trường hợp admin là null hoặc undedined .
Nếu admin tồn tại nhưng không phải hàm , JS vẫn báo lỗi TypeErrror

Ví dụ : 
const user = {
    admin: "yes"
};

user.admin?.(); // TypeError
4.2. ?.[] — Truy cập thuộc tính bằng biến
Bạn đã biết cú pháp ngoặc vuông obj[key] dùng khi tên thuộc tính nằm trong biến.
Nếu user có thể là null hoặc undefined, dùng ?.[]:

const key = "firstName";

const user1 = {
    firstName: "John"
};

const user2 = null;

console.log(user1?.[key]); // "John"
console.log(user2?.[key]); // undefined

user?.[key]
   │
   └── Nếu user là null/undefined → undefined
       Nếu user tồn tại           → đọc user[key]

4.3. Có thể dùng ?. với delete, nhưng không dùng để gán giá trị
Xóa thuộc tính an toàn:
const user = null;
delete user?.name; // Không lỗi
Nhưng không thể dùng optional chaining ở vế trái phép gán
const user = null;
user?.name = "John"; // SyntaxError

Bài tập tự luyện 
const user = {
    name: "Martin"
};

const key = "name";

console.log(user?.[key]);
console.log(user.admin?.());
Ghi nhớ
user?.[key]  → truy cập thuộc tính bằng key một cách an toàn
user.admin?.() → gọi hàm nếu admin tồn tại

Mục 5. Summary — Tổng kết Optional chaining ?.

Optional chaining '?.'
├── 1. Truy cập thuộc tính
│   ├── user?.name

│   └── user?.address?.street
├── 3. Gọi hàm tùy chọn
│   └── user.admin?.()
├── 4. Truy cập key động
│   └── user?.[key]
├── 5. Short-circuiting
│   └── Dừng đánh giá phần còn lại khi gặp null/undefined
└── 6. Giới hạn
    ├── Không bảo vệ biến chưa khai báo
    ├── Không tự động bảo vệ các cấp tiếp theo
    └── Không dùng làm vế trái phép gán

const data = {
    user: null
};

console.log(data.user?.name);
console.log(data.user.name);
