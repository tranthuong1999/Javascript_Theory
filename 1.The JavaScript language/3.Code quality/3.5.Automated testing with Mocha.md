Mục 1 — Why do we need tests?
function sum(a, b) {
  return a + b;
}

console.log(sum(2, 3)); // 5
Vấn đề lá sau này sửa hàm làm sao biết các trường hợp cũ vẫn đúng
Vô tình sưa hầm code :
function sum(a, b) {
  if (a === 1) {
    return 3;
  }

  return a - b; // Lỗi: đáng lẽ phải cộng
}
2. Automated testing là gì?
Là kiểm thử tự động là viết các đoạn code riêng để:
1. Gọi hàm với đầu vào đã chọn 
2. Xác định kết quả mong đợi 
3. So sánh kết quả thực tế với kết quả mong đợi
4. Báo lỗi nếu kết quả không khớp
   
Mục 1 — Why do we need tests?

- Kiểm tra thủ công dễ bỏ sót trường hợp.
- Sửa code có thể làm hỏng chức năng đang hoạt động (regression).
- Automated testing chạy hàm với nhiều đầu vào và so sánh kết quả thực tế với kết quả mong đợi.
- Mục tiêu: phát hiện lỗi sớm và tự tin hơn khi thay đổi code.

Mục 2 — Behavior Driven Development (BDD)
Mô tả BDD là 3 thứ kết hợp : test + documentation + examples
1. BDD là gì?
 Ví dụ, ta muốn viết hàm pow(x, n):
pow(2, 3) phải trả về 8.
pow(3, 4) phải trả về 81.
2. Spec có ba vai trò
Test _ kiểm thử: Xác nhận hàm có cho kết quả đúng như mong đợi không.
Documentation - Tài liệu : Tên các test giúp người đọc hiểu chức năng được kỳ vọng hoạt động như thế nào.
Examples — Ví dụ: Test cho thấy cách gọi hàm và kết quả tương ứng.

****************************************
Mục 2 — Behavior Driven Development (BDD)

BDD = Tests + Documentation + Examples

- Spec: mô tả hành vi mong đợi của chương trình.
- describe(): nhóm các test theo chức năng.
- it(): mô tả một trường hợp kiểm thử.
- assert: kiểm tra kết quả thực tế với kết quả mong đợi.

Mục tiêu: xác định hành vi cần có, kiểm tra nó và dùng test
để người khác hiểu chức năng của code.

Mục 3 — Development of pow: the spec
1. Xác định yêu cầu của hàm
Trước khi viết hàm ta cần xác định những kết quả mà hàm phải trả về . Các case này là cơ sở để viết test
2. Viết spec trước khi viết code
describe("pow", function() {
  it("raises to n-th power", function() {
    assert.equal(pow(2, 3), 8);
  });
});
3. Hiểu luồng thực thi
Mục 3 — Development of "pow": the spec

- pow(x, n): tính x mũ n, với n là số nguyên không âm.
- Spec: mô tả hành vi mong đợi và các trường hợp kiểm tra.
- describe(): nhóm test theo chức năng.
- it(): mô tả một trường hợp cần kiểm tra.
- assert.equal(actual, expected): kiểm tra hai giá trị có bằng nhau theo ==.
- Viết spec trước, sau đó mới cài đặt hàm.

Mục 4 — The development flow (Quy trình phát triển)
Quy trình phát triên BDD là 1 vòng lặp : viết spect => cài đặt => chạy test => bổ sung test => cải thiện code 
Viết spec => viết code => chạy test => sưa code hoặc bổ sung spec
2. Ví dụ với hàm pow(x, n)
it("2 raised to power 3 is 8", function () {
  assert.equal(pow(2, 3), 8);
});
Bước 2: Viết code ban đầu
function pow(x, n) {
  return 8;
}
Bước 3: Chạy test
Bước 4: Bổ sung test
Bước 5: Sửa code

Mục 4 — The development flow

1. Viết spec cho chức năng cơ bản.
2. Viết implementation ban đầu.
3. Chạy test và sửa lỗi.
4. Bổ sung use cases vào spec.
5. Chạy lại test và cập nhật implementation.
6. Lặp lại cho đến khi đáp ứng yêu cầu.

Ghi nhớ:
Spec → Implementation → Test → Improve → Repeat

Mục 7: Improving the spec
1. Mục tiêu
Improving the spec nghĩa là cải thiện và bổ sung các bài test để kiểm tra thêm những bào test ban đầu chưa phù hợp 
Improving the spec
├── Bổ sung test cho các trường hợp cần kiểm tra
└── Mỗi it() nên kiểm tra một hành vi rõ ràng

****************************************
Mục 8 — Improving the implementation

1. Chạy test để phát hiện lỗi.
2. Cập nhật implementation để xử lý đúng các trường hợp.
3. Dùng vòng lặp/helper function khi cần tạo nhiều test tương tự.
4. Chạy lại toàn bộ test để kiểm tra.

Mục tiêu: Code đáp ứng yêu cầu tổng quát,
không chỉ vượt qua một vài test cụ thể.

Mục 9 — Nested describe
1. Nested describe là gì?
2. Tại sao cần nhóm lồng nhau?
Mục 9 — Nested describe

- describe() ngoài: nhóm chức năng lớn.
- describe() trong: chia thành nhóm nhỏ theo hành vi.
- it(): một trường hợp kiểm thử cụ thể.

Hooks:
- before / after: chạy một lần trước / sau nhóm test.
- beforeEach / afterEach: chạy trước / sau mỗi test.

Mục đích: tổ chức test rõ ràng, dễ đọc và dễ tìm lỗi.

Mục 10: Extending the spec
1. Lý thuyết
Extending the spec là mở rộng đặc tả bằng cách thêm các trươngg hợp kiểm thử mới khi chức năng cơ bản đã hạot động 
2. Các assertion cần nhớ
| Assertion                  | Ý nghĩa                                    |
| -------------------------- | ------------------------------------------ |
| `assert.equal(a, b)`       | So sánh bằng theo `==`                     |
| `assert.strictEqual(a, b)` | So sánh bằng nghiêm ngặt theo `===`        |
| `assert.isNaN(value)`      | Kiểm tra `NaN`                             |
| `assert.isTrue(value)`     | Kiểm tra giá trị đúng chính xác là `true`  |
| `assert.isFalse(value)`    | Kiểm tra giá trị đúng chính xác là `false` |

Mục 10 — Extending the spec

1. Khi chức năng cơ bản hoạt động, xem lại yêu cầu.
2. Bổ sung test cho các trường hợp chưa được kiểm tra.
3. Chạy test để xác định implementation còn thiếu gì.
4. Cập nhật code để đáp ứng yêu cầu mới.
5. Chạy lại toàn bộ test.

Quy trình:
Mở rộng spec → Test thất bại → Cập nhật implementation → Test thành công
